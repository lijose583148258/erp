# 包装换算前置：物料基本单位治理 v1

## 为什么先做这一项

受控包装净量需要固定的计量基础。修复前隔离复现：基底提交 d6013e1，源码指纹 f5e2f2c843555b384004458fee50f6ea57800c7b1b7c89899d48547d6ab87b91；证据 output/round2/1790692661938-5191d2d0/material-unit-exploration.json。已经有库存、BOM 和工单的原料与成品，PATCH 基本单位 kg → t 都返回 200，主数据变成 t，历史库存及 BOM 仍为 kg。没有继续用错误单位记账；这里证明主数据与历史单位可漂移，不把未执行的后续损失当作事实。

## 本包规则

- 物料为 active、blocked、retired 时不能更改基本单位。不能先回到 draft 绕过：已有状态机禁止该逆向转换。
- 仅无任何持久化业务引用的 draft 可以改单位，且必须提交 expectedUpdatedAt。零余额、取消和已完成记录也算历史引用，不能因当前数量为零而忽略。
- 检查 13 类引用：BOM 原料/成品、工单、销售行、采购单、出库、批次、库存余额、库存流水、追溯输入/输出、货抵协议行/结算行。引用计数缺失时不开放编辑。
- 更新事务在读取之前锁定物料父行，生命周期和单位修改共用入口；采用 Serializable、已有有限整事务重试、当前版本 CAS 及严格递增毫秒时间戳。带同一旧版本的审批/改单位、两次改单位最多一方成功。
- 同单位回传及名称、合规备注等非计量修订仍可执行；不把整个物料主数据冻结。更新审计记录 beforeBaseUnit/afterBaseUnit。
- API 返回只读 baseUnitEditable；UI 对不可编辑的基本单位显示只读和原因，服务端独立拒绝绕过。该字段缺失时前端保守只读。
- 存在未保存表单修改时禁止审核、冻结或停用；保留输入并提示先保存回读。保存后使用服务器返回的规范值重置表单，再允许审批；审批后基本单位立即只读，刷新和双实例回读一致。
- 不改写已存库存、批次、BOM、工单或凭证；不自动迁移历史数量，不创建隐式换算或新库存。

## 验证与限界

新增校验并入现有 BOM API/浏览器累计检查，不删除前序义务，不增加 37 项目录的假通过。包含已生产物料拒绝前后的库存/成本/追溯/审计快照、无版本/旧版本拒绝、两种双实例竞争、零余额历史引用、真实管理员界面只读与草稿修正刷新回读。

零余额草稿是直接建立的隔离旧数据夹具，明确不是正常业务允许未放行物料入库；被测修改通过真实 API。并发证据覆盖本包物料更新/审批入口，不宣称已穷尽所有草稿业务写入与首次引用的竞争；正式库存/财务释放仍依赖既有 active+非临时物料闸门。

修复前后单测日志位于 output/review/material-unit-*.log；最终累计和 PostgreSQL 企业云结果须另行记入下面，不用类型检查或模拟单测代替。

## 后续包装净量包（本包未实现）

1. 独立的物料包装规格修订，不解析 specification 自由文本当作换算依据。字段至少包含物料身份、规格标识、包装单位、净质量数值/单位、版本、来源文件引用、创建/审核人和审核时间。
2. 草稿 → 审核放行 → 停用；已放行数值不能原地改写，更正创建新修订。启用前明确主单位、规格、净量和来源；审批与编制职责分开。
3. 首个垂直切片仅覆盖“质量单位原料 → 明确净量的包装成品”。BOM 显式引用批准规格并冻结规则/净量/单耗；规格修订不改变在制及历史工单。包装输入、拆零、混合包装和密度不暗中顺带支持。
4. 密度另包：来源、质量/体积单位、参考温度、批次适用范围与有效条件必须齐全；不把现有 BOM density 单值视为合法授权。
5. 新规格/作废规格与新 BOM/工单的竞争、重复审批、权限、数量/成本守恒、浏览器回读、旧库升级与 PostgreSQL 双实例共同验收。每个增量重放全部前序关键用例。

包装修订、审批 UI、数据库迁移和实际包装换算均未完成；本包只封住主单位直接改写入口。原 mass-packaging-density-conversion / conversion-cost-conservation 继续保持未完成。
