# 投入批次 QC 隔离与独立放行 v1

## 业务边界

本包修复生产完工耗料对投入批次质量状态的遗漏，同时在共享库存过账路径保护普通生产耗料、销售出库和货抵发出。授权隔离调拨、调整、退货/反冲不是普通发料，本包不把这些路径一律禁止，也不变更原权限矩阵。

实际闭环使用“已有库存支持的半成品批次关联上游待检工单 → 下游以其为投入料”。库存、检验、复核、完工均从正式 API 建立；Prisma 用于业务回读，账号创建使用已有测试夹具。不是采购收货质检新模块、独立领料/WIP、完整 20 岗位或多级召回验收。

## 最小实现

1. 在同一库存事务中，遵循既有“库位库存 → 批次”锁序，对实际投入批次取得写锁后再读取质量状态；锁持有至整笔事务提交。明确只允许 `released`、`not_required`，未知状态、缺失批次、错配物料身份均拒绝。失败返回类型化业务冲突，回滚工单、出入库、成本、追溯和成功审计。
2. 检验修订、质量审核与工单状态改变共用工单父记录锁；不改写历史时间戳。事务冲突有限重试；新检验不能穿过已完工/取消边界，旧检验修订不能放行。
3. 检验和审核成功审计移入质量事务，保留实际操作者、IP、User-Agent 和检验修订；审计失败不再吞掉。双审核人只允许一个真实决定，重复审核返回冲突且不增加成功审计。没有删除历史重复记录。
4. 既有 QC 面板显示历史审核依据，并明确“成品质检放行”不等于投入批次或库存自动合格。沿用既有设计，不重做页面布局。

## 验收用例

- `qc-quarantine-blocks-issue`：待放行/隔离批次拒绝后全量业务快照不变；已放行对照正常消耗 10 kg，成本 -100/+100，产出、追溯和两实例回读一致。
- 失败检验不能放行；权限不足的仓库账号被拒；拥有检验和放行双权限的同一账号也不能自审。
- 两个检验账号并发生成相邻且不重复修订；过期修订复核被拒；两个审核人跨实例分别放行/拒绝，恰一个成功，质量投影对应赢家，旧检验不变，重复决定不增加审计。
- `qa-release-traceability-browser`：仓库检验账号在真实界面复检、待审核不能自审；独立经理审核账号不能录检验，真实点击放行；旧失败记录、第二人身份及审核依据可读。放行后下游耗料 API 成功、重复完工全状态不变，原检验账号刷新读到相同审核人。
- 通用发料守卫的 `pending_qc`、未知/空状态、身份缺失/错配、允许的例外路径由服务单测覆盖；本包没有把这些单测说成逐一完成的销售/货抵隔离浏览器业务链。
