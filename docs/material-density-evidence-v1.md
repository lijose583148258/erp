# 批次密度依据台账 v1（本地/企业云累计已通过；不等于密度换算已交付）

## 发现与本包边界

原 ProductionBom.density 只是无单位、批次、测定条件和审批的 Float 参考字段。它目前不参与生产领料换算，不能把录入一个数值或批准一个记录当成可跨单位扣库存的授权。

本包只交付有业务界面的来源依据台账，不新增换算模式、不改变历史 BOM、QC、库存数量或成本，不关闭 R2-06 的任何全量条件。未来真正的体积/质量领料还须验证实际批次与操作条件、冻结工单使用的依据、精确计量及批次成本守恒，禁止默认为已完成。

## 数据与治理契约

- 依据按物料、真实批次、编码、版本唯一。保存物料/批次外键及批次号、主单位快照；草稿也不原地覆写，错误另建版本。
- densityKgPerL 明确为 kg/L 十进制文本，测定温度 °C、绝对压力 kPa、组分/浓度及适用条件、方法/报告编号、来源文件编号、测定时间全部必填。不推断密度单位，不默认温度/压力，不做温压外推。
- 来源由编制人与批准人核对，本软件不自动鉴定检测报告真实性，不声称任意物料在其他批次或测定点有相同密度。
- production.read 是批次依据接口的共同权限前提；读取还需 materials.read，编制需 materials.write，批准/停用需 materials.govern。禁止自批，版本戳强制校验，事务内锁定记录、状态 CAS 与审计同事务。
- 允许记录 QC 隔离批次的密度依据，但批准密度绝不解除隔离。台账状态与批次 QC 状态分开；不会自动领料、出库、建立 BOM 或改成本。
- 新记录重新核对物料启用状态、原料/半成品类别、物料与批次身份及单位一致。停用不要求物料仍启用，避免冻结错误依据后无法撤销使用资格。
- 使用新增 MaterialDensityRevision 表；主数据单位冻结计数纳入密度记录。SQLite 幂等创建与 PostgreSQL 版本迁移；导入顺序在物料/批次之后。旧参考密度不自动迁入批准台账。

## 用户路径

生产配方页 → “批次密度依据 · 独立核对台账”：选择物料、填写真实批次和测定报告内容、保存后回读 → 另一位治理权限人员填写核对依据并批准 → 刷新查看来源、测定点和批准人。停用只改变依据状态，不修改原值。旧 BOM 的“密度”入口更名“参考密度（不用于库存换算）”。

## 验收门禁

新增探针接入原 QC 隔离 API 链及 QC 独立放行浏览器链；每次累计必须完整重放此前已通过工作包，固定 37 项目录不缩减。

- 自批、越权、缺条件、无来源、错误批次、未来测定、重复版本、过期版本戳、覆写、复活已停用版本必须拒绝且不增加审计或记录。
- 双实例同一批准人重复提交只能批准一次；不冒充两个不同岗位参与审批。
- 使用真实 QC 隔离的批次，比较密度台账操作前后完整批次/库存/移动/成本/QC/工单与 BOM 数量，必须不变。
- 批准密度记录后，旧自由密度仍不能授权 L/kg 百分比换算。
- 真实浏览器由 manager 编制、admin 独立批准；刷新及两个 API 实例回读一致，桌面/移动端截图人工复核。
- 旧库新建隔离副本重复升级，旧表行不变、无推断生成的密度记录。原业务库不删除任何表。
