# 采购关联补货计划 v1（R2-01 的有界前置包）

## 已实现的边界

销售订单 → 本订单已审批采购单 → 只读版本快照的补货草稿 → 独立审批 → 真实采购收货 → 仓库调拨 → 销售出库 → 客户正常签收 → 有证据结案。

- 实际入口：`#orders` → 履约动作 → 精确订单行的「采购补货计划」。中、英、越三语；移动端可用。
- 创建权限 `orders.update`，读取 `orders.read`，审批/结案 `orders.status.manage`；全部还要通过后端订单数据范围。销售同事不能读取或写入别人的私有订单。
- 采购必须绑定当前订单，物料、单位一致，且已审批。计划冻结采购修订号、数量、单位、预计到货时间。采购变更后即使重新审批，旧计划也不能直接通过或结案。
- 创建人（包括管理员）不能自批。审批同时锁定订单与采购来源，累计已审批/已结案承诺不得超过订单数量和来源数量；两个审批人跨实例竞争同一来源只能一方获得剩余额度。
- 计划不创建、预留或扣减实物库存，不登记回款，不修改库存成本。收货/调拨/出库仍走现有过账链。
- 只有整单正常交齐且来源采购实收批次的客户正常签收能覆盖该来源累计承诺，才允许结案。结案固化采购收货、发货、签收 ID 与数量，保留审计。
- 创建与结案具备服务端幂等键；键复用但业务事实/操作人改变返回冲突。审批采用版本匹配，不自动覆盖。
- 浏览器提交期间防双击；创建请求先存储当前会话的固定请求键。不明确提交结果只能回读；已成功 POST 后 GET 即使返回 4xx，也不会重新开放新增提交。
- 已关联计划的订单行不能用 `deleteMany + create` 原地替换，返回 409，保留历史证据。
