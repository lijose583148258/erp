# 回款登记持久请求身份验收 v1

## 交付边界

本包对应固定目录 `payment-submit-durable-replay`，与已经验收的核销事件投递 `payment-event-audit-once` 分开。只新增登记幂等，不把应用重启说成数据库服务器重启，不涵盖部分退款、余额结转、全岗位权限或整页 UI 改版。

正式进度暂保持已验收的 **23/37、14 未完成**，直到本包最终源码累计与 PostgreSQL 企业云原始证据均完成独立核对。37 项目录不缩减，每包必须重放前序所有包关键用例。

## 实现与兼容规则

- 所有新登记必须传稳定 `Idempotency-Key` 头或 `idempotencyKey` 载荷；两者同时存在必须一致。键为 8–100 位 ASCII 标识。缺失键 400，不退回时间窗口猜测。现有销售入口和内部真实审计调用点同步升级。
- 订单锁与 Serializable 事务中一次写入回款、PAYMENT_SUBMITTED 审计及 `payment_submissions` 原始回执；数据库唯一键防止跨实例、跨订单竞争。同键同事实返回原回执、当前订单读回，既不重复记账，也不重复登记通知。同键改金额、方式、日期、付款人、备注、代付标志、订单或主体均拒绝。
- 原回执是登记时的不可变 pending 回执，不冒充回款当前状态；核销后可重放原请求，响应中的订单另行反映最新状态。不同键允许同金额的真实第二笔回款，仍受已核销余额和待核销容量约束。
- 本入口当前登记 CNY，拒绝被忽略的外币/汇率/不一致本位币字段。多币种回款另需完整换算验收，不从本包推断支持。
- 浏览器发送前可靠保存 actor/order 隔离的请求身份和事实；双击只提交一次，未知回执后保留原事实并锁定编辑。刷新重新打开仍用原键确认，不生成新请求。存储损坏、拒写、清理失败均关闭新登记通道，而非冒险建立新键。
- 本地草稿含付款人、备注及金额等业务字段，保存在当前浏览器 localStorage，非外部模型数据。不同用户/订单不共用槽位；未知请求不自动过期或随登出丢弃，避免恢复时重复入账。确认成功或明确事务拒绝后才清理本键。共享设备仍需账号退出与浏览器档案隔离管理。
- 新表只保护新登记，不为历史回款伪造请求键。SQLite 插入检查及 UPDATE/DELETE 拒绝触发器、PostgreSQL CHECK/RESTRICT/不可变触发器均实施。仅新增 `202610030001_payment-submission-identities`，不修改此前已应用迁移或其校验和。
- 登记后通知仍是现有 best-effort 路径，本包不声称 `payment.submitted` 通知持久投递；核销事件 outbox 的前序保证单独累计重放。
