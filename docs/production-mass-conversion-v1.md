# 显式质量百分比换算 v1

## 本包边界

R2-06 前置增量：支持明确选择 `mass_percentage_v1` 的质量百分比 BOM 行，范围为 mg/g/kg/t 及列明的中文质量单位。不实现包装净含量或密度；不提升原 37 项目录中的完整 `mass-packaging-density-conversion` / `conversion-cost-conservation`，不缩减此前累计义务。

旧 `percentage` 含义不变：输入/输出单位不同仍拒绝。`fixed` 仍为经过核定的输入单位/输出单位单耗，包括既有 20 kg/桶。创建请求只接受已知用量模式，未知规则版本不再回落为固定单耗。

## 冻结模型与精度

- 冻结元组：BOM 行的 `dosageMode=mass_percentage_v1`、`percentage`、输入 `unit`、计算后的 `quantityPerUnit`，以及 BOM 的 `outputUnit`。
- 规则 v1 使用固定质量比例。未来规则变化必须使用新版本标识，不改写 v1；既有 BOM 引用冻结继续约束工单和治理回填/回滚。
- 服务端计算 `quantityPerUnit`，不信任客户端提交的规范单耗；客户端共享同一无外部依赖的计算模块，用于预览、桌面/移动行、粘贴和保存回读核对。
- 用 BigInt 十进制有理数运算避免先进行浮点比例乘法。结果必须能无损保存为库存六位小数；不能精确表示、归零、溢出时明确拒绝，不自动舍入。
- 耗料预览和完工用冻结单耗计算目标量与损耗，实际要求量同样检查六位精度。新模式的数量验收不继承旧 0.001 最小容差，避免微量原料差异被掩盖。
- 新工单、预览、首次完工均校验冻结元组；旧模式不被追溯重新解释；已完工同状态重放不重写历史。
- 使用现有字段，无数据库迁移或新依赖。JSON/API 仍返回原字段。历史数据中的伪造/损坏 v1 元组拒绝继续执行，不自动修正其旧记录。
