# 受控包装净量 v1（本包本地/企业云累计验证通过；全量验收未完成）

## 范围与计量契约

- 仅“质量单位原料 → 单一批准净量的整桶/袋/罐/瓶成品”。原料可用不同质量单位；各行质量占比必须恰好 100%，单耗和实际耗用必须能无损表示为库存六位小数。
- 新增不可原地修改的包装规格修订，持久化物料身份、规格编码、版本、包装单位、十进制净质量文本/单位、来源文件编号、编制人和独立批准人/时间。草稿错误也新建修订；同一物料/规格/版本唯一，重复请求不会生成第二份。
- 草稿由 materials.write 编制；批准、停用由 materials.govern 操作，编制人不能自批。当前沿用已有管理员治理权限，不宣称 20 岗位完整权限矩阵已经完成；可由已有权限管理分配治理权。
- 来源是用户声明并由审核人核对的文件/编号，本包不自动判断外部文件真实性，也不从自由规格文本、密度数值或模型推测净量。
- 新模式 packaging_percentage_v1；BOM 仅接受批准规格 ID，服务端读取并冻结完整 provenance 快照和计算出的单耗，不接受客户端伪造快照或任意单耗。旧 fixed/percentage/mass_percentage_v1 语义不变。
- 创建 BOM、停用规格、新建工单共用规格行锁。停用后不允许新 BOM/新工单；已在制工单仍使用原绑定 BOM/净量。发布新修订不改变旧配方和历史凭证。
- v1 禁止拆零、配方损耗、非零容差和替代组；实际整包装数必须等于计划数。生产损耗、余料/返工/报废成本另包，不能默认正确。
- UI 单独入口“受控包装净量 · 版本与配方”，使用既有物料选择器/表单样式，配方创建带单包装净质量结构化 QC 上下限（明确等于批准净量），仍须检验与独立放行才完工。
- 不把包装实物耗材成本计入本包：桶/标签等包装物领用、混合包装与密度不在范围。成本验收限已投入质量原料到包装成品的账本守恒，不宣称完整生产成本已完成。

## 数据库和回归

新增 MaterialPackagingRevision；BOM 增加可空规格外键及冻结 JSON，旧 BOM 不回填、不重新解释。SQLite 幂等升级及 PostgreSQL 版本迁移均需验证；迁移顺序先主数据规格、后配方引用。物料基本单位的引用检查同时纳入包装修订。

新增 API/真实浏览器探针接入已有 BOM 累计链；旧库包装升级接入现有独立迁移回放，保留之前货抵升级原有断言。每次完整重放之前所有包，37 项原始验收目录不缩减，R2-06 的密度与完整换算成本条件仍未完成。

## 操作与恢复边界

1. 先在物料主数据批准包装成品，主单位为桶/袋/罐/瓶，填好保质期；质量原料也须已启用。
2. 进入生产与售后 → 配方页 → “受控包装净量 · 版本与配方”。编制人选择成品，填写规格编码、版本、净质量、质量单位、来源文件编号并保存。
3. 由另一位具备 materials.govern 权限的人核对来源，填写审核依据并独立批准。制单与审批分离不等于所有 20 岗位权限已完成。
4. 选择批准规格，填新 BOM 版本、质量原料及总计 100% 的占比，核对每包装单耗后创建。刷新后查看冻结净量、来源与批准人；不要靠重按保存处理不确定回执。
5. 工单填写正整数计划/实际包装数，损耗为 0；按冻结单耗领料。检验员填净质量实测，另一人 QC 放行后完工。数量、批次追溯和投入原料成本须同时对得上。
6. 规格错误不覆写，不删除历史 BOM 或凭证。另建并批准新版本，按需要停用旧规格；旧在制工单保持原依据，新工单不得继续选择停用规格。

升级前备份业务库。此包只新增表和可空字段，不自动将历史自由规格解释为包装净量。回退应用程序不能撤销已发生的包装生产业务；不可用删除新表/旧凭证的方式“回滚”。实际业务库升级、密度、包装耗材成本、损耗余料及全量故障恢复仍须各自验收。
