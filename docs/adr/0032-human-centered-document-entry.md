# ADR 0032：复杂业务单据采用“单据头 + 明细行 + 保存回读”交互

- 状态：Accepted
- 日期：2026-07-29
- 适用范围：BOM、销售订单、采购订单、收货、发货、回款、库存调整

## 问题

复杂 ERP 页面不能只保证字段齐全。用户还必须能立即判断：

1. 当前在填写哪个业务对象；
2. 字段属于单据头、哪一条明细或哪个后续动作；
3. 哪些必填、哪些可稍后补、哪些由系统计算；
4. 下拉项改变后会影响哪一列、哪张台账和哪个后续流程；
5. 错误属于哪一行、哪一字段；
6. 保存后实际写入了什么。

如果这些关系不清楚，即使接口和数据库正确，页面仍属于不可稳定使用。

## 参考模式

采用金蝶星辰、Odoo、ERPNext 等成熟产品中反复出现的交互结构，但不复制其代码或商业资源：

- 单据级字段放在紧凑的“单据头”；
- 可重复业务对象放在有明确行号的“明细行”；
- 日常字段默认可见，高级字段按需展开；
- 支持模糊查找、快速粘贴、批量填充和键盘连续录入；
- 系统计算值与人工输入值视觉分离；
- 保存后必须提供只读回读和下游影响说明；
- 移动端改为逐行卡片，不把十几列桌面表格压缩到窄屏。

- 金蝶云星辰进销存：https://www.jdy.com/domain/invoicing/
- 金蝶云星辰移动应用：https://www.jdy.com/yjxc-mobile/

## 强制规则

### 1. 对象边界

- 页面必须显示“当前对象”。
- 每一明细行必须有稳定行号。
- 字段的 `label`、`aria-label`、错误提示必须包含业务含义；行错误还要包含行号。

### 2. 字段层级

- 默认层只保留高频必填字段。
- 低频、模拟、诊断和技术字段进入高级区。
- 模拟库存、成本和风险不能伪装成真实台账数据。

### 3. 输入效率

- 明细支持新增、复制、删除、粘贴导入。
- 物料主数据完成后，编码字段必须支持编码、名称、规格的模糊查找。
- 批量填充必须先预览影响行，不能静默覆盖。

### 4. 结果可解释

- 保存按钮说明写入对象。
- 保存成功后必须从服务端重新读取，并逐字段核对关键值。
- 页面必须说明后续会影响工单、库存、应收或会计凭证中的哪些对象。

### 5. 响应式布局

- 桌面端使用紧凑表格并固定行号、操作列。
- 移动端使用一行一卡片，字段按业务顺序纵向排列。
- 不允许把宽表仅靠横向滚动当作移动端适配完成。

## 首个落地：生产 BOM

当前 BOM 页面已经实施：

- 配方主数据与原料明细分区；
- 当前对象、当前行和字段归属提示；
- 三条默认空行，空白行不再误报为无效数据；
- 日常字段与高级列分离；
- 固定单耗和百分比只显示当前有效的用量输入；
- 计划模拟明确标注“不写库存台账”；
- 移动端逐行卡片；
- 保存后只读回读；
- 浏览器人工录入覆盖固定单耗与百分比混合行。

尚未完成：

- 物料主数据模糊搜索与行内新建；
- 批量填充预览；
- 中文拼音和越南文 Telex 物理 IME 验收；
- 从 BOM 行直接展示真实可用库存时的数据来源与刷新时间；
- 将本规范推广到销售、采购、仓储和财务的全部复杂单据。

## 验收门禁

每个复杂单据至少验证：

1. 首次使用者能在 30 秒内指出单据头、明细行和保存结果；
2. 逐字段键盘输入、下拉选择、复制、删除、粘贴可完成；
3. 错误精确定位到字段和行；
4. 保存后服务端回读一致；
5. 360、390、430、768、1024、1280、1366、1440 宽度无阻断；
6. 中文/越南文 IME、弱网、长会话和真实角色在目标 Windows 上人工通过。
