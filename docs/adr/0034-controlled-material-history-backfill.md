# ADR 0034：历史自由文本物料采用“预览—人工确认—原子写入—可回滚”治理

- 状态：Accepted
- 日期：2026-07-30
- 适用范围：统一物料主数据、历史生产 BOM 明细

## 背景

历史 BOM 使用 `materialName`、`materialCode` 和 `unit` 自由文本。直接按名称自动合并会把同名异物、异名单物、不同单位和临时物料误关联；继续保留自由文本又会让库存、成本、质量和批次追溯长期漂移。

## 决策

1. 历史文本继续保留，只新增 `ProductionBomItem.materialId` 关系，不改写原名称、编码和单位。
2. 系统只生成编码、中文/英文/越南文名称或受管别名的**精确匹配**提示，不使用模糊结果自动写入。
3. 只有 `materials.govern` 可以预览、执行和回滚；该权限默认只授予管理员，不随 `materials.write` 下放。
4. 每个来源组由“历史名称 + 历史编码 + 单位”组成。目标必须是已启用、非临时且基础单位一致的正式物料。
5. 预览返回该组全部明细 ID 的 SHA-256 指纹。执行时重新读取并核对数量和指纹；任何变化都拒绝整批写入。
6. 每批最多修改 500 条明细，并在单一数据库事务中写入关系、逐条变更记录和审计日志。
7. 回滚只清除仍指向本批目标物料的关系。存在后续修改时拒绝整批回滚，不能覆盖新业务数据。
8. 相同输入只有在历史批次仍与当前数据完全一致时才返回幂等成功；状态漂移必须显式报错。

## 页面层级与交互

治理入口与“新建物料”分开，避免把高风险批量动作伪装成普通编辑。

1. 页面头先说明不改历史文本、不会自动写入。
2. 固定展示三步：核对来源 → 选择目标 → 保存回读与审计。
3. 表格一行只回答四个问题：原来是什么、影响多少、要关联到哪里、是否已人工确认。
4. 唯一精确匹配可以预填下拉框，但复选框默认不选；执行按钮在明确勾选前禁用。
5. 手机端把同一行转换为顺序卡片，不横向压缩四列。
6. 执行和回滚都必须经过二次确认；未提交选择关闭时必须提示。
7. 动效只用于抽屉进入和层级切换，遵循 `prefers-reduced-motion`，不使用影响录入节奏的装饰动画。

## 后果

- 优点：不会静默误合并；并发预览过期会失败；每次变更可追踪、可回读、可安全回滚。
- 代价：管理员需要逐组核对；超大历史数据要分批执行。
- 后续：采购、库存、批次和销售自由文本迁移复用同一治理运行/变更模型，但必须分别定义实体规则，不能用一个“万能回填”绕过业务边界。
