# ADR 0041：受控单据物料放行边界与人工修复

- 状态：已接受
- 日期：2026-08-01

## 背景

销售、采购、库存、发货、货抵和产品批次仍允许在草稿阶段录入自由文本，方便历史资料补录和信息不完整时保存。但自由文本不能直接形成已确认订单、已批准采购、库存流水、发货或货抵过账，否则同名异物、单位漂移和临时物料会进入企业事实账。

仅在页面上把输入框改成下拉框不构成控制：API、导入、并发请求和旧客户端仍可能绕过前端。仅在状态变更前查询一次也不安全，因为检查和写入之间可能被并发修改。

## 决策

1. 草稿允许缺少 `materialId`，但受控状态和过账必须关联存在、启用、非临时的统一物料。
2. `assertMaterialReleaseReadiness` 是统一后端放行合同。订单确认、采购批准/在途/收货、发货创建、库存记账、货抵批准/过账和产品批次创建必须调用该合同。
3. 放行检查与状态抢占或业务过账位于同一数据库事务。检查失败时，状态、回款、库存和流水全部回滚。
4. 单位必须与物料基础单位一致；显示名称由物料主数据回填，业务代码不得根据相似文本自动猜测物料。
5. 历史已过账物料停用后，允许库存调整、调拨、冲回及完全相同的幂等重放；停用物料不得产生新的采购收货、发货或普通入库事实。
6. 失败响应采用 `material-release-readiness/v1`，逐行返回行号、当前名称、物料编号、失败原因、请求单位和基础单位。
7. 前端以非阻塞修复面板展示问题，只提供“留在原单修复”和“打开物料中心”两个明确动作。不得静默改值、跳页或用动效掩盖错误。
8. 修复面板遵循统一页面层级：单据上下文在上、逐行问题在中、操作在下；动效只用于状态反馈，持续时间 150ms，并尊重 `prefers-reduced-motion`。

## 可验证合同

- 未关联物料的草稿可保存，但确认/批准/过账返回 HTTP 409。
- 响应中的每个问题可定位到确定的单据行，且不泄露堆栈或数据库细节。
- 两个并发确认请求最多一个修改状态；失败的放行检查不得留下中间状态。
- 重复库存 requestId 只允许完全相同的物料、库位、批次、单位和数量。
- 已过账记录在物料停用后仍可精确幂等回读，但同一停用物料的新普通过账被拒绝。
- 浏览器审计必须通过真实物料选择器录入受控单据，并在 API 和数据库回读 `materialId`。

## 后果

正面结果是业务可以继续“先存草稿、后补资料”，同时企业事实账不再依赖自由文本。错误会落到具体行并给出修复路径，减少用户面对泛化 409 或未知下拉逻辑时的困惑。

代价是历史草稿在首次确认前必须完成物料治理，自动化审计数据也必须创建脱敏统一物料。旧数据不做静默批量绑定；应通过治理候选、人工确认和指纹校验分批回填。

## 回滚

前端修复面板可独立撤回而不改变后端安全边界。后端放行边界不得通过功能开关关闭；若发布出现兼容问题，只允许保留草稿状态并暂停受控过账，不能恢复自由文本直接入账。
