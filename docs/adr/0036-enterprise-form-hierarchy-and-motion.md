# ADR 0036：企业单据页面层级与动效必须可解释、可自检

- 状态：Accepted
- 日期：2026-08-01
- 范围：采购、销售、BOM、生产、仓储、财务等复杂录入页与数据表

## 决策

复杂页面统一采用五层信息结构：

1. **职责边界**：先说明当前页面记录什么、不记录什么，以及后续入口在哪里。
2. **当前对象**：显示正在编辑的供应商、客户、物料、订单、批次或工单。
3. **高频必填步骤**：按人类业务顺序编号分组，不使用一排无标签输入框代替字段关系。
4. **低频高级信息**：默认折叠，折叠按钮必须显示摘要、`aria-expanded` 和目标区域关系。
5. **保存结果与下游影响**：保存按钮必须说明写入的业务对象，以及不会立即发生的动作。

复杂表格统一遵守：

- 标题区说明表格对象、数据范围和刷新状态；
- 桌面表格固定关键身份列和操作列，金额、数量、日期、状态按类型对齐；
- 行编辑必须显示稳定行号，错误定位到行号和字段；
- 移动端使用任务卡片，不把横向滚动当作唯一适配；
- 空、加载、错误、无权限和数据过期状态必须彼此可区分；
- 大批量粘贴、删除、填充必须先预览影响，保存后从服务端回读。

## 动效边界

动效只用于解释状态变化，不用于装饰：

- 折叠、开关、焦点和选中反馈采用 120–200ms 的颜色或位移动效；
- 加载只允许局部旋转指示，不阻塞无关区域；
- 数据表载入、分页和大批量更新不做逐行动画，避免卡顿与视觉漂移；
- 下拉浮层使用 viewport 定位，空间不足时自动向上展开，禁止被卡片滚动容器裁切；
- 所有非必要动效必须支持 `prefers-reduced-motion`；
- 动效不得改变保存语义、吞掉键盘输入、延迟错误显示或制造布局跳动。

## 首个执行点：采购订单

采购订单新增区按以下层级执行：

- `1. 采购对象`：供应商与统一物料；
- `2. 数量、价格与到货`：数量、单位、单价与日期；
- 系统计算区：到岸成本明确标注为预估；
- 高级区：背靠背、币种、汇率、税费；
- 固定保存区：明确“生成采购承诺，不立即增加库存”。

统一物料下拉采用 Portal、键盘选择、查询失败与无结果分离、桌面/移动端自动翻转；物料选中后名称和基础单位由主数据控制。

## 自动自检门禁

每个改造页面至少保留以下证据：

1. 源码契约：编号分组、显式字段标签、折叠关系、开关语义、减少动效和保存影响说明；
2. 类型检查与正式构建；
3. 360/390/768/1024/1280/1366/1440 宽度的溢出与固定导航遮挡检查；
4. 键盘 Tab、方向键、Enter、Escape 与中文/越南文 IME；
5. 浏览器写入、API 回读、数据库身份字段回读；
6. 控制台错误、弱网、查询失败、无结果、无权限与重复提交状态。

只通过构建或只看到页面“好看”，均不得判定交互成熟。
