# ADR 0036：企业单据页面层级与动效必须可解释、可自检

- 状态：Accepted
- 日期：2026-08-01
- 范围：采购、销售、BOM、生产、仓储、财务等复杂录入页与数据表

## 决策

复杂页面统一采用五层信息结构：

1. **职责边界**：先说明当前页面记录什么、不记录什么，以及后续入口在哪里。
2. **当前对象**：显示正在编辑的供应商、客户、物料、订单、批次或工单。
3. **高频必填步骤**：按人类业务顺序编号分组，不使用一排无标签输入框代替字段关系。
4. **低频高级信息**：默认折叠，折叠按钮必须显示摘要、`aria-expanded` 和目标区域关系。
5. **保存结果与下游影响**：保存按钮必须说明写入的业务对象，以及不会立即发生的动作。

复杂表格统一遵守：

- 标题区说明表格对象、数据范围和刷新状态；
- 桌面表格固定关键身份列和操作列，金额、数量、日期、状态按类型对齐；
- 行编辑必须显示稳定行号，错误定位到行号和字段；
- 移动端使用任务卡片，不把横向滚动当作唯一适配；
- 五列及以上的业务表在移动端必须提供可见的任务卡片替代视图；卡片优先显示身份、状态、关键金额/数量和下一步动作，不能机械复制全部列；
- 空、加载、错误、无权限和数据过期状态必须彼此可区分；
- 大批量粘贴、删除、填充必须先预览影响，保存后从服务端回读。

## 动效边界

动效只用于解释状态变化，不用于装饰：

- 折叠、开关、焦点和选中反馈采用 120–200ms 的颜色或位移动效；
- 加载只允许局部旋转指示，不阻塞无关区域；
- 数据表载入、分页和大批量更新不做逐行动画，避免卡顿与视觉漂移；
- 下拉浮层使用 viewport 定位，空间不足时自动向上展开，禁止被卡片滚动容器裁切；
- 所有非必要动效必须支持 `prefers-reduced-motion`；
- 动效不得改变保存语义、吞掉键盘输入、延迟错误显示或制造布局跳动。

### 时长与属性矩阵

| 场景 | 允许时长 | 允许属性 | 禁止 |
| --- | ---: | --- | --- |
| 输入框焦点、校验状态 | 120–150ms | 边框、阴影、颜色 | 位移、缩放 |
| 下拉、折叠、任务切换 | 150ms | 颜色、透明度；必要时小幅位移 | `transition-all`、弹跳 |
| 对话框进入 | 150–200ms，仅一次 | 透明度或单轴位移 | 500ms 以上、旋转、连续动画 |
| 表格行选中、错误定位 | 150ms | 背景、边框、阴影 | 逐行入场、缩放、布局尺寸 |
| 进度条 | 最多 200ms | `width` | 对整张卡片应用动画 |
| 加载 | 请求期间 | 局部旋转 | 阻塞无关区域或无限装饰动画 |

P0/P1 高频业务源码禁止 `transition-all`、未受 `motion-safe` 约束的入场动画和 300ms 以上的交互动效。全局 `prefers-reduced-motion` 仍作为最后一道兜底，但不能用它掩盖正常模式下的过度动画。

## 字段关系与下拉语义

- Placeholder 只提供示例，不得充当字段名。复杂表单中的每个输入和下拉必须有持续可见的标签。
- 复杂表单使用具名业务分区（`data-form-section` + `aria-labelledby`），分区标题回答“这一组属于哪个对象”。
- 行表格必须显示稳定行号；输入的 accessible name 必须包含行号和字段名，错误也必须回到同一行号。
- 主数据下拉必须同时显示编码、名称、规格/单位和发布状态；选择后由主数据回填的字段必须只读或明确提示“由主数据控制”。
- 高级字段默认折叠，并明确说明“可后补”还是“保存前必填”，不得让用户猜测。
- 复杂保存区必须暴露 `data-save-impact`，明确本次会创建/修改什么，以及不会自动触发什么。

## 首个执行点：采购订单

采购订单新增区按以下层级执行：

- `1. 采购对象`：供应商与统一物料；
- `2. 数量、价格与到货`：数量、单位、单价与日期；
- 系统计算区：到岸成本明确标注为预估；
- 高级区：背靠背、币种、汇率、税费；
- 固定保存区：明确“生成采购承诺，不立即增加库存”。

统一物料下拉采用 Portal、键盘选择、查询失败与无结果分离、桌面/移动端自动翻转；物料选中后名称和基础单位由主数据控制。

## 自动自检门禁

每个改造页面至少保留以下证据：

1. 源码契约：编号分组、显式字段标签、折叠关系、开关语义、减少动效和保存影响说明；
2. 类型检查与正式构建；
3. 360/390/430/768/1024/1280/1366/1440 宽度的溢出与固定导航遮挡检查；
4. 键盘 Tab、方向键、Enter、Escape 与中文/越南文 IME；
5. 浏览器写入、API 回读、数据库身份字段回读；
6. 控制台错误、弱网、查询失败、无结果、无权限与重复提交状态。

只通过构建或只看到页面“好看”，均不得判定交互成熟。

## 2026-08-01 执行补充

- 通用浏览器审计在 20 条业务路由、8 个视口上检查五列及以上移动端复杂表，缺少 `[data-mobile-card-list]` 时产生明确告警；列数按表头与首行的最大值计算，禁止把二者相加制造误报。
- 减少动效通过浏览器上下文模拟，不再注入 `<style>`，避免审计自身违反生产 CSP。
- 审计证据默认只保留最近 2 轮，并在删除后验证目录确实不存在，防止 Windows 下测试产物无限累积。
- 财务流水/现金流、近期回款/调整、生产 BOM 版本、调整记录和经销经营对比已采用“移动任务卡 + 桌面高密度表”的同源双视图；两种视图读取同一数据，不形成第二套业务逻辑。
- 高频行反馈只使用 150–200ms 的颜色变化，并提供 `motion-reduce:transition-none`；禁止 `transition-all`、500ms 以上入场和逐行动画。
- `PageShell`、`DocumentInputGuide`、`WorkspaceTaskNavigator` 已成为受治理层级原语：页面只保留一个可引用的 `h1`，填写步骤使用有序列表，任务切换使用单选中 `tablist`，并支持方向键、Home 和 End。
- `DataTable` 与 `EnterpriseDataGrid` 统一暴露业务对象名称及 `loading / empty / ready` 状态；浏览器审计会拒绝无名称、无状态的受治理表格。
- 列显示菜单统一改为 `ColumnVisibilityMenu` Portal：按触发按钮实时测量，使用 viewport 固定定位、边缘钳制和上下自动翻转，不再依赖提高 `z-index` 掩盖滚动容器裁切。
- 自检不再只搜索 CSS 类名：真实浏览器会操作任务导航方向键、打开并测量列菜单，同时在 `prefers-reduced-motion` 下检查可见元素的计算后动画与过渡时长。
- 本轮自检同时发现 SQLite 运行库缺少 `production_boms.shelf_life_days`；运行时修复链已补列，并在修复后强制执行完整 Prisma/SQLite schema audit，残留漂移会阻断启动而不是等到页面接口返回 500。
- CRM 客户建档已改为“客户身份 → 主地址 → 主联系人 → 可后补高级信息 → 保存结果预览”的可见顺序；中英越名称、证照、信用、地址和联系人不再依赖 placeholder 猜字段。
- 销售订单商品行和生产 BOM 原料行统一声明桌面业务表名称，并为移动端暴露 `data-mobile-card-list`；同一行始终保留稳定行号。
- 通用浏览器审计会真实打开 CRM 建档弹窗、展开高级区、检查具名分区、显式字段标签和保存影响，再关闭弹窗；不再仅从入口页面推断复杂录入可用。
- 复杂输入治理审计现在读取页面及其拆分子目录，P0/P1 的 `transition-all`、慢动效和未受约束入场动效会形成阻断风险，避免入口文件“看起来干净”而子组件仍残留过度动画。
- 全局 `Layout` 也作为 P0 治理对象纳入同一门禁；侧栏、顶栏、语言/币种菜单和移动导航只保留 150ms 状态反馈，不再使用 300–700ms 入场、旋转、弹跳或悬浮缩放。
