# ADR 0035：统一物料身份先贯通采购收货、库存余额、流水与批次

- 状态：Accepted
- 日期：2026-08-01
- 适用范围：采购订单、采购收货、库存余额、库存流水、产品批次、生产耗料

## 背景

历史链路依靠 `item`、`productName`、`batchNo` 等自由文本连接采购、库存与生产。同名异物、别名变化或多语言名称会造成库存拆分、错误耗料匹配和批次追溯漂移。仅在 BOM 明细增加 `materialId` 仍无法证明实际收货、库存和耗料对应同一物料。

## 决策

1. 在 `PurchaseOrder`、`ProductBatch`、`StockBalance` 和 `StockMovement` 增加可空 `materialId`，历史展示文本保留，不做静默覆盖。
2. 新链路提供 `materialId` 时，写入前必须读取物料主数据并验证：存在、已启用、非临时、基础单位一致。
3. 受控写入的 `productName` 和 `unit` 由主数据规范化，调用方文本不能覆盖正式名称与单位。
4. 库存身份查询优先使用 `locationId + materialId + batchNo`；仅当 `materialId` 缺失时继续使用历史 `locationId + productName + batchNo`。
5. 幂等签名包含 `materialId`，同一个请求号不能用相同显示名称替换成另一物料。
6. 已存在的历史库存行不会在业务写入中被自动认领。发生名称唯一键冲突时拒绝写入，必须走后续受控治理任务。
7. 生产完工耗料校验在任一侧已有 `materialId` 时只允许 ID 精确相等；只有双方都未治理时才保留历史文本兼容匹配。
8. 受控物料首次创建批次时，有效期必须来自物料主数据 `shelfLifeDays`；缺失时拒绝入库，不再套用统一一年。只有未治理历史链路暂时保留旧默认值。
9. 采购录入提供可键盘操作的统一物料搜索框。选择正式物料后，名称和单位自动回填；未选择时明确显示历史兼容状态，不伪装成已治理。
10. 动效只服务于搜索结果层级与状态反馈，并遵循 `prefers-reduced-motion`；下拉层使用明确的浮层层级，不推动表单或遮挡固定保存区。

## 分阶段边界

- 本阶段不自动回填历史采购、库存或批次记录。
- 本阶段不删除原有文本列与文本唯一键。
- 成品物料身份、销售订单行物料身份、完整批次谱系和召回 API 进入后续独立阶段。
- 当历史治理完成并完成冲突审计后，才评估将新业务的 `materialId` 改为必填并移除文本身份唯一键。

## 后果

- 优点：采购收货生成的库存余额、流水和批次可以共享稳定身份；BOM 耗料不再因相似名称误匹配。
- 代价：迁移期同时维护关系身份与历史显示文本；历史冲突需要人工治理。
- 上线门禁：SQLite 运行时修复、PostgreSQL 版本化迁移、精确身份单测、真实收货回读、旧数据兼容与浏览器键盘/移动端验证必须同时通过。
