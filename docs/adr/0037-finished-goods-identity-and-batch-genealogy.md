# ADR 0037：成品统一身份与批次谱系必须贯穿生产、销售和发货

- 状态：Accepted
- 日期：2026-08-01
- 范围：成品 BOM、生产工单、批次、销售订单行、发货与召回查询

## 决策

1. `Material` 是原料、半成品和成品的唯一业务身份源；名称只作可读快照，不能再作为受控交易的关联键。
2. 受控 BOM 必须选择已启用且非临时的成品或半成品物料。名称、输出单位和保质期从物料主数据回填；草稿可暂存未归档文本，但必须显示“未关联”状态。
3. 工单从 BOM 继承输出 `materialId`，不得让操作员重新输入另一套成品身份。已有成品批次必须与工单身份一致。
4. 完工事务同时创建/更新成品批次、库存凭证、成本台账和不可变的 `BatchGenealogyEdge`。任一环节失败，整笔事务回滚。
5. 谱系边保存实际原料库存行、原料批号、实际耗用量、工单和成品批次，不以理论 BOM 用量替代实际耗用。
6. 销售订单行可兼容历史自由文本，但新建受控记录选择统一物料后，名称、规格和单位由主数据控制。人工改名会明确解除关联，不允许保留“名称已变、ID 未变”的隐性错配。
7. 发货优先绑定订单行和成品批次；有 `materialId` 时库存只能按该 ID 和批号精确扣减，禁止退回同名模糊匹配。
8. 追溯接口是只读证据视图，返回上游原料批次、工单、下游发货、订单和客户；召回立案、通知、处置和关闭属于后续独立生命周期，不在本次接口中伪装完成。
9. 关联订单行的发货创建使用 Serializable 事务核对累计已分配数量；并发请求中只允许不超过订单行数量的事务提交，冲突请求返回 409。
10. 受控 BOM 的完工领料建议只能按 `materialId` 查找库存；同名但未治理的历史库存不得出现在可确认扣料列表中。

## 人因与页面层级

- 成品身份必须位于 BOM 和销售明细的第一编辑层，先选“是什么”，再填“多少、多少钱、何时交付”。
- 表格固定显示行号、物料状态、数量、单位、单价、金额和操作；低频规格与备注不得挤压首屏主链。
- “已关联”“历史文本”“主数据不可用”使用文字与图标双重表达，不能只靠颜色。
- 下拉浮层不得推动表格、不得被滚动容器裁切；键盘、IME 和屏幕阅读器状态必须稳定。
- 动效只解释展开、选中、保存和错误定位，时长 120–200ms；分页和批量回读不做逐行动画，并服从 `prefers-reduced-motion`。
- 保存区必须说明本次写入对象及下一步：销售订单保存不扣库存，发货过账才扣减；BOM 保存不自动开工，工单完工才生成批次谱系。
- 手机端保存区保持在文档流内，不覆盖正在编辑的原料卡；完工耗料在桌面显示对账表，在手机显示逐批任务卡，主操作位于取消操作之前并服从减少动效偏好。

## 兼容与迁移

- 新字段先 nullable，旧数据保持可读；正式写入逐入口收紧，不做无证据的名称自动合并。
- 历史数据通过治理任务产生候选、人工确认、执行清单和可回滚证据后再补 ID。
- PostgreSQL 使用版本化迁移；SQLite 仅用于开发兼容修复，不作为生产发布依据。

## 自动自检门禁

1. Prisma 校验、类型检查、正式构建和 OpenAPI 契约；
2. 完工并发、重复提交、事务回滚及谱系唯一约束测试；
3. 销售/发货按 ID 精确匹配的负向测试；
4. 360/390/768/1024/1280/1440 宽度溢出、固定列和保存区遮挡；
5. Tab、方向键、Enter、Escape、中文/越南文 IME 与减少动效；
6. 浏览器写入、API 回读、数据库 `materialId` 与谱系边逐字段核对；
7. 查询失败、无结果、无权限、旧数据未关联和重复提交必须呈现不同状态。
