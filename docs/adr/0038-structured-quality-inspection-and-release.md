# ADR 0038：化工质检必须结构化、双人放行并阻断未放行批次

- 状态：Accepted
- 日期：2026-08-01
- 范围：BOM 放行标准、生产检验、复检、完工、成品批次与发货

## 问题

旧链路只保存 `pass/fail + defectRate + note + checkedBy`。客户端可以直接提交“通过”，质检人是自由文本，仓库角色同时拥有录入、判定和完工能力；工单也可以绕过质检直接完工。它无法证明固含、粘度、pH、外观等具体指标是否被测量，更无法满足职责分离和批次隔离。

## 决策

1. BOM 使用 `ProductionQualityCharacteristic` 保存结构化标准。每项必须有稳定编码、名称、类型、单位、上下限或文本合格值、检验方法和必检标记。
2. 检验提交只接收样品编号和实测值；客户端不得提交最终 `result`。服务端使用 BOM 标准逐项计算并保存标准快照和结果。
3. 每个工单的检验记录按 revision 递增且不可覆盖。失败后通过新 revision 复检，不修改历史证据。
4. `production.quality.inspect` 与 `production.quality.release` 是两个独立权限。即使一个账号同时拥有二者，也不得审核自己录入的检验记录。
5. 只有最新 revision 为 `released + pass` 时，结构化质检工单才能完工。未提交、待审核、失败、拒绝或旧 revision 都不能通过。
6. 检验提交后处置状态为 `hold`；审核拒绝后为 `quarantine`；审核通过后为 `released`。发货创建和库存过账都必须拒绝 hold/quarantine/pending_qc 批次。
7. 检验员身份、放行人身份和时间来自认证上下文，禁止信任客户端自由文本。
8. 历史浅层质检保留为 `legacy_recorded/legacy`，不伪装成完成了双人放行。新受控化工 BOM 启用前必须配置结构化标准。
9. 缺陷率只由服务端按结构化检验项计算；即使旧客户端仍发送 `defectRate`，服务端也不得采用。审核使用 `submitted` 状态条件更新抢占，重复或并发审核只有一个请求能改变状态。

## 人因与页面层级

页面固定为四步：送交质检 → 逐项录值 → 独立审核 → 耗料确认并完工。系统不再显示“直接完工”按钮。桌面和手机都以逐项任务卡显示标准、实测值、仪器和结果，避免在宽表中丢失当前检验对象。

## 验收门禁

- 客户端伪造 `result=pass` 不进入请求契约。
- 缺必检项、数值非法、错误 characteristicId 均失败关闭。
- 自审、放行失败记录、放行旧 revision、未放行完工均返回冲突。
- 隔离批次不能创建发货单，也不能在无批号发货时被库存选择器命中。
- 两个真实账号完成检验和放行，浏览器回读检验人、放行人、测量快照、批次质量状态和审计日志。
- 390px 移动端必须显示卡片式耗料输入，桌面表格不得同时显示；确认按钮中心点必须实际可点击，不能被底部导航遮挡。
- 正式验收统一由 `production-browser-audit-v1.cjs` 覆盖 BOM、工单、质检、完工、批次和冲销；未接入任何门禁且已被该链路替代的 `production-api-audit-v1.cjs` 删除，输入负向边界由 Jest 验证器测试承担。
- 每次生产浏览器验收只清理自身固定的 `output/playwright/production-browser-audit-v1/` 后再写证据，防止旧失败截图混入新结论；路径必须先校验为固定产物根的直接子目录，禁止字符串拼接式广域删除。
