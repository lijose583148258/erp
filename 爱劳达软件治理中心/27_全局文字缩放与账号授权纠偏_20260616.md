# 27 全局文字缩放与账号授权纠偏

日期：2026-06-16

## 结论

账号、角色、授权不是“不该做”，而是只能算 P0 门禁基线。成熟 ERP 不能只证明“谁能登录、谁有权限”，还必须证明一线员工能高频完成录单、查账、盘点、审批、异常处理等业务动作。

## 为什么账号角色授权不能代表成熟体验

- 它解决的是进入系统和边界控制，不解决订单、客户、库存、回款等页面是否好用。
- 它能防越权，但不能防止字段太小、按钮隐藏、长文本溢出、表格难比较、移动端找不到操作。
- 它是发布安全门槛，不是商业闭环。后续判断仍要回到“真实业务链是否可持续使用”。

## 本节点治理

- 增加全局文字缩放控制：`100% / 110% / 120%` 循环。
- 通过 CSS 变量 `--app-text-zoom` 调整根字号，尽量保持实现简单。
- 偏向解决仓库、外勤、平板、强光环境和视力弱用户的可读性问题。
- 保留浏览器原生缩放能力，`index.html` 未发现 `user-scalable=no`。
- 移动端菜单同步增加文字缩放入口，避免触屏用户只能看到功能但无法使用。

## 反幻觉依据

- W3C WCAG 2.2 的 Resize Text 要求文本可以放大且不丢内容或功能。
- W3C WCAG Reflow 要求内容在窄视口下仍可重排，数据表等二维内容需要单独评估。
- W3C WCAG 2.2 Target Size Minimum 要求指针目标至少达到 `24px × 24px` 或满足等效/间距例外。
- NN/g 对企业数据表的任务拆解强调：查找、比对、编辑单行、对记录采取行动。
- NN/g 对触屏目标的建议强调：移动端交互目标过小会增加误触和操作挫败。

## 验证证据

- `npx tsc --noEmit --pretty false`：通过。
- `npm run build`：通过，生成入口 `dist/assets/index-DEQCZE_8.js`。
- Node UTF-8 检查：`components/Layout.tsx`、`index.css`、`app/useAppShell.tsx`、CRM 与销售订单关键表单文件未发现源码级乱码信号。
- Playwright 预览检查：`text-scale-toggle` 可见，点击后根字号按 `16px -> 17.6px -> 19.2px -> 16px` 循环。
- 移动触屏预览检查：390px 宽视口下 `mobile-text-scale-toggle` 可见，点击后根字号按 `16px -> 17.6px -> 19.2px` 变化；按钮实测高度从 `50px` 起，满足触屏目标尺寸底线。

## 后续治理顺序

1. 继续检查 120% 文字缩放下的 CRM、销售订单、采购、库存页面是否出现遮挡或横向溢出。
2. 对高频表格继续补齐：固定表头、触屏操作显性化、长字段 title/截断、关键列密度。
3. 账号角色授权保持 P0 安全基线，但不再让它挤占业务页面可用性治理的主线。
