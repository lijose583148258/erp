# 祖先模块到当前包映射表

## 1. 这份表的用途

这份表用来回答两个问题：

1. `爱牢达_CleanMigration.zip` 里的老模块，后来被收进了当前仓库的哪一块
2. 哪些模块已经进入当前主线包，哪些还只是业务骨架或支撑能力

## 2. 总体判断

祖先包不是简单的“旧版本代码”，而是一个已经具备完整业务骨架的迁移期原型。

当前仓库是在这个原型上做两件事：

- 先治理收口
- 再按包补全主线

- 目录和归档
- 文档治理
- 命令口径
- Prisma 版本
- 翻译资源
- 旧 JS 入口退场

### 包 1 收什么

- 数据库底座
- 单机 / 线上统一的数据库准备
- 备份、恢复、状态、seed

### 包 2 收什么

- 账龄
- 承诺付款
- 争议
- hold / release
- 核销闭环

### 包 3 收什么

- BOM
- 工单
- 工序
- 损耗
- 库存联动

### 包 4 收什么

- 应收应付
- 利润
- 现金流
- 经营分析
- 导出与报表

### 包 5 收什么

- 单机稳定
- Docker / 线上部署
- 备份恢复
- 验收清单

## 6. 从祖先包到当前版的演变逻辑

祖先包解决的是“有什么”。

当前治理中心解决的是：

- 这些东西谁负责
- 哪些是主线
- 哪些是支撑
- 哪些是历史
- 哪些必须先收口

所以这次演变不是改名，而是把原型系统拆成了可维护的业务台账。
