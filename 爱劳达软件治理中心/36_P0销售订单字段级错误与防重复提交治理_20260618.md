# 36_P0销售订单字段级错误与防重复提交治理_20260618

## 治理结论

本轮继续执行 P0 表单可用性底座，优先治理销售订单编辑器中的两个高频风险：

- 明细行错误不能只靠红框，必须能定位到“第 N 行、哪个字段、为什么错”。
- 保存按钮不能在网络慢或用户连点时重复提交。

本轮不新增业务功能，不重构订单流程，只在现有校验和保存链路上做最小补强。

## 修改范围

- `pages/sales-orders/useSalesOrders.ts`
  - 增加 `isSavingOrder`。
  - `handleSaveOrder` 增加防重入保护。
  - 保存中禁用重复提交。
  - 保存失败提示带上具体错误消息，避免只有“保存失败”。
  - 清理该文件现有 ESLint warning，补齐 hook 依赖。

- `pages/sales-orders/SalesOrderEditorModal.tsx`
  - 增加 `isSaving` 入参。
  - 保存按钮增加 `disabled`、`aria-busy`。
  - 保存中显示“保存中...”。

- `pages/SalesOrders.tsx`
  - 向销售订单编辑器传入 `state.isSavingOrder`。

- `pages/sales-orders/SalesOrderLineGrid.tsx`
  - 明细行字段增加 `aria-invalid`。
  - 错误字段通过 `aria-describedby` 关联到本行错误说明。
  - 复用现有错误对象，不新增复杂校验体系。

## 乱码三步法结论

PowerShell 输出中销售订单文件的中文看起来像乱码，但 Node UTF-8 检测证明文件内容是正常中文。

因此本轮没有误修文案，只针对真实缺口修改：

1. 意图：字段级错误定位、防重复提交。
2. 层级：React UI 状态层与表单可访问性层。
3. 修复：保存状态、防重入、错误字段 ARIA 关联。

## 反幻觉校准

联网复核后，本轮方向与成熟表单 UX / 可访问性标准一致：

- NN/g 表单错误指南强调错误信息应贴近问题字段，且要明确、可操作。
- W3C ARIA21 明确说明 `aria-invalid` 可配合 `aria-describedby` 让错误字段和错误说明建立程序化关联。
- MDN 对 `aria-invalid` 的说明也强调它用于标识输入值不被应用接受。
- 防重复提交是表单系统的常见稳定性治理点，尤其适用于订单、付款、库存等不可重复写入场景。
