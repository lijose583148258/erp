# P3 重构冻结门禁与低复杂度治理计划

日期：2026-06-18

## 结论

当前包可以继续做冻结与迁移测试，但不能继续在以下三个大文件里叠加新功能：

- `pages/ProductionWorkspaceV2.tsx`
- `pages/WarehouseWorkspace.tsx`
- `pages/team/RoleManagementPanel.tsx`

这三个文件已经超过运行代码 650 行硬阈值。处理原则不是马上大拆重写，而是冻结新增功能入口，只允许做缺陷修复、验证补强和低风险抽取。

## 治理原则

- 不重写业务流程。
- 不改接口契约。
- 不改权限判断口径。
- 不在页面里继续新增大块 JSX。
- 优先抽离纯展示组件、静态 copy、表单校验 helper。
- 涉及金额、库存、权限、订单状态时，必须有 API 回读和浏览器回读证据。

## 文件级计划

### `pages/ProductionWorkspaceV2.tsx`

现状：生产工作台承担 BOM、工单、质检、批次调整的入口编排。

下一步只允许：

- 抽离生产工作台的校验 helper。
- 抽离批次追踪事件组装 helper。
- 保持 `ProductionWorkspaceV2.tsx` 只负责编排状态和调用现有子组件。

验收：

- TypeScript 通过。
- `audit:production:background` 通过。
- `verify:phase3` 通过。

### `pages/WarehouseWorkspace.tsx`

现状：仓储工作台承担仓库主档、库存台账、流水、手工入库、调拨弹窗的编排。

下一步只允许：

- 抽离统计卡片组件。
- 抽离库存查询与流水查询参数组装 helper。
- 保持库存写入仍由 `warehouseService` 和现有弹窗/面板执行。

验收：

- TypeScript 通过。
- `audit:warehouse:transfer` 通过。
- `audit:warehouse:transfer:browser` 通过。

### `pages/team/RoleManagementPanel.tsx`

现状：角色授权页面同时包含多语言 copy、权限分组、风险识别、授权预览和保存动作。

下一步只允许：

- 抽离静态 copy 与权限分组配置。
- 抽离 diff/review helper。
- 保持创建角色、修改权限、数据范围保存动作不变。

验收：

- TypeScript 通过。
- `audit:permissions:system-ui` 通过。
- `audit:auth:account-lifecycle` 通过。

## 发布冻结口径

本计划只代表“允许当前冻结包继续进入迁移/服务器测试”。它不代表 P1/P2/P3 蓝图全部完成。

冻结后如果继续开发，必须先从上述三个文件中选择一个做低风险拆薄，再进入功能补齐。
