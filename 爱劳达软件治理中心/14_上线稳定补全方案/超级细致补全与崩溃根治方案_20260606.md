### 禁止直接执行的历史建议

1. 不得在稳定运行模式下自动切换到另一个 SQLite 文件。无提示 fallback 会造成“系统能启动但数据像丢失”的分库事故。
2. 不得在每次启动时无条件执行破坏性迁移。启动链只允许幂等结构准备，并必须先备份、再验证、失败即停止。
3. 不得因为 PowerShell 显示乱码就重写 UTF-8 文件。必须先检查原始字节和 Node UTF-8 解码结果。
4. 不得把构建成功、HTTP 200 或单个 API 成功当作发布完成；仍需浏览器回读、数据库回读和运行包来源证明。

| # | 根因类别 | 严重程度 | 典型症状 |
|---|---------|---------|---------|
| 1 | **数据库路径解析失败** | 🔴 P0 | 后端启动即崩溃，`D:\AilaoDaRuntime\stable.db` 在部分机器不可写 |

### P0-3：Lazy 路由无独立 ErrorBoundary

**问题描述**

`app/appContent.tsx` 将所有页面通过 `lazy()` 加载，但：
- `App.tsx` 的 `<Suspense>` 只有 loading fallback，**没有** error 捕获
- 任意一个页面（如 `BarterWorkspaceView.tsx`）的 import 失败 → 整个应用白屏

**修复步骤**

**步骤 1** — 创建 `components/PageErrorBoundary.tsx`（页面级隔离边界）：

```tsx
import React, { ErrorInfo } from 'react';
import { AlertOctagon, RefreshCcw, ChevronDown } from 'lucide-react';

interface State {
  hasError: boolean;
  error: Error | null;
  showDetail: boolean;
}

class PageErrorBoundary extends React.Component<{ children: React.ReactNode; pageId?: string }, State> {
  state: State = { hasError: false, error: null, showDetail: false };

  static getDerivedStateFromError(error: Error): Partial<State> {
    return { hasError: true, error };
  }

  componentDidCatch(error: Error, info: ErrorInfo) {
    console.error(`[PageErrorBoundary] 页面 ${this.props.pageId} 加载失败:`, error, info);
  }

  render() {
    if (!this.state.hasError) return this.props.children;
    return (
      <div className="flex flex-col items-center justify-center min-h-[40vh] gap-4 p-8">
        <div className="w-16 h-16 bg-rose-100 rounded-full flex items-center justify-center">
          <AlertOctagon className="text-rose-500" size={32} />
        </div>
        <h2 className="text-xl font-black text-slate-800 dark:text-white">
          当前页面加载失败
        </h2>
        <p className="text-slate-500 text-sm text-center max-w-sm">
          该模块遇到了问题，其他模块不受影响。
          请尝试刷新，若持续失败请联系管理员。
        </p>
        <button
          onClick={() => this.setState({ hasError: false, error: null })}
          className="flex items-center gap-2 px-6 py-3 bg-blue-600 text-white rounded-xl font-black text-sm"
        >
          <RefreshCcw size={16} /> 重试此页面
        </button>
        <button
          onClick={() => this.setState(s => ({ showDetail: !s.showDetail }))}
          className="text-xs text-slate-400 flex items-center gap-1"
        >
          <ChevronDown size={12} /> 查看错误详情
        </button>
        {this.state.showDetail && (
          <pre className="text-xs bg-slate-100 dark:bg-slate-800 p-4 rounded-lg max-w-full overflow-auto text-slate-600 dark:text-slate-400 max-h-40">
            {this.state.error?.toString()}
          </pre>
        )}
      </div>
    );
  }
}

export default PageErrorBoundary;
```

**步骤 2** — 修改 `app/appContent.tsx`，用 PageErrorBoundary 包裹每个页面：

```tsx
export const renderAppContent = (activeTab: string): React.ReactNode => {
  const Page = activePages[activeTab as ActivePageId] || activePages.dashboard;
  return (
    <PageErrorBoundary pageId={activeTab} key={activeTab}>
      <Page />
    </PageErrorBoundary>
  );
};
```

**步骤 3** — 在 `App.tsx` 中，用顶层 `ErrorBoundary` + 页面级 `PageErrorBoundary` 形成双层保护：

```tsx
// App.tsx 结构（双层保护）：
<ErrorBoundary>            {/* 顶层：防整个 shell 崩溃 */}
  <AppContext.Provider>
    <Layout>
      <Suspense fallback={<LoadingSpinner />}>
        {renderAppContent()}   {/* 内部已有 PageErrorBoundary */}
      </Suspense>
    </Layout>
  </AppContext.Provider>
</ErrorBoundary>
```

### P1-1：翻译合并顺序错误

**问题描述**（`app/useAppShell.tsx` 第 145-149 行）

```typescript
// ❌ 当前错误写法：合并了三份，中间的 'en' 会覆盖 'zh' 的 key
const t = useMemo(() => ({

const t = useMemo(() => ({
  ...(translations['zh'] || {}),    // 中文作为基础兜底
  ...(translations[language] || {}), // 当前语言覆盖（如 language=zh，则等于重复写 zh）
}), [language]);
```

### P1-2：auditMiddleware 异步安全问题

**问题描述**（`backend/src/middleware/auditMiddleware.ts` 第 29 行）

```typescript
res.on('finish', async () => {  // ← 这是 async 回调
  // 如果这里抛出错误，是 unhandled promise rejection！
  await prisma.auditLog.create({...});
```

Node.js 中，`res.on('finish', ...)` 的异步回调如果 reject，不会被 Express 错误中间件捕获，在高并发下可能导致进程崩溃（Node 默认 `unhandledRejection` 行为在不同版本不同）。

**修复步骤**

```typescript
res.on('finish', () => {
  // 不使用 async，改用 .catch() 链式处理
  const logPromise = async () => {
    // ... 日志逻辑
    if (method !== 'GET' && userId) {
      await prisma.auditLog.create({ data: { ... } });
    }
  };
  
  logPromise().catch(err => {
    // 仅记录，不上抛，确保不影响主进程
    logger.error('审计日志写入失败（非阻断）', err);
  });
});
```

### P1-4：dist 资产完整性校验

**问题描述**

稳定启动脚本 `scripts/start-stable-v2.ps1` 未校验以下内容：
1. `dist/index.html` 是否存在
2. `dist/assets/` 内 JS/CSS 是否损坏（0 字节文件）
3. dist 内容是否是最新构建（构建时间戳对比）

**修复步骤**

在 `start-stable-v2.ps1` 的启动前检查段，追加：

```powershell
# ── dist 完整性预检 ──────────────────────────────────────
$distIndex = Join-Path $PSScriptRoot "..\dist\index.html"
if (-not (Test-Path $distIndex)) {
  Write-Host "[❌ 致命] dist/index.html 不存在！请先执行 npm run build" -ForegroundColor Red
  exit 1
}

$distSize = (Get-Item $distIndex).Length
if ($distSize -lt 500) {
  Write-Host "[❌ 致命] dist/index.html 文件异常，大小仅 $distSize 字节，请重新构建" -ForegroundColor Red
  exit 1
}

# 检查是否有 0 字节的 JS 资产
$zeroByteAssets = Get-ChildItem (Join-Path $PSScriptRoot "..\dist\assets") -Filter "*.js" |
  Where-Object { $_.Length -eq 0 }
if ($zeroByteAssets.Count -gt 0) {
  Write-Host "[❌ 致命] 发现 $($zeroByteAssets.Count) 个 0 字节 JS 文件，dist 构建损坏，请重新构建" -ForegroundColor Red
  exit 1
}

Write-Host "[✅] dist 完整性检查通过" -ForegroundColor Green
```

### P2-5：前端未处理 401 全局跳转登录

**问题描述**

当 JWT token 过期（7天后）时，所有 API 请求返回 401，但前端各个 service 文件**各自处理**，没有统一的 401 拦截器，导致：
- 部分页面显示"认证令牌已过期"的技术错误
- 用户不知道需要重新登录
- 页面不会自动跳回登录页

**修复步骤**

**步骤 1** — 在 `services/` 目录下创建 `apiClient.ts` 统一 fetch 封装：

```typescript
// services/apiClient.ts
const BASE_URL = import.meta.env.VITE_API_URL || '';

class ApiError extends Error {
  constructor(public status: number, message: string) {
    super(message);
  }
}

let _onUnauthorized: (() => void) | null = null;

export const setUnauthorizedHandler = (fn: () => void) => {
  _onUnauthorized = fn;
};

export const apiClient = async (path: string, options?: RequestInit) => {
  const token = localStorage.getItem('ailao.token');
  const res = await fetch(`${BASE_URL}${path}`, {
    ...options,
    headers: {
      'Content-Type': 'application/json',
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
      ...options?.headers,
    },
  });
  
  if (res.status === 401) {
    localStorage.removeItem('ailao.token');
    _onUnauthorized?.();  // 触发跳转登录页
    throw new ApiError(401, 'session-expired');
  }
  
  if (!res.ok) {
    const body = await res.json().catch(() => ({}));
    throw new ApiError(res.status, body?.message || `HTTP ${res.status}`);
  }
  
  return res.json();
};
```

**步骤 2** — 在 `app/useAppShell.tsx` 中注册 handler：

```typescript
useEffect(() => {
  setUnauthorizedHandler(() => {
    handleLogout();
    notify('error', '登录已过期，请重新登录');
  });
}, []);
```

### P2-8：后端缺少 unhandledRejection 全局捕获

**问题描述**

`backend/src/server.ts` 只监听了 `SIGTERM` 和 `SIGINT`，但没有：

```typescript
process.on('unhandledRejection', ...)
process.on('uncaughtException', ...)
```

当有未捕获的 Promise rejection 时，根据 Node 版本，可能直接崩溃退出。

**修复步骤**

在 `server.ts` 底部追加：

```typescript
process.on('unhandledRejection', (reason: unknown, promise: Promise<unknown>) => {
  logger.error('未处理的 Promise rejection，系统继续运行', {
    reason: reason instanceof Error ? reason.message : String(reason),
    stack: reason instanceof Error ? reason.stack : undefined,
  });
  // 注意：不要 process.exit()，记录后继续运行
});

process.on('uncaughtException', (error: Error) => {
  logger.error('未捕获的同步异常，即将优雅退出', {
    message: error.message,
    stack: error.stack,
  });
  // 同步异常是致命的，需要退出
  shutdownGracefully('uncaughtException');
});
```

## 九、特别注意事项（细节陷阱）

> 以下是容易被忽视但导致崩溃的细节，逐条记录：

1. **`npm run build` 必须在前端根目录（`f:\爱牢达\`）执行，不是在 `backend/` 里**
   - 错误操作：在 `backend/` 里执行 `npm run build` 会构建错误的东西

2. **稳定包部署时，必须同时复制 `dist/` 和 `backend/dist/` 两个目录**
   - 遗漏 `backend/dist/` → 后端无法启动
   - 遗漏 `dist/` → 前端 404

3. **SQLite WAL 模式下，备份必须同时备份 `-wal` 和 `-shm` 文件**
   - 已有代码处理，但恢复时必须全部一起恢复，不能只恢复 `.db` 文件

4. **`prisma generate` 必须在每次 schema 变更后执行，否则 Prisma Client 类型不匹配**
   - 常见症状：TypeScript 编译通过但运行时字段报 undefined

5. **Windows 路径中反斜杠 `\` 在 JS 字符串和 Prisma URL 中必须处理**
   - 已有 `replace(/\\/g, '/')` 处理，但每次新增路径拼接时必须检查

6. **JWT_SECRET 必须在生产环境更换**
   - 当前 `.env` 中的 secret 已提交到代码，生产必须使用环境变量覆盖

7. **`localStorage` 操作全部包裹 try/catch**
   - 已处理，但新增 localStorage 操作时必须遵守此规则

8. **大文件上传（>10MB）会被后端 express.json limit 拦截**
   - 当前 limit = 10MB，如需上传更大文件，需同时修改前后端配置

9. **Prisma `prismaSchemaFolder` 预览特性**
   - 当前使用了 Prisma 5 的预览特性，升级 Prisma 版本前必须确认兼容性

10. **`AdvancedReports.tsx` 只有 61 字节**（内容为空），点击会白屏
    - 需要跟 PM 确认：是删除模块还是补充内容
