# 代码目录结构梳理

这份目录图按“职责分层 + 业务域”整理，后续新增功能尽量沿这套结构往下放。

## 1. 根目录

- `App.tsx`：应用壳和主视图切换
- `components/`：通用组件
- `pages/`：页面级模块
- `services/`：前端 API 封装和业务服务
- `utils/`：基础工具、API 适配器、mock 层
- `backend/`：后端服务
- `爱劳达软件治理中心/`：方案书、阶段判定、版本治理、部署说明、结构梳理

## 2. 前端页面层

### 2.1 现有主页面

- `pages/Dashboard.tsx`
- `pages/CRM.tsx`
- `pages/SalesOrders.tsx`
- `pages/Shipping.tsx`
- `pages/Assets.tsx`
- `pages/Procurement.tsx`
- `pages/Contracts.tsx`
- `pages/RiskControl.tsx`
- `pages/AuditLogs.tsx`
- `pages/DealerAnalytics.tsx`

### 2.2 调账中心拆分后的结构

- `pages/adjustment/AdjustmentCenterView.tsx`：调账中心规范版容器
- `pages/adjustment/AdjustmentHero.tsx`：顶部总览卡
- `pages/adjustment/AdjustmentFilters.tsx`：筛选与搜索
- `pages/adjustment/AdjustmentRecordTable.tsx`：台账列表
- `pages/adjustment/AdjustmentForm.tsx`：新建调账表单
- `pages/adjustment/AdjustmentDetail.tsx`：单据详情
- `pages/adjustment/adjustment.constants.tsx`：表单默认值、模板、状态映射
- `pages/adjustment/adjustment.helpers.tsx`：payload、搜索串、变动展示

### 2.3 说明

- `pages/AdjustmentCenter.tsx` 目前仍保留为历史版本，不建议继续扩写。
- 后续如果要正式接入调账中心，优先使用 `pages/adjustment/AdjustmentCenterView.tsx`。

## 3. 服务层

- `services/auth.service.ts`：登录态
- `services/order.service.ts`：订单相关接口
- `services/customer.service.ts`：客户相关接口
- `services/dashboard.service.ts`：看板接口
- `services/collectionService.ts`：回款催收策略
- `services/adjustment.service.ts`：调账中心接口
- `services/procurement.service.ts`：采购接口

## 4. Mock 与接口适配

- `utils/api.ts`：统一 API 客户端
- `utils/mockAdapter.ts`：本地 mock 数据和接口模拟

## 5. 后端目录

- `backend/src/server.ts`：服务入口
- `backend/src/config/`：运行配置、数据库配置、环境配置
- `backend/src/controllers/`：控制器
- `backend/src/routes/`：路由
- `backend/src/services/`：业务服务
- `backend/src/database/`：数据库维护脚本
- `backend/prisma/schema.prisma`：数据模型

## 6. 文档治理目录

- `01_方案书原件/`：原始方案书
- `02_对照表/`：已完成 / 进行中 / 待补全
- `03_系统核对/`：阶段判定
- `04_清理清单/`：建议清理项
- `05_接入清单/`：重新接入项
- `06_版本治理/`：版本分级与文档治理
- `07_部署落地/`：部署、数据库、运行说明
- `08_代码结构梳理/`：当前目录图

## 7. 当前整理原则

- 一个目录只放同一类职责
- 页面级逻辑尽量下沉到 `pages/<feature>/`
- static 配置、模板、状态映射从页面里拆出去
- 逻辑函数和视图组件分开
- legacy 文件要标明历史，不再作为主入口扩写
