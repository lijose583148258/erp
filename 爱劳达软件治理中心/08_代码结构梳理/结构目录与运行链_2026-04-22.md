## 3. 运行链

### 3.1 本地稳定运行链

```text
npm run start:stable
  -> scripts/start-stable-v2.ps1
  -> 清理/检查已有端口和进程
  -> 运行 backend/dist/database/manage-db.cli.js repair
  -> 使用 runtime schema/data repair 对齐 stable.db
  -> 启动 backend/dist/server.js
  -> 后端静态托管 dist/
  -> 浏览器访问 http://127.0.0.1:5001/
```

稳定链的事实边界：

| 项目 | 当前口径 |
| --- | --- |
| 稳定端口 | `5001` |
| 稳定 URL | `http://127.0.0.1:5001/` |
| 开发端口 | `3000` 只允许项目内 Vite 开发，不作为稳定验收入口 |
| 禁止误判 | `5173`、智仔页面、浏览器新标签页、搜索页都不算爱劳达运行成功 |
| 数据库 | `D:\AilaoDaRuntime\stable.db` |
| 旧 SQLite | `backend/prisma/*.db` 作为影子库治理对象，不允许运行时误连 |

## 8. 乱码制度

本次复核结论：旧结构文档在 PowerShell `Get-Content` 输出中出现乱码，是终端显示层误解码；用 Node `fs.readFileSync(path, 'utf8')` 读取为正常中文。这类情况不能直接重写文件。

固定流程：

1. 先翻译：确认乱码字符大概对应什么业务文案或是否只是显示层。
2. 再判断：区分源码损坏、构建产物陈旧、浏览器字体/编码、终端显示层误解码、旧入口误挂。
3. 再修复：只修对应层，不跨层重写。
4. 禁乱码闸门：新增文案和审计报告必须用 UTF-8 复核；PowerShell 显示乱码不能单独作为源码坏的证据。
