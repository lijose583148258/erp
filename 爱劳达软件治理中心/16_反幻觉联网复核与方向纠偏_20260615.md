# 反幻觉联网复核与方向纠偏

日期：2026-06-15

## 1. 审计结论

结论分为两层：

1. UI 改良方向基本正确：减少永久教学内容、提高信息密度、增加触控尺寸、保护未保存数据、让客户可搜索，均符合成熟企业软件和无障碍规范。
2. 全局任务方向发生收缩：当前清单主要覆盖销售订单、CRM、组件一致性和商品主档，遗漏 PostgreSQL/SaaS、员工账号、发布冻结、迁移打包等原始主线。不能把当前 P0-P3 清单等同于全系统完成路线图。

## 3. 联网规范对照

### 符合方向

- W3C WCAG 2.2 要求交互目标具备足够尺寸或间距；当前高频按钮采用约 44px 触控区，方向正确。
- W3C Reflow 要求缩放后避免页面双向滚动；业务数据表可以保留局部横向滚动，但页面主体不能整体溢出。
- SAP Fiori 建议复杂对象使用统一创建/编辑模式，并在无标准草稿机制时提供数据丢失确认；当前草稿和离开保护方向正确。
- 移除高频工作区永久占屏教学卡片，改为字段提示和折叠辅助区，符合操作型工作台优先原则。

### 需要纠偏

- 销售订单客户 Combobox 只有鼠标点击和单一 Enter 分支，没有完整的方向键导航、活动选项管理和 `aria-activedescendant`，不能标记为无障碍完成。
- 备注等长文本直接使用 HTML `maxLength` 截断。GOV.UK Design System 建议允许用户暂时超限，再用字符计数和明确错误帮助其修改，避免粘贴内容被静默截断。
- 当前 Modal 多数没有 `role="dialog"`、`aria-modal="true"`、焦点锁定、初始焦点和关闭后焦点恢复。
- 通用 `DataTable` 仍保留存量模块的内存分页，但已支持受控服务端分页和可选服务端导出；CRM 已迁移，其他大数据量模块仍需逐项评估。
- `AuditLog.details` 仍主要存储自由 JSON 字符串，尚未形成稳定的字段级 `before/after` 差异合同。

## 4. 对当前 P1 的重新判定

P1 不能继续标记为全部完成，应拆成：

- P1-A 高频布局与触控：通过。
- P1-B 数据长度边界：后端边界通过，前端长文本交互需要从硬截断改为超限提示。
- P1-C 客户搜索：鼠标与触屏流程通过，键盘和读屏流程未完成。
- P1-D CRM 信息密度：核心入口通过，详情抽屉和其他 CRM 子区尚未全量收敛。

## 7. 2026-06-16 反幻觉复核与纠偏执行

### 联网复核结论

- OWASP 对默认账号/默认密码的测试目标包含“确认应用是否存在默认密码账号”，并要求检查默认账号是否被禁用或修改；因此本轮把“发布包拒绝 admin/admin123 等演示账号”提升为发布闸门是正确方向。
- OWASP Top 10 A05 将“默认账号及密码仍启用且未修改”列为安全配置错误风险；这证明当前不能只继续 UI 打磨，必须先把发布安全和账号治理闭环。
- W3C WCAG 2.2 继续支持文本对比度、可缩放、触控目标和不依赖 hover 的方向；当前 UI 可用性治理没有跑偏，但不能把局部通过说成全站完成。
- PostgreSQL 官方文档确认高可用、读负载分担和复制是可行路线；但当前仍是 SQLite 稳定包优先，PostgreSQL 主从备应作为 P3 架构迁移包，不应混入本轮小修。
- SAP Design System 强调企业软件的可访问和包容性；这支持继续治理紧凑模式、键盘、焦点、对比度和高频操作密度。

### GPT-5.5 使用说明

本轮没有可用的网页版 ChatGPT 5.5 授权会话，也没有本地 OpenAI API Key。不能伪称“网页版 5.5 已审计”。实际执行方式为：使用本地证据、官方联网资料和 GPT-5.5 子代理角色审计进行交叉复核。
