# 28 触屏目标尺寸与 Toast 通知治理

日期：2026-06-16

## 问题来源

在 `120%` 文字缩放、移动端 `390px`、平板 `820px` 视口下审计 CRM、销售订单、采购、仓库、资产模块时，发现多个页面都会出现同一类 `14px × 14px` 小按钮。

三步定位后确认：该按钮来自全局 Toast 通知关闭按钮，不是各业务页面单独问题。

## 治理内容

- `components/app/ToastStack.tsx`
  - 为关闭按钮增加 `aria-label="关闭通知"`。
  - 将触屏目标提升为 `min-h-10 min-w-10`，在 `120%` 字号下实测为 `48px × 48px`。
  - 将消息文本改为 `min-w-0 flex-1 break-words`，避免长错误信息撑爆通知。

## 为什么这是 P0/P1 可发布细节

- Toast 会出现在登录、接口错误、保存反馈、网络断开等全局场景。
- 如果关闭按钮过小，一线员工在平板或触屏设备上很容易误触或点不中。
- 如果错误消息过长且不换行，会遮挡业务页面，造成“系统崩了”的体感。

## 反幻觉依据

- W3C WCAG 2.2 Target Size Minimum 要求指针目标至少 `24px × 24px`，或满足等效/间距例外。
- W3C WCAG Resize Text 要求文本放大后不丢失内容或功能。
- NN/g 对触屏目标的建议强调，过小目标会增加操作时间、误触和挫败感。

## 验证证据

- `npx tsc --noEmit --pretty false`：通过。
- `npm run build`：通过，生成入口 `dist/assets/index-Bpi0LMyO.js`。
- Node UTF-8 检查：`ToastStack.tsx` 无 `U+FFFD`，确认存在 `aria-label="关闭通知"`、`min-h-10 min-w-10`、`break-words`。
- Playwright 移动触屏检查：
  - 视口：`390 × 844`
  - 字号：`120%`，根字号 `19.2px`
  - Toast 关闭按钮：`48px × 48px`
  - 可访问名称：`关闭通知`
  - 可见按钮中未发现小于 `24px` 的目标。

## 边界说明

本节点证明的是全局 Toast 触屏目标修复，不证明 CRM、销售订单、采购、仓库、资产的完整业务闭环已经通过。由于 `4174` 静态预览访问 `5001` API 存在 CORS，业务读写闭环仍需在稳定运行入口或同源部署后验证。
