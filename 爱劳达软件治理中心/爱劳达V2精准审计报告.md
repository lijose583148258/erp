## 二、`useUnsavedForm` — 实现到位但存在 6 个具体缺陷

### 实际 Hook 逻辑（已读 479 字节全文）

Hook 的逻辑是：打开时序列化记录初始值，关闭时比对当前值是否不同，若有变化调用 `confirmDiscardChanges()`。实现逻辑正确，但有以下缺陷：

**缺陷 A — 只接入了 SalesOrders 编辑器关闭按钮，以下模块完全无保护**

CollectionActionModal、Procurement、ProductionWorkspace（BOM/工单）、WarehouseWorkspace、Contracts、Assets、RMA、Samples、TeamManagement、BarterWorkspaceView — 共 10 个模块，用户填写一半后导航离开，数据静默丢失。

**缺陷 B — `JSON.stringify(formData)` 每次按键触发，高频序列化**

`useMemo(() => JSON.stringify(value), [value])` 中 value 是整个表单对象，20 行明细时约 5KB。每次按键都触发一次序列化，低配 PC 上积累卡顿。修复方案：仅在 `requestClose` 时做一次对比，不实时追踪。

**缺陷 C — Escape 键关闭 Modal 未经过 `requestClose`**

编辑器没有拦截 Escape 键，用户按 Esc 直接关闭，绕过脏检查丢失数据。修复：在编辑器根容器监听 `keydown`，`e.key === 'Escape'` 时调用 `requestClose(onClose)`。

**缺陷 D — 编辑模式不保存草稿**

```javascript
useEffect(() => {
  !isOpen || isEditMode || localStorage.setItem("orderDraft", ...)
}, [formData, isOpen, isEditMode])
```

`isEditMode` 为 true 时跳过草稿保存。编辑现有订单时浏览器崩溃，所有修改丢失。修复：编辑模式用 `"orderDraft_edit_" + orderId` 独立存草稿。

**缺陷 E — 草稿 key 无用户隔离**

`"orderDraft"` 是全局固定 key，同一台 PC 不同用户登录后会互相看到对方草稿。修复：Key 改为 `"orderDraft_" + currentUser.id`，退出登录时清除。

**缺陷 F — `confirmDiscardChanges` 若基于 `window.confirm()` 则体验割裂**

原生弹窗与 ERP UI 风格不一致，建议改为 React Modal 实现。

## 三、SalesOrders 页面 12 个具体 UX 问题（读源码逐一确认）

### 3.1 客户选择器是原生 `<select>`，百人客户库无法搜索

```javascript
<select data-testid="sales-order-customer-select">
  {customers.map(c => <option value={c.id}>{customerName(c)}</option>)}
</select>
```

越南三个经销商各有数十至数百客户，原生下拉逐条翻找是最高频的反人类操作。修复：替换为 Combobox，支持输入搜索和近期客户置顶。

---

### 3.2 订单行表格在 1440px 以下屏幕永久横向滚动

```javascript
// 编辑器面板最大宽度
<div className="w-full max-w-[96vw]">
  <div className="xl:grid-cols-[360px,minmax(0,1fr)]">

// 订单行表格最小宽度
<table className="min-w-[1080px] w-full">
```

计算：`1440 × 0.96 = 1382px - 360px - 24px(gap) - 64px(padding) = 934px`，小于 1080px 的要求。结果：表格区域在绝大多数用户屏幕上**始终需要横向滚动**，这是最核心的布局问题。

修复方案A（推荐）：改为两步流程——Step 1 填写订单头，Step 2 进入全宽行表格。
修复方案B：将编辑器改为 100vw 全屏，左侧折叠。
修复方案C：将列数由 11 列精简至 8 列（合并模式列到品名列，删除独立金额只保留总计）。

---

### 3.3 `DocumentInputGuide` 每次开单都默认展开

指引卡始终默认展开，没有"以后不再提示"机制。对每天开 20 单的业务员，这是必须滚过才能看到表单的障碍。修复：首次看完后写入 `localStorage.setItem("guide_dismissed_order", "true")`，之后默认折叠。

---

### 3.4 "辅助录入"区默认折叠，草稿/离线时不自动展开

```javascript
const [assistiveOpen, setAssistiveOpen] = useState(false) // 默认折叠
// 但没有：
// useEffect(() => { if (draftAvailable || isOffline) setAssistiveOpen(true) }, [...])
```

检测到草稿或离线时有角标提示，但辅助录入区仍然折叠，用户不知道该点哪里恢复草稿。修复：加 useEffect 在草稿/离线时自动展开。

---

### 3.5 付款方式 value 存英文字符串进数据库

```javascript
<option value="Bank Transfer">银行转账</option>
<option value="Cash">现金</option>
```

数据库里存的是 `"Bank Transfer"`，越南业务员的回款记录审计日志全是英文值，影响后续报表和过滤。修复：value 改为枚举码 `"bank_transfer"`，显示文字走 i18n。

---

### 3.6 结案按钮持续 `animate-pulse`，多行订单同时闪烁

```javascript
className="p-2 bg-emerald-600 text-white rounded-xl hover:bg-emerald-700 shadow-xl animate-pulse"
```

满足结案条件的订单行全部持续闪烁，10 条以上时视觉噪音极大，无法聚焦重要信息。修复：去掉 `animate-pulse`，改用 `hover:ring-2 hover:ring-emerald-400`。

---

### 3.7 佣金比例硬编码 3%

```javascript
const defaultForm = { commissionRateSubmitted: 3, ... }  // 写死
```

修复：从 `currentUser.defaultCommissionRate` 读取，或记住上次填写值。

---

### 3.8 `paymentTermsDays` 无上限校验

```javascript
<input type="number" min={0} />  // 没有 max
```

可填入 9999 天（约 27 年账期）静默通过。修复：加 `max={365}`。

---

### 3.9 `handleQuickShip` 用 `window.location.hash` 导航，绕过路由守卫

```javascript
window.location.hash = "#/shipping?" + params.toString()
```

直接操作 hash 不经过 React Router，若当前表单有脏数据，跳转前不会弹出确认对话框。修复：改用 `useNavigate`，跳转前先调用 `requestClose`。

---

### 3.10 "三轴"状态在 130px 列宽下文字被截断且无提示

"待财务核验"（6字 + badge 样式）在 130px 列宽下会被截断，没有 tooltip 显示完整内容。修复：Badge 加 `title` 属性或 Tooltip 组件。

---

### 3.11 空状态文字硬编码为英文

```javascript
// 历史 Modal 里
children: "No payments recorded."
children: "No history available."
```

中文界面出现英文空状态，是明显的 i18n 遗漏。修复：改为 `{t.noPayments || "暂无回款记录"}`。

---

### 3.12 订单行表格无虚拟滚动，100+ 行时冻结

```javascript
<tbody>
  {formData.items.map((item, index) => (
    <tr>... 10 个 input ...</tr>  // 每行 10 个受控输入
  ))}
</tbody>
```

"粘贴 Excel"功能可能一次导入 200 行 = 2000 个受控 input，低配 PC 上约 1-3 秒冻结。快速修复：超过 50 行时展示分页，每页 50 行。

## 四、后端层：完全未修改，5 个遗留问题

4. Customer 双轨字段未合并 — 旧单值字段与新 JSON 字段并存

## 五、V2 新引入的 3 个问题

**5.1 `offline_scans` 无用户隔离**

```javascript
localStorage.getItem("offline_scans")  // key 无用户 ID
```

同 PC 不同用户共享离线扫描记录。修复：Key 改为 `"offline_scans_" + currentUser.id`。

**5.2 草稿写入 `useEffect` 无 debounce，每次按键触发 localStorage I/O**

```javascript
useEffect(() => {
  localStorage.setItem("orderDraft", JSON.stringify(formData))
}, [formData])  // formData 每次按键变化，即每次写 localStorage
```

修复：加 1000ms debounce。

**5.3 `formatPrice` 在"净额"列未传货币参数**

"余额追踪"列正确使用了 `vi-VN` locale 格式化 VND，但"净额"列调用 `formatPrice(r.finalAmount)` 没有传货币参数，VND 订单净额可能显示为 CNY 格式。
