# 可用性负评对标与发布冻结治理

生成时间：2026-06-08

## 外部负评归纳

成熟 ERP / B 端系统的负面反馈集中在六类问题：

1. 难学、难找、导航成本高  
   G2 上 Epicor Kinetic 的负面标签包含 learning curve、not user-friendly、navigation difficulty、missing features。结论不是“少做功能”，而是默认路径必须更清晰，复杂能力要分层显示。来源：https://www.g2.com/products/epicor-kinetic/reviews

2. 一屏看不全，查账和追溯困难  
   Capterra 上 Sage Intacct 评价中有用户反馈，查交易和追踪系统发生过什么很困难，因为不能一次看到所需全部信息。结论是财务、库存、订单列表必须优先保证扫描密度和关键列稳定。来源：https://www.capterra.com/p/76/Intacct/reviews/

3. 录入重复、流程顺序靠记忆  
   ERP 可用性研究指出，用户会因为交易界面复杂而使用内部小抄或自制压缩表单，也会抱怨重复输入同一数据。结论是系统应减少重复输入，并在组合业务流程里给出上下文。来源：https://cis.bentley.edu/tbabaian/papers/iceis-05.pdf

4. 移动端和触屏被当成附属场景  
   企业仪表盘负评常见问题包括忽视移动端、依赖 hover、在小屏只缩小不重排。结论是触屏必须显示可操作按钮，移动端先展示异常、待办、关键指标。来源：https://studiovigo.co.uk/insights/enterprise-dashboard-ux-fail

5. 一线作业流程和管理层设计脱节  
   制造型 ERP 反馈中，常见阻力包括纸表/Excel 影子流程、库存收发错误、产线现实约束未被设计覆盖。结论是仓库、生产、发运不能只按理想审批流设计，要保留异常、补录、回读证据。来源：https://sysgenpro.com/implementation/manufacturing-erp-adoption-challenges-how-to-address-resistance-on-the-shop-floor

6. 发布后不稳定导致用户失去信任  
   ERP 用户对“升级后流程变了、旧数据对不上、报表看不懂”的容忍度很低。结论是发布必须冻结包、源码状态、运行目录、验证报告，不能靠人工记忆。

## 已落地的设计治理

1. 缩放  
   `index.html` 当前未设置 `user-scalable=no`，继续禁止加入该配置。移动端和弱视用户必须能使用浏览器缩放。

2. 长文本和长编号  
   公共样式增加 `input/textarea/select` 的 `min-width: 0` 和 `max-width: 100%`，防止长客户名、批号、单据号撑破布局。备注类文本使用 `app-long-text`，允许长词换行。

3. 表单备注  
   `FormField` 的 textarea 改为可纵向拉伸，不再强制 `resize-none`。长值超过 18 字时提供 `title`，方便查看完整内容。

4. 表格长值  
   `DataTable` 和 `EnterpriseDataGrid` 对普通文本单元格使用统一 `truncate-cell`，默认截断并提供完整 `title`。自定义 React 单元格不强包，避免破坏复杂列。

5. 触屏操作  
   继续保留触屏下强制显示操作按钮的规则，不能依赖 hover 才出现编辑、删除、审批等按钮。

6. 紧凑模式  
   紧凑模式只作用于 `.app-density-surface` 和 `.app-density-table`，不再全局压缩所有圆角和 padding，避免页面互相误伤。

## 后续判断标准

需要优化：

- 页面能跑通，但存在长文本撑破、按钮靠 hover、关键字段太浅、表格扫读困难。
- 改动能放在公共组件、公共样式或局部列配置中完成。
- 不改变业务状态机、库存/财务/权限语义。

需要重构：

- 同一业务流程跨多个页面重复录入同一字段，且出现数据不一致。
- 页面必须靠用户记忆流程顺序才能完成闭环。
- 核心表格无法通过列配置解决，需要改为统一数据网格能力。
- 发布门禁无法判断源码、构建产物、压缩包、运行目录是否一致。

禁止做法：

- 为了视觉效果重新引入 `user-scalable=no`。
- 为了“干净”隐藏触屏关键操作。
- 给每个页面单独写一套长文本处理规则。
- 为了短期通过审计，把冻结脚本改成永远通过。

## 发布冻结治理

新增入口：

```bash
npm run audit:release:freeze
```

该审计会生成：

- `output/audit/release-freeze-manifest-v1.json`
- `output/audit/release-freeze-manifest-v1.md`

冻结判定必须同时满足：

- 发布压缩包存在并生成 SHA256。
- `E:\爱劳达纯净系统` 中存在 EXE、前端入口、后端入口、生产环境配置、纯净运行目录 manifest。
- `PURE_RUNTIME_PACKAGE.json` 可解析。
- Git 工作区没有未冻结变更。

当前若工作区仍有大量 modified/untracked，审计必须返回 `blocked`。这是正确行为，代表“可测试包”和“最终冻结商业发布包”没有混淆。
