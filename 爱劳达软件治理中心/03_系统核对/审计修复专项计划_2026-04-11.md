# 系统数据流动与交互稳定性修复计划 (Audit Remediation)

经过多轮“人工+自动化”审计，系统已解决编译中断（P0），但在真实数据流转中暴露了两个关键性业务 Bug 和一个性能瓶颈。

## User Review Required

> [!IMPORTANT]
> **1. 客户录入“隐身” Bug**
> 经核查，由于后端权限过滤器（Access Clause）对 `manager` 角色设置了死锁：如果经理被标记为“直销部”，他将无法看到任何被标记为“混合/公海”的客户。
> **方案**：放宽经理角色的查询权限，改为 `segment: { in: [userSegment, 'mixed'] }`。这符合 ERP 经理审计全盘的逻辑。**是否同意此权限放宽？**

> [!IMPORTANT]
> **2. 数据库扩展：Region 字段**
> 目前 `Customer` 表缺少“地区”物理字段。
> **方案**：在 `schema.prisma` 中新增 `region String?`（建议使用受控值，例如 `CN/VN/US/OTHER`），并更新 `CRMCreateModal` 增加下拉框。**是否需要同步支持多个国家（CN/VN/US）的分区统计？**
>
> **审计补充（2026-04-11）**：当前运行环境存在 Prisma `schema-engine` 无法执行（`spawn EPERM`）的问题，导致 `prisma db push / prisma generate` 在本机不可用。
> 在该阻塞解除前，不建议强行落库该字段（会导致编译/运行链不稳定）。建议把 `region` 作为下一阶段数据模型项：
> 1) 先解除 Prisma 引擎执行阻塞或切到 PostgreSQL 后再落库。
> 2) 落库时保持值域受控（代码/枚举/字典），避免自由字符串导致统计不可控。

> [!TIP]
> **3. 性能优化：消除 Loading 挂起**
> 观察到切换 Tab 时有 31:Suspense 带来的 Loading 闪烁。
> **方案**：优化 `appContent.tsx` 的加载逻辑，减少重复 `useEffect` 触发，并增加数据池缓存。
