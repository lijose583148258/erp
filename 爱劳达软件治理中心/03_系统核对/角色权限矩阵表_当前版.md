# 角色权限矩阵表（当前版）

> 更新时间：2026-04-18  
> 说明：本表记录系统各角色在各功能模块的操作边界，前端隐藏 ≠ 后端拦截，两者均需核对。2026-04-18 起，客户、订单、回款、采购、仓储、资产、货抵主链路以动态权限点和数据范围为准。

---

## 系统角色定义

| 角色标识 | 中文名称 | 定位 |
|---|---|---|
| `admin` | 超级管理员 | 全权限，无数据隔离 |
| `manager` | 销售经理 | 全数据可见，可审批调整 |
| `sales` | 业务员 | 只能看自己名下客户/订单 |
| `warehouse` | 仓库员 | 主要管资产和出货 |
| `finance` | 财务员 | 主要管回款、合同、财务报表 |

## 2026-04-18 补充修正：客户运营链路动态权限

> 以下口径覆盖上方合同、样品、售后、发货相关旧描述。后续以动态权限点 + 数据范围为准，不再只以固定角色白名单为准。

| 链路 | 读取权限 | 写入/动作权限 | 数据范围 |
|---|---|---|---|
| 合同 | `contracts.read` | `contracts.write` | 客户范围；财务可通过 `finance_visible` 查看合同，但不能写入 |
| 样品 | `samples.read` | `samples.create` / `samples.status.manage` | 客户范围；仓储可通过 `warehouse_visible` 处理样品状态 |
| 售后 | `rma.read` | `rma.write` / `rma.resolve` | 客户范围；处理售后必须具备 `all` 或 `team_customers` 等可覆盖客户的范围 |
| 发货 | `shipping.read` | `shipping.write` | 发货写入必须具备 `warehouse_visible` |
| 签收批次 | `shipping.receipts.read` | 写入仍归 `shipping.write` | 客户范围、仓储范围或财务 `finance_visible` 可查看 |

## 2026-04-18 补充修正：回款动作动态权限
> 以下口径覆盖回款中心内的写入/动作类接口。后续自定义角色不再只按 `admin/manager/finance/sales` 固定角色判断，而是按动态权限点 + 数据范围判断。

| 链路 | 读取权限 | 写入/动作权限 | 数据范围 |
|---|---|---|---|
| 回款中心读取 | `collections.read` | - | `own_customers/team_customers/all/finance_visible` 等范围进入订单、回款、承诺、争议读模型 |
| 逾期同步 | `collections.read` | `collections.sync` | 必须具备 `finance_visible` |
| 回款核验 | `collections.read` | `orders.payment.verify` | 必须具备 `finance_visible`，且订单创建者不能核验自己订单的付款记录 |
| 催收提醒 | `collections.read` | `collections.reminder.write` | 必须能操作对应订单；批量催收要求所有订单均在范围内 |
| 承诺付款 | `collections.read` | `collections.promise.write` | 必须能操作对应订单，且 `customerId` 必须匹配订单客户 |
| 回款争议 | `collections.read` | `collections.dispute.write` | 必须能操作对应订单，且 `customerId` 必须匹配订单客户 |
| 客户冻结 / 放行 | `collections.read` | `collections.hold.manage` | 必须具备 `finance_visible`；冻结类型必须明确为 `credit` 或 `shipment` |
| 订单发货冻结 / 放行 | `collections.read` | `collections.hold.manage` | 必须具备 `finance_visible`，并能覆盖对应订单 |

专项验收：`scripts/collection-action-permission-scope-audit-v1.cjs` 已通过。
