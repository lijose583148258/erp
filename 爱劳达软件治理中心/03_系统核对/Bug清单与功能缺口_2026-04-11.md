# Bug 清单与功能缺口报告（2026-04-11）

> 本报告通过代码走查和日志分析生成，覆盖后端所有 19 个控制器和前端主要页面。

---

## 一、已确认 Bug（代码级缺陷）

### 🔴 Bug #001 — 出货物流新建：customerId 类型错误（**已修复**）
- **位置**：`shipping.controller.ts → createShipment()`
- **症状**：新建发货单时 500 报错，"Expected Int, provided String"
- **修复**：`Number(customerId)` + `Number(orderId)` 强制转换
- **状态**：✅ 2026-04-11 已修复并重新构建上线

---

### 🔴 Bug #002 — 样品申请新建：customerId 类型错误（**待修复**）
- **位置**：`sample.controller.ts → createSample()` 第 81 行
- **症状**：新建样品申请时有概率 500 报错（视前端是否传字符串而定）
- **原因**：`customerId` 直接从 `req.body` 取值写入 Prisma，未做 `Number()` 转换
- **优先级**：🔴 高（阻断新建样品申请）

---

### 🔴 Bug #003 — 售后申请新建：customerId 类型错误（**待修复**）
- **位置**：`rma.controller.ts → createRma()` 第 82 行
- **症状**：新建售后申请时有概率 500 报错
- **原因**：同上，`customerId` 未做 `Number()` 转换
- **优先级**：🔴 高

---

### 🟡 Bug #004 — 订单新建：customerId 未做 Number 转换（**待验证**）
- **位置**：`order.controller.ts → createOrder()` 第 126 行
- **情况**：`customerId` 未显式 `Number()` 转换，但第 84 行用 `{ where: { id: customerId } }` 直接查找客户。若前端传字符串，Prisma 可能接受（SQLite 模糊匹配），也可能失败。
- **建议**：加 `Number(customerId)` 防御，优先级中等。

---

### 🟡 Bug #005 — 合同 OCR 识别：返回固定模拟数据（**待实现**）
- **位置**：`contract.controller.ts → analyzeContract()` 第 213-231 行
- **症状**：合同 AI 识别按钮点击后，永远返回固定的模拟数据（`"模拟合同识别结果"`, `50000 CNY`）
- **原因**：该函数是占位实现，真实 OCR 服务未对接
- **优先级**：🟡 中（功能上没有崩溃，但用户会有错误预期）

---

### 🟡 Bug #006 — 开发模式下前端走 Mock 而非真实 API（**配置问题**）
- **位置**：`utils/api.ts` 第 20 行，`services/auth.service.ts` 第 35 行
- **症状**：用 `npm run dev`（Vite 开发服务器）运行时，所有接口请求均走 `mockAdapter.ts`，不打到真实后端
- **影响**：开发调试时看到的数据是假数据（"供应商 A" 等），与生产环境不一致
- **修复**：在根目录 `.env` 中加 `VITE_USE_MOCK=false` 即可切换

---

### 🟢 Bug #007 — 登录界面：角色选择冗余（体验缺陷）
- **位置**：`components/Login.tsx`
- **症状**：页面同时展示 5 个"选择角色"按钮 + 4 个"快捷账号"按钮，逻辑重叠
- **快捷账号当前行为**：仅填充表单，需要再手动点"登录系统"

---

### 🟢 Bug #008 — ClickSpark 点击特效过密（视觉干扰）
- **位置**：`components/app/ClickSpark.tsx`
- **症状**：每次点击弹出 8 个较大彩色粒子（8-18px），视觉干扰较强
- **修复**：粒子数量改 2-3 个，尺寸缩小至 4px

## 二、功能缺口（未完成或未对接的功能）

### 📋 前端有入口但后端是占位实现

| 功能 | 位置 | 状态 |
|---|---|---|
| **合同 AI OCR 识别** | `contract.controller.ts:analyzeContract` | 固定返回模拟数据，未对接真实 OCR 服务 |
| **AI 助手（Gemini）** | `services/geminiService.ts` | 需要配置 `GEMINI_API_KEY` 才能使用，否则 AI 聊天框报错 |
| **发货单 OCR 识别** | `ShippingOcrPanel.tsx` | 前端有 UI，但 `handleOcrParse` 实际上调用的是 Gemini，Key 未配则失效 |

### 📋 前端导航存在但功能较弱

| 模块 | 当前状态 | 缺口 |
|---|---|---|
| **生产管理** | `ProductionWorkspaceV2.tsx` 已完成 | 生产批次与出货物流、采购的联动数据流未打通 |
| **经销商分析** | `DealerAnalytics.tsx` 已完成 | 依赖 dashboard 聚合数据，无独立经销商维度 API |
| **核心风控** | `RiskControl.tsx` 已完成 | 逾期预警依赖 `overdueAmount` 字段，该字段需手动输入而非自动计算 |
| **团队管理** | `TeamManagement.tsx` 已完成 | 提成审核流程仅前端模拟，无后端审批状态机 |

### 📋 部署层面的配置遗漏

| 项目 | 说明 |
|---|---|
| `docker-compose.yml` CORS | 写死为 `localhost:8080`，部署到真实服务器必须修改 |
| `backend/.env` JWT_SECRET | 如未设置，使用默认值（安全风险） |
| 后端独立 Dockerfile | `backend/` 目录没有自己的 `Dockerfile`，当前 docker-compose 依赖根目录的 Dockerfile（仅打包前端），需要补充 |
| 根目录临时文件 | 约 20 个 `.tmp-*.cjs`、`tmp_*.ps1` 调试文件未清理 |
