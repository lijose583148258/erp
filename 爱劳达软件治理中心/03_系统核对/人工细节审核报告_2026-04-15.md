### S2. Vite 无 API Proxy 配置

`vite.config.ts` 中**没有配置 `/api` 代理到后端**：

```typescript
// 缺少 proxy 配置：
server: {
  port: 3000,
  strictPort: true,
  host: '0.0.0.0',
  // ❌ 无 proxy: { '/api': { target: 'http://127.0.0.1:5001' } }
}
```

前端双口径测试之所以能通过，是因为前端 `services/*.ts` 中用 axios 直接请求 `http://127.0.0.1:5001`（硬编码绝对路径）。这在生产环境不成问题（nginx 反向代理），但开发环境中：
- ❌ 不够规范（应该用相对路径 `/api/*` + Vite proxy 转发）
- ✅ 当前能正常工作（不影响功能）

**优先级：中（非阻塞，生产部署通过 nginx 解决）**

## 🔴 严重（补充）

### S4. 越南语翻译缺失 35 个 key（反复修但不断漏）

**根因分析**：每次新增 en/zh key 时没有同步补 vi.ts，且没有编译时检查机制。

| 维度 | en.ts | vi.ts | zh.ts（含 overrides） |
|------|-------|-------|----------------------|
| Key 数 | 991 | 959 | 991（zh 主体 913 + overrides 补 78） |
| 缺失 | — | **35 个** | 0 个 |

**vi.ts 缺失的 35 个 key**：

```
AI 相关（20 个）: aiAnalysisReport, aiCustomerMgmt, aiHelpAnalysis, aiHelpOps,
  aiHelpTip, aiHelpTitle, aiInsight[Advice/Excellent/High/Low/Medium/Normal],
  aiLogisticsMgmt, aiOcrDragDrop, aiOrderStats, aiPlaceholder, aiProcessing,
  aiRiskAlert, aiType[Customer/Order/Sample/Shipment]

客户/导入（5 个）: custCreated, custCreateFail, custImportFail, custImportSuccess,
  custRequired

化学品（4 个）: casNo, grade, purity, msds

其他（6 个）: backToBack, hazardousLicense, quickOrder, Try
```

**为什么反复修不好**：
1. zh 采用 overrides 补丁机制（`zh.overrides.ts` + `zh.clean-overrides.ts`），加 key 不需要改主文件
2. vi 没有 overrides 机制，每次要直接改 vi.ts 主文件
3. 没有编译时 key 对齐检查，新增 key 时很容易漏掉 vi

---

### S5. zh 翻译的"补丁架构"——三文件合并

```typescript
// translations/index.ts
export const translations = {
  zh: { ...zh, ...zhOverrides, ...zhCleanOverrides },  // 三层合并
  en,                                                     // 单文件
  vi,                                                     // 单文件
};
```

zh 拆成了 3 个文件（主体 35KB + overrides 1.3KB + clean-overrides 3.6KB），而 en/vi 是单文件。这造成：
- 改 zh 时不确定该改哪个文件
- 合并顺序不同会产生不同结果
- 维护成本高
