# CRM细节不足优先级清单（三档版）

## 说明

这份清单只做一件事：按“先碰哪块最划算”排序。

三档含义：

1. **立刻影响维护**：现在不收，后面会越改越乱
2. **会影响上线**：不先补，后面 CRM 分线、池子和权限没法稳定上线
3. **只是美化治理**：不影响当前主链路，可以后置

## 1. 立刻影响维护

| 项目 | 问题 | 为什么先处理 |
| --- | --- | --- |
| `pages/CRM.tsx` 过重 | 一个页面同时承担列表、筛选、视图切换、创建、导入、分页、弹窗 | 后面继续加功能会越来越难维护 |
| `backend/src/controllers/customer.controller.ts` 过重 | 查询、创建、更新、删除、导入导出、归属控制都在一起 | 业务规则一变就容易互相牵连 |
| `App.tsx` 过重 | 主题、语言、币种、角色切换、业务线切换都混在一起 | 全局壳太重，改动风险高 |
| 导入导出逻辑分散 | 各模块自己处理 Excel / CSV / 模板 | 新模块一来就会重复造轮子 |
| 多语/文案资源继续扩散 | 页面里如果再长硬编码，后面会回到“到处找文案”的状态 | 维护成本会再次升高 |

## 2. 会影响上线

| 项目 | 问题 | 为什么会影响上线 |
| --- | --- | --- |
| 内销 / 分销未正式落到客户池模型 | 代码里有 `direct / channel / mixed`，但客户池治理还没正式分线 | 上线后经理和销售会不知道到底按哪条线操作 |
| 公海 / 内部池 / 私海未正式事件化 | 现在更多是前端视图或字段变化，不是完整流转事件 | 无法稳定审计、无法追责、无法回放 |
| 经理工作台边界未明确 | 经理能看什么、能改什么还没完全收口 | 容易出现越权、误操作或口径混乱 |
| 客户回收 / 转派审计不完整 | 缺少统一回收单、转派记录、领取记录 | 客户归属上线后会失真 |
| 统一汇率服务未接事实源 | 当前换算还是硬编码 | 多币种经营分析上线后数据口径会不稳定 |

## 3. 只是美化治理

| 项目 | 问题 | 为什么可后置 |
| --- | --- | --- |
| 三语全量统一 | 页面上还有部分硬编码文案 | 不影响主线闭环 |
| 公海健康度看板 | 容量、超时、领取效率的管理面板 | 属于管理增强，不是当前主闭环 |
| AI 客户评分 / 推荐领取 | 建议优先跟进对象 | 属于智能增强 |
| 经理工作台视觉精修 | 视觉/交互再优化 | 不影响核心数据治理 |
| 客户分层标签体系 | 标签标准化 | 可以放到经营分析阶段 |

## 优先执行顺序

1. 先清 `pages/CRM.tsx`、`customer.controller.ts`、`App.tsx` 这类重文件
2. 再把内销 / 分销和客户池流转做成正式模型
3. 再补经理工作台、回收、转派、审计
4. 最后再做三语、AI、健康度看板这类增强项

## 结论

这份清单的核心不是“功能多少”，而是：

**先让维护成本下降，再让上线风险下降，最后才做治理美化。**
