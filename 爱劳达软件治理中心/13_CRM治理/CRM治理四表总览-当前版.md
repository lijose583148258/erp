# CRM治理四表总览（当前版）

## 一句话

这份总览把你要的四类内容放在一起：

1. 系统现状评审表
2. 待拆分模块清单
3. 扩展层优先级
4. 细节不足优先级三档清单

## 1. 系统现状评审表

当前 CRM 的事实是：

- 私海有基础，`salespersonId` 已经在用
- 公海有前端概念，但还没有完整落成池子模型
- 内销 / 分销已经在前端和样例数据里出现了
- 经理 / 销售 / 管理员的角色基础有了，但还没按业务线正式分层

对应文档：

- [CRM现状评审表-当前版](./CRM现状评审表-当前版.md)

## 2. 待拆分模块清单

最该先拆的是：

- `pages/CRM.tsx`
- `backend/src/controllers/customer.controller.ts`
- `App.tsx`
- 导入导出相关逻辑

如果继续往下拆，`pages/SalesOrders.tsx`、`pages/Shipping.tsx`、`backend/src/controllers/order.controller.ts` 也应该进拆分池。

对应文档：

- [CRM待拆分模块清单-当前版](./CRM待拆分模块清单-当前版.md)

## 3. 扩展层优先级

当前扩展层先放这三类：

1. 离线同步 / 冲突处理
2. 正式财务核算层
3. 报表导出与审计增强

对应文档：

- [CRM扩展层优先级建议-当前版](./CRM扩展层优先级建议-当前版.md)
- [扩展层总表-当前版](../12_扩展层/扩展层总表-当前版.md)

## 4. 细节不足优先级三档清单

### 立刻影响维护

- `pages/CRM.tsx` 过重
- `backend/src/controllers/customer.controller.ts` 过重
- `App.tsx` 过重
- 导入导出逻辑分散
- 多语/文案资源还需要继续收口

### 会影响上线

- 内销 / 分销未正式落到客户池模型
- 公海 / 内部池 / 私海未正式事件化
- 经理工作台边界未明确
- 客户回收 / 转派审计不完整
- 统一汇率服务未接事实源

### 只是美化治理

- 三语全量统一
- 公海健康度看板
- AI 客户评分 / 推荐领取
- 经理工作台视觉精修
- 客户分层标签体系

对应文档：

- [CRM细节不足优先级清单-三档版](./CRM细节不足优先级清单-三档版.md)
- [CRM细节不足优先级清单-当前版](./CRM细节不足优先级清单-当前版.md)

## 结论

先让维护成本下降，再让上线风险下降，最后才做治理美化。
