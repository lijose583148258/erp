# 内销分销业务线下的客户池治理方案（当前版）

## 1. 结论先说

这个系统里的 CRM，不能只按“公海 / 私海”来做。
它已经有明确的业务线分段：

- `direct` = 内销
- `channel` = 分销 / 渠道
- `mixed` = 管理层 / 总部视角

所以，正确的治理方式应该是：

**先分业务线，再分客户池，再分角色权限，再分动作流程。**

不是反过来，也不是只做一个公海池。

当前前端和样例数据里已经出现了：

- `direct`

- `mixed`

## 3. 当前问题在哪里

### 3.1 只做公海 / 私海还不够

现在 CRM 页面有 `my / public` 的视图概念，但这更像界面筛选，不是正式业务模型。

问题是：

- 你看得到“公海”
- 但系统没有把公海、内部池、私海做成正式状态
- 也没有把内销 / 分销分别切开

### 3.2 内销 / 分销没有进入正式客户池治理

现在系统里已经有 `direct / channel`，但客户池治理还没有按这两个业务线正式分层。

这会导致：

- 内销客户和分销客户混在同一池
- 分配规则不一致
- 经理看板不清晰
- 回收和转派缺少业务边界

### 3.3 客户分配 / 回收还不是正式事件

现在更像是改字段，而不是完整的流转事件。

缺少：

- 分配单
- 回收单
- 转派单
- 领取记录
- 审计留痕

## 4. 正确的客户池结构

建议把每条业务线都做成“三层池”：

### 4.1 内销线 `direct`

- 内销公海
- 内销内部池
- 内销私海

### 4.2 分销线 `channel`

- 分销公海
- 分销内部池
- 分销私海

### 4.3 总部 / 管理视角 `mixed`

- 看全局
- 做规则配置
- 做审计
- 做跨线回收和重分配

## 5. 客户池之间怎么流转

### 5.1 公海 -> 内部池

适合场景：

- 新客户导入后先进入共享池
- 经理筛选后放入某业务线的内部池
- 系统根据区域 / 业务线 / 客户等级自动分流

建议执行人：

- `admin`
- `manager`

建议留痕：

- `assignedAt`
- `assignedBy`
- `assignedReason`
- `businessLine`

### 5.2 内部池 -> 私海

适合场景：

- 经理派发给具体销售
- 销售领取后确认接单
- 系统按负载、区域、客户等级自动分配

建议执行人：

- `admin`
- `manager`
- 允许受控领取的 `sales`

建议留痕：

- `claimedAt`
- `claimedBy`
- `ownerId`
- `salespersonId`

### 5.3 私海 -> 内部池

适合场景：

- 销售离职
- 销售转岗
- 客户长期无跟进
- 经理回收
- 系统 SLA 超时自动回收

建议执行人：

- `admin`
- `manager`

建议留痕：

- `reclaimedAt`
- `reclaimedBy`
- `reclaimReason`

### 5.4 内部池 -> 公海

这个动作要谨慎。

建议场景：

- 归类错误
- 客户不属于当前业务线
- 需要重新进入共享筛选池

建议执行人：

- `admin`
- `manager`

建议不要：

- 让销售自己随意把客户甩回公海

因为那样会破坏审计和责任链。

## 6. 角色权限建议

### 6.1 销售 `sales`

建议权限：

- 看自己私海
- 看本业务线允许领取的公海 / 内部池
- 领取客户
- 更新自己客户的跟进记录

不建议权限：

- 不能回收别人客户
- 不能跨业务线领取
- 不能把客户直接改成公海

### 6.2 经理 `manager`

建议权限：

- 看自己业务线的公海 / 内部池 / 私海
- 分配客户
- 回收客户
- 查看领取和转派历史
- 查看团队负载和未跟进客户

### 6.3 管理员 `admin`

建议权限：

- 看全局
- 配置业务线规则
- 配置池子规则
- 审计全部动作
- 跨线调整客户归属

### 6.4 财务 / 仓库

建议权限：

- 只读客户基础信息
- 只读信用、回款、发货相关字段
- 不参与客户归属变更

## 7. 建议的数据概念

现有 `salespersonId` 可以继续保留，但不够。

建议补这些概念：

- `businessLine`: `direct` / `channel`
- `poolType`: `public` / `internal` / `private`
- `ownerType`: `pool` / `team` / `user`
- `ownerId`
- `ownerTeamId`
- `assignedAt`
- `assignedBy`
- `claimedAt`
- `claimedBy`
- `reclaimedAt`
- `reclaimedBy`
- `assignmentStatus`
- `assignmentReason`

## 8. 经理该看到什么

经理不应该只看到“客户列表”。

经理应该看到：

- 本业务线公海
- 本业务线内部池
- 本业务线私海
- 领取记录
- 回收记录
- 客户超时未跟进清单
- 团队负载
- 当前转派待处理

这样经理才是“管池子的人”，不是只是一个更高级的销售账号。

## 9. 这套方案和当前代码的关系

当前代码已经具备这些基础：

- 业务线分段
- 角色权限
- 私海归属字段
- CRM 页面筛选

还没有正式具备这些：

- 业务线下的客户池模型
- 公海 / 内部池 / 私海正式流转
- 分配 / 回收事件表
- 经理业务线工作台

所以这份方案是“顺着现有系统补结构”，不是重做一套 CRM。

## 10. 最后结论

如果按现有系统来做，CRM 优化的正确顺序应该是：

1. 先把内销 / 分销分开
2. 再把每条业务线下的公海 / 内部池 / 私海做清楚
3. 再把分配 / 回收 / 转派做成事件
4. 再补经理工作台
5. 最后再上智能分配和 AI 辅助
