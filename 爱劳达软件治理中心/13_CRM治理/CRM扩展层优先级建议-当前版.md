# CRM扩展层优先级建议（当前版）

## 定位

扩展层不是拿来替代 CRM 主闭环的，而是给 CRM 加“更聪明、更自动、更可扩展”的能力。

## 建议优先级

### P0

| 项目 | 说明 |
| --- | --- |
| 公海/私海正式化 | 这是 CRM 的基础治理，不应该再拖 |
| 分配/回收事件化 | 先把流程留痕做好 |

### P1

| 项目 | 说明 |
| --- | --- |
| 智能分配 | 依据容量、地区、行业、等级做分配 |
| 自动回收 | 依据 SLA、无跟进、离职、超时做回收 |
| 批量领取 | 公海客户支持批量领取，但要有上限和审计 |

### P2

| 项目 | 说明 |
| --- | --- |
| AI 客户评分 | 用于建议优先跟进对象 |
| 跟进建议生成 | 帮助经理生成跟进计划 |
| 经理看板增强 | 看团队负载、公海健康度、回收率 |

### P3

| 项目 | 说明 |
| --- | --- |
| 离线同步 | 适合后续多端/低网场景 |
| 冲突处理 | 适合将来多端同时编辑 |
| 与外部 CRM/营销系统同步 | 等内部闭环稳定后再做 |

## 执行原则

1. 主闭环先稳定，扩展层后接入
2. 扩展层不能改变主数据归属规则
3. 扩展层所有动作必须可回放、可审计
4. 不把 AI 先做成主流程依赖

## 结论

CRM 的扩展层最适合放“智能分配、自动回收、经理看板、AI 辅助”，不适合先做复杂审批和多层组织树。
