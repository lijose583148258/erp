# P0 账号角色权限审计收口

日期：2026-06-16

## 1. 本轮范围

本轮处理第 22 份工作树盘点中的 P0 第一组：

- 账号
- 员工子账号
- 默认演示凭据
- 角色权限
- 权限变更审计差异

本轮不重构权限系统，不改业务权限模型，只修复审计脚本与发布安全策略不一致导致的假红/假绿。

## 2. 发现的问题

### 2.1 员工账号生命周期审计使用默认 admin

现象：

- `npm run audit:team:account-lifecycle` 失败。
- 浏览器截图停留在“首次登录需要修改密码”页面。
- 脚本等待 `[data-testid="team-new-member"]` 超时。

原因：

- 发布安全策略已经要求默认演示账号不能直接进入业务区。
- 旧审计脚本仍用 `admin/admin123` 登录。
- 因此审计失败不是团队页面坏了，而是脚本与安全策略冲突。

修复：

- `scripts/team-account-lifecycle-browser-audit-v1.cjs`
- 参考角色权限审计方式，临时创建审计管理员：
  - `role = admin`
  - `isActive = true`
  - `mustChangePassword = false`
- 审计结束后清理临时管理员与临时员工账号。

### 2.2 角色权限 UI 审计存在假绿

现象：

- `npm run audit:permissions:system-ui` 命令退出码为 0。
- 但 `output/playwright/role-system-permission-ui-browser-audit-report-v1.json` 中 `status = failed`。
- 失败点是恢复原始销售权限时等待 `role-change-review` 超时。

原因：

- 恢复阶段目标权限本来已经等于原始值。
- 脚本仍然点击保存并等待“变更复核”弹窗。
- 同时 finally 中把报告设为 failed 后，没有让进程退出失败。

修复：

- `scripts/role-system-permission-ui-browser-audit-v1.cjs`
- `setPermissionViaUi` 在权限无需变化时直接返回 `{ changed: false }`，不触发保存。
- `main().then` 中增加 `report.status !== 'passed'` 的退出保护。

## 3. 验证结果

### 默认凭据发布安全

命令：

- `npm run audit:auth:default-credentials`

结果：

- `status = passed`
- 默认演示账号可以进入强制改密/安全流程。
- `businessAccess = []`
- 结论：默认演示账号不能进入业务区。

### 员工账号生命周期

命令：

- `npm run audit:team:account-lifecycle`

结果：

- `status = passed`
- 覆盖：
  - 审计管理员登录
  - 创建员工账号
  - API 回读员工
  - 员工首次登录强制改密
  - 管理员停用员工
  - 停用后员工登录被拦截

### 角色权限 UI

命令：

- `npm run audit:permissions:system-ui`

结果：

- `status = passed`
- 覆盖：
  - 角色加载中失败关闭
  - 角色加载错误失败关闭
  - 销售角色权限读取
  - UI 授予权限
  - UI 撤销权限
  - 恢复原始权限

### 角色结构化审计差异

命令：

- `npm run audit:permissions:role-audit-diff`

结果：

- `status = passed`
- 覆盖：
  - 创建临时角色
  - 更新权限和数据范围
  - `auditLog` 中存在 `before / after / changed`
  - 新增权限和新增数据范围可追踪

## 4. 反幻觉结论

- 不能再说“无法给员工做个人登录账户”：员工账号创建、首次登录强制改密、停用拦截已经有浏览器证据。
- 不能再用默认 `admin/admin123` 做业务页审计：发布安全模式下它必须被阻断在强制改密流程。
- 角色 UI 审计现在避免假绿：报告失败会让进程失败。
- 本轮没有降低安全门槛，也没有绕过默认凭据限制。
