# HarnessEngine 隔离架构治理规范

## 1. 定义

在爱劳达 ERP+CRM 中，`HarnessEngine` 不是业务引擎，不是页面入口，不是正式运行壳，不是主数据链路。

它的唯一定位是：

- 审计隔离层
- 点测驱动层
- 验收编排层
- 压测与冲突注入层
- 恢复演练辅助层

一句话：  
`HarnessEngine` 只能验证系统，不能代表系统。

## 2. 为什么必须降为隔离架构

过去多轮偏航的共同风险是：

- 用测试壳替代正式壳
- 用审计入口替代业务入口
- 用 mock / harness 状态掩盖真实接口问题
- 用“脚本通过”误判“人工可用”

因此从当前版开始，`HarnessEngine` 一律降为隔离层。

## 3. 架构原则

### 3.1 单向原则

正式系统可以被 `HarnessEngine` 调用验证，  
但正式系统不得反向依赖 `HarnessEngine` 才能运行。

### 3.2 非侵入原则

`HarnessEngine` 不得：

- 改写正式默认入口
- 改写正式默认路由
- 默认开启 mock
- 默认注入假数据
- 修改正式 UI 壳结构
- 修改正式权限口径

### 3.3 可拔插原则

完全移除 `HarnessEngine` 后，正式系统仍必须满足：

- 能启动
- 能登录
- 能创建与回读
- 能构建
- 能打包

### 3.4 证据原则

`HarnessEngine` 的结论只能作为证据之一，不能单独作为“修复完成”结论。

最终结论必须包含：

- 编译结果
- 构建结果
- 浏览器人工点测结果
- 写入回读结果

## 4. 允许承担的职责

`HarnessEngine` 允许承担：

- 浏览器级冒烟
- 固定路径人工点测辅助
- API 审计
- 并发与幂等冲突注入
- 恢复演练
- 双端口核对
- 报告生成
- 时间门禁与卡住判定

## 5. 禁止承担的职责

`HarnessEngine` 禁止承担：

- 正式首页入口
- 正式菜单渲染
- 正式状态机
- 正式权限判断
- 正式 CRUD 真实逻辑
- 正式多语言切换核心逻辑
- 正式数据库迁移主逻辑
- 正式上传下载主链路

## 6. 接入规则

凡是 `HarnessEngine` 相关能力，必须满足以下接入规则：

1. 显式开关  
   必须通过单独命令、脚本、环境变量或专用审计脚本触发。

2. 默认关闭  
   正式启动时必须默认关闭，不允许隐式开启。

3. 路径隔离  
   审计脚本、验收脚本、恢复脚本、mock 逻辑、测试报告必须与正式运行链分开。

4. 数据隔离  
   压测、冲突注入、假数据写入必须带明确标记，可追溯，可清理。

5. 输出诚实  
   报告必须区分：
   - 脚本通过
   - 人工通过
   - 仅 API 通过
   - 仅浏览器壳通过

## 7. 判定矩阵

### 属于正式运行链

- `App.tsx`
- 正式路由挂载
- 当前活跃页面与 service
- 当前后端 controller / route / validator
- 正式启动脚本

### 属于 HarnessEngine 隔离层

- 浏览器点测脚本
- dual-port 审计脚本
- 冒烟脚本
- 并发冲突脚本
- 验收报告生成脚本
- 恢复演练脚本

## 8. 发现越界时的处理

若发现 `HarnessEngine` 越界进入主运行链，必须立即执行：

1. 标注越界点
2. 停止继续加补丁
3. 将其降级为独立脚本或独立隔离模块
4. 恢复正式运行链的唯一入口
5. 重新执行人工点测与回读验证

## 9. 与乱码治理联动

凡是出现以下现象时，必须优先怀疑 `HarnessEngine` 越界：

- 页面突然回到裸 HTML 风格
- 样式壳丢失
- 菜单语言口径混乱
- 审计报告显示通过，但页面仍脱钩
- 页面字段像测试字段而不是业务字段

## 10. 一句话原则

`HarnessEngine` 只能做“隔离验证层”，  
永远不能再变成“业务主入口替身”。
