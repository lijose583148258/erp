# 发布冻结工作树变更盘点

日期：2026-06-16

## 1. 本轮目标

上一轮 `audit:release:freeze` 已经证明当前不能进入最终发布冻结，阻断点是：

- 源码工作树未冻结。
- 当前稳定包来自脏工作树。

本轮不直接清理、不回滚、不合并大改，而是先把工作树变更按发布风险分组，避免继续用“83/85 个变更”这种无法执行的笼统描述推进。

## 2. 新增审计脚本

新增：

- `scripts/release-worktree-change-inventory-v1.cjs`
- `npm run audit:release:worktree`

脚本行为：

- 只读取 `git status` 和 `git diff --numstat`。
- 输出 JSON 与 Markdown：
  - `output/audit/release-worktree-change-inventory-v1.json`
  - `output/audit/release-worktree-change-inventory-v1.md`
- 工作树有变更时返回非零退出码，这是预期行为，因为“脏工作树”本身就是发布冻结阻断。
- 使用 `git -c core.quotepath=false`，避免中文路径被 Git 转义后误归类。

## 4. 三步法乱码核查

现象：

- PowerShell 直接 `Get-Content` 读取 `output/audit/release-worktree-change-inventory-v1.md` 时显示乱码。

核查：

1. 使用 Node 按 UTF-8 读取文件。
2. 检查替换字符 `U+FFFD`。
3. 检查中文关键字和 Git 中文路径。

结论：

- `replacement: 0`
- 标题 `发布冻结工作树变更盘点` 存在。
- `爱劳达软件治理中心` 中文路径存在。
- 未检测到常见 mojibake 片段。

因此本轮不修 Markdown 内容，只记录为 PowerShell 显示层问题。

## 5. P0 处置顺序

### 第一组：账号、角色、权限与默认凭据

原因：

- 涉及登录、员工子账号、默认演示账号、角色权限、审计差异。
- 这是用户最关心的“其他人怎么登录/怎么建员工账号”的基础。
- 一旦这里有问题，发布包不能给员工试用。

处置要求：

- 保持默认演示账号不能进入业务区。
- 员工账号创建、停用、改密、角色分配必须有 API/浏览器证据。
- 角色权限变更必须有结构化审计差异。

### 第二组：发布冻结与打包闸门

原因：

- 决定最终 zip 是否可信。
- 当前 `audit:release:freeze` 已经能正确选中最新包，但仍被脏工作树阻断。

处置要求：

- 不能降低冻结门槛。
- 打包前必须让 `SOURCE_MANIFEST.json` 的 `sourceDirtyCount` 为 0。
- 最终包必须重新从冻结源码构建。
