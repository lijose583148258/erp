# 生产 BOM 完工强校验执行记录

日期：2026-04-17

## 目标

避免生产模块出现“假完工”：

- 有 10 种原料的胶水、树脂、涂料配方，不能只耗用 1 种原料就完成工单。
- 后端必须强制检查 BOM 原料覆盖，不允许只靠前端提醒。
- 支持保密代号：物料名称可以不填，但物料代号必须能和实际库存匹配。
- 支持替代组：同一替代组内至少一种物料被耗用即可，不要求组内全部耗用。

## 本次改动

- `backend/src/services/production-mutation.service.ts`
  - 新增 BOM 原料覆盖校验。
  - 完工前读取工单 BOM 明细。
  - 对无替代组的 BOM 行逐项校验是否有实际耗料记录。
  - 对有替代组的 BOM 行按组校验，组内至少一种物料被实际耗用。
  - 匹配字段支持 `materialCode`、`materialName` 对应库存的 `productName`、`batchNo`。

## 为什么先做覆盖校验，不直接做严格数量公式

当前系统还没有完整的计量单位换算主数据，例如：

- kg / 吨 / 桶 / 升 / 方
- 固含量
- 密度
- 损耗率
- 计量基准是每 kg 成品、每批、还是百分比

如果现在直接用一个硬公式强行判断数量，容易误伤真实生产。所以本包先做最值钱、最稳的后端硬规则：

- 必需原料不能漏。
- 替代组不能整组漏。
- 实耗必须来自真实库存余额。
- 库存不足仍由统一库存服务阻止。

数量合理性将在下一阶段接入“单位换算 + 配方基准 + 损耗率”后继续深化。

## 第二次加固：理论耗用量偏差闸门

继续补强内容：

- 完工时不再只校验“有没有覆盖 BOM 原料”，还会校验“实际耗用量是否在理论耗用量允许偏差内”。
- 理论耗用量 = `BOM 单耗 * 产量 * (1 + 损耗率)`。
- 当前默认偏差阈值为 8%。
- 单位不一致时不默默换算，直接阻止完工并提示单位不匹配。
- 百分比配方行暂不做强数量校验，等单位换算、密度、固含量主数据补齐后再启用。
- 完工预览从只按 `materialName` 找库存，升级为按 `materialCode` 或 `materialName` 匹配库存的 `productName` / `batchNo`，支持保密代号。
- 生产状态更新的业务错误从通用 500 调整为 409，避免把正常业务拦截误判为系统崩溃。

## 第三次加固：角色级偏差与结构化异常

继续修正“固定 8% 可能过硬或过松”的问题：

- 主树脂、基础树脂默认偏差：3%。
- 固化剂、催化剂、引发剂默认偏差：2%。
- 助剂、填料、颜料、溶剂默认偏差：5%。
- 包装、容器、标签默认偏差：0%。
- 未识别角色暂用 8%。

后端新增结构化异常：

- `missing_material`：缺少 BOM 原料耗用。
- `unit_mismatch`：BOM 单位和库存单位不一致。
- `quantity_under`：实耗低于理论范围。
- `quantity_over`：实耗高于理论范围。

异常严重度：

- `blocking`：必须阻止完工。
- `approval_required`：后续接主管审批入口，目前仍阻止直接完工并把异常明细返回前端。

前端保持原有弹窗风格，只补充逐条异常明细：

- 显示物料/代号。
- 显示理论值、实耗值、单位。

## 第四次加固：BOM 行级允许偏差

- 新增 BOM 明细字段：`allowedVarianceRate`。
- 数据库运行库平滑补列：`production_bom_items.allowed_variance_rate`。
- 后端创建 BOM 时保存该字段。
- 查询 BOM 时返回该字段。
- 完工校验优先使用 BOM 行级允许偏差；未配置时才回退到角色默认偏差。
- 为避免 Prisma Client 被 Windows 文件锁卡住，本轮完工校验通过 raw SQL 合并 `allowed_variance_rate`，不依赖重新生成客户端即可稳定运行。

## 浏览器真实闭环补验与隐性缺陷修复

时间：2026-04-17

本轮先失败后通过，保留失败原因，避免“假绿灯”：

1. 第一次失败：浏览器审计脚本仍在找旧按钮“添加物料”，但当前页面已经升级为 Excel 网格。结论：验收链旧噪声，不是页面业务失败。
2. 第二次失败：运行中的 5001 后端还是旧进程，API 返回 `allowedVarianceRate` 未识别。结论：构建通过不等于运行层已刷新，必须重启 stable runtime 后再验。
3. 第三次失败：完工弹窗正确阻止无库存完工。结论：不是坏事，说明“防假完工”生效；测试脚本必须先准备真实原料库存。
4. 隐性缺陷：新建工单会把页面默认选中的旧批次带入，导致完工产出挂到旧批次。结论：这是业务假关联风险，必须修前端逻辑。

修复内容：

- `ProductionWorkspaceV2.tsx`
  - 加载批次后不再默认选中第一条批次。
  - 新建工单时，只有当选中批次的产品名与工单产品名一致，才允许带入 `batchId`。
  - 避免工单产出错误叠加到旧批次。
- `production-browser-audit-v1.cjs`
  - 按当前 BOM Excel 网格填 10 行化工配方。
  - 准备 `LOC-RAW` 测试原料库存。
  - 打开“工单完工耗料确认”弹窗并点击“确认扣减并完工”。
  - 增加断言：完工批次产品名必须等于本次工单产品名，防止旧批次假关联。
