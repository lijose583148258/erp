# 化工 BOM 链路纳入阶段 3 闸门记录 2026-04-21

## 1. 本包目标

本包属于阶段 3 的生产/BOM 业务链路治理包。

目标是确认胶水、树脂、涂料这类化工配方场景不是只停留在“生产页面能打开”，而是具备真实 API 闭环：

1. 支持 10 行原料 BOM。
2. 支持只填代号，避免泄露真实配方名称。
3. 少耗用原料时必须被后端阻止，不能假完工。
4. 补齐原料后可以完工。
5. 完工后必须生成原料扣减、成品入库和成本凭证。
6. 该链路必须进入阶段 3 默认验收。

## 2. 发现的问题

运行 `node .\scripts\chemical-bom-production-chain-audit-v1.cjs` 后业务链路通过，但审计过程中发现一个细节风险：

`scripts/lib/chemical-bom-audit-utils.cjs` 中默认仓库/库位 seed 常量存在真实源码乱码：

| 原风险 | 正确含义 |
| --- | --- |
| `涓讳粨搴?` | `主仓库` |
| `鍘熸枡鍖?` | `原料区` |
| `鎴愬搧鍖?` | `成品区` |
| `鍗婃垚鍝佸尯` | `半成品区` |
| `搴熸枡鍖?` | `废料区` |

这是源码常量层问题，不是终端显示层问题。按乱码三步法处理：先翻译、再定位层级、再修复脚本。

同时发现报告字段 `complete_work_order` 的 `status` 被 HTTP 状态码覆盖，容易造成报告误读。已改成：

1. `returnedWorkOrderStatus`
2. `httpStatus`

## 5. 反思

本包方向正确：

1. 没有凭页面冒烟判断生产模块可用。
2. 没有把“凭证 1 条”误判为“只扣了 1 种原料”，而是补看了 10 条原料库存扣减回读。
3. 发现脚本源码乱码后，执行了乱码三步法，而不是直接大范围重写。
4. 将化工 BOM 链路纳入阶段 3 闸门，避免后续回归遗漏。

后续仍需继续：

1. 浏览器级生产 BOM 人工输入体验还需要继续增强，尤其是 10+ 原料 Excel 化录入体验。
2. 成本凭证当前是聚合行，需要在财务/成本报表中明确“聚合凭证”和“原料明细”的穿透关系。
3. 生产页面文件 `ProductionWorkspaceV2.tsx` 仍然过大，后续应拆成工作台壳、BOM 网格、完工面板、成本摘要、库存提示。
