# 回款动作权限与数据范围落地执行记录（2026-04-18）

## 本包目标

把回款中心中仍然依赖固定角色白名单的动作接口，迁移到“动态权限点 + 数据范围”的三层权限模型，重点覆盖：

- 逾期同步
- 回款核验
- 催收提醒
- 承诺付款
- 回款争议
- 客户信用冻结 / 发货冻结
- 订单发货冻结

本包不改变现有页面风格、不删除旧数据、不重写回款服务层，只在入口处补齐权限点和记录级范围守卫。

### 3. 动作级数据范围守卫

`backend/src/controllers/collection.controller.ts` 已补齐入口守卫：

- 催收提醒、承诺付款、回款争议：必须能操作对应订单，支持 `own_customers/team_customers/all/finance_visible` 等范围。
- 批量催收：先校验所有订单存在，再校验所有订单均在当前用户可操作范围内。
- 回款核验：必须具备 `finance_visible`，并补齐“订单创建者不能核验自己订单付款”的职责分离。
- 逾期同步：必须具备 `finance_visible`。
- 客户冻结、订单发货冻结：必须具备 `finance_visible`。

### 4. 校验器补洞

修复 `customerHoldSchema` / `customerHoldReleaseSchema` 未强制要求 `type` 的问题：

- 现在必须显式传入 `credit` 或 `shipment`。
- 避免前端漏传 `type` 时被服务层误判为发货冻结分支。

## 反思

本包方向没有偏离：仍然服务于“本地稳定运行、后续可服务器部署、动态权限可治理”的主线。

本包没有解决的事项：

- 浏览器级回款中心逐页人工点测还需要单独执行，当前只证明 API 业务闭环。
- 前端按钮是否完全按新增动作权限隐藏/显示，还需要浏览器角色切换截图验证。
- `collections` 模块里的中文状态显示已按 Node UTF-8 判定为源码正常，PowerShell 显示层仍可能出现误解码，后续报告必须继续区分“源码乱码”和“终端显示乱码”。

下一步建议：

1. 做回款中心浏览器角色点测：owner / no-scope / finance 三角色逐页切换，验证按钮、弹窗、保存、刷新回读。
2. 继续扫描剩余固定角色白名单接口，优先处理仍涉及金额、库存、审批的动作。
3. 补前端权限按钮级映射，避免“后端已拦截但前端仍显示不可用按钮”的体验问题。
