# 货抵支付 / 换货贸易库存闭环执行记录

日期：2026-04-17

## 目标

把货抵支付从“金额抵扣闭环”升级为“金额 + 库存双闭环”：

- 我方交付货物时，生成真实出库凭证。
- 对方交付货物时，生成真实入库凭证。
- 货抵结算反过账时，按原库存流水生成反向凭证。
- 如果库存已经被后续业务使用，反过账应被库存不足规则阻止，避免账实不一致。

## 本次改动

- `backend/src/services/barter.service.ts`
  - 货抵结算过账时，`our` 侧写入 `barter_issue` 库存凭证，默认从 `LOC-FG` 成品区出库。
  - 货抵结算过账时，`counterparty` 侧写入 `barter_receipt` 库存凭证，默认进入 `LOC-RAW` 原料区。
  - 货抵结算反过账时，读取原始 `barter_issue` / `barter_receipt` 库存流水，并生成反向凭证。
- `backend/src/services/stock-movement.service.ts`
  - 增加 `barter_issue_reversal` 和 `barter_receipt_reversal` 两类反向库存来源类型。
- `scripts/verify-barter-stock-closure.cjs`
  - 新增服务层验收脚本，用真实运行库验证货抵过账和反过账库存不丢、不重复。

## 验收结果

运行命令：

```powershell
node .\scripts\verify-barter-stock-closure.cjs
```

通过结果：

```json
{
  "ok": true,
  "settlementId": 12,
  "sourceRef": "BARTER-12",
  "beforeOur": 120,
  "afterPostOur": 108,
  "afterReverseOur": 120,
  "beforeReceived": 0,
  "afterPostReceived": 6,
  "afterReverseReceived": 0,
  "postEntryCount": 2,
  "reversalEntryCount": 2
}
```

解释：

- 我方胶水成品库存：`120 -> 108 -> 120`。
- 对方交付货物库存：`0 -> 6 -> 0`。
- 过账生成 2 张库存凭证：`barter_issue`、`barter_receipt`。
- 反过账生成 2 张反向库存凭证：`barter_issue_reversal`、`barter_receipt_reversal`。
