# 运行链误杀与超时收口

日期：2026-04-18

## 本包目标

本包只处理运行链稳定性，不扩大到业务功能重构。

目标是解决三类高风险问题：

1. 启动脚本不能误杀其他项目进程，尤其不能影响智仔。
2. 所有长运行健康检查必须有 5 分钟总闸门，超过即判定卡住。
3. 启动结果必须能用证据证明是爱牢达运行层，而不是旧入口、错误端口或其他系统页面。

## 修改内容

### 1. 稳定启动器增加进程归属守卫

文件：`scripts/start-stable-v2.ps1`

关键变化：

1. 新增 `Get-ProcessCommandLine`，通过 PID 读取实际命令行。
2. 新增 `Test-AilaoDaProcessOwner`，只有命令行归属于当前工作区、`backend\dist\server.js` 或当前启动器时，才允许停止该进程。
3. `Stop-PortProcess` 增加 `WorkspaceRoot` 和 `Required` 参数。
4. 5001 作为爱牢达稳定后端端口，如果被非爱牢达进程占用，直接失败并提示人工处理，不再强杀。
5. 3000、3001、3002、4173 作为可选前端/预览端口，如果被非爱牢达进程占用，只警告并跳过。
6. 增加同一 PID 去重，避免 `netstat` 多行导致已停止进程被二次判断成未知进程。

### 2. 健康检查增加 5 分钟总时限

文件：`check-timeboxed-health.ps1`

关键变化：

1. 新增 `TotalTimeoutSeconds`，默认 300 秒。
2. 每个子命令的实际时限取 `TimeoutSeconds` 与剩余总时限的较小值。
3. 如果总时限耗尽，后续步骤直接标记 `stuck`。
4. 健康检查日志从系统临时目录迁移到工作区内 `logs\timeboxed-health`，避免写到不可控的 C 盘临时路径。

## 反思

### 做对的地方

1. 没有再使用全局 `taskkill node.exe` 或无归属强杀。
2. 没有把 5173/5180 纳入爱牢达启动清理范围。
3. 5 分钟规则从口头要求变成脚本默认行为。
4. 日志路径从临时目录收回项目工作区，便于后续排查和迁移。

### 仍然不足

1. 当前目录不是 Git 仓库，不能用 `git status` 作为变更证据，后续必须依靠文件内容、脚本输出和治理台账。
2. `npm run lint` 仍有 100 个 warning，虽然不阻断运行，但会降低后续维护效率。
3. 全仓审计仍有 76 个 P2 和 91 个 P3，说明系统还不是“干净代码”，只是 P1 已归零。
4. 5001 当前作为稳定本地入口可用，但如果用户强需求 `localhost:3000`，还需要单独统一“开发入口”和“稳定入口”的产品口径。

## 下一包建议

按价值排序，下一包建议继续做：

1. 启动入口统一：明确 `localhost:3000`、`127.0.0.1:5001`、EXE 壳入口三者关系，避免用户看到空白浏览器或错误页面。
2. Lint warning 降噪：优先清理未使用变量和明显 hook 依赖，降低维护噪音。
3. P2 大文件继续拆分：优先处理订单、生产、仓储、回款中仍过大的页面/服务。
4. 浏览器级入口验收：从登录到主壳、CRM、采购、生产、仓储、货抵逐页确认不是旧入口、不是无 CSS 页面、不是乱码页面。
