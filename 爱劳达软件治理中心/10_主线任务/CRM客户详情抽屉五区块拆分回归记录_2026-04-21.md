# CRM 客户详情抽屉五区块拆分回归记录 2026-04-21

## 1. 背景

`pages/crm/CRMCustomerDrawer.tsx` 之前同时承担客户详情外壳、主数据概览、主名称/别名编辑、证照上传、客户池分配、地址站点、联系人、AI 洞察和客户池审计。

这类文件不是运行立即坏，而是维护成本很高：后续任何一个小问题，例如“客户池释放到公海”“联系人语言字段”“营业执照上传”“主地址多国家名称”，都容易在同一个大抽屉里互相影响。

## 2. 本轮拆分

本轮保持视觉风格和业务动作不变，把客户详情抽屉拆成外壳 + 五个稳定区块。

| 文件 | 职责 |
| --- | --- |
| `pages/crm/CRMCustomerDrawer.tsx` | 只保留抽屉外壳、顶部标题、基础数据装配和五区块挂载 |
| `pages/crm/CRMCustomerDrawerSections.tsx` | 承接主数据、归属池、地址、联系人、审计五个区块 |

五个区块分别是：

| 区块 | 说明 |
| --- | --- |
| `CRMCustomerMasterProfileSection` | 客户池快照、信用快照、三语名称、别名、备注、证照上传 |
| `CRMCustomerOwnershipSection` | 公海、内部池、私海分配动作，保留手填 + 联想候选 |
| `CRMCustomerAddressesSection` | 多地址、多站点、法定/发货/账单/办公地址 |
| `CRMCustomerContactsSection` | 多联系人、语言、部门、手机、站点标签 |
| `CRMCustomerAuditSection` | AI 风险摘要入口和客户池审计时间线 |

拆分后行数：

| 文件 | 行数 |
| --- | ---: |
| `CRMCustomerDrawer.tsx` | 170 |
| `CRMCustomerDrawerSections.tsx` | 408 |

## 3. 保持不变的业务约束

- 客户详情仍然展示中文、英文、越南文名称和别名。
- 客户池动作仍然是内部池、公海、私海三类，不改变原有权限判断。
- 销售分配仍然支持手填和姓名/ID/业务线联想。
- 地址仍然支持法定主体、发货地址、账单地址、办公地址、其他站点。
- 联系人仍然支持语言、部门、手机、站点标签。
- AI 风险摘要和客户池审计记录仍然在审计区块，不扩大数据权限。

## 5. 反思

这包没有追求“漂亮重做”，而是把客户详情从大抽屉里拆成维护边界清楚的五个区块。方向没有偏离：客户主数据仍然服务于真实跨国公司场景，一家公司一条主数据，三语名称、多地址、多联系人、归属池和审计都在同一个客户详情里闭环。

下一步 CRM 方向更值钱的动作不再是继续拆 UI 外壳，而是把后端 `customer.controller.ts` 按查询、写入、导入、关系、客户池动作拆开，并补客户池动作的 API 读回归证据。
