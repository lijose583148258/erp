# 业务拒绝日志分类自动闸门记录

## 背景

上一包已经把预期业务拒绝从 `error.log` 中降噪，但如果没有自动验收，后续改 logger 或新增业务错误码时仍可能回退。

## 本包目标

- 把业务拒绝日志分类变成可重复执行的自动闸门。
- 不通过真实写日志测试污染日志文件。
- 直接测试分类函数，确保业务拒绝会被识别，系统异常不会被误降级。

## 改动

- `scripts/business-rejection-log-classification-audit-v1.ts`
  - 覆盖 8 个样例。
  - 正向样例包括应收调整超额、采购非法状态、生产 BOM 未覆盖、库存不足、货抵重复提交。
  - 反向样例包括 Prisma 系统错误、TypeError、数据库连接失败。
- `package.json`
  - 新增 `audit:log-classification`。
- `scripts/phase3-readiness-audit-v1.cjs`
  - 将 `business-rejection-log-classification` 纳入阶段 3 基础闸门。
- `scripts/run-release-verification-v1.cjs`
  - 将 `business-rejection-log-classification` 纳入 release core/full 闸门。

## 验收

- `npm run audit:log-classification`：通过，8/8。
- `npx tsc --noEmit`：通过。
- `node scripts/effective-source-mojibake-gate-v1.cjs`：通过。
- `npm run verify:phase3`：通过，15/15。
- `npm run verify:release`：通过，22/22。

## 结论

日志分层现在不只是一次性修复，而是进入默认验收制度。后续如果有人把业务拒绝重新打进 error 级别，阶段 3 或 release 会直接拦住。
