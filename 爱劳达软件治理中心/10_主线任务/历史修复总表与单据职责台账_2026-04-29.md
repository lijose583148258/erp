# 历史修复总表与单据职责台账

日期：2026-04-29

本文是后续治理跟进的总入口。以后不要再把同一类问题散落到多个临时报告里反复判断；新问题先回到本表定位：属于哪个单据、哪个职责边界、哪个历史修复包、是否已有证据可复用。

## 1. 单据职责总原则

| 原则 | 说明 | 禁止事项 |
| --- | --- | --- |
| 一张单据只负责一个业务事件 | 例如销售订单负责成交承诺，回款单负责收款登记，应收调整单负责减免/坏账/折让 | 不允许回款弹窗直接承担财务核销、不允许库存台账页面直接维护仓库主数据 |
| 主数据和交易单据分离 | 客户、供应商、物料、仓库/库位是主数据；订单、回款、采购、入库、发货、生产完工是交易 | 不允许在列表里同时塞复杂主数据维护和交易过账 |
| 明细行和执行流水分离 | BOM 明细、订单明细是对象子行；库存流水、成本台账、审计日志是执行结果 | 不允许用户直接编辑台账流水来“修业务” |
| 登记和核验分离 | 业务员可以登记事实，财务/管理员负责核验、过账、冲销 | 不允许普通登记动作直接改正式已收、正式库存、正式成本 |
| 保存后必须回读 | 新建/修改后必须能在列表、详情、台账或审计中回读 | 不允许只有提示成功但找不到记录 |

## 2. 单据职责是否正确

| 单据/对象 | 正确主责 | 不该承担 | 当前判断 | 后续动作 |
| --- | --- | --- | --- | --- |
| 客户主数据 | 一家公司一条主记录，支持中/越/美多名称、多地址、多联系人、归属池、审计 | 不承担销售订单、回款核销、AI 越权问答 | 方向正确，仍需持续点测搜索和回读 | 保留五区块：主数据/地址/联系人/归属池/审计 |
| 供应商主数据 | 供应商档案、多名称、多地址、多联系人、采购引用 | 不承担采购收货和库存入库 | 方向正确 | 客户规则迁移到供应商时继续保持两边搜索隔离 |
| 销售订单 | 成交承诺、订单头、订单明细、金额、账期、客户关联 | 不直接完成正式收款核销 | 已拉正：订单回款快捷入口只登记 | 继续补订单详情对象页和状态解释 |
| 回款登记单 | 记录一次收款事实，状态为 pending/verified | 不直接认定订单已收，不能绕过财务核验 | 已拉正 | 继续完善历史测试脏数据隔离 |
| 回款核验/核销 | 财务确认回款有效，更新 paidAmount/paymentStatus | 不维护客户主档，不做应收减免 | 后端链路较强 | UI 侧继续补核验证据 |
| 应收调整单 | 折让、贷项、坏账、短款核销、汇差等减少有效应收 | 不等同真实回款，不应塞进 paidAmount | 已拉正为 receivableAdjustmentAmount | 历史 finance 调账仍需分类隔离 |
| 货抵协议 | 定义双方货值、总额度、规则、对手方、币种/估值 | 不记录每次实际抵扣明细 | 方向正确 | 保持“协议 -> 执行批次 -> 过账流水” |
| 货抵执行批次 | 记录分批交付、分批抵扣、余额变化 | 不重新定义协议总额 | 方向正确 | 继续补分批回读证据 |
| 采购订单 | 采购承诺、供应商、物料、数量、价格、预计到货 | 不直接改库存余额 | 方向正确 | 采购右侧表单已收口，仍需长期人工体验复查 |
| 采购收货单 | 记录实际到货、部分收货、容差、入库动作 | 不维护供应商主数据 | 方向正确 | 保持并发第二次收货 409 闸门 |
| 仓库/库位主数据 | 维护 WH-MAIN、LOC-RAW、LOC-FG、LOC-WIP、LOC-SCRAP 等结构 | 不作为库存交易单据 | 方向正确 | 仓储 UI 保持独立页面 |
| 库存移动/入库/调拨 | 记录库存数量变化和来源单据 | 不维护物料定义，不改历史台账 | 方向正确 | 后续补调拨浏览器证据 |
| 库存流水/成本台账 | 只读审计结果，追溯数量和成本 | 不允许人工直接编辑业务事实 | 方向正确 | 继续作为只读审计区 |
| 生产 BOM/化工配方 | 定义产品配方、10+ 原料、单位、损耗、工艺/质检参数 | 不执行完工扣料，不承担库存调整 | 已拉正 | 继续保持“主数据 + 明细行 + 高级折叠” |
| 生产工单 | 根据 BOM 执行生产计划、领料、完工 | 不修改 BOM 主定义 | 方向正确 | 继续验证少耗用被阻止、完整耗用可完工 |
| 生产完工单 | 记录实际耗料、产出、成品入库、成本台账 | 不回写篡改 BOM 标准配方 | 方向正确 | 保持 API 与浏览器双证据 |
| 发货单 | 记录出库物流、OCR/手填、签收状态 | 不处理售后结案，不维护资产台账 | 已拆除旧 Tab 抢职责 | 继续保持发货职责导航 |
| 收发货差异单 | 记录短少、破损、错发、容差和处理 | 不直接等同 RMA，也不直接改采购/销售主单 | 方向正确 | 继续补差异转 RMA 闭环 |
| RMA/售后单 | 售后退换修、责任、处理结果 | 不承担物流 OCR 录入 | 方向正确 | 后续补浏览器证据 |
| 权限角色单/授权记录 | 角色创建、权限勾选、分配、回收、审计 | 不由普通业务页面临时判断越权 | 后端较强 | UI 权限矩阵继续点测 |
| 备份/恢复单 | 备份生成、恢复预检、恢复后指纹校验 | 不承担业务纠错 | 方向正确 | 长期试跑必须每日执行 |
| AI 助手问答 | 只做授权范围内解释、摘要、辅助输入 | 不泄露越权数据，不替代审批 | 后端红队已有证据 | UI 多角色红队还要继续 |

当前结论：主要单据职责方向已经拉回正轨，但“历史 finance 调账 vs 当前应收调整/回款核验”的边界仍是后续最需要防重复误判的点。

## 5. 防重复工作规则

| 场景 | 是否重跑 | 规则 |
| --- | --- | --- |
| 没改业务代码，只改治理文档 | 不重跑全链路 | 只检查文档是否能定位到证据 |
| 改了钱相关代码 | 必须重跑目标 API + 浏览器 + 对账脚本 | 不用重跑无关生产/发货脚本 |
| 改了库存/生产代码 | 必须重跑库存台账/生产完工/成本链 | 不用重跑 CRM 搜索 |
| 改了 UI 布局 | 跑目标页面浏览器点测 + 乱码闸门 | 不用重跑后端并发，除非保存逻辑也改了 |
| 改了启动/打包/EXE | 跑 package、deploy、origin、runtime check | 不用重跑每个业务页面，除非资产变更 |
| 发现乱码 | 必须三步法 | 不允许直接重写文件 |
| 子任务声称通过 | 主控必须复核关键链 | 不允许只信子任务报告 |
