# 生产 API 审计脚本对齐耗料规则记录_2026-04-21

## 背景

- 准备拆分 `pages/ProductionWorkspaceV2.tsx` 前，先跑生产基线审计。
- `production-browser-audit-v1.cjs` 通过。
- `chemical-bom-production-chain-audit-v1.cjs` 通过。
- `production-api-audit-v1.cjs` 失败。

## 三步法判断

### 1. 翻译

- 失败信息：`Completing a BOM work order requires confirmed material consumption records`。
- 含义：BOM 工单完工必须带确认耗料记录。

### 2. 判断

- 这不是生产后端缺陷。
- 当前后端规则是正确的：化工 BOM 不能“假完工”，必须确认原料耗用后才能完工。
- 旧 `production-api-audit-v1.cjs` 仍按旧逻辑直接把工单改成 completed，因此误报失败。

### 3. 修复

- 引入现有 `scripts/lib/chemical-bom-audit-utils.cjs` 中的仓库与原料库存辅助能力。
- 在旧生产 API 审计脚本中：
  - 创建 BOM 后引导默认仓库/库位。
  - 为 BOM 三条原料线种入原料区库存。
  - 完工时提交 `consumptionRecords`。
  - 继续验证生产批次生成、生产调账、批次库存变化、调账反冲恢复。
- 同时修正生产调账请求：
  - 旧脚本同时传了 `targetId=batchId` 和 `batchId`。
  - 当前调整控制器会把 `targetId` 作为 `orderId` 兜底，导致生产批次 ID 被误写进订单外键。
  - 正确写法：生产调账只传 `batchId`，不传 `targetId`。

## 反思

- 这是一个典型“旧测试脚本落后于业务规则”的问题，如果直接拆生产页，会把真实风险和测试噪声混在一起。
- 正确顺序是先修验收链，再拆生产页。
- 生产链路现在的关键口径是：
  - 不完整耗料必须阻止完工。
  - 完整确认耗料才能完工。
  - 完工后要生成批次和成本/库存凭证。
  - 生产调账要能扣减并反冲恢复。
