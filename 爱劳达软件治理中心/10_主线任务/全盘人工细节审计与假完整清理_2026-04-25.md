# 全盘人工细节审计与假完整清理

日期：2026-04-25

## 审计目标

本轮不是只看编译是否通过，而是按真实人工使用者视角扣细节：

- 页面是否展示假数据、演示数据或误导性趋势。
- 导入、保存、入库、调拨是否先提示成功再失败。
- API 或页面加载失败时，是否静默变成空表，导致用户误判为真实 0。
- 浏览器验收是否因为并行抢上下文产生假失败。
- E 盘纯净运行版是否同步到最新构建。

## 发现并修复的问题

### P0：AI 表格导入存在假成功风险

原问题：

- 表格识别后先显示“成功导入”，再异步写入数据库。
- 如果写入失败，只在控制台报错，用户会误以为数据已经入库。

修复：

- 改为先提示“正在写入业务数据库”。
- 每条写入成功后累计 `persistedCount`。
- 全部成功后才显示完成。
- 失败时明确显示已写入数量、失败原因，并提示先回读核对，避免重复导入。

涉及文件：

- `components/AIAssistant.tsx`

### P0：渠道经营页展示 mock 经营数据

原问题：

- `DealerAnalytics` 是活跃路由，不是废文件。
- 页面使用 `dealer_hanoi`、`dealer_saigon`、`dealer_haiphong` 等硬编码数据生成销售额、库存、健康分和风险分段。
- 这会让管理者误以为渠道经营报表已真实闭环。

修复：

- 移除 mock 数据和自动刷新。
- 页面改成“三语诚实空态”：真实数据未接入时不展示假指标。
- 明确说明后续必须接入客户/供应商主数据、订单、回款、库存、风险规则后，才能开放排行、健康分和行动建议。
- 服务层取消 `averageCollectionDays: 30` 默认账期，防止未来再次生成模拟评分。

涉及文件：

- `pages/DealerAnalytics.tsx`
- `services/dealerAnalyticsService.ts`

### P1：Dashboard 存在假趋势和静默失败

原问题：

- 收入趋势里曾有 `risk: amount * 0.05` 的模拟风险柱。
- 首页统计卡存在硬编码趋势值。
- Dashboard 加载失败只写 `console.error`，用户可能把空数据误判为真实 0。

修复：

- 删除模拟风险柱和硬编码趋势。
- 加载失败时通过 `notify` 明确提示用户刷新并重新核对收入、库存和待办。

涉及文件：

- `pages/Dashboard.tsx`

### P1：仓储加载失败会静默变空表

原问题：

- 仓库列表、库存余额、库存流水加载失败时，页面可能只留下空表。
- 用户会误以为当前没有库存或没有流水。

修复：

- 加载失败统一给出可见错误提示。
- 将 `any` 错误类型收束为 `unknown` + `resolveWarehouseErrorMessage`。
- 库存查询参数改用服务签名推导，降低后续维护时改坏接口的概率。

涉及文件：

- `pages/WarehouseWorkspace.tsx`

### P1：销售订单回款提示含“模拟通知管理员”

原问题：

- 登记回款成功后出现“模拟通知管理员”文案。
- 这会暴露开发语气，并误导用户以为存在通知链路。

修复：

- 改为“已进入待核验队列，请回读订单余额和回款记录”。

涉及文件：

- `pages/sales-orders/useSalesOrderPayments.ts`
