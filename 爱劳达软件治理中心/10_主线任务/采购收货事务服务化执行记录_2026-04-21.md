# 采购收货事务服务化执行记录（2026-04-21）

## 背景

- 上一包已把采购领域纯规则从 `procurement.controller.ts` 拆到 `procurement-domain.service.ts`。
- 本包继续处理采购控制器过大的问题，优先拆“收货 / 入库 / 差异 / 状态推进”这条业务小闭环。
- 目标是降低维护成本，而不是重写采购模块。

## 修复前问题

- `backend/src/controllers/procurement.controller.ts` 同时承担：
  - HTTP 权限判断
  - 供应商查询
  - 采购单创建
  - 采购收货
  - 库存入库
  - 收货差异
  - 采购状态推进
  - B2B 状态同步
- 收货批次逻辑散落在控制器顶部 helper 和 `createReceipt` 方法里。
- 一旦后续调整分批收货、差异处理、库存成本，很容易误改 HTTP 层或审计层。

## 已执行改造

- 新增服务：`backend/src/services/procurement-receipt.service.ts`
- 从控制器移出：
  - 收货默认库位解析
  - 状态流转直接收货时的入库兜底
  - 收货批次查询
  - 收货汇总
  - 收货详情 bundle
  - 分批收货创建事务
  - 合格数量 / 差异数量校验
  - 收货日期校验
  - 差异工单创建
  - 入库成本金额计算调用
- 控制器保留：
  - 角色权限判断
  - HTTP 状态码与中文错误响应
  - 审计日志写入
  - DTO 输出 `mapPurchaseOrder`

## 额外收紧

- 原先 `createReceipt` 只检查“总数量 = 合格 + 差异”。
- 本包补上：
  - 收货数量必须为有限数字。
  - 收货数量必须大于 0。
  - 合格数量和差异数量不能为负数。
  - 收货日期必须能被解析为有效日期。
- 这属于真实业务防呆，不改变正常成功路径。
