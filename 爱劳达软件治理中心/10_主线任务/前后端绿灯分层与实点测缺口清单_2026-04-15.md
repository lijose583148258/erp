# 前后端绿灯分层与实点测缺口清单

- 日期：2026-04-15
- 目的：把“代码能构建”和“业务能实操闭环”分开，避免误把后端或构建绿灯当成全系统可用。

## 一、绿灯分层定义

### L1：代码门禁绿
- 前端 TypeScript 检查通过
- 前端生产构建通过
- 后端 TypeScript 构建通过

### L2：路由与页面壳绿
- 浏览器能登录
- 页面能打开
- 样式没有掉成裸 HTML
- 主要标题或关键文案能被断言

### L3：真实业务闭环绿
- 浏览器真实点击
- 真实输入
- 真实保存
- 刷新或 API 回读
- 有报告和截图证据

## 二、当前代码门禁状态

### 已通过
- `tsc --noEmit`
- `npm run build`
- `npm run build:backend`

### 结论
- 当前不是“只有后端代码绿”
- 前端类型检查和前端构建也绿
- 但这仍然不代表全部前端业务模块都完成实点测

### 2. SalesOrders / 销售订单

## 四、当前只有 L2 路由级证据的模块

这些模块能打开，但还没有真实业务闭环证据。

### 1. Assets / 资产管理
- 已有路由证据
- 缺少：新增资产、盘点、状态调整、归属调整、回读

### 2. Adjustment / 调账中心
- 已有路由证据
- 缺少：新建调账、审批或冲销、金额回读、订单/批次联动校验

### 3. Barter / 货抵支付 / 换货贸易
- 已有路由证据
- 缺少：新建货抵单、标的估值行、冲抵换算、审批或确认、回读

## 五、当前缺少本轮专项实点测证据的模块

### 1. Production / 生产管理
- 缺少：工单、BOM、排产、报工、损耗、质检回读

### 2. Contracts / 合同管理中心
- 缺少：合同创建、合同节点、附件、回款节点联动、回读

### 3. RiskControl / 核心风控
- 缺少：授信、冻结、释放、原因记录、回读

### 4. Samples / 样品管理
- 缺少：样品申请、样品明细、寄送、回读

### 5. TeamManagement / 团队管理
- 缺少：成员新增、角色变更、权限可见范围、回读

### 6. RMA / 售后管理
- 缺少：售后单创建、状态推进、处理记录、回读

### 7. AuditLogs / 审计日志
- 缺少：关键动作是否入审计、筛选、回读

### 8. FinanceAnalytics / DealerAnalytics / Dashboard
- 缺少：指标口径核对、数据来源核对、图表与后端金额一致性验证

## 六、当前最容易误判的地方

1. `build` 绿，不等于页面实操绿
2. 路由能打开，不等于录入和回读闭环
3. API 能通，不等于浏览器交互链无脱钩
4. 截图看起来正常，不等于刷新后数据不会丢
5. 报告 JSON 里仍可能有 PowerShell 显示层乱码，要以截图和真实页面为准

## 八、当前结论

- 后端构建绿
- 前端构建绿
- 主链浏览器验收绿
- CRM / SalesOrders / Procurement / Collections / Shipping 已有 L3 真实闭环证据
- Assets / Adjustment / Barter 目前仍只有 L2 路由级证据

所以当前系统不是“只有后端绿”，但也不是“全模块完美绿”。下一步应该继续补 L2 和无证据模块的实点测闭环。
