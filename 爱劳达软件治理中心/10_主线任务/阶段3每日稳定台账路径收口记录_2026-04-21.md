# 阶段 3 每日稳定台账路径收口记录 2026-04-21

## 1. 本次修复结论

本次修复的是阶段 3 每日稳定运行审计的证据归档路径，不是业务功能重写。

原脚本 `scripts/phase3-daily-stability-audit-v1.cjs` 已经能生成每日稳定运行记录，但台账文件落在 `output/audit/` 根层，单次报告落在 `output/audit/phase3-daily/` 子目录，容易造成后续查看时误判为“没有写台账”。

同时，旧版台账记录里保存了绝对路径。中文项目目录在部分 PowerShell/终端显示层会被误解码，容易让人误以为源码乱码。按乱码三步法判断后，本次确认属于报告展示层和旧记录路径格式问题，不属于有效源码损坏。

## 2. 修复范围

| 项目 | 修复前 | 修复后 |
| --- | --- | --- |
| 单次报告 | `output/audit/phase3-daily/phase3-daily-stability-*.json` | 保持不变 |
| 主台账 JSONL | `output/audit/phase3-daily-stability-ledger-v1.jsonl` | `output/audit/phase3-daily/phase3-daily-stability-ledger-v1.jsonl` |
| 主台账摘要 | `output/audit/phase3-daily-stability-ledger-v1.json` | `output/audit/phase3-daily/phase3-daily-stability-ledger-v1.json` |
| 旧路径兼容 | 仅旧路径 | 旧摘要保留，并指向 canonical 路径；旧 JSONL 继续追加兼容记录 |
| 报告路径字段 | 绝对路径 | 相对项目路径，例如 `output/audit/phase3-daily/phase3-daily-stability-20260421150449.json` |
| 失败时间统计 | compact 记录缺少 `finishedAt`，`lastFailureAt` 难以可靠统计 | compact 记录包含 `finishedAt` |

## 3. 为什么不删除旧台账

不删除旧台账是为了避免破坏历史证据链。

旧路径现在降级为兼容层：

1. 当前主台账以 `output/audit/phase3-daily/` 为准。
2. 旧摘要 `output/audit/phase3-daily-stability-ledger-v1.json` 会写入 `canonicalLedgerPath` 和 `canonicalSummaryPath`。
3. 旧 JSONL 继续追加新记录，保证旧查看脚本不会立刻失效。
4. 后续如要彻底下线旧路径，必须先确认没有脚本依赖旧路径，再做隔离标记，不直接删除。

## 5. 后续固定规则

1. 阶段 3 每日稳定证据以 `output/audit/phase3-daily/phase3-daily-stability-ledger-v1.json` 为主摘要。
2. 不再用旧根层台账作为主判断，只作为兼容入口。
3. 报告里默认写相对路径，减少中文绝对路径在终端里被误解码的概率。
4. 如果终端显示乱码，先用 Node UTF-8 读取确认，不直接改源码。
5. 两个月稳定运行不能靠一次 `verify:phase3` 证明，必须靠每日台账持续累积。
