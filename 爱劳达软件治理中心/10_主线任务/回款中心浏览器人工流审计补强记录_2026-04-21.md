# 回款中心浏览器人工流审计补强记录 2026-04-21

## 范围

- 模块：回款中心 / 应收治理中心。
- 入口：`http://127.0.0.1:5001/#collections`。
- 脚本：`scripts/collection-center-human-flow-browser-audit-v1.cjs`。
- 命令：`npm run audit:collection:human-flow`。

## 为什么补这一包

- 之前已有 API 权限与数据范围验证，但浏览器层仍缺少“像财务人员一样点击”的证据。
- 回款中心涉及逾期、承诺、争议、拦截、核销和导出，不能只用 `tsc` 或 API 200 判定完成。
- 本包用真实种子数据打通：客户 -> 订单 -> 待核销回款 -> 逾期同步 -> 发货拦截 -> 浏览器动作 -> API 回读。

## 覆盖点

- 打开稳定入口并确认页面归属是爱劳达回款中心。
- 切换逾期清单、收款台账、合同节点。
- 选中真实逾期订单，确认动作对象显示订单号。
- 浏览器提交承诺付款，并用 `/api/collections/promises` 回读。
- 浏览器提交争议记录，并用 `/api/collections/disputes` 回读。
- 点击承诺、争议、拦截筛选与排序控件。
- 导出承诺表、争议表、拦截表，并保存下载文件作为证据。
- 在收款台账核销待确认回款，并用 `/api/orders/:id` 回读 `paidAmount` 和 `paymentStatus`。
- 扫描页面正文禁止 `undefined`、`NaN`、替换符和常见乱码 token。
- 收集浏览器 console error 和 pageerror，作为假通过拦截项。

## 验收证据路径

- JSON 报告：`output/playwright/collection-center-human-flow-browser-audit-report-v1.json`。
- 截图目录：`output/playwright/collection-center-human-flow-browser-audit-v1/`。
- 导出文件：同截图目录内的 `promises-*`、`disputes-*`、`holds-*`。

## 制度约束

- 5 分钟总上限，单步有独立 timeout，超时即卡住。
- 乱码三步法默认开启：先翻译意图，再判断层级，最后只修正确层。
- 不信子任务报告；本脚本结果只能作为证据之一，最终仍需主控结合构建、运行、API 和浏览器结果判定。

## 本轮发现并修复的真实问题

- 发现方式：并行执行浏览器人工流、回款权限链、订单/回款数据范围链时，两个任务同时触发 `/collections/sync-overdue`，出现 10 秒超时。
- 根因：`CollectionStateService.syncAllCustomerOverdueAmounts()` 对全量客户逐个执行订单查询和状态刷新，属于 N+1 同步逻辑；审计数据变多后会被 SQLite 锁竞争和重复查询放大。
- 修复：改为一次批量读取客户、未结清订单、开放承诺、开放争议，在内存中推导逾期金额、催收等级、承诺/争议/拦截状态，再分块事务更新客户状态。
- 性能证据：优化后 887 个客户全量同步耗时约 689ms；并行复测浏览器人工流、回款权限链、订单/回款数据范围链全部通过。
- 风控保留：职责分离未被放宽，订单创建人仍不能核销自己创建订单的回款；浏览器脚本改为使用非当前核销人的订单创建者造数。
