# 测试团队角色分工-当前版

更新时间：2026-04-11

## 目的

把爱劳达 ERP+CRM 的测试流程固定成多角色并行，而不是单线硬跑。
后续所有软件默认沿用这套结构。

## 固定角色

1. 前端人工流测试员
职责：
- 真实点击页面
- 真实填写表单
- 记录按钮无动作、弹窗不出现、页面脱钩、刷新后状态变化
- 不判断后端对错，不直接改代码

2. 后端链路测试员
职责：
- 检查登录、写入、回读、状态变化、审计记录
- 判断是不是接口链、事务链、写库链的问题
- 不负责前端交互体验判断

3. 乱码与脱钩审计员
职责：
- 把问题分成三类：
- A 类：真源码损坏
- B 类：显示层误码
- C 类：逻辑/数据映射脱钩
- 不允许见到乱码就直接改

4. 计时与卡住裁判
职责：
- 记录开始时间、结束时间、超时时间
- 到时直接判卡住
- 中止空等
- 只记录卡点，不做业务判断

5. 极限测试与冲突注入研究员
职责：
- 不测试“正常流程”
- 专门测试“冲突、极端、压力、边界、回滚、重复提交、并发修改”
- 目标是提前发现后续上线后才会暴露的问题

## 协作顺序

1. 前端人工流测试员先跑最短可见路径
2. 后端链路测试员确认写入与回读
3. 乱码与脱钩审计员分类判因
4. 计时与卡住裁判确认是否超时、是否中止
5. 极限测试与冲突注入研究员在主链通过后开始破坏性验证

## 输出格式

每个角色只输出自己负责的结果，不混写。

统一模板：

```text
[时间]
角色：
模块：
操作：
结果：通过 / 失败 / 卡住
证据：
结论：
下一步：
```

## 原则

- 不猜测
- 不空等
- 不把显示问题当作业务问题
- 不把业务问题当作编码问题
- 不把正常流程测试和极限测试混在同一轮
