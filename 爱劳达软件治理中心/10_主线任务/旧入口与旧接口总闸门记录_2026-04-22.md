# 旧入口与旧接口总闸门记录 2026-04-22

## 结论

本包把旧入口、旧接口、旧木材 API 的隔离验证提升到主线验收闸门。

这次不删除历史文件，也不重新接入旧接口。正确处理方式是：

- 旧 `/api/timber/*` 继续返回 `410 Gone`。
- 响应必须带 `LEGACY_TIMBER_API_DISABLED`。
- 响应必须明确替代入口 `/api/barter`。
- 旧 `pages/TimberWorkspace.tsx` 只保留兼容导出壳，统一落到货抵支付 / 换货贸易工作台。
- `active-source-inventory` 继续保证旧文件不混入有效源码判断。

## 为什么要做

系统之前反复出现的问题不是单点功能不会写，而是旧入口、旧脚本、旧测试报告和当前运行链之间边界不够硬。

如果旧接口只在单独治理包里测试，而没有进入 `verify:phase3` 和 `verify:release`，后续任何人改路由、改启动器、改包脚本时，都可能让旧链路悄悄复活，造成页面、API、测试报告互相打架。

  - 新增 `audit:legacy:disconnect`。

## 本包不做什么

- 不删除历史归档。
- 不删除隔离区。
- 不删除旧稳定包。
- 不改变货抵支付 / 换货贸易业务逻辑。
- 不把木材旧模块重新做成业务入口。

## 验收目标

- `npm run audit:legacy:disconnect` 必须通过。
- `npm run audit:entrypoints` 必须通过。
- `npm run audit:active-source` 必须通过。
- `npm run verify:phase3` 必须包含旧接口断开检查。
- `npm run verify:release` 必须包含旧接口断开检查。

## 后续规则

任何“不能接的旧接口”都按这个模式治理：

1. 保留明确的断开壳或迁移提示，不静默 404。
2. 返回可机器识别的禁用码。
3. 返回替代入口。
4. 加独立审计脚本。
5. 加入 Phase 3 / Release 总闸门。
