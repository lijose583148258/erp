# 销售订单 Hook 副作用拆分回归记录 2026-04-21

## 1. 本次修复结论

本次只拆 `pages/sales-orders/useSalesOrders.ts` 中的两个低风险副作用：

1. 在线/离线状态监听。
2. 全局命令快捷入口监听。

没有改订单保存、订单状态机、回款登记、回款核验、发货跳转、OCR 解析和订单明细 Excel 输入逻辑。

## 2. 改动范围

| 文件 | 改动 |
| --- | --- |
| `pages/sales-orders/useSalesOrders.ts` | 移除网络监听 effect 和命令监听 effect，改为调用专用 hook |
| `pages/sales-orders/useSalesOrderNetworkStatus.ts` | 新增在线/离线状态监听 hook |
| `pages/sales-orders/useSalesOrderCommandShortcuts.ts` | 新增 `command:create-order` 和 `command:ocr-invoice` 快捷入口 hook |

## 3. 为什么先拆这两个点

1. 它们是横切副作用，不直接参与订单金额、回款、状态和库存逻辑。
2. 拆完能降低 `useSalesOrders.ts` 行数，同时不打断销售订单大闭环。
3. `openCreateModal` 改为 `useCallback`，使命令监听 hook 的依赖更稳定。
4. 这比直接拆 `handleSaveOrder` 或 `handleRecordPayment` 风险更低。

## 7. 后续建议

1. 下一轮如继续拆销售订单 hook，应优先拆 OCR/离线扫描逻辑或表单明细编辑逻辑。
2. 不建议直接拆 `handleSaveOrder`、`handleRecordPayment`、`handleVerifyPayment`，除非先补订单创建、回款登记、核验和历史回读的专门回归。
3. 销售订单后续仍应保持 API 回读 + 浏览器回读双证据，不能只看页面能打开。
