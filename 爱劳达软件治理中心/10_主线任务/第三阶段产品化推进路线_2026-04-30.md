# 第三阶段产品化推进路线

更新时间：2026-04-30

## 1. 阶段目标

第三阶段不是重做一个新系统，而是在现有爱劳达 ERP+CRM 功能链已经通过准入闸门后，把它整理成可以本地稳定试跑两个月、后续可迁移服务器的产品化版本。

核心目标：

- 不丢失现有功能：CRM、销售订单、回款、采购、生产、仓储、货抵、权限、备份恢复、离线运行、乱码治理都必须保留。
- 不盲目照搬国外 ERP：必须保留中国中小企业软件的开单、明细表、审核、反审核、往来账、库存流水、老板看板等操作习惯。
- 贴合越南靠近中国的业务环境：支持中越英多名称、多地址、多联系人、CNY/VND/USD、跨境物流、货抵贸易、分批回款和分批抵扣。
- 不继续堆补丁：每次改动必须回答“单据职责是否更清楚、输入是否更像人用、链路是否仍闭环、证据是否可复跑”。

## 2. 不可丢失功能清单

以下能力属于第三阶段保留闸门的核心资产，后续 UI 或结构优化不得删除、绕开或降级：

- 客户与供应商主数据：一家公司一条主数据，多名称、多地址、多联系人，客户和供应商共享规则但搜索结果必须按业务域隔离展示。
- CRM 公海、内池、私海、分配、收回、归属、审计：权限和客户池流转必须保留。
- 销售订单：订单头、明细行、客户回读、回款状态、支付核验、创建人和审计信息必须保留。
- 回款中心：一笔订单多次回款、核验、冲突防重、应收调整、逾期查询必须保留。
- 采购：供应商、采购单、到货、收货、差异、RMA 关联必须保留。
- 生产：化工配方/BOM、至少 10 行原料、工单领料、实际耗用、成品入库、防假完工必须保留。
- 仓储：仓库、库位、库存、流水、调拨、入库、出库、负库存防护必须保留。
- 货抵支付/换货贸易：协议、批次抵扣、分批交付、入账、反冲、库存闭环必须保留。
- 权限：超级管理员创建角色、分配权限、角色授权、只读/编辑/审批边界必须保留。
- 备份恢复与迁移：本地 SQLite、E 盘纯净包、D 盘运行库、服务器迁移准备必须保留。
- AI 隔离：AI 不得越权读取角色不可见数据，内部助手必须受权限边界约束。
- 乱码三步法：翻译意图、判断层级、只修正确层；禁乱码闸门默认开启。

## 3. 中国中小企业软件习惯

后续页面优化要吸收金蝶、用友/畅捷通、速达、管家婆等中小企业软件的成熟习惯，但不直接照抄复杂套件：

- 业务入口要像“开单”：用户先知道今天要做什么单，再进入录入。
- 单据页面要分“单据头 + 明细表 + 底部保存/审核/作废/打印/导出”。
- 明细行适合 Excel 化：销售订单明细、采购明细、BOM 原料、入库出库明细、货抵批次、回款流水。
- 主数据适合表单化：客户、供应商、联系人、地址、角色、仓库、库位。
- 复杂对象适合双轨：先简版快速创建，再高级字段折叠展开。
- 台账与动作分开：列表负责查找和状态判断，弹窗/抽屉负责动作，审计区只负责追溯。
- 保存后必须回读：新增、修改、审核后必须刷新列表和详情，避免用户不确定是否成功。
- 单据状态必须清楚：草稿、待审、已审、执行中、已完成、已作废、已反冲不能混用。

## 4. 越南靠近中国的业务特色

爱劳达不是纯内销软件，也不是纯海外 SaaS，后续要把以下跨境细节作为默认产品约束：

- 公司名称：同一家公司可能有中文名、越南名、英文名，且营业执照地址、发货地址、账单地址可能不同。
- 联系人：采购、财务、仓库、老板、报关/物流联系人要拆分，不要塞在一个备注里。
- 币种：CNY、VND、USD 并存，汇率要按单据发生时快照，不允许事后汇率变化污染历史单据。
- 物流：跨境发货、收货、差异、补货、RMA、照片/OCR 凭证要能够挂到单据链上。
- 货抵贸易：货值标定、等值抵扣、分批交付、分批抵扣、库存和财务入账必须形成闭环。
- 语言：登录后也要能切换语言；中文为主工作语境，越南语和英文用于名称、地址、联系人、外部单据。

## 5. 后续包执行顺序

后续按价值和风险排序推进，不再因为单点反馈来回跑偏：

1. 功能保留闸门：每次产品化改动前后检查关键功能、脚本、纯净包来源。
2. 单据职责闸门：继续清理“同一区域抢职责”的页面，保证列表、动作、详情、审计分区清楚。
3. CRM/供应商主数据体验：简版新建、联想搜索、多名称、多地址、多联系人、归属池、审计。
4. 销售订单与回款：订单头表单 + 明细 Excel 表 + 回款流水 + 核验回读。
5. 采购与收货：供应商主数据、采购单、到货单、差异处理、RMA 不混在一个入口。
6. 生产化工配方：配方主档、BOM 明细、工单实际耗用、成品入库、防假完工。
7. 仓储与库存：仓库库位、库存流水、调拨、入库出库、批次追踪、负库存防护。
8. 货抵支付：协议、批次、库存、财务入账、反冲、分批抵扣。
9. 权限与 AI 隔离：超级管理员配置角色，AI 严格按角色可见数据回答。
10. 本地 EXE 与服务器迁移：Win10 本地两个月试跑、备份恢复、迁移脚本、部署文档。

## 6. 每包验收制度

每包完成后必须至少保留以下证据：

- 静态检查：TypeScript/构建/源码乱码闸门。
- 功能保留检查：`npm run audit:phase3:feature-preservation`。
- 目标链路检查：按改动模块选择 API 与浏览器审计。
- 回读检查：新增、修改、审核、反冲后必须查列表和详情。
- 数据一致性检查：涉及金额、库存、权限、备份时必须做并发或恢复验证。
- 人工体验检查：页面是否一眼能看懂“这是台账、这是开单、这是动作、这是审计”。

## 7. 当前结论

当前系统已经进入第三阶段准入，但第三阶段的重点不是继续扩功能，而是把已经通过的功能收束成稳定、清楚、可维护、可迁移的产品。

判断标准不是“功能更多”，而是：

- 用户知道从哪里录入。
- 用户知道录入后产生什么单据。
- 用户知道这张单据影响库存、财务、客户还是审计。
- 系统能证明数据没有丢。
- 后续维护者能从目录、脚本和台账找到修改方向。
