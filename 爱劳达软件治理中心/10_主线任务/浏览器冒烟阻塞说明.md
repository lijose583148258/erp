# 浏览器冒烟阻塞说明

## 当前状态

当前系统前端和后端都可以成功构建，且本地服务可以启动并返回 200。

- `npm run build` 已通过
- `npm run build:backend` 已通过
- `http://127.0.0.1:5173` 可正常响应

## 阻塞点

浏览器级冒烟验证目前被工具层卡住，不是被业务代码卡住。

### 具体表现

- 本地 `playwright-cli` 会话可见
- 但 `goto` 等命令触发 `ENOTCACHED`
- 这说明当前浏览器自动化命令链存在缓存/安装层问题

## 结论

这意味着：

1. 代码层面并没有发现“无法启动”的阻断错误
2. 但真实浏览器冒烟暂时无法完整执行
3. 因此不能把“构建通过”直接等同于“冒烟通过”

## 当前建议

1. 先把浏览器工具链恢复到可用状态。
2. 在工具链恢复前，不再继续假设已经完成浏览器冒烟。
3. 当前阶段继续按包级风险推进，不再做细碎字段清洗。

## 后续执行原则

- 构建通过，只能说明编译链路正常。
- 冒烟通过，才说明关键入口在真实浏览器里可用。
- 二者不能互相替代。
