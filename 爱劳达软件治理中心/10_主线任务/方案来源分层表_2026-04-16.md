# 方案来源分层表（2026-04-16）

状态：当前有效  
用途：把后续方案明确分成 `已调研支撑项 / 待调研项 / 内部治理项`，避免把商业交互判断和项目治理判断混为一谈。

## 一、已调研支撑项

这部分表示：已经结合成熟产品或成熟模式做过外部调研，不是纯拍脑袋建议。

### 1. 回款中心内部功能排版

已调研依据：

- SAP Collections Management
- Oracle PeopleSoft Collections Workbench
- Microsoft Dynamics 365 Finance Collections

已落地结论：

- 回款中心不应该把全部信息塞进左侧动作栏
- 应该围绕“当前业务对象焦点”展开
- 应该采用“三层结构”：动作区 + 当前订单详情区 + 全局台账
- 回款和货抵应统一成“主单 + 子记录”的交互语义

当前状态：已落地到 `collections`

### 2. 主单 + 子记录模式

已调研结合项：

- 回款多次执行
- 货抵分批执行
- 合同/节点/批次类业务的执行流水模式

已落地结论：

- 订单不是一次性回款
- 货抵协议也不应是一张单反复硬改
- 应采用主单汇总、子记录执行、状态自动汇总的商业模型

当前状态：`collections` 已成型，`barter` 已进入同语义方向

### 3. 工作台型模块交互方向

已调研结合项：

- 列表入口
- 当前对象详情页
- 高频动作区
- 全局台账与当前对象详情分离

已落地结论：

- 适合用于 `collections`
- 后续适合复制到 `adjustment`、部分风控和执行流水型模块

## 二、待调研项

这部分表示：方向已有初步判断，但还没有完成模块级、逐包级的外部调研支撑，后续要继续补研究。

### 1. adjustment 内部功能排版

当前状态：

- 已进入优先治理队列
- 还没有像 `collections` 那样完成成熟案例对照与模块级排版研究

需要调研：

- 调账 / 冲销 / 差额处理 / 财务工作台的成熟交互
- 金额调整、审批、过账、冲销记录如何分层显示

### 2. salesOrders 双轨交互

当前状态：

- 已确定“头表单 + 明细 Excel 网格”方向值得推进
- 但还需要更系统地比较成熟中美企业订单录入与明细编辑模式

需要调研：

- 订单头信息应该保留多少表单化字段
- 明细行哪些必须表格化
- 哪些字段适合联想搜索，哪些适合手填

### 3. procurement 与供应商建档交互

当前状态：

- 真实新增 / 搜索 / 保存 / 回读已被识别为高价值问题
- 但供应商侧是否完全共用客户主数据交互，还需要更细调研支持

需要调研：

- 供应商主数据是否与客户完全同形
- 搜索时如何避免客户和供应商信息混显
- 采购、财务、仓库三个角色的视图差异

### 4. 风控 / 拦截 / 合同节点协同排版

当前状态：

- 已知道它们不能散落在不同页面完全脱钩
- 但还没完成成熟产品对照后的统一排版方案

需要调研：

- 风控拦截应更偏工作台还是订单详情侧栏
- 合同节点应更偏合同轴还是收款轴
- 拦截释放记录如何和订单、客户双维度联动展示

### 5. 全系统内部功能排版统一度

当前状态：

- 还没有做到每个模块都逐一外部调研、逐一归类

后续要补：

- 哪些模块必须 Excel 化
- 哪些模块坚持表单化
- 哪些模块适合双轨入口

## 三、内部治理项

这部分表示：不是外部产品抄来的，而是针对爱劳达当前项目问题总结出来的治理制度和执行规则。

### 1. 6 条主线、3 个阶段、1 套验收制度

性质：项目总控治理框架

作用：

- 防止后续推进继续零碎化
- 让每一包都有统一挂靠位置

### 2. 三步法 + 禁乱码闸门

性质：乱码治理制度

作用：

- 防止把显示层误判成源码问题
- 防止修复后仍然假绿
- 防止同类问题反复出现

### 3. 5 分钟卡住裁判规则

性质：运行治理制度

作用：

- 防止任务无限挂起
- 防止用等待冒充推进

### 4. 模块状态分级表

性质：项目治理制度

作用：

- 统一判断 `green / yellow / red`
- 后续排期和风险判断更清楚

### 5. 重写 / 修补判定规则

性质：代码治理制度

作用：

- 防止该重构的东西被无限补丁化
- 防止简单问题被过度重写

### 6. 证据包标准

性质：验收治理制度

作用：

- 每轮推进留下可追溯证据
- 后续复盘不依赖聊天记录

### 7. 冻结 / 解冻、回退 / 恢复规则

性质：风险治理制度

作用：

- 防止“越修越坏”时没有停手点
- 防止改坏后无退路

## 四、后续使用规则

从本表开始：

- 讨论“排版、交互、商业模式”时，要优先区分它属于 `已调研支撑项` 还是 `待调研项`
- 讨论“超时、入口、证据、回退、乱码制度”时，归入 `内部治理项`
- 后续新方案尽量都标一行：
  - 来源分类
  - 当前状态
  - 是否已落地
