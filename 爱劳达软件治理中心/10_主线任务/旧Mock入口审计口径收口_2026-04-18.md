# 旧 Mock 入口审计口径收口（2026-04-18）

## 结论

`backend/complete-server.js` 当前不是正式运行入口，文件顶部已经强制输出禁用提示并 `process.exit(1)`：

```text
[legacy mock backend disabled] Use npm run start:stable or npm --prefix backend run start.
```

正式后端入口仍是 `backend/src/server.ts` 编译后的 `backend/dist/server.js`，根目录脚本使用 `scripts/start-stable-v2.ps1` 启动。

## 本次修正

全仓审计脚本 `scripts/full-codebase-audit-v1.cjs` 增加 `disabledLegacyFiles` 识别：

| 文件 | 处理 |
| --- | --- |
| `backend/complete-server.js` | 识别为已禁用旧 mock 入口，不再作为活跃 oversized source 计入 P2 |

## 验收证据

| 闸门 | 结果 |
| --- | --- |
| `node scripts/full-codebase-audit-v1.cjs` | 通过，P2 从 77 降到 76，`disabledLegacyFiles=1` |
| `npm run lint` | 0 error / 100 warning |

## 反思

这次没有删除旧文件，是为了遵守“历史文件不随意删”的原则；但也不能让已禁用 mock 文件继续污染活跃审计结果。以后类似旧入口必须满足三个条件才能降级为 disabled legacy：

1. 文件顶部明确说明不是正式运行入口。
2. 文件在执行前强制退出，不能真正启动旧服务。
3. 正式启动链、`package.json` 和运行脚本不引用它。

不满足这三点的旧入口，仍必须作为 P1/P2 风险继续治理。
