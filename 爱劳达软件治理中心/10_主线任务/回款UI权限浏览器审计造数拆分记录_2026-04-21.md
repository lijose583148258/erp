# 回款 UI 权限浏览器审计造数拆分记录 2026-04-21

## 1. 本次修复结论

本次拆分的是审计脚本，不是回款业务运行代码。

`scripts/collection-ui-permission-browser-audit-v1.cjs` 原来同时负责造角色、造用户、造客户、造订单、造回款、打开浏览器、检查按钮显隐和读回结果。职责过多会导致后续排查时难以判断失败发生在造数层、接口层、权限层还是浏览器层。

本次将造数逻辑拆到 `scripts/lib/collection-ui-permission-seed.cjs`，主脚本只保留审计编排和浏览器断言。

## 2. 改动范围

| 文件 | 改动 |
| --- | --- |
| `scripts/collection-ui-permission-browser-audit-v1.cjs` | 移除造数函数，调用 seed helper；保留 API fetch、浏览器打开、按钮显隐、回读断言 |
| `scripts/lib/collection-ui-permission-seed.cjs` | 新增回款 UI 权限审计专用造数 helper |

## 3. 为什么这样拆

1. 审计脚本也会变成屎山，尤其是会写库、开浏览器、做权限断言的脚本。
2. 造数和浏览器断言拆开后，失败定位更清楚。
3. 没有改变 viewer/operator/finance 三类角色权限断言。
4. 没有改变稳定入口，仍以 `http://127.0.0.1:5001/` 为准。

## 7. 后续建议

1. 其它浏览器审计脚本也应按“造数 / 打开页面 / 操作断言 / 报告输出”拆层。

3. 审计脚本里的测试密码属于测试资产，必须继续由全仓审计标记为 test credential asset，不能进入生产配置。
