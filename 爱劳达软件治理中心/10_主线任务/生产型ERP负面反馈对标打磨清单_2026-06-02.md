# 生产型 ERP 负面反馈对标打磨清单（2026-06-02）

## 外部负面反馈归纳

生产型 ERP 的负面反馈比贸易型 ERP 更集中在“现场真实发生的事”和“系统认为发生的事”不一致。常见抱怨不是界面不好看，而是 BOM 不准、工单不准、库存不准、成本不准、计划不准，最后车间仍靠 Excel、微信群、纸质流转和人工经验。

参考来源：
- SysgenPro, “Manufacturing ERP Adoption Mistakes That Disrupt Production Workflows”, 2026
- TechTarget, ERP manufacturing failure case reports
- FocusCFO, “Manufacturing ERP System Implementation Challenge”
- Reddit / r/manufacturing / r/ERP：BOM、MRP、工单、车间数据采集和成本核算负面反馈
- 人人都是产品经理、简道云、制造业 ERP 实施难点相关文章

## 1. BOM / 配方主档

外部差评：
- “BOM 版本管不好，现场用的是 A 版，系统成本算的是 B 版。”
- “BOM 和工艺路线割裂，MRP 算出来的物料需求不可信。”
- “营销/研发改产品太快，生产系统记录跟不上。”

当前系统风险：
- 当前已有生产配方、BOM 行、配方物料角色和容差字段，但 BOM 版本锁定、ECO 工程变更、工单引用版本还需要强化。
- 如果工单不锁定 BOM 版本，后续改配方会影响已下达工单的耗料和成本判断。

打磨动作：
- P0：工单创建时锁定 BOM 版本快照，后续 BOM 修改不得影响已下达工单。
- P0：BOM 变更必须走版本化和变更原因，保留旧版可追溯。
- P1：BOM 行增加替代料、损耗率、工序阶段、质量关键项的显式标记。
- P1：BOM 导入预检：重复物料、缺失单位、损耗异常、用量为 0、替代料冲突。

## 2. 工单 / Work Order

外部差评：
- “工单信息到车间已经变了，但 ERP 还没更新。”
- “ERP 工单适合财务，不适合车间实时执行。”
- “工单状态太理想化，现场有返工、暂停、拆批、插单。”

当前系统风险：
- 当前工单有创建、耗料、完工链路，但复杂车间状态如暂停、返工、拆批、插单、报废、返修仍未完整模型化。
- 如果只用 pending/in_progress/completed 这类粗状态，现场异常会绕开系统。

打磨动作：
- P0：工单状态增加异常分支：暂停、返工、报废、部分完工、关闭。
- P0：工单完工必须校验耗料记录、批次库存、成本台账和成品入库一致。
- P1：支持拆批完工和部分完工，避免大工单被迫一次性结案。
- P1：每次状态变更记录责任人、原因、时间和影响。

## 3. 生产计划 / MPS / MRP

外部差评：
- “MRP 算出来的采购建议没人敢用。”
- “销售插单、采购延期、库存不准，计划每天救火。”
- “ERP 擅长交易记录，不擅长车间细排程。”

当前系统风险：
- 当前系统更偏业务交易和库存台账，尚未形成成熟 MPS/MRP 计划引擎。
- 如果贸然宣称生产计划能力，会被客户拿实际排产、缺料、延期来验证，风险很高。

打磨动作：
- P0：先明确生产计划当前能力边界，不宣称完整 APS/MES。
- P1：建立轻量 MRP：销售需求、库存余额、在途采购、在制工单、BOM 用量。
- P1：缺料清单必须 drill-down 到 SKU、批次、采购单、供应商交期。
- P2：细排程、设备负荷、换线优化建议未来接 MES/APS，不在 ERP 内硬做。

## 4. 领料 / 耗料

外部差评：
- “车间实际领料和系统倒冲不一致。”
- “替代料、损耗、返工耗料没有地方记。”
- “库存被系统扣了，但现场没领；现场领了，系统没扣。”

当前系统风险：
- 当前完工前要求确认耗料记录，这是正确方向。
- 但实际耗料、标准耗料、替代料、报废损耗、返工补料还需要更细区分。

打磨动作：
- P0：耗料单区分标准耗料、实际耗料、替代料、损耗、返工补料。
- P0：耗料扣库必须同事务写库存流水、批次余额、成本台账。
- P1：超耗和少耗需要原因码和审批。
- P1：扫码领料/批次选择优先，减少手工录错。

## 5. 完工 / 成品入库

外部差评：
- “完工数量报了，成品库存没准。”
- “良品、次品、报废、返工没有明确分账。”
- “完工后成本算不出来，财务月结拖很久。”

当前系统风险：
- 当前完工会涉及库存和成本，但必须持续验证双库存口径和幂等。
- 如果完工重复提交、库存流水和 productBatch 不一致，会直接破坏库存可信度。

打磨动作：
- P0：完工接口增加幂等键，重复提交必须返回同一结果或明确拒绝。
- P0：完工同时写良品入库、报废、返工、成本差异，不允许只改工单状态。
- P1：完工后自动生成对账证据：原料扣减、成品入库、成本台账、库存余额。
- P1：支持部分完工和多批次完工。

## 6. 质量 / QC

外部差评：
- “质量问题无法追溯到原料批次、工单、人员、设备。”
- “质检只是备注，没有阻止不合格品入库或发货。”
- “返工返修没有成本归集。”

当前系统风险：
- 当前系统有差异、RMA、库存和生产模块，但生产质检还不是独立闭环。
- 质量动作如果不影响库存状态和发货资格，会变成记录型模块。

打磨动作：
- P0：建立质检状态：待检、合格、让步接收、不合格、返工、报废。
- P0：不合格批次禁止销售发货，除非有让步审批。
- P1：质检记录绑定原料批次、工单、成品批次、检验人。
- P1：返工/报废成本进入工单成本差异。

## 7. 批次追溯 / Traceability

外部差评：
- “出了质量事故，不知道哪些客户收到哪些批次。”
- “原料批次、生产批次、销售批次断链。”

当前系统风险：
- 当前已有 batchNo、productBatch、stock movements 等基础，但全链路正反向追溯需要做成显式功能。

打磨动作：
- P0：建立批次谱系：原料批次 -> 工单 -> 成品批次 -> 发货单 -> 客户。
- P1：支持正向追溯和反向追溯。
- P1：批次召回清单一键生成：客户、订单、发货、数量、联系人。
- P2：批次质量异常自动触发库存冻结和风险待办。

## 8. 成本核算 / Costing

外部差评：
- “标准成本和实际成本差异没人解释。”
- “工时不准、材料耗用不准，成本报表只是估算。”
- “制造费用分摊规则不透明。”

当前系统风险：
- 当前有生产成本台账，但如果没有标准成本、实际材料、实际工时、制造费用分摊，成本仍会被财务质疑。

打磨动作：
- P0：工单成本拆为材料、人工、制造费用、报废、返工、差异。
- P1：标准成本和实际成本并列展示，差异必须有来源。
- P1：工时采集可先轻量化：岗位/工序/小时/人员。
- P2：制造费用分摊规则版本化。

## 9. 库存准确性

外部差评：
- “系统库存和现场库存永远不一样。”
- “盘点后没多久又乱了。”
- “MRP 不准，本质是库存和主数据不准。”

当前系统风险：
- 当前库存流水、负库存保护、批次库存已有基础，但生产耗料和完工会增加更多库存变动来源。

打磨动作：
- P0：库存可信面板必须纳入生产耗料、完工入库、报废、返工、调拨、手工补录。
- P0：库存调整必须强制来源单号和原因，禁止无来源改库存。
- P1：盘点差异形成审批和库存凭证，不只改余额。
- P1：MRP 只基于已核验库存，不基于未审核调整。

## 10. 主数据 / Material Master

外部差评：
- “物料主数据太烂，MRP 和 BOM 全部失效。”
- “单位、规格、替代料、采购包装、生产用量口径混乱。”

当前系统风险：
- 当前生产和仓储围绕 productName/batchNo 的地方较多，正式生产型 ERP 需要更强 SKU/物料主数据模型。

打磨动作：
- P0：建立物料主数据：物料编码、名称、规格、单位、采购单位、生产单位、换算率。
- P1：BOM、库存、采购、销售、生产统一使用物料编码，而不是自由文本品名。
- P1：主数据导入预检和重复合并。
- P2：替代料和禁用料治理。

## 11. 工艺路线 / Routing

外部差评：
- “BOM 有了，但工序、设备、工时没有，排产和成本仍不准。”
- “不同产品路线不同，ERP 只支持简单流程。”

当前系统风险：
- 当前生产配方字段有 processStage，但完整 routing 仍不足。

打磨动作：
- P1：工艺路线表：工序、顺序、设备/工位、标准工时、质检点。
- P1：工单引用 routing 版本快照。
- P2：瓶颈工序产能和排队时间后续接 APS/MES。

## 12. 车间报工 / Shop Floor Reporting

外部差评：
- “现场不愿意填 ERP，补录导致数据滞后。”
- “ERP 不是实时车间系统，强行让车间用反而失败。”

当前系统风险：
- 如果生产模块要求大量复杂录入，现场会回到纸质和 Excel。

打磨动作：
- P0：车间入口必须极简：扫码工单、扫码物料、录数量、选异常原因。
- P1：移动端/PDA 优先适配，按钮大、字段少、允许离线暂存。
- P1：报工失败必须可重试，不丢数据。
- P2：复杂实时设备数据交给 MES，不在 ERP 内硬做。

## 13. 工程变更 / ECO

外部差评：
- “工程改了图纸，采购和生产不知道。”
- “旧工单和新 BOM 混用，现场出错。”

当前系统风险：
- 当前缺少正式 ECO 流程。

打磨动作：
- P0：ECO 影响分析：未开工工单、在制工单、采购未到料、库存替代料。
- P1：ECO 审批后生成新 BOM/routing 版本。
- P1：在制工单是否切换版本必须人工确认并审计。

## 14. 供应链协同

外部差评：
- “生产缺料，采购才发现供应商交期不行。”
- “采购、库存、生产计划互相甩锅。”

当前系统风险：
- 采购收货已有，但生产需求到采购建议尚未闭环。

打磨动作：
- P1：缺料需求生成采购建议。
- P1：采购在途量进入 MRP 可用量。
- P1：供应商延期影响工单和订单交期预警。

## 15. 报表与月结

外部差评：
- “生产报表和财务月结对不上。”
- “WIP 在制、已完工未入库、已入库未核算都混在一起。”

当前系统风险：
- 如果生产成本、库存、财务报表没有统一期间和状态口径，月结会失信。

打磨动作：
- P0：生产月结口径：在制、完工、报废、返工、库存、成本差异。
- P1：每个工单提供结案对账页。
- P1：报表显示口径版本、统计时间和异常数据。

## 16. 实施与培训

外部差评：
- “ERP 是 IT 项目，不是业务项目，最后业务不买账。”
- “关键用户被抽去实施，本职工作堆积，反而抱怨 ERP 耽误生产。”

当前系统风险：
- 功能复杂度已经较高，如果没有岗位化任务流和培训材料，一线采用会困难。

打磨动作：
- P1：按岗位设计任务流：计划员、仓管、车间班组长、质检、财务、采购。
- P1：每个岗位 5 个核心动作先跑通，再扩展高级功能。
- P2：新增演练数据和验收脚本：创建 BOM、下工单、领料、完工、质检、成本对账。

## 当前系统已做得相对正确的方向

1. 已经有生产配方、工单、耗料、完工、库存流水、成本台账基础。
2. 完工前要求确认耗料记录，避免完全空耗料完工。
3. 仓储库存有负库存保护和幂等方向。
4. 生产模块已开始从“展示型页面”向“业务链路”推进。

## 当前系统不应过度宣称的能力

1. 不应宣称完整 MRP/APS。
2. 不应宣称完整 MES 或实时车间执行。
3. 不应宣称完整质量追溯闭环。
4. 不应宣称完整实际成本核算，除非材料、工时、制造费用和差异都能落账。

## 下一轮建议优先级

1. P0：工单锁 BOM 版本快照。
2. P0：完工幂等和完工对账证据页。
3. P0：耗料分类和超耗原因码。
4. P1：物料主数据编码化，减少 productName/batchNo 自由文本依赖。
5. P1：批次谱系追溯。
6. P1：生产岗位化移动入口。
