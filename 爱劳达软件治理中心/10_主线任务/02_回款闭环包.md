# 02_回款闭环包

## 包定位

本包用于把“客户应收 -> 逾期预警 -> 催收动作 -> 承诺付款 -> 争议处理 -> 核销留痕”收成一条主线。

原则：

- 正常收款只走台账和核销
- 异常事项只在逾期场景里发起
- 调账中心只做纠偏，不替代主业务
- 视觉风格保持爱劳达现有风格，内部字段和表格口径按成熟商业系统收口

## 当前已完成

### 1. 回款工作台

- 已建立独立的回款中心页面
- 主工作台分为：
  - 逾期清单
  - 收款台账
  - 合同节点
- 异常处理分为：
  - 承诺付款执行表
  - 争议处理表
  - 追款拦截表

### 2. 业务动作

- 已支持收款登记
- 已支持收款核销
- 已支持催收提醒
- 已支持承诺付款
- 已支持发起争议
- 已支持信用 / 发货拦截释放

### 3. 专业表格口径

- 主表和异常表均已补齐：
  - 筛选
  - 排序
  - 执行统计
  - Excel 导出
- 承诺付款已按时间点记录，不再只记日期
- 逾期清单已补齐：
  - 责任人
  - 最近提醒
  - 催收等级
  - 下一动作

### 4. 页面协同

- 回款中心与订单页已共用同一套承诺付款 / 争议弹层
- 订单页已补轻量追款摘要
- 订单页和回款中心的动作口径已开始统一

## 当前未收口

- 订单页的追款字段仍是轻摘要，未完全镜像回款中心的全部筛选口径
- 回款模板体系仍未单独固化成正式制度文档
- Promise / Dispute / Hold 的统计报表还未下沉到财务报表包
- 法务升级、批量催收、自动策略队列还未进入本包

## 这一包的阶段判断

当前判断：

- 回款闭环主结构：已成型
- 日常执行工作台：已成型
- 异常处理台账：已成型
- 主表专业化：已成型
- 全量制度化：进行中

1. 统一订单页与回款中心的追款文案和状态语言
2. 把回款字段口径、排序口径、导出口径沉淀成治理文档
3. 继续限制异常入口，避免回款流程重新变重
