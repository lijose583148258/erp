# 采购到岸成本与仓储回读闭环记录_2026-04-21

## 本包目标

- 让采购单支持多币种采购单价与到岸成本字段。
- 让采购收货入库时，库存成本台账使用到岸单位成本，而不是裸采购价。
- 让分批/并发/B2B 同步收货不会重复入库，也不会产生金额舍入漂移。
- 修复仓储库存台账的隐藏仓库过滤，避免真实有库存但前端搜索显示为空。

## 业务口径

- `price` 保留为采购单交易币种单价。
- `currency` 支持 `CNY / USD / VND` 等交易币种。
- `exchangeRate` 采用系统既有口径：`1 CNY = X 外币`。
- 外币采购时，物料金额按 `price * quantity / exchangeRate` 换算为 CNY。
- `freightCost / dutyCost / insuranceCost / otherCost` 暂按 CNY 基币金额录入。
- `taxAmount` 留空时按 `baseItemAmount * taxRate / 100` 自动计算；显式填写时使用填写值。
- `landedCostAmount` 是 CNY 到岸总成本。
- `landedUnitCost` 是 CNY 到岸单位成本。

## 关键修复

- 采购单新增 `currency / exchangeRate / taxRate / taxAmount / freightCost / dutyCost / insuranceCost / otherCost / landedCostAmount / landedUnitCost`。
- 运行库 `purchase_orders` 自动补 10 个新增列，避免 Prisma Schema 与 SQLite 文件不同步。
- 采购创建接口验证新增成本字段，避免前端传了但后端校验层丢弃。
- 采购单列表与服务映射回读新增成本字段。
- 采购页新增轻量到岸成本输入区与预估总成本/单位成本，不改变现有页面风格。
- 采购收货入库成本从 `price` 改为 `landedUnitCost`。
- 库存成本台账金额支持精确 `costAmountDelta`，解决 `135.71 * 7 = 949.97` 与理论总成本 `950` 的舍入差。
- 分批收货最后一批会吸收前面四舍五入差额，避免长期财务漂移。
- 仓储库存台账移除隐藏的 `selectedWarehouse` 过滤，搜索语义改回全局库存台账，避免“API 有数据、UI 看不到”的假丢失。

## 真实发现的问题

- 首次采购 API 审计失败不是卡住，而是抓到金额舍入缺口。
- 失败样例：B2B 同步单数量 `7`，理论到岸总成本 `950`，原台账入成 `949.97`。
- 浏览器人工流首次失败不是后端丢数据，而是仓储库存台账被隐藏仓库过滤挡住。
- 后端 API 能查到 `胶水原料-20260421001040` 的 `30kg` 库存，UI 因隐藏过滤显示空。

## 仍需后续成熟化

- 当前到岸成本是单行采购单口径，后续多行采购单需要按行分摊运费、关税、保险和其他费用。
- 费用币种当前统一按 CNY 录入；如果以后要记录外币费用，需要新增费用币种和费用汇率。
- 采购页当前为直接展开成本区，后续数据更多时可改为“基础字段 + 高级成本折叠”。
- 仓储库存台账后续可以补显式仓库/库位筛选器，不能再使用用户看不见的隐藏筛选。

## 反思

- 本包没有只看 build，而是被真实 API 审计抓出金额舍入问题，再修到成本台账精确闭环。
- 本包没有把 UI 空列表误判成数据丢失，而是先查 API/DB，确认是前端隐藏过滤导致的假丢失。
- 方向没有偏离主线：采购金额源头、库存入库、成本台账、浏览器回读都属于 ERP 真实业务链路。
