# 阶段 3 七条主链收口清单_2026-04-23

## 总判断

当前系统已经具备本地稳定试跑基础，但还不能说已经完整对标主流商业 ERP/CRM。

2. 生产
3. 库存
4. 权限
5. AI 隔离
6. 导入导出

## 七条主链现状

### 1. 财务主链

已具备：

- 回款核验
- 应收调整
- 部分收款场景
- 货抵支付与金额抵扣
- 业务金额回读审计
- 财务调整边界审计
- 回款核验并发审计
- 回款中心并发对账
- 货抵并发对账
- 货抵金额链 API 审计

仍需收口：

- 总账凭证
- 应收/应付统一口径
- 库存估值与成本结转
- 月结/反结账
- 汇率重估
- 财务报表

阶段 3 最小可用目标：

- 订单、回款、货抵、采购、库存变动都能生成可追溯财务台账
- 金额字段禁止 NaN、丢失、前后端口径不一致

本轮新增证据：

- `npm run audit:adjustment:finance-boundary`
- `npm run audit:payment:verification-concurrency`
- `npm run audit:collection:concurrency`
- `npm run audit:barter:concurrency`
- `node .\scripts\money-goods-chain-api-audit-v1.cjs`

已接入 Phase 3 固定闸门：

- `adjustment-finance-boundary`
- `payment-verification-concurrency`
- `collection-concurrency-reconcile`
- `barter-concurrency-reconcile`
- `money-goods-chain`

### 2. 生产主链

已具备：

- 化工 BOM 链路
- 原料耗用
- 完工入库
- 防假完工校验
- 10 原料场景审计

仍需收口：

- 配方版本
- 批号追溯
- 质检点
- 损耗率
- 替代料
- 副产物
- 返工/报废
- 成本核算联动

阶段 3 最小可用目标：

- 少耗料不能完工
- 补齐耗料后可完工
- 完工后必须有原料消耗和成品入库凭证
- 生产数据能回查到库存和成本

### 3. 库存主链

已具备：

- 仓库/库位
- 采购入库
- 发货出库
- 生产耗用
- 成品入库
- 库存台账审计

仍需收口：

- 盘点
- 调拨
- 批次/库位级查询
- 库存冻结
- 废料/损耗
- 库存估值

阶段 3 最小可用目标：

- 所有入库、出库、调整都有台账
- 库存不能被并发扣成负数
- 前端数量必须与后端库存一致

### 4. 权限主链

已具备：

- 角色权限基础
- 客户数据范围
- 供应商/采购敏感数据隔离
- AI 权限隔离回归
- 动态 RBAC 审计入口

仍需收口：

- 自定义角色可视化
- 权限点勾选
- 字段级权限
- 数据范围模板
- 审批权限
- 操作日志不可篡改

阶段 3 最小可用目标：

- 不同角色看到的数据不同
- 不该操作的按钮不可见且后端拒绝
- 不该看的客户/供应商/金额不能通过接口绕过

### 5. AI 隔离主链

已具备：

- AI 安全回归审计
- CRM 权限与 AI 隔离测试
- 权限内数据查询意识
- AI 红队隔离回归
- 越南语敏感数据请求识别
- 本地规则引擎隐藏数据请求入口拒答

仍需收口：

- AI 查询必须走后端权限过滤
- AI 回复必须按角色字段脱敏
- AI 拒答要入审计日志
- AI 不能跨客户池、跨部门、跨角色泄露数据

阶段 3 最小可用目标：

- 用户问 AI，也只能得到自己有权限的数据
- AI 不能因为自然语言绕过接口权限
- AI 所有敏感查询都有日志

本轮新增证据：

- `npm run audit:ai:isolation`
- `npx tsx .\scripts\ai-security-regression.ts`
- `npm run verify:phase3:package-browser`

新增红队场景：

- 英文诱导导出全部客户、供应商银行账户、私海客户、联系方式
- 越南语诱导列出客户、手机号、地址、供应商、订单、财务明细
- 即使误传原始 customers / suppliers / orders 上下文，本地 AI 入口也必须拒答
- 外部 AI 默认关闭；即使手动打开外部 AI，敏感业务内容也必须阻断

### 6. 导入导出主链

已具备：

- 部分 Excel 化入口
- 表格化录入方向
- 部分导入导出按钮和审计

仍需收口：

- 模板下载
- 字段映射
- 错误行报告
- 重复检测
- 幂等导入
- 批量更新
- 导出权限
- 中文/英文/越南文导入验证

阶段 3 最小可用目标：

- 客户、供应商、采购、订单、BOM、库存至少有标准模板
- 导入失败不能写一半丢一半
- 导入后必须刷新回读验证

### 7. 备份恢复主链

已具备：

- 备份 API
- manifest
- sha256 指纹
- 恢复前快照
- 备份恢复读回
- package-mode 路径兼容
- report-only 保留策略

仍需收口：

- 定时备份
- 异地备份
- 备份容量预警
- 恢复演练记录
- 迁服务器前备份清单

阶段 3 最小可用目标：

- 每次备份有 manifest 和校验
- 恢复前自动创建快照
- 恢复后业务数据读回一致
- 默认不自动删除历史备份

## 反思

当前方向没有偏离：本轮没有继续扩大业务补丁，而是先把本地壳、启动链、全仓扫描、稳定包证据链收紧。

但还不能说“完美”：

- 主流 ERP/CRM 的深度在财务、生产、库存、权限、批量数据、审计追溯上更完整
- 当前系统已经具备稳定试跑基础，但还需要用真实业务数据持续跑
- 任何后续功能补齐，都必须先形成小闭环，再接入大闸门
