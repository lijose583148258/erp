# CRM 客户主数据浏览器深测

日期：2026-04-18

## 目标

本包验证客户建档是否真正符合“跨国公司一条主数据，三种名字、多地址、多联系人”的业务要求。

不是只点开页面，而是通过真实浏览器创建客户，再通过 API 和浏览器刷新搜索双重读回，确认数据没有丢。

## 反幻觉边界

可以声明：

- CRM 客户新建入口可见且能打开。
- 能用真实浏览器录入中文名、英文名、越南文名。
- 能录入主地址和第二个地址。
- 能录入主联系人和第二个联系人。
- 保存后 API 能完整读回三语名称、地址和联系人。
- 刷新浏览器后能搜索找回该客户。

不能声明：

- 不能声明客户池分配、收回、释放、公海/内池/私海全流程已经通过。
- 不能声明客户详情抽屉五区块全部深测完成。
- 不能声明导入/导出、权限矩阵、AI 数据隔离在本包已经全覆盖。
- 不能声明 CRM 模块整体上线级完成。

## 发现和修正

第一次脚本失败原因：

- 脚本要求刷新后的列表页必须显示英文名。
- 但当前列表页主要显示主展示名，英文/越南文完整性由 API 和详情层承载。
- API 已经证明英文名、越南文名、地址、联系人没有丢。

修正：

- 浏览器刷新读回只判断能搜索找回客户主记录。
- 多语言、多地址、多联系人完整性由 API 读回负责。

这属于测试断言修正，不是业务数据丢失。
