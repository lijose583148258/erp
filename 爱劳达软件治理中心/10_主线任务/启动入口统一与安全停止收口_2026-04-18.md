# 启动入口统一与安全停止收口

日期：2026-04-18

## 本包目标

本包处理“打开错页面、停错进程、3000/5001 口径混乱”的运行入口问题。

原则：

1. 正式本地稳定入口统一为 `http://127.0.0.1:5001/`。
2. `localhost:3000` 只作为开发代理入口，不作为正式验收入口。
3. 停止脚本只能停止爱牢达归属进程，不能全局杀 `node.exe`。
4. 5173/5180 默认不处理，避免影响其他项目或开发工具。
5. 浏览器烟测和截图脚本默认走稳定入口 5001，避免再打开旧开发口。

## 发现的问题

### 1. 旧开发启动器仍有无归属强杀

文件：`启动系统.bat`

旧逻辑在 `dev` 模式下直接按端口 `taskkill`，包括 5001、3000、3001、3002。它虽然没有直接清理 5173/5180，但仍可能误杀其他项目占用的前端端口。

### 2. 停止脚本会影响外部项目

文件：`scripts/stop-runtime.ps1`

旧逻辑存在两个严重问题：

1. 会停止 5173。
2. 会强制停止所有 `node` 进程。

这是最容易导致“别的系统被一起关掉”的旧入口风险。

### 3. 旧烟测脚本默认指向 3000

文件：

1. `playwright-smoke.cjs`
2. `scripts/ui-screenshot.cjs`
3. `scripts/collection-ui-permission-browser-audit-v1.cjs`

这些脚本默认还会打开 3000，容易在没有开发服务时误判系统打不开，或在有其他开发服务时打开错页面。

## 修改内容

### 1. 安全停止脚本重写为归属判断

文件：`scripts/stop-runtime.ps1`

新增能力：

1. 读取 PID 对应命令行。
2. 只停止命令行归属于当前工作区、`backend\dist\server.js`、`backend\src\server.ts` 或稳定启动器的进程。
3. 对同一 PID 去重，避免同一监听多行重复处理。
4. 只处理 5001、3000、3001、3002、4173。
5. 明确跳过 5173/5180。
6. 删除全局停止 `node.exe` 的逻辑。
7. 运行输出改为 ASCII，避免终端显示层乱码被误判为源码乱码。

### 2. 开发启动器改走安全停止

文件：`启动系统.bat`

`dev` 模式不再直接 `taskkill`，改为调用：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File "%~dp0scripts\stop-runtime.ps1"
```

### 3. 稳定启动器打开正确页面

文件：`稳定启动.bat`

稳定启动成功后自动打开：

```text
http://127.0.0.1:5001/
```

这样用户双击稳定启动后不再停留在浏览器新标签页或错误首页。

### 4. 浏览器脚本默认入口改为 5001

文件：

1. `playwright-smoke.cjs`
2. `scripts/ui-screenshot.cjs`
3. `scripts/collection-ui-permission-browser-audit-v1.cjs`

默认入口统一改为 `http://127.0.0.1:5001/`。

### 5. 烟测断言更新为当前财务页面真实文案

文件：`playwright-smoke.cjs`

财务页面当前真实文案是：

1. `财务经营`
2. `营收与风险趋势`
3. `财务台账`

旧断言还在找 `月度经营趋势 / 经营分析`，这属于脚本预期过时，不是页面打不开。

## 反思

### 方向是否偏离

没有偏离。本包没有改业务模块，只处理运行入口和验收入口。它直接对应用户反复遇到的“浏览器打开了但不是系统”“启动挂住”“误伤其他项目”“3000/5001 说不清”的核心问题。

### 为什么这次是必要修复

如果停止脚本继续全局杀 `node.exe`，后续任何浏览器点测、EXE 壳测试、开发代理测试都有概率误伤其他项目，导致测试结论失真。这个问题不修，业务功能再多也会被运行层噪声拖垮。

### 仍然不足

1. `npm run lint` 还有 100 个 warning，下一轮应继续降噪。
2. 3000 仍保留为开发入口，但必须明确不是稳定验收入口。
3. `dual-port-audit` 系列仍保留 3000/5001 双口径测试，这是刻意保留的开发一致性验证，不属于错误入口。
4. 当前不是 Git 仓库，变更追踪依赖治理台账和文件审计结果。

## 下一包建议

继续按价值排序：

1. Lint warning 降噪首包：优先清理未使用变量，降低“真错误淹没在警告里”的风险。
2. 浏览器逐页回归：用 5001 稳定口重跑 UI 截图和核心页面烟测，确认没有无 CSS、乱码、旧入口。
3. 大文件拆分第二包：优先处理生产、采购、销售订单中仍过大的页面和服务。
