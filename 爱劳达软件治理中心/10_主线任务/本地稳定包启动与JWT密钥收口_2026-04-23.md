# 本地稳定包启动与 JWT 密钥收口_2026-04-23

## 结论

当前项目还没有真正的 Electron/Tauri/安装器级 `.exe` 打包链。

当前可用形态是：

- 根目录稳定启动链：`稳定启动.bat` / `启动系统.bat`
- 稳定本地包：`AilaoDa_Stable_Package`
- 稳定访问入口：`http://127.0.0.1:5001`
- 稳定运行库：`D:\AilaoDaRuntime\stable.db`

所以现阶段不能说“EXE 已完成”，只能说“本地稳定包和 BAT 壳已能启动”。真正 EXE 需要后续单独接 Electron、Tauri 或其他 Windows 打包器。

## 本轮发现的问题

第一次从 `AilaoDa_Stable_Package\scripts\start-stable-v2.ps1` 启动失败。

失败原因：

- 后端处于 `NODE_ENV=production`。
- `backend/src/utils/jwt.ts` 要求生产模式必须设置 `JWT_SECRET`。
- 根目录运行可能依赖现有环境或本地 env 文件，但稳定包内没有 `.env.production`。
- 因此包内生产模式启动时报错：`JWT_SECRET must be set in production`。

这是一个真实本地包运行问题，不是浏览器假失败，也不是数据问题。

## 修复

修改：

- `scripts/start-stable-v2.ps1`

处理方式：

- 如果外部环境已有 `JWT_SECRET`，保留外部值。
- 如果没有，则使用明确的本地稳定默认密钥：
  - `ailao-da-local-stable-jwt-secret-change-before-server-deploy-20260423`
- 服务器部署前仍必须替换为长随机密钥。

新增入口审计：

- `scripts/stable-entrypoint-policy-audit-v1.cjs`

新增规则：

- 稳定启动脚本必须设置或保留 `JWT_SECRET`，否则入口审计失败。

## 后续边界

本轮不引入 Electron/Tauri。

原因：

- 当前阶段目标是先保证本地稳定包能稳定运行。
- 真 EXE 会引入新的运行壳、自动更新、日志路径、数据库路径、权限、杀进程、浏览器内核等问题。
- 必须等稳定包连续运行和业务闭环更稳定后，再做 EXE 壳。

后续若要做真正 EXE，必须单独立项：

- 选择 Electron 或 Tauri。
- 明确数据库写入目录。
- 明确日志、上传、备份目录。
- 明确启动/停止后台服务方式。
- 明确升级不覆盖用户数据。
- 明确离线资源不可依赖 CDN。
