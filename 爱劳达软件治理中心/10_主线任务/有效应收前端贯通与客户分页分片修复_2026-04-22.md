# 有效应收前端贯通与客户分页分片修复

## 范围

- 本包承接“应收调整独立闭环”和“应收调整前端工作台”之后的前端口径贯通。
- 目标不是新增大功能，而是把已经存在的有效应收口径传到销售订单回款入口、订单列表财务进度、回款中心详情回读。
- 同时修复浏览器审计暴露出的 `/api/customers?pageSize=1000` 后端 500，避免订单页面客户候选加载触发 Prisma/SQLite 参数上限。

## 三步法结论

1. 翻译现象：
   - 页面进入销售订单后加载客户候选，浏览器控制台出现 `/api/customers?pageSize=1000` 500。
   - 应收调整过账后，销售订单回款弹窗仍可能按原订单金额默认回款，和后端有效应收校验不一致。
2. 判断层级：
   - 500 是后端客户查询的订单统计分片问题，不是前端乱码、入口错误或浏览器缓存。
   - 回款默认金额是前端展示和输入口径未贯通，不是后端金额链路错误。
3. 修复方式：
   - 后端 `loadOrderStats`、客户地址、联系人加载统一改为客户 ID 分片查询。
   - 前端订单、回款中心统一读取 `receivableAdjustmentAmount`、`effectiveReceivableAmount`、`outstandingAmount`。
   - 浏览器审计升级：发现 5xx、page error、console error 直接失败，避免“步骤绿但控制台红”的假绿。

## 改动清单

- `backend/src/controllers/customer/customer.persistence.ts`
  - 新增客户 ID 去重与分片 helper。
  - `loadOrderStats` 分片读取订单统计，避免 Prisma 因 `status: { not: 'cancelled' }` 和大 `in` 列表无法自动拆分。
  - `loadCustomerAddressMap`、`loadCustomerContactMap` 同步分片，降低后续大客户量下的参数上限风险。
- `pages/sales-orders/salesOrderFormHelpers.ts`
  - 增加有效应收、应收调整、未收金额统一计算入口。
- `pages/sales-orders/SalesOrderPaymentModal.tsx`
  - 回款弹窗默认金额改为有效未收。
  - 增加原应收、已收、应收调整、有效未收摘要。
- `pages/sales-orders/useSalesOrders.ts`
  - 打开回款弹窗和提交前校验都使用有效未收。
- `pages/sales-orders/SalesOrderColumns.tsx`
  - 财务进度按有效应收作为分母，并显示应收调整提示。
- `pages/collections/CollectionCurrentOrderDetail.tsx`
  - 回款中心订单详情补原应收、已收、应收调整、有效应收、剩余未收。
- `services/collections.service.ts`
  - 补充回款中心记录的 `receivableAdjustmentAmount` 类型。
- `scripts/receivable-adjustment-browser-audit-v1.cjs`
  - 增加销售订单回款弹窗有效应收默认值验证。
  - 增加 5xx、page error、console error 硬闸门。

## 风险与后续

- 本包没有改变客户权限范围，也没有改变客户列表返回结构。
- 浏览器审计已覆盖“应收调整过账后回款弹窗默认金额 = 有效未收”，但后续还应把同一口径扩展到更多报表导出字段。
- `error.log` 中仍会出现负向审计故意触发的业务拒绝，例如超额应收调整；这类不是系统崩溃，但后续可以把负向审计日志降级为业务审计日志，减少误判。
