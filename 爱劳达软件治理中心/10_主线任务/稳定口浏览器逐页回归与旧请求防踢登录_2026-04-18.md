3. 修复：不重写源码中文；只修验收脚本的等待、分类、证据字段，以及 API 客户端的旧请求 401 防误踢。

## 代码改动
- `scripts/cdp-core-pages-smoke-audit-v1.cjs`
  - 增加 `passed_with_warnings` 状态，避免把可追踪 API timeout 当作当前页面崩溃。
  - 区分 `console` 与 `pageerror`：console 中的 API timeout 降为 warning，真实 `pageerror` 仍为 fatal。
  - 增加 `httpFailures`，以后 401/403/500 能落到具体 URL。
  - 页面断言改为等待期望文案出现，而不是固定等待后立刻判断。
- `utils/api.ts`
  - 请求时记录本次请求使用的 token。
  - 401 时只有“当前 token 对应请求”才清登录并跳转。
  - 旧页面/旧 token 的迟到 401 不允许把当前页面踢回登录。
- `playwright-smoke.cjs`
  - 增加等待期望文案机制。
  - `#collections` 期望文案同步为当前页面口径：`回款工作台`、`收款台账`、`承诺付款`。
- `pages/shipping/useShipping.ts`
  - 清理 BOM 文件头导致的默认 `React` 未使用导入 warning。

## 反思
- 这次不能宣称“完美运行”。更准确的状态是：稳定口 18 页可打开、无可见崩溃、无 HTTP 失败、无 pageerror，但快速连续切页时仍会产生 API timeout warning。
- timeout warning 的直连 API 并不慢，更多暴露的是前端页面卸载后旧请求没有统一取消，以及多页面快速切换时并发请求噪声偏多。
- 下一包最值得做的是“前端请求取消与聚合读模型治理”：对 `dashboard`、`risk`、`receipt-discrepancies`、`production`、`shipping` 这几类加载密集页面增加 AbortController 或路由级请求生命周期管理。
