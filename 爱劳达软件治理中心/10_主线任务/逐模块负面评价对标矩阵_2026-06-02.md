# 逐模块负面评价对标矩阵（2026-06-02）

## 对标口径

外部 ERP 负面反馈集中在五类：数据不可信、流程不闭环、UI 高频操作低效、迁移/培训不足、报表漂亮但不能决策。以下按当前系统模块逐项对标，目的是找出会被真实贸易企业用户批评的点，并转成可执行打磨项。

参考来源：
- TechTarget：ERP 失败常见于仓储、订单、库存、跨部门沟通中断。
- Prosci / Priority Software：失败常见于变更管理、培训、流程职责不清。
- Trax Group：ERP 数据迁移问题会导致库存、报表和财务失信。
- Reddit ERP / InventoryManagement 用户反馈：库存与现场不一致、用户回到 Excel、培训不足、流程没人负责。

## 1. 经营总览 / Dashboard

负面评价对标：
- “看板很好看，但一线不信数据。”
- “指标没有解释来源，业务发现和现场不一致。”

当前风险：
- 指标如果直接聚合业务表，缺少口径说明、刷新时间、异常数据剔除规则，会被质疑为展示层。
- 待办、风险、库存、回款如果没有 drill-down 到原始单据，用户不能处理问题。

打磨动作：
- P1：每个指标显示口径、更新时间、可点击明细。
- P1：异常指标必须能跳转到订单、库存、回款、差异单。
- P2：增加“数据可信度”提示，如未同步、异常数据、迁移数据标记。

## 2. CRM / 客户档案

负面评价对标：
- “客户资料重复、联系人错误，销售还是靠 Excel。”
- “公海/私海规则不清，客户归属争议多。”

当前风险：
- 多语言客户名、地址、联系人已经复杂，但主数据去重、合并、变更审批仍不足。
- 客户导入后如果没有重复检测和字段质量评分，会把脏数据带入订单、回款、风控。

打磨动作：
- P0：客户导入预检：重名、税号、电话、邮箱、地址相似度检测。
- P1：客户合并流程：保留订单、回款、合同、售后关联。
- P1：客户归属变更必须有原因、审批和审计轨迹。

## 3. 销售订单

负面评价对标：
- “订单状态乱，谁都能改，交付和财务对不上。”
- “行项目录入太慢，错误提示看不懂。”

当前风险：
- 订单已有关联发货、回款、状态机和职责分离，但审批流尚未成为可配置流程引擎。
- 复杂行项目在小屏和高频录入场景仍需继续密度优化。

已打磨：
- 回款/订单高频错误提示已中文化。
- 订单创建者不能审批自己订单。

打磨动作：
- P0：订单状态变更接入可配置审批或明确保持固定状态机，不混用。
- P1：订单行批量录入、复制行、快捷键、错误定位到具体行。
- P1：订单全链路页：订单 -> 发货 -> 签收 -> 回款 -> 售后。

## 4. 回款中心 / Collections

负面评价对标：
- “财务不知道哪些款已登记、哪些已到账、哪些只是销售口头承诺。”
- “重复登记、超额登记后对账困难。”

当前风险：
- 已有 pending/verified/rejected 和重复窗口，但承诺付款、争议、挂起动作多，表格操作列容易拥挤。
- 多角色职责分离要持续验证，避免销售既登记又核销。

已打磨：
- EnterpriseDataGrid 操作列宽与横向动作容器已调整。
- 回款重复提交、超额、无权限等文案已中文化。

打磨动作：
- P0：回款核销必须和订单快照、应收余额、审计日志一致。
- P1：承诺、争议、挂起操作改为“主按钮 + 更多菜单”，减少表格行高。
- P1：回款异常工作台增加处理 SLA 和责任人。

## 5. 应收调整 / Adjustment

负面评价对标：
- “财务调账没有依据，最后报表没人敢信。”
- “库存、生产、财务调整混在一起，责任不清。”

当前风险：
- 调整模块覆盖财务、生产、库存、客户应收，能力强但边界容易被误用。
- 若每类调整没有单独原因码和凭证引用，会被视为万能后门。

打磨动作：
- P0：所有应收/库存/生产调整强制原因码、附件/来源单据、审批人。
- P1：调整反冲必须和原调整一一对应，禁止重复反冲。
- P1：调账影响报表需展示“调整前/调整后/差额/责任人”。

## 6. 财务经营 / Finance Analytics

负面评价对标：
- “报表漂亮，但和财务账不一致。”
- “账龄、现金流、库存成本口径不清。”

当前风险：
- 经营报表若没有宽表/读模型和口径版本，会在迁移和多人使用后失信。
- 回款、货抵、应收调整、坏账、账龄需要统一口径。

打磨动作：
- P0：财务指标建立口径清单：来源表、状态过滤、时间口径、币种口径。
- P1：账龄和现金流支持 drill-down 到订单/回款/调整。
- P2：报表显示“口径版本”和“最近计算时间”。

## 7. 合同中心

负面评价对标：
- “合同录了，但履约、付款、发货还是断开的。”
- “OCR 提取出来不可信，还要人工重复核对。”

当前风险：
- 合同、订单、里程碑、回款有连接，但合同条款到业务动作的自动化还不充分。
- OCR/AI 提取必须有置信度、人工确认、字段来源。

打磨动作：
- P1：合同里程碑与订单回款节点强绑定。
- P1：OCR 字段必须标记来源、置信度、人工确认状态。
- P2：合同变更与订单变更联动审计。

## 8. 货抵结算 / Barter

负面评价对标：
- “以货抵款到底算库存、算回款还是算调账，系统说不清。”
- “换货/抵扣和真实库存、应收没有闭环。”

当前风险：
- 货抵比普通回款更复杂，涉及协议、批次、估值、库存、订单应收。
- 页面术语若在“货抵、换货、结算、抵扣”之间摇摆，财务和仓库会理解不一致。

已打磨：
- 权限标签统一为“货抵结算”。
- 多个货抵过账/冲回错误已中文化。

打磨动作：
- P0：货抵过账必须同事务更新库存流水、回款记录、订单应收、协议剩余额。
- P1：协议、批次、过账、冲回四层状态必须可视化。
- P1：货抵估值需要审批、附件和市场价依据。

## 9. 风控中心

负面评价对标：
- “风控只是红黄绿标签，不知道怎么处理。”
- “信用额度、逾期、库存风险没有闭环动作。”

当前风险：
- 风控如果只提示风险，不绑定冻结、审批、催收、放行，会被忽略。

打磨动作：
- P0：风险规则触发后形成待办：负责人、处理动作、关闭原因。
- P1：信用风险影响订单确认/发货必须有放行审批。
- P2：风险规则可配置，但必须有默认模板。

## 10. 渠道经营 / Dealer Analytics

负面评价对标：
- “渠道报表全是 0 或演示数据，业务不信。”
- “经销商归属规则不清，排行榜没意义。”

当前风险：
- 当前页面保持诚实空态是正确的，但商业化前必须接真实渠道身份、订单、回款、库存、风险。

打磨动作：
- P0：定义渠道身份字段和归属规则。
- P1：渠道读模型接订单、发货、回款、库存、风险。
- P2：未接真实数据前禁止演示排行。

## 11. 样品管理

负面评价对标：
- “样品寄出后没人跟，客户反馈没回到销售机会。”
- “样品库存和正式库存混在一起。”

当前风险：
- 样品状态与 CRM 跟进、库存扣减、销售转化闭环仍需加强。

打磨动作：
- P1：样品寄送 -> 签收 -> 客户反馈 -> 转订单的任务流。
- P1：样品库存与正式库存分账或标记来源。
- P2：样品逾期未反馈提醒。

## 12. 发货签收 / Shipping

负面评价对标：
- “仓库现场已经发了，系统还显示没发。”
- “PDA/iPad 上按钮太小，签收录入难。”
- “签收差异没有后续处理。”

当前风险：
- 发货和签收已接库存扣减和差异入口，但移动端细节必须持续压测。

已打磨：
- 签收抽屉小屏网格降为 1-2 列，输入不再被压缩。

打磨动作：
- P0：发货扣库、签收、差异、售后/RMA 要端到端闭环。
- P1：POD 附件上传失败必须有明确错误和重试。
- P1：移动端按钮尺寸、固定保存按钮、扫码/批次输入。

## 13. 收发差异 / Discrepancy

负面评价对标：
- “差异单只是登记，没人处理，库存/财务没变化。”
- “差异状态叫已过账，但实际没过账。”

当前风险：
- 部分 action 仍是登记动作，不是库存或财务过账。

已打磨：
- customer_rma 动作从 posted 调整为 approved，避免把“创建售后单”误称为过账。

打磨动作：
- P0：差异 action 副作用矩阵：登记、审批、过账、结案严格区分。
- P0：customer_rma 要能驱动 RMA 结案和后续库存/应收动作。
- P1：差异案自动/手动结案规则明确。

## 14. 售后退换 / RMA

负面评价对标：
- “售后只是工单，没有退款、退货入库、换货出库。”
- “客户投诉处理和财务/仓库断开。”

当前风险：
- RMA 当前仍偏售后工单，未完整同事务打通库存和应收。

打磨动作：
- P0：RMA 增加来源差异单、订单、发货、批次、库存凭证、应收调整引用。
- P0：处理动作拆分为退货入库、换货出库、退款/应收调整、不处理关闭。
- P1：RMA 结案必须回写差异案和审计日志。

## 15. 组织权限 / Team & Roles

负面评价对标：
- “谁都能改权限，离职员工还能登录。”
- “权限太粗，不符合部门职责。”

已打磨：
- 账号禁用/降权后请求会回查当前用户和角色。
- 改密后旧 access token、refresh token 失效。
- 团队成员更新增加目标用户数据范围校验。

打磨动作：
- P0：refresh token 持久化并支持多实例。
- P1：系统角色权限变更需要更严格治理，防止锁死/提权。
- P1：角色变更、禁用、改密要有安全审计看板。

## 16. 资产台账

负面评价对标：
- “资产流转和客户/发货/押金/回收对不上。”
- “资产数量台账和实际现场不一致。”

当前风险：
- 资产流水有记录，但押金、回收、损坏、客户归属和财务影响需要更强闭环。

打磨动作：
- P1：资产发出、回收、损坏、报废、赔偿形成完整状态机。
- P1：资产与客户、订单、发货单关联。
- P2：资产盘点和异常提醒。

## 17. 生产配方 / Production

负面评价对标：
- “BOM 和库存成本对不上。”
- “完工、耗料、批次库存出现双口径。”

当前风险：
- 生产完工有库存/成本动作，但仍需防重复提交和批次库存/流水口径一致。

打磨动作：
- P0：完工前后对账：原料扣减、成品入库、批次库存、成本台账。
- P1：BOM 变更版本化，生产工单锁定 BOM 版本。
- P1：完工和耗料并发幂等测试常态化。

## 18. 仓储库存 / Warehouse

负面评价对标：
- “ERP 说有货，仓库没有。”
- “库存调整太随意，没人知道为什么变了。”

当前风险：
- 库存流水和负库存保护已有，但账面库存、批次库存、现场盘点、手工补录需要统一可信视图。

打磨动作：
- P0：库存可信面板：流水汇总、批次余额、productBatch、盘点差异。
- P0：手工入库/调整强制来源单号和原因。
- P1：所有 sourceType 纳入幂等唯一策略。

## 19. 采购收货 / Procurement

负面评价对标：
- “采购收货可以绕过审批。”
- “供应商资料维护太重，一线不愿填。”
- “收货差异没有后续索赔/退货/扣款。”

已打磨：
- 采购收货抽屉移动端降为 1-2 列。
- 供应商空态改为明确下一步说明。

打磨动作：
- P0：pending 采购单不能收货，审批状态必须前后端一致。
- P1：供应商主数据分阶段录入，导入预检重复和字段质量。
- P1：采购差异动作接供应商索赔、退货、应付扣款。

## 20. 审计日志 / Audit

负面评价对标：
- “出了问题查不到谁看过、谁改过。”
- “审计权限太宽，普通管理者能看全员轨迹。”

当前风险：
- 非 GET 审计已有，敏感读取和审计查询数据范围仍需加强。

打磨动作：
- P0：敏感 GET 读取落审计，如导出、财务、客户详情、权限详情。
- P1：audit.read 拆成安全管理员和业务范围审计。
- P2：审计日志支持异常过滤和导出。

## 21. 商业运营面板 / Commercial Ops

负面评价对标：
- “审批中心只是待办，业务状态没变化。”
- “BI 看板没有权限范围，平台方和业务方混用。”

已打磨：
- 文案已明确为运营待办与提醒工作台。
- workflow 创建/处理/BI summary 收紧到 admin/manager。

打磨动作：
- P0：建立 `documentType -> domain adapter -> permission -> state transition`。
- P0：审批通过后必须调用真实领域服务。
- P1：BI 汇总必须按角色和数据范围过滤。

## 总结

当前系统已经从“功能堆砌”向“可运行、可验证、有权限边界”的方向推进，但贸易型 ERP 最容易被负面评价击中的不是 UI 精致度，而是：库存可信、主数据治理、端到端闭环、迁移验证、岗位培训和异常处理。后续打磨应优先投入这些位置，而不是继续增加新模块。
