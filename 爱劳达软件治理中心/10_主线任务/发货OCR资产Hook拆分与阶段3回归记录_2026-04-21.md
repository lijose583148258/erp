# 发货 OCR / 资产 Hook 拆分与阶段 3 回归记录 2026-04-21

## 1. 本包目标

本包属于阶段 3 的“发货模块剩余拆分”治理包。

目标不是改业务规则，而是降低发货页的维护风险：

1. 将 `useShipping.ts` 中的 OCR 图片、文本识别、客户匹配、应用到发货单逻辑拆到独立 hook。
2. 将发货资产周转弹窗、资产表单和资产提交逻辑拆到独立 hook。
3. 保留现有页面风格、接口路径、业务动作和测试选择器。
4. 拆分后必须通过构建、乱码闸门、稳定入口、发货浏览器、OCR 专项、阶段 3 浏览器集合、核心发布验证。

## 2. 改动范围

| 文件 | 动作 | 说明 |
| --- | --- | --- |
| `pages/shipping/useShippingOcr.ts` | 新增 | 负责 OCR 文本、图片、画廊、解析、客户刷新匹配、创建发货单 |
| `pages/shipping/useShippingAssets.ts` | 新增 | 负责资产弹窗、资产表单、资产周转记录提交 |
| `pages/shipping/useShipping.ts` | 修改 | 收敛为发货工作台编排层，继续负责加载数据、物流状态、统计和 AI 风险提示 |

## 3. 拆分后的职责边界

```text
Shipping.tsx
  -> useShipping.ts
     -> loadData / shipments / laneStats / coldChainSeries / status update / ai insights
     -> useShippingOcr.ts
        -> OCR input / image upload / parse / apply shipment / refresh customer list once
     -> useShippingReceipts.ts
        -> receipt upload / receipt drawer / receipt event batch
     -> useShippingAssets.ts
        -> asset modal / asset form / asset transaction
```

这样后续排查时可以按小闭环定位：

1. OCR 不创建发货单：先看 `useShippingOcr.ts`。
2. 签收批次或凭证异常：先看 `useShippingReceipts.ts`。
3. 周转资产记录异常：先看 `useShippingAssets.ts`。
4. 发货列表、冷链、状态和 AI 风险提示异常：先看 `useShipping.ts`。

## 5. `tsc --noEmit` 诚实记录

本包修复了拆分时新增的 `language` 类型错误。

当前全仓 `npx tsc --noEmit` 仍未清零，剩余为既有类型债，不能混入本包假装已解决：

1. `components/AIAssistant.tsx`：`SafeAIContext` 与 `ContextData` 索引签名不一致。
2. `pages/CRM.tsx`：客户导入回调类型与 `Customer[]` 不一致。
3. `pages/ReceiptDiscrepancyWorkbench.tsx`：差异规则类型名未导入或未定义。
4. `services/freeAI/tableRecognition.ts`：`unknown` 数值累加未收窄。
5. `services/order.service.ts`：订单快照类型与 `SalesOrder` / `OrderSnapshot` 不一致。
6. `services/rma.service.ts`：`RmaRecord` 字段定义与使用不一致。
7. `services/shipping.service.ts`：发货服务响应映射存在 `unknown` 日期和 receipt 字段类型不一致。
8. `utils/quarantine/mockAdapter.legacy-mojibake.ts`：隔离区旧 mock 仍被 `tsc` 扫到。
9. `vite.config.ts`：`build.minify` 字面量类型未收窄。

这些应进入后续“全仓 TypeScript 清零包”，不能作为发货拆分包继续扩大范围，否则容易重新产生补丁化。

## 6. 反思

本包方向没有偏离阶段 3：

1. 没有改变用户可见设计风格。
2. 没有改数据库 schema。
3. 没有删除历史文件和用户数据。
4. 没有把旧端口当运行入口。
5. 没有用 build-only 宣布完成。
6. 将大 hook 继续拆小，降低后续维护成本。

下一包建议：

1. 优先做“全仓 TypeScript 清零包”的低风险项，尤其是 `services/shipping.service.ts` 与本模块相关的类型债。
2. 再进入生产/BOM 化工链路，验证 10+ 原料、代号保密、库存扣减、成品入库、成本凭证。
3. 同步继续清理旧脚本和旧入口，避免 `tsc` 或审计脚本把隔离区旧 mock 当有效源码。
