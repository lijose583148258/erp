# 复杂输入页面成熟方案调研与全局改造矩阵

更新时间：2026-04-30

## 1. 为什么要做这份矩阵

当前爱劳达系统的问题不是单个按钮不好看，而是复杂业务页面同时承担太多职责：主数据、单据录入、明细行、审核动作、台账回读、异常处理、审计追踪混在一起，用户进入页面后不知道先做什么、输入后会影响哪里。

第三阶段必须把“页面能打开”升级为“人能顺手用”。这份矩阵用于约束后续所有模块，不再只根据临时反馈修一块。

## 2. 调研提炼

### 2.1 国际成熟系统共性

- SAP Fiori：将业务界面拆成列表页、对象页、向导页、分析页。对象页用于展示、创建、编辑一个业务对象；复杂内容应分区、分段、可渐进展开，不应把对象页当成万能容器。
- Microsoft Dynamics 365 Business Central：财务输入强调 journal template、batch、line、posting、review 的分层，输入行、批次和过账动作分开，避免未过账数据被误认为真实结果。
- Odoo：订单、发票、采购等对象常用父表单 + one2many 明细行结构，单据头管理主信息，明细表管理子项，动作按钮负责确认、过账、取消等状态转换。

### 2.2 中国中小企业软件共性

金蝶、用友/畅捷通、速达、管家婆等中小企业软件更贴近爱劳达当前用户习惯：

- 先开单，再录明细。
- 表头只放客户、供应商、日期、币种、仓库、经办人、备注等主信息。
- 明细行像 Excel：物料、规格、数量、单价、金额、批次、库位。
- 审核、反审核、作废、红冲、过账必须有明确按钮和状态。
- 保存后必须回读列表、台账、库存流水或往来账。
- 老板/经理看报表，业务员开单，仓库处理出入库，财务处理回款和调账。

### 2.3 爱劳达必须保留的区域特色

- 越南靠近中国贸易环境：中文名、越南名、英文名并存。
- 一个公司可能有多个营业执照地址、发货地址、账单地址、办公地址。
- CNY/VND/USD 多币种，汇率必须按单据快照保存。
- 货抵贸易、分批交付、分批抵扣、分批回款是常态。
- 化工生产需要配方/BOM 明细，保密原料可以只填代号。

## 3. 爱劳达页面形态规则

| 页面形态 | 用途 | 适合模块 | 不该做什么 |
| --- | --- | --- | --- |
| 看板页 | 看结果、看风险、看待办 | 首页、财务经营、渠道经营 | 不直接改业务数据 |
| 主数据页 | 管客户、供应商、物料、仓库、角色 | CRM、供应商、仓库、权限 | 不做真实交易动作 |
| 单据页 | 开销售单、采购单、货抵协议、调整单 | 销售、采购、货抵、调账 | 不把审计和报表塞进录入区 |
| 明细表 | 批量输入子项 | 订单明细、采购明细、BOM 原料、收发货明细 | 不放主档字段 |
| 动作台 | 审核、过账、收货、完工、核销、冲回 | 回款、采购收货、生产完工、货抵入账 | 不偷偷改历史数据 |
| 台账页 | 查询、回读、导出 | 库存流水、财务台账、审计日志 | 不承担新建复杂单据 |
| 异常页 | 处理差异、RMA、坏账、短款 | 差异处理、RMA、应收调整 | 不替代正常业务链 |

| CRM | 主数据与客户池容易混在一起 | 简版建档 + 高级详情 + 归属池 + 审计 | P0 | 已补输入导览，后续继续细分详情区块 |
| 销售订单 | 已具备订单头 + 明细行方向 | 单据头 + Excel 明细 + 保存回读 | P0 | 保持现有链路，继续优化明细行可读性 |
| 回款中心 | 已偏工作台化 | 动作弹窗 + 回款台账 | P0 | 继续强化分批回款与核验回读 |
| 应收/调账 | 容易被误当真实回款 | 调整凭证 + 过账 + 冲回 + 台账 | P0 | 已补输入导览，后续补更多原因模板 |
| 财务经营 | 看板、调账、台账同屏压力大 | 看板只读 + 正确动作入口 | P0 | 已补输入导览，后续可做分区折叠 |
| 采购 | 供应商、采购单、收货职责容易抢 | 供应商主数据 + PO 明细 + 分批收货 | P0 | 已补输入导览，后续重点做 PO 明细表清晰化 |
| 生产 BOM | BOM 管理与 BOM 明细曾冲突 | 配方主档 + 原料明细 + 工单执行 | P0 | 已补输入导览，继续优化 10 行化工 BOM 输入 |
| 仓储 | 库存、调拨、入库、台账同屏复杂 | 仓库库位主档 + 库存流水 + 调拨动作 | P0 | 下一包继续强化调拨/入库/台账边界 |
| 货抵 | 协议、批次、库存、财务入账复杂 | 协议 + 分批抵扣明细 + 入账/反冲台账 | P0 | 下一包补明细网格和回读证据 |
| 发货物流 | 发货、POD、OCR、差异连接复杂 | 发货单 + 包装/签收明细 + 差异入口 | P1 | 下一包补保存后回读证据和签收边界 |
| 权限 | 用户、角色、权限点不应像普通表 | 账号 + 角色 + 权限矩阵 + 审计 | P1 | 已补输入导览，后续强化超级管理员授权链 |
| 审计日志 | 只读定位证据 | 筛选表格 + 追溯 + 导出 | P1 | 已补输入导览，禁止产生业务写入 |
| 合同 | 合同对象页 | 合同头 + 条款/附件 + 履约链接 | P2 | 后续处理 |
| 样品/RMA/资产 | 案件或台账 | 简单申请 + 状态流 + 台账 | P2 | 后续处理 |
