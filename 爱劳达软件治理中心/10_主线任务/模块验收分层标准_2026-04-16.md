# 模块验收分层标准（2026-04-16）

状态：本助手默认执行  
适用范围：本助手在爱劳达 ERP + CRM 项目中的所有模块验收  
执行要求：后续所有模块，本助手都必须按本分层标准验收；不得把低层通过误判成高层完成。

## 一、目标

把“代码能跑”“页面能开”“业务真的闭环”“环境能恢复”彻底分层，避免假绿。

## 二、验收分层

### L0：问题层判断通过

必须先说明问题属于哪一层：

- 源码层
- 路由入口层
- 接口层
- 数据层
- 运行层
- 报告层

未完成 L0，不得直接判定修复完成。

### L1：静态与构建层通过

至少包括：

1. `tsc --noEmit`
2. `npm run build`
3. `npm run build:backend`

通过含义：

- 代码可编译
- 依赖图未明显损坏

不代表：

- 页面可用
- 业务可用
- 上线可用

### L2：路由与页面壳通过

至少包括：

- 模块可进入
- 样式没有掉成裸 HTML
- 主标题与关键文案正常
- 没有明显错入口

通过含义：

- 页面壳层正常

不代表：

- 表单可保存
- 数据可回读
- 闭环已验证

### L3：真实业务闭环通过

至少包括：

1. 真实输入
2. 真实保存
3. 刷新或重新进入
4. 列表或详情回读
5. API 回读一致

适用于：

- 客户建档
- 订单与回款
- 采购与供应商
- 货抵协议与批次
- 生产 BOM / 工单 / 批次
- 调账与冲销

### L4：恢复与环境切换通过

至少包括：

- 稳定启动
- 健康检查
- 备份
- 恢复
- 恢复后重新登录
- 恢复后回读关键记录

通过含义：

- 出问题后系统能回得来

### L5：近上线稳定性通过

至少包括：

- 运行链单一
- 端口口径统一
- 旧入口不抢链
- 长时间运行不过度漂移
- 环境切换后 schema 不掉链

通过含义：

- 才接近“可上线”

## 三、模块状态分级

### `green`

满足：

- L1 通过
- L2 通过
- L3 通过
- 关键模块要求时 L4 通过

### `yellow`

满足：

- 主链可用
- 但仍缺某层验收
- 或仍有旧入口 / 文案污染 / 报告口径问题

### `red`

存在：

- 入口不清
- 闭环未通
- 金额/库存/状态有高风险
- 报告不可信

## 四、核心模块最小验收要求

### 1. 客户 / 供应商主数据

必须至少到 L3：

- 新建
- 列表回读
- 地址 / 联系人回读

### 2. 订单 / 回款

必须至少到 L3：

- 订单创建
- 回款录入
- 核验 / 汇总回写
- 刷新回读

### 3. 货抵支付 / 换货贸易

必须至少到 L3：

- 协议主单创建
- 批次执行
- 审批 / 过账
- 剩余待抵回读

### 4. 生产管理

必须至少到 L3：

- BOM 创建
- 工单创建
- 完工生成批次
- 生产调账
- 冲销恢复

若涉及库存与成本，再追加 L4。

### 5. 调账中心

必须至少到 L3：

- 创建
- 生效
- 冲销
- 金额或库存回读恢复

### 6. 财务分析 / Dashboard

至少要有：

- 指标来源核对
- 本位币口径核对
- 口径说明

这类模块不只看页面图表，要做口径审计。

## 五、证据包标准

每次验收必须至少留：

1. 审计脚本
2. 报告 JSON
3. 关键记录 ID
4. 关键截图或页面证据

必要时追加：

5. 数据库核对结果
6. 恢复验证结果

## 六、默认执行结论

从现在开始：

- 本助手处理的任何模块都必须挂验收层级
- 本助手说“已完成”时都必须说明完成到哪一层
- 本助手不允许再出现“build 通过 = 模块完成”的口径
