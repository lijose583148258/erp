## 2. 治理执行明细

### A. 浏览器运行时探针前置
对以下活跃浏览器审计脚本进行了重构，引入了 `browser-launch-guard.cjs`：
- [x] `procurement-browser-audit-v1.cjs`
- [x] `collections-browser-audit-v1.cjs`
- [x] `adjustment-browser-audit-v1.cjs`

**改进点**：
- 解决了在无浏览器环境（如部分服务器或权限受限环境）下运行审计时报出的 `spawn EPERM` 导致审计崩溃的问题。
- 现在脚本会报出 `blocked_env` 状态，而非业务失败。

### B. 纯 API 审计脚本新建（脱离浏览器依赖）
为了实现更快速、更稳定的后端逻辑治理，新建了以下审计：
- **[backup-restore-api-audit-v1.cjs](../../scripts/backup-restore-api-audit-v1.cjs)**：
  - 链路：登录 -> 检查数据库状态 -> 触发备份 -> 列表核对 -> 触发恢复 -> 状态再次核对 -> 再次登录验证。
- **[orders-api-audit-v1.cjs](../../scripts/orders-api-audit-v1.cjs)**：
  - 链路：双角色登录 -> 客户获取 -> 创建订单 -> 回读 -> 经理确认 -> 状态变更验证。
- **[procurement-api-audit-v1.cjs](../../scripts/procurement-api-audit-v1.cjs)**：
  - 链路：供应商创建 -> 回读 -> 关联销售订单 -> 采购单创建 -> 审批 -> 发货状态流转验证。

### C. 离线诚实化 (Honest-Offline Logic)
消除了代码库中残留的“假数据”干扰源：
- **`auth.service.ts`**：移除了 `VITE_USE_MOCK` 下的假登录逻辑。现在即使开启 Mock 模式，也不会产生假 Token 和随机用户 ID，必须连接后端。
- **`freeAIService.ts`**：
  - 移除了合同分析中的 `Math.random()` 假金额。
  - 移除了产品标签识别中的假批次号生成。
  - **诚实准则**：无法识别时返回 `null` 并提示“需人工补充”，不再提供误导性的随机假数据。
