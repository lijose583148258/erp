# CRM 建档弹窗组件拆分与主数据回归记录 2026-04-21

## 1. 背景

`pages/crm/CRMCreateModal.tsx` 之前承担了三类职责：

- 客户建档流程和状态管理。
- 地址、联系人输入卡片。
- 右侧商业预览、建档完成度和提交按钮。

这些能力都属于客户主数据，但不应该全部堆在同一个组件里。后续继续补“三语名称、多地址、多联系人、归属池、审计”时，如果不拆，维护者很难判断要改哪一段，也容易把客户建档和客户详情页做成两套重复交互。

## 2. 本轮拆分

| 文件 | 职责 |
| --- | --- |
| `pages/crm/CRMCreateModal.tsx` | 保留客户建档主流程、状态拼装、主数据输入区和高级字段入口 |
| `pages/crm/CRMCustomerFormCards.tsx` | 承接地址卡片、联系人卡片、空地址/空联系人工厂函数 |
| `pages/crm/CRMCreatePreviewPanel.tsx` | 承接右侧商业预览、建档完成度和提交按钮 |

拆分后行数：

| 文件 | 行数 |
| --- | ---: |
| `CRMCreateModal.tsx` | 345 |
| `CRMCustomerFormCards.tsx` | 174 |
| `CRMCreatePreviewPanel.tsx` | 99 |

## 3. 保持不变的业务约束

- 一家公司仍然是一条主数据。
- 中文名、英文名、越南文名仍然同时保留。
- 主地址和主联系人仍然是简版建档的最低录入面。
- 更多地址、更多联系人、证照、信用额度、账期、风险等级仍然在高级字段里折叠。
- 保存按钮和完成度提示仍然在右侧预览区，不改变当前轻玻璃、蓝色主调和圆角工作台风格。

## 5. 结论

这不是换皮，也不是继续堆补丁，而是把客户建档页从“大组件混合职责”拉回到可维护的主流程 + 子组件边界。

下一步如果继续治理 CRM，优先级应该是：

1. `CRMCustomerDrawer.tsx` 拆成“主数据 / 地址 / 联系人 / 归属池 / 审计”五区块。
2. `CollectionCenterView.tsx` 拆出列表、详情、动作栏、状态映射。
3. 后端 `customer.controller.ts` 拆成查询、写入、导入、关系、归属池动作，避免客户主数据和权限逻辑继续混在一个控制器。
