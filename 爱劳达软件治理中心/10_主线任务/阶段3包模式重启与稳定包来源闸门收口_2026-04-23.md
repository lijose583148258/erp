# 阶段3 包模式重启与稳定包来源闸门收口_2026-04-23

## 背景

本轮最终审计时发现一个严重但可控的问题：`verify:phase3` 内部的重启类脚本虽然业务链路全部通过，但重启后 5001 曾被拉回根目录运行。

这会造成典型假绿：

| 现象 | 风险 |
| --- | --- |
| `/api/health` 返回 production/ok | 只能证明服务健康，不能证明来自稳定包 |
| 业务审计通过 | 可能是在根目录最新源码上通过，不代表 `AilaoDa_Stable_Package` 用户壳通过 |
| 用户打开稳定包 | 可能和刚才验收的运行来源不同 |

## 本轮改动

| 文件 | 改动 |
| --- | --- |
| `scripts/phase3-readiness-audit-v1.cjs` | 如果存在 `AilaoDa_Stable_Package\scripts\start-stable-v2.ps1`，阶段 3 子任务默认带上 `AILAODA_RESTART_FROM_PACKAGE=1` |
| `scripts/phase3-readiness-audit-v1.cjs` | 阶段 3 默认追加 `stable-package-origin-final`，最终确认 5001 来自稳定包 |
| `AilaoDa_Stable_Package` | 已重新打包，包内脚本同步到最新版本 |

## 当前规则

| 场景 | 当前要求 |
| --- | --- |
| 普通 `npm run verify:phase3` | 默认优先包模式重启 |
| 阶段 3 内部重启 | 走 `AilaoDa_Stable_Package\scripts\start-stable-v2.ps1` |
| 阶段 3 最后一项 | 必跑 `stable-package-origin-final` |
| 判断本地能不能跑 | 不能只看 health，必须看 `stable-package-origin-audit-v1.json` |

## 反思

这是本轮最重要的反幻觉修正之一。之前“业务链路绿”仍然可能掩盖“运行来源不对”。以后所有稳定性结论必须同时满足：

1. 业务链路通过。
2. 错误日志安静。
3. 5001 来自 `AilaoDa_Stable_Package`。
4. 运行数据库仍是 `D:\AilaoDaRuntime\stable.db`。

只满足 health 或 API 通过，不足以宣称本地稳定包可用。
