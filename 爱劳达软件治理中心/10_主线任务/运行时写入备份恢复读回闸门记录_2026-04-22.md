# 运行时写入备份恢复读回闸门记录 2026-04-22

## 目标

本包继续推进阶段 3：本地稳定两个月 + 后续服务器可迁移。

上一包已经证明“新写入数据重启后能读回”。本包进一步验证“新写入数据进入备份文件，并在恢复后仍能读回”。  
这条闸门主要防止备份恢复链路假绿：备份 API 返回成功，但备份文件缺关键写入；恢复 API 返回成功，但恢复后的库丢失刚写入的数据。

## 闸门判断

写入-备份-恢复-读回闸门必须同时满足：

- active runtime DB 存在。
- 先向 `audit_logs` 写入唯一 `probeId` 探针。
- 写入后立即读回同一行。
- 通过系统 API 创建备份文件。
- 直接打开备份文件，按同一 `probeId` 读回同一行。
- 通过系统 API 恢复该备份文件。
- 恢复后从 active runtime DB 再次读回同一行。
- 备份 manifest 存在且校验通过。
- 43 张业务核心表在备份前、备份文件、恢复后三段哈希一致。
- 恢复后运行资源检查无失败项。

## 反思

这条闸门比普通备份恢复测试更严格，因为它不是只比较已有业务汇总，而是先制造一条新写入，再证明这条新写入穿过备份文件和恢复后的运行库。  
它对后续服务器迁移很关键：迁移前如果备份文件不真实，或者恢复后读取的是旧库，这条闸门会直接红灯。
