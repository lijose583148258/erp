# 测试团队增强说明-当前版

更新时间：2026-04-11

## 目的

在现有测试流程基础上，补齐更完整的团队分工，避免后续测试只停留在“正常点点看”。

## 建议固定角色

1. 前端人工流测试员
- 负责真实点击、真实填写、真实保存
- 记录按钮无动作、弹窗不出现、页面脱钩、刷新后状态变化

2. 后端链路测试员
- 负责登录、写入、回读、状态变化、审计记录
- 判断是否为接口链、事务链、写库链问题

3. 乱码与脱钩审计员
- 把问题分成三类：
- A 类：真源码损坏
- B 类：显示层误码
- C 类：逻辑或数据映射脱钩

4. 计时与卡住裁判
- 负责计时、判定卡住、终止空等
- 不做业务判断

5. 极限测试与冲突注入研究员
- 不测正常流程
- 只测冲突、极端、边界、回滚、重复提交、并发修改

6. 对账官
- 专门检查跨模块不变量
- 核对金额、数量、状态三类核心数据

7. 恢复官
- 专门检查备份、恢复、回滚后的可用性
- 验证恢复后是否还能继续写入

## 建议协作顺序

1. 前端人工流先跑最短路径
2. 后端链路确认写入和回读
3. 乱码与脱钩审计分类判因
4. 计时与卡住裁判判定是否中止
5. 极限测试与冲突注入研究员做破坏性验证
6. 对账官核对跨模块一致性
7. 恢复官做恢复演练

## 统一记录模板

```text
[时间]
角色：
模块：
操作：
结果：通过 / 失败 / 卡住
证据：
结论：
下一步：
```

## 原则

- 不猜测
- 不空等
- 不把显示问题当作业务问题
- 不把业务问题当作编码问题
- 不把正常流程测试和极限测试混在同一轮
