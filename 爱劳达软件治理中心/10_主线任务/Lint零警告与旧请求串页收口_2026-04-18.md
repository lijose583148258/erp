# Lint 零警告与旧请求串页收口（2026-04-18）

## 范围
- 目标系统：爱劳达 ERP+CRM。
- 固定入口：`http://127.0.0.1:5001/`。
- 不触碰：智仔端口 `5173/5180`、用户数据、历史归档、业务视觉风格。
- 目标：把剩余 13 个 React lint warning 收口，同时验证快速切页不会再把旧请求错误串到新页面。

## 三步法结论
1. 翻译：PowerShell `Get-Content` 中出现的疑似乱码属于终端显示层误解码；Node 按 UTF-8 扫描当前有效源码未发现同类源码损坏。
2. 判断：本包真正问题不是中文源码损坏，而是 React hook 依赖不完整、旧页面请求未取消、清理 Promise 产生未处理异常。
3. 修复：只改生命周期、错误捕获和列配置结构，不重写业务页面，不改变 UI 风格。

## 中间失败与真实根因
- 第一次 build 后 CDP 失败
  - 失败点：`#production` 路由超过 9 秒。
  - 根因：上一页 `#samples` 的 `/api/samples` 旧请求返回 401，并在新页面上升级成 `pageerror`。
  - 修复：Samples 页面请求取消与错误捕获。
- 第二次 CDP 失败
  - 失败点：`#collections` 出现 1 个 fatal console/pageerror。
  - 根因：回款中心聚合加载的 `promise.finally(...)` 返回 Promise 未接住，底层 timeout 会变成未处理异常。
  - 修复：清理分支补 `.catch(() => {})`，原始调用方仍负责展示真实加载失败。

## 反思
- 方向没有偏离：这包不是为了“好看地清 lint”，而是借 lint 把旧请求串页、未捕获 Promise、刷新按钮误传事件这些真实运行细节挖出来。
- 不能宣称“全系统完美”：当前只是核心 18 路由烟测和关键 smoke 通过，仍需继续做模块级写入、保存、刷新回读、并发与长时运行验证。
- 下一步最值钱：继续扩展“请求生命周期取消”到尚未覆盖的低频页面，并把写入型页面的保存后回读做成固定脚本。
