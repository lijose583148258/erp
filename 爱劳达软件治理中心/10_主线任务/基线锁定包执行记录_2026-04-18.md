## 本包目标

本包只处理启动基线和验收基线，不改业务设计、不改页面风格。

核心目标：

- 防止稳定启动继续服务旧的 `dist` 或旧后端构建。
- 防止 `localhost:3000`、`3001`、`3002`、`4173` 等旧前端端口残留误导人工点测。
- 每个关键运行动作保持 5 分钟以内的超时原则。
- 遇到乱码先走“三步法”：先翻译意图，再判断层级，最后只修正确层。

### 2. 禁止构建失败后回退旧包

文件：

- `F:\爱牢达\scripts\start-stable-v2.ps1`

改动：

- 前端源码变更时必须在 180 秒内 `npm run build` 成功。
- 后端源码变更时必须在 180 秒内 `npm run build:backend` 成功。
- 构建失败即停止，不再 fallback 到旧 `dist` 或旧 `backend/dist`。

原因：

- 旧逻辑会产生“启动成功但实际跑旧页面”的假绿。
- 这会直接导致人工点测、浏览器截图、API 回读互相对不上。

### 3. 数据库修复成功时静默

文件：

- `F:\爱牢达\scripts\start-stable-v2.ps1`

改动：

- `Runtime database repair` 成功时不再打印子进程详细路径。
- 失败时仍然输出详细日志。

原因：

- PowerShell 子进程输出中文路径时可能被显示层误解码。
- 这不是源码乱码，但会在终端层误导判断。
