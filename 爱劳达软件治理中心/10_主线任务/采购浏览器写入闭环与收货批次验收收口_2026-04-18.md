# 采购浏览器写入闭环与收货批次验收收口（2026-04-18）

## 本包边界
- 只处理采购模块真实浏览器写入闭环，不改品牌视觉、不改后端数据结构、不删除历史文件。
- 继续使用 5 分钟总时限和步骤级短时限，发现卡点后按证据定位，不用“构建通过”替代业务通过。
- 遇到疑似乱码先执行三步法：Node UTF-8 原文复核显示中文正常，PowerShell 中看到的 `浠?/鏆傛棤` 属于终端显示层误解码，本包没有重写中文文案。

## 真实发现
- 供应商保存不是后端失败：POST `/api/procurement/suppliers` 返回 201，API 搜索可读回。
- 前端失败点是初始 `loadData()` 晚返回后，用旧的前 100 条供应商列表覆盖了刚创建成功的本地记录，导致浏览器脚本搜索新供应商时左侧显示 0 条。
- 采购 B2B 订单创建此前存在 N+1 B2B 状态预加载和缺少 `salesOrderId` 直传的问题，已在上一轮定位并收口。
- 浏览器验收脚本仍按旧“一键 received”按钮走，但当前采购页的成熟业务设计已经升级为“收货批次抽屉”，脚本口径滞后。
- 库存核验脚本仍按旧 `PO-${orderId}` 批次口径核验，而真实后端现在返回 `stockEntryRef = PO-{id}-RCV-{receiptNo}`、`batchNo = 实际入库批次`。

## 修复内容
- `pages/Procurement.tsx`
  - 增加本地写入版本号 `localWriteVersionRef`。
  - 初始加载如果晚于本地写入返回，不再覆盖刚创建的供应商/采购单，而是合并保留本地新记录。
  - 新建供应商和新建采购单改为按 id upsert 到列表顶部，避免重复和搜索回读丢失。
- `scripts/procurement-browser-audit-v1.cjs`
  - 供应商创建后继续要求 API 读回和 UI 搜索精确行可见。
  - 收货流程从旧按钮升级为真实“收货批次抽屉”：打开抽屉、填写数量/合格/差异/批次、保存、API 回读。
  - 库存验收改用收货凭证返回的 `stockEntryRef` 和 `batchNo`，并短轮询等待 stock movement 明细稳定。

## 反思
- 这次不是“越修越坏”的结构性重写，而是通过浏览器实点抓出两个小闭环脱钩：列表状态被旧加载覆盖、验收脚本没有跟上收货批次业务模型。
- 正确方向是继续让脚本模拟真实人工流程，而不是为了绿灯补旧按钮或绕过页面。
- 后续同类页面需要重点防守：保存成功后被晚返回的初始化请求覆盖、列表只取前 100 条导致新记录不可见、脚本还按旧交互跑。
