# 阶段 3 稳定包日检与包模式验收收口记录_2026-04-23

## 结论

本轮不是继续拆业务代码，而是把阶段 3 的“本地稳定两个月”证据链收口到稳定包运行形态。

当前可证明的状态：

- 稳定访问入口：`http://127.0.0.1:5001`
- 当前运行形态：`AilaoDa_Stable_Package`
- 当前运行库：`D:\AilaoDaRuntime\stable.db`
- 当前不是正式 EXE：仍是本地稳定包 + BAT/PowerShell 启动链
- 本轮不删除历史包、不删除备份、不删除影子库

本轮完成后，日常验收不再只证明“根目录源码能跑”，而是可以证明“当前 5001 的运行服务来自稳定包”。

## 本轮修正

### 1. 稳定包来源证明

`scripts/start-stable-v2.ps1` 启动成功后会写入：

- `AilaoDa_Stable_Package/output/audit/stable-runtime-origin-v1.json`

来源证明包含：

- 稳定包根目录
- 是否为 packaged mode
- 5001 当前监听 PID
- 前端 `dist/index.html`
- 后端 `backend/dist/server.js`
- 运行数据库路径

`scripts/stable-package-origin-audit-v1.cjs` 会校验：

- 5001 健康可达
- 运行模式为 production
- 监听 PID 与稳定包来源证明一致
- 来源根目录必须是 `AilaoDa_Stable_Package`
- `packagedMode` 必须是 `true`

### 2. 每日稳定台账接入 package-mode

新增命令：

- `npm run audit:phase3:daily:package`

它在原每日检查前追加两道闸门：

- `package-origin`
- `package-freshness`

这避免出现“日检绿了，但实际跑的不是稳定包”的假绿。

### 3. 本地长稳 soak 接入 package-mode

新增命令：

- `npm run audit:phase3:soak:package`

它会串联：

- 稳定包来源证明
- 运行健康检查
- package-mode 每日台账
- SQLite 完整性
- 影子库隔离
- 备份保留治理
- 阶段 3 治理看板

所有子任务仍保持 5 分钟上限，超过即判定卡住。

### 4. 包内备份路径兼容

稳定包运行时，备份会出现在：

- `AilaoDa_Stable_Package/backups`

根目录运行时，备份可能出现在：

- `backups`

已修正两个回归脚本，让它们优先找真实创建路径，而不是硬编码只找根目录：

- `scripts/backup-restore-data-fingerprint-audit-v1.ts`
- `scripts/runtime-write-backup-restore-readback-audit-v1.ts`

## 乱码三步法复核

现象：

- PowerShell `Get-Content` 直接显示 `F:\爱牢达` 时出现过典型的 UTF-8 被错误代码页解码形态。

判断：

- 用 Node 以 UTF-8 读取 `output/audit/stable-package-origin-audit-v1.json`
- 确认 `packageRoot.includes('爱牢达') === true`
- 确认报告内容不包含典型坏码字符组

结论：

- 本次不是报告文件损坏
- 属于终端显示层误解码
- 不需要改业务代码或报告结构
