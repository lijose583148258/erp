# 阶段 3 本地两个月稳定运行与服务器迁移准入记录

日期：2026-04-21

## 目标

阶段 3 的目标不是“今天能打开”，而是：

- 本地稳定运行两个月。
- 每天有轻量巡检证据。
- 每周有备份恢复演练证据。
- 发现卡住、乱码、数据丢失、上传失败时能定位层级。
- 后续迁移到服务器时，不需要重新猜启动链、数据库路径、上传目录和环境变量。

## 本轮新增工具

### 1. 阶段 3 准入闸门

新增脚本：

- `scripts/phase3-readiness-audit-v1.cjs`

新增命令：

- `npm run verify:phase3`
- `npm run verify:phase3:browser`
- `npm run verify:phase3:release`

默认 `verify:phase3` 覆盖：

- 运行资源检查。
- 乱码闸门。
- dist/EXE 静态资源边界。
- 备份恢复 API 链路。
- 供应商权限与敏感字段隔离。
- 采购主链路。
- 发货主链路。
- AI 数据隔离安全回归。
- 服务器迁移静态配置检查。

`verify:phase3:browser` 在默认基础上追加：

- CDP 核心页面烟测。
- 采购到仓储浏览器人工流。
- 发货浏览器链路。

### 2. 两个月每日巡检

新增脚本：

- `scripts/phase3-daily-stability-audit-v1.cjs`

新增命令：

- `npm run audit:phase3:daily`

每日巡检覆盖：

- `/api/health`
- 管理员登录。
- 系统状态。
- 备份列表。
- 客户、订单、供应商、仓储、发货核心读接口。

输出目录：

- `output/audit/phase3-daily/`

## 本轮环境模板补强

更新文件：

- `.env.production.example`

新增/补充配置：

- `AILAODA_RUNTIME_DB_PATH`
- `BACKUP_DIR`
- `LOG_DIR`
- `UPLOAD_DIR`
- `FRONTEND_DIST_DIR`
- `SERVE_FRONTEND`
- `TRUST_PROXY`
- `API_RATE_LIMIT_WINDOW_MS`
- `API_RATE_LIMIT_MAX`

目的：

- 本地 EXE 和服务器部署都可以把数据库、备份、日志、上传目录放在可写运行区。
- 不把运行数据固定死在源码目录或打包目录里。
- 服务器迁移时可以用环境变量切换路径和 CORS，不改业务代码。

## 两个月本地稳定运行制度

### 每天

执行：

```powershell
npm run audit:phase3:daily
```

通过标准：

- health 正常。
- admin 登录正常。
- system status 正常。
- 备份列表可读取。
- 客户、订单、供应商、仓储、发货核心读接口正常。
- 单次运行不超过 5 分钟。

### 每周

执行：

```powershell
npm run verify:phase3
```

通过标准：

- 备份恢复链路正常。
- 采购主链、发货主链、权限安全、乱码闸门全部正常。

### 重大改动后

执行：

```powershell
npm run verify:phase3:browser
npm run verify:release:core
```

通过标准：

- API 链路和浏览器链路都通过。
- 前端构建、后端构建、lint、全仓审计都通过。

## 服务器迁移前最低条件

必须满足：

- 连续两个月每日巡检通过，或异常都有明确修复记录。
- 每周至少一次 `verify:phase3` 通过。
- 每次代码改动后 `verify:release:core` 通过。
- `.env.production` 按 `.env.production.example` 配置完成。
- 服务器上明确配置 `DATABASE_URL` 或 `AILAODA_RUNTIME_DB_PATH`。
- 服务器上明确配置 `BACKUP_DIR`、`LOG_DIR`、`UPLOAD_DIR`。
- `CORS_ORIGIN` 设置为正式域名。
- `JWT_SECRET` 换成高强度生产密钥。
- 如使用反向代理，`TRUST_PROXY=true`。

## 现阶段诚实结论

当前已经具备进入“本地两个月稳定试运行”的工程条件。

但还不能直接说已经经历了两个月稳定运行。阶段 3 真正完成，需要实际连续运行、每日记录、每周恢复演练和异常复盘。现在完成的是“阶段 3 启动准入”和“可迁移路径打底”。

## 下一步

优先级如下：

1. 继续每天跑 `audit:phase3:daily`，形成连续证据。
2. 每周跑 `verify:phase3`，确认备份恢复和关键业务链。
3. 继续拆 `shipping.controller.ts`、`customer.controller.ts`、`Procurement.tsx`、`ProductionWorkspaceV2.tsx` 这类超大文件，降低后续维护成本。
4. 在准备服务器时，用 `.env.production.example` 生成真实 `.env.production`，再跑 `verify:phase3:browser` 和 `verify:release:core`。
