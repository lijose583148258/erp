# 客户运营链路动态权限与数据范围落地执行记录（2026-04-18）

## 目标

本包处理合同、样品、售后、发货四条客户相关运营链路中残留的固定角色白名单，避免后续自定义角色上线后出现：

- 前端菜单能配置权限，但后端旧路由仍只认 `admin/manager/sales/warehouse/finance`。
- 自定义角色有 `read/write` 权限后，缺少数据范围仍能看到客户相关记录。
- 发货签收、样品状态、售后处理这类动作只靠路由角色判断，缺少记录级边界。

## 改动范围

### 权限注册表

- 新增 `contracts.write`。
- 新增 `samples.create`、`samples.status.manage`。
- 新增 `shipping.write`、`shipping.receipts.read`。
- 新增 `rma.write`、`rma.resolve`。
- 同步更新后端 `ROLE_POLICIES` 与前端 `FRONTEND_ROLE_PERMISSIONS`。

### 路由迁移

- `backend/src/routes/contract.routes.ts` 改为 `authorizePermission('contracts.read/write')`。
- `backend/src/routes/sample.routes.ts` 改为 `samples.read/create/status.manage`。
- `backend/src/routes/rma.routes.ts` 改为 `rma.read/write/resolve`。
- `backend/src/routes/shipping.routes.ts` 改为 `shipping.read/write/receipts.read`。

### 记录级范围

- 合同读取按客户数据范围过滤，财务可通过 `finance_visible` 查看合同，写入仍必须有客户业务写权限。
- 样品读取支持客户范围和仓储范围；样品状态变更支持仓储范围、创建人本人、或客户业务范围。
- 售后读取支持客户范围；售后处理支持 `all/team_customers` 范围，不允许无范围角色处理任意售后。
- 发货读取支持客户范围和仓储范围；发货写入必须有 `warehouse_visible`；签收批次读取允许客户范围、仓储范围、财务范围。

## 新增验收脚本

- `scripts/customer-ops-permission-scope-audit-v1.cjs`

脚本真实创建动态角色、用户、客户、合同、样品、售后、发货单，并验证：

- 有权限且有数据范围的角色能读回对应记录。
- 只有权限、没有数据范围的角色不能偷看合同、样品、售后、发货。
- 只有权限、没有数据范围的角色不能创建合同、推进样品状态、处理售后、创建发货。
- 仓储范围角色可以创建发货和推进样品状态。
- 财务范围角色可以查看签收批次，但不能获得发货写权限。

## 乱码三步法结果

1. 翻译：PowerShell 输出中出现的乱码属于终端显示层误解码，不是源码真实损坏。
2. 判断：用 Node 按 UTF-8 读取本包触达源码，未发现 `U+FFFD` 和典型 mojibake 字符。
3. 修复：本包未对显示层乱码做大面积重写，只在新增代码中保持 UTF-8 正常中文。

## 反思

- 本包方向没有偏离主线：仍然围绕“角色可配置 + 数据范围 + 后端真实拦截”推进。
- 没有改 UI 风格，没有重写业务页面，没有删除历史文件。
- 当前仍未迁移的固定角色入口主要集中在系统、审计、生产、调整、收发货差异等高风险模块，应继续按包推进，不应一次性大范围重写。
- 后续浏览器级人工点测仍需覆盖这些角色切换后的页面显隐、按钮禁用、表单提交和刷新回读。
