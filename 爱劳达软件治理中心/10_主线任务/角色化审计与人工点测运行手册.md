# 角色化审计与人工点测运行手册

版本：2026-04-11  
适用范围：爱劳达 ERP+CRM 本地版、离线运行版、后续服务器迁移版

## 1. 目标

把“审计、点测、对账、恢复、压力测试”拆成稳定的角色职责，避免单人视角遗漏问题。  
每个角色都必须有明确输入、动作、输出和停止条件。

## 2. 角色总览

| 角色 | 核心职责 | 主要输出 |
|---|---|---|
| 前端人工流测试员 | 按真实用户路径逐页点测 | 页面是否正常、乱码是否存在、脱钩是否出现 |
| 后端链路测试员 | 按 API / 业务链路真实写入 | 成功/失败、回读结果、是否丢数据 |
| 乱码与脱钩审计员 | 专查乱码、错链、错入口、旧壳层 | 乱码清单、错误来源、修复建议 |
| 计时与卡住裁判 | 监督每个动作的时长 | 超时判定、卡住判定、重试建议 |
| 极限测试与冲突注入研究员 | 制造并发、重复提交、状态冲突 | 冲突报告、重复提交结果、并发风险点 |
| 对账官 | 核对金额、状态、数量、回读 | 金额一致性、状态闭环、差异清单 |
| 恢复官 | 负责重启、回滚、恢复、重试 | 恢复步骤、恢复结果、不可恢复点 |

## 3. 角色边界

### 3.1 前端人工流测试员

职责：
- 按真实用户顺序点测首页、登录、客户、订单、样品、回款、货抵、生产、采购、财务等页面。
- 检查页面布局是否退化为纯文本。
- 检查切换语言、切换角色、切换池状态后是否还能正常显示。

必须记录：
- 进入页面的 URL
- 页面标题
- 是否乱码
- 是否脱钩
- 是否出现空白页、纯文本页、重复页

停止条件：
- 页面卡住超过阈值
- 页面进入错误入口
- 页面出现明显乱码或样式断裂

### 3.2 后端链路测试员

职责：
- 用真实数据执行登录、创建、回读、审核、回款、出入库、池流转等链路。
- 必须验证“写入成功后能回读”，“审核后能变更状态”，“列表和详情一致”。

必须记录：
- 请求地址
- 请求体
- 返回码
- 返回消息
- 回读结果

停止条件：
- 连续 500
- 唯一键冲突
- 数据写入后无法回读

### 3.3 乱码与脱钩审计员

职责：
- 专门处理乱码、错文案、错入口、旧页面残留、旧打包残留。
- 识别“是文件内容乱码，还是显示层误解码”。
- 对每个问题只做低风险修复，避免误删正确逻辑。

判定规则：
- 如果源码本身就坏，归入“文件级问题”
- 如果源码正常但页面乱码，归入“展示层问题”
- 如果点击后跳到别的系统或旧页面，归入“入口脱钩问题”

### 3.4 计时与卡住裁判

职责：
- 为每个动作设定最大运行时长。
- 超时就判定为卡住，不允许继续盲等。
- 识别“慢”与“挂死”的区别。

建议阈值：
- 前端单步点测：30 秒
- 后端普通写入：30 秒
- 高风险事务：60 秒
- 批量压力测试：120 秒

判定输出：
- `正常完成`
- `超时疑似卡住`
- `明确卡死`
- `需要重试`

### 3.5 极限测试与冲突注入研究员

职责：
- 制造重复点击、重复提交、并发写入、重复审核、重复过账。
- 专找“看起来成功，但实际上丢数据”的问题。
- 专找“状态重复变更”和“金额重复累计”的问题。

必须覆盖：
- 同一客户并发建单
- 同一订单并发回款
- 同一单据重复审核
- 公海 / 私海来回切换
- 生产 / 货抵 / 回款交叉冲突

### 3.6 对账官

职责：
- 核对前后金额、状态、数量、历史记录。
- 核对“创建后、审核后、恢复后”的三段结果。
- 发现差异时先记账，不直接改逻辑。

必须核对：
- 订单金额
- 回款累计金额
- 客户池当前状态
- 业务历史条数
- 回读条数与创建条数是否一致

### 3.7 恢复官

职责：
- 负责停旧进程、重启新进程、重新编译、重新加载产物。
- 当测试对象不是最新代码时，先恢复到正确运行态，再继续测。
- 任何修复后必须重新验证，不允许只改源码不换运行时。

必须执行：
- 停旧进程
- 重新构建
- 重新启动
- 重新登录
- 重新复测

## 4. 执行流程

### 4.1 日常流程

1. 前端人工流测试员先走页面。
2. 后端链路测试员跟进真实数据。
3. 乱码与脱钩审计员专门清理异常入口。
4. 对账官核对结果是否一致。
5. 计时与卡住裁判判断是否需要终止等待。

### 4.2 压测流程

1. 极限测试与冲突注入研究员发起并发。
2. 后端链路测试员回读结果。
3. 对账官检查是否多写、漏写、重复写。
4. 恢复官在必要时重启并重复验证。

## 5. 并行与串行

### 可以并行

- 前端点测
- 后端链路测试
- 乱码审计
- 对账

### 必须串行

- 停旧进程 -> 重启 -> 再测
- 修复入口 -> 再做浏览器验证
- 改数据库结构 -> 再做真实写入

## 6. 记录格式

每轮测试都按下面格式记录：

| 时间 | 角色 | 动作 | 结果 | 是否卡住 | 是否丢数据 | 备注 |
|---|---|---|---|---|---|---|
| 2026-04-11 06:00 | 后端链路测试员 | 创建订单 | 成功 | 否 | 否 | 新单号正常 |

## 7. 终止条件

任一项出现时，当前轮停止：
- 连续超时
- 连续 500
- 写入后无法回读
- 金额或状态对不上
- 发现旧进程或旧产物仍在运行

## 8. 当前结论

这套角色已经能发挥作用，但需要按本手册固定下来，才能变成真正的治理台账。  
后续每一轮测试都建议先声明角色，再执行，再对账，再恢复。
