# 企业级审计补充清单-当前版

更新时间：2026-04-11

## 目的

在现有“人工点测 + 后端链路 + 乱码 triage + 计时裁判 + 极限测试”基础上，
补齐企业级软件上线前更应该覆盖的审计维度。

## 需要补充的 8 个维度

1. 稳态指标
- 每轮测试前先定义什么叫“系统正常”
- 至少包括：`/health`、登录成功、核心写链成功、数据库可写、首屏可达

2. 会话与并发登录
- 同账号多端登录是否允许
- 新登录是否踢旧会话
- 登录后切角色是否要求重取身份

3. 幂等与重复提交
- 连点保存
- 连点核销
- 同一业务单重复提交
- 两窗口同时提交同一业务

4. 跨模块对账不变量
- 订单、回款、财务金额一致
- 货抵支付与应收核销一致
- 采购、生产、物流、资产数量一致

5. 上传文件完整性
- 上传成功但主表失败时是否留下脏文件
- 下载回来的文件是否可用
- 文件大小和格式边界是否稳定

6. 语言、币种、时区交叉
- 语言切换后是否出现乱码或错位
- 币种切换后金额是否一致
- 日期与时区在前后端是否统一

7. 恢复演练
- 备份后恢复能否继续写
- 恢复后关键页面能否正常读取
- 半成功事务能否通过恢复和补偿收口

8. 壳层与业务本体分离验证
- 登录页、全局覆盖层、语言切换、AI 弹层不能干扰 ERP 业务页
- 页面壳正常不等于业务流正常，必须分别验证

## 推荐执行顺序

1. 正常最短闭环
2. 极限测试与冲突注入
3. 对账不变量核对
4. 恢复演练
5. 最后再做体验和性能优化

## 当前最值得先补的 4 项

1. 幂等与重复提交
2. 跨模块对账不变量
3. 恢复演练
4. 语言、币种、时区交叉
