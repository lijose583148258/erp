# 分批收发货页面接线包执行记录

日期：2026-04-18  
范围：采购收货批次 UI、发货签收批次 UI、浏览器真实点测  
结论：后端分批台账已接入现有采购/发货页面，完成浏览器级点击、输入、保存、回读验证。

## 一、本包目标

上一包已经补齐后端分批收货/签收台账，但如果页面不能操作，业务仍然只能停留在 API 层。

本包目标：

- 采购订单页面可以打开“收货批次”抽屉。
- 发货物流页面可以打开“签收批次”抽屉。
- 保存后必须回读后端台账，而不是只改前端状态。
- 保留现有轻玻璃、圆角、蓝色工作台风格，不做大换皮。

## 二、页面改动

### 1. 采购页面

涉及文件：

- `pages/Procurement.tsx`
- `services/procurement.service.ts`

新增能力：

- 采购单行操作增加“收货批次”入口。
- 抽屉展示订单量、已处理、合格、剩余。
- 支持输入本次数量、合格数量、差异数量、入库批次、差异原因、备注。
- 保存后调用 `POST /api/procurement/orders/:id/receipts`。
- 保存成功后回读并刷新当前采购单状态和批次列表。
- 对已收满采购单禁用继续新增。

设计原则：

- 不再把“确认收货”直接做成旧状态按钮，避免用户误以为整单一次性完成。
- 对简单一次性收货，用户仍可在批次抽屉里录入一次完整批次。

### 2. 发货页面

涉及文件：

- `pages/Shipping.tsx`
- `pages/shipping/ShippingColumns.tsx`
- `pages/shipping/useShipping.ts`
- `services/shipping.service.ts`

新增能力：

- 发货单行操作增加“签收批次”入口。
- 抽屉展示发货量、已签收、正常、剩余。
- 支持输入本次数量、正常签收、异常数量、异常原因、备注、签收凭证文件。
- 保存后调用 `POST /api/shipping/:id/receipt-events`。
- 保存成功后回读并刷新当前发货单状态和批次列表。
- 已完成签收的发货单禁用继续新增。

设计原则：

- 原“一次性上传回单”入口保留，用于没有分批记录的简单场景。
- 一旦业务进入分批签收，后端会拦截旧整单签收，避免重复完成。

## 四、测试中发现并修正的问题

### 1. 测试数据违反私海客户规则

现象：

- 脚本创建 `private` 私海客户但没有指定销售负责人，后端返回 400。

判断：

- 这是 CRM 权限规则正常生效，不是 bug。

修复：

- 浏览器点测脚本改用 `internal` 内部池客户，避免测试数据绕过业务制度。

### 2. 测试审批违反职责分离

现象：

- 同一用户创建销售订单后又审批，后端返回 403。

判断：

- 这是职责分离规则正常生效，不是 bug。

修复：

- 脚本改为 admin 建数据、manager 审批，模拟真实团队分工。

### 3. 脚本等待条件过弱

现象：

- 抽屉异步回读会重置默认数量，脚本过早输入导致前端校验拦截，没有发出 POST。

判断：

- 这是浏览器点测脚本节奏问题，不是业务接口失败。

修复：

- 脚本改为等待抽屉数据稳定，再输入。
- 保存时等待真实 POST 响应和批次号出现，不再只等待静态标题。
