# 阶段 3 库存流水与调拨记录可视化收口

日期：2026-04-23

## 本包目标

上一包已经把“库存调拨”接入仓储页面。本包继续把调拨后的凭证和库存移动记录做成可查、可追溯的小闭环：

1. 仓管员能在页面看到“库存流水”页签。
2. 默认优先查看“调拨记录”，避免全部库存流水混杂。
3. 支持按产品、批次、仓库、库位查询。
4. 支持按来源单号/工单号查询，方便从生产工单、调拨来源号、采购/发货来源号反查库存流水。
5. 调拨记录必须展示来源库位、目标库位、产品、批次、数量、来源凭证号、备注。
6. 浏览器点测后必须能在 UI 看到刚才调拨产生的真实流水。
7. API 验收必须确认调拨流水由 `stock_entries / stock_movements` 真实表产生，不是前端假日志。

## 过程里抓到并修复的真实问题

浏览器验收第一次失败并不是后端错误，也不是数据丢失，而是库存流水筛选区在 `1440x980` 视口、左侧导航存在的真实工作台宽度下，列数设置过多，导致产品搜索输入框被压成 `0px` 宽。  

修复方式：

1. 给库存流水面板增加稳定根节点 `data-testid="warehouse-ledger-panel"`。
2. 浏览器脚本只在可见面板内定位输入框，避免隐藏节点误导。
3. 筛选区从固定 7 列改成可换行响应式布局：常规工作台下最多 3 列，超宽屏才展开到 7 列。

修复后：

- `npm run audit:warehouse:transfer:browser` 从 FAIL 恢复为 PASS。
- `npm run verify:phase3:package-browser` 通过 47/47。

## 反思

本包没有新造“调拨单表”，而是复用现有库存凭证和库存移动行。这是更稳的方向：

1. 库存余额、库存流水、调拨操作使用同一条账务来源。
2. 不会出现“页面有调拨记录，但库存流水没有”的双账问题。
3. 后续生产领料、采购入库、销售出库、货抵出入库都可以统一在这张流水视图追踪。

## 仍需后续收口

1. 调拨审批：当前仓管员可直接调拨，后续可按高价值物料、危险化学品、跨仓库调拨触发审批。
2. 单据打印/导出：当前可查，但还没有调拨单打印模板和标准导出。
3. 生产联动视图：当前能看到生产耗用/入库来源类型，后续应把工单号、BOM、批次成本进一步串起来。
4. 权限细分：当前按仓储权限看流水，后续可以细分为“只看库存”“可调拨”“可看成本金额”。
