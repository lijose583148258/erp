# Lint 降噪首包

日期：2026-04-18

## 本包目标

本包目标不是为了追求数字漂亮，而是减少“真错误被警告淹没”的风险。

执行原则：

1. 只清理低风险未使用导入、未使用变量、未使用本地函数。
2. 不强改 hook 依赖，避免改变页面加载时序。
3. 不为了 Fast Refresh 警告拆文件，除非后续做对应模块结构重构。
4. 每次清理后必须跑 `lint`、`build`、全仓审计和浏览器烟测。

## 剩余 15 条为何不在本包硬改

剩余 warning 类型：

1. `react-hooks/exhaustive-deps`
2. `react-refresh/only-export-components`
3. `pages/shipping/useShipping.ts` 的单个历史 React 默认导入 warning

不继续硬改的原因：

1. Hook 依赖警告可能影响页面初次加载、重复加载、防抖、权限上下文和数据回读，必须按页面逐个验证，不能批量机械修改。
2. Fast Refresh 警告需要拆分 `SalesOrderColumns.tsx` 的常量和组件导出，应该跟销售订单模块结构治理一起做。
3. `useShipping.ts` 的单个 React 默认导入不影响运行；后续和出货物流模块 hook 依赖一起收口更稳。

## 反思

### 做对的地方

1. 没有为了清零强改 hook 依赖。
2. 每一刀后都跑了构建。
3. 最终仍跑了全仓审计和浏览器烟测，避免只看 lint 变绿。

### 仍然不足

1. 15 条 warning 仍然存在，后续需要按页面闭环单独处理。
2. 清理未使用代码降低了噪声，但没有解决 P2/P3 的大文件和重复文件问题。
3. 当前不是 Git 仓库，变更追踪仍依赖治理台账。

## 下一包建议

1. Hook 依赖专项：按页面逐个处理，并且每个页面处理后做浏览器点测。
2. 销售订单结构治理：处理 `SalesOrderColumns.tsx` Fast Refresh 警告，并继续拆销售订单大 hook。
3. 出货物流专项：把 `useShipping.ts` 的历史 React 导入和 hook 依赖一起收口。
