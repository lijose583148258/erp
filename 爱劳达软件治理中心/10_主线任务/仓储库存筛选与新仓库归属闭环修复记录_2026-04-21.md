# 仓储库存筛选与新仓库归属闭环修复记录_2026-04-21

## 结论

本轮不是简单补丁，而是围绕“采购 → 仓储 → 入库 → 库存台账回读 → 显式筛选回读”的真实浏览器闭环做的治理修复。

已确认并修复 4 个关键问题：

1. 库存台账存在隐藏/竞态筛选风险：产品名、仓库、库位筛选在 React 状态提交与查询按钮之间可能不同步。
2. 库存页自动加载请求可能覆盖人工查询结果，造成“API 有数据，但页面显示暂无库存数据”的假丢失。
3. 新建仓库后没有自动选中新仓库，后续新增库位可能被挂到旧仓库下。
4. 创建仓库接口返回对象可能没有 `locations/_summary`，前端立即渲染会触发白屏：`Cannot read properties of undefined (reading 'length')`。

## 三步法复核

### 1. 翻译现象

用户看到的是：

- 入库提示成功。
- 库存台账搜索新产品时显示空表。
- 有时切换或新建仓库后页面白屏。

业务含义是：

- 仓储保存后必须能在库存台账中回读。
- 仓库/库位归属必须准确，不能把新库位挂到旧仓库。
- 页面不能因为接口返回缺少子数组而崩溃。

### 2. 判断层级

本轮分层判断结果：

- 数据库层：不是数据丢失。API 可查到新入库库存。
- API 层：库存查询接口按 `productName` 可返回正确数据。
- UI 状态层：存在筛选状态竞态，旧请求可覆盖新查询结果。
- UI 业务交互层：新建仓库后未自动选中新仓库，导致后续库位归属错误。
- UI 兜底层：仓库对象缺少 `locations` 时会白屏。
- 验收脚本层：登录曾把登录页误判成主壳；已改为 token + 登录输入框消失双闸门。

### 3. 修复动作

修复点：

- `pages/WarehouseWorkspace.tsx`
  - 增加仓库记录归一化 `normalizeWarehouseRecord`。
  - `locations` 缺失时兜底为空数组。
  - `_summary` 缺失时兜底为 0。
  - 新建仓库成功后立即选中新仓库，避免新增库位挂到旧仓库。
  - 库存筛选使用稳定 ref 保存当前产品名、仓库、库位。
  - 库存查询增加请求序号，旧请求返回后不能覆盖新结果。
  - 仓库/库位筛选从隐藏状态改成显式控件。

- `services/warehouse.service.ts`
  - 将仓库、库位 DTO 归一化上移到服务层。
  - `listWarehouses/createWarehouse/createLocation` 的返回值统一兜底。
  - 页面层复用同一个归一化函数，避免其他仓储调用方重复踩 `locations/stockBalances` 缺失白屏问题。

- `scripts/lib/browser-human-flow-audit-utils.cjs`
  - 登录验收不再用 `ERP+CRM` 字样判断成功。
  - 必须满足 `localStorage.token` 存在且 `#login-username` 不存在，才算进入系统。

- `scripts/browser-human-flow-audit-v1.cjs`
  - 仓储入库回读改为 15 秒内循环查询，模拟真实人工等待与再次查询。
  - 增加显式库位筛选后的回读验证。

- `scripts/warehouse-filter-network-probe.cjs`
  - 新增网络探针，用于抓取库存查询真实 URL、响应和页面渲染结果。
  - 该脚本用于诊断，不替代正式 Release Core。

## 反思

### 方向是否偏离

没有偏离。仍然围绕主线：

- 本地稳定运行。
- 真实浏览器点测。
- 保存后回读。
- API 与 UI 双证据。
- 不靠单一 build 绿灯宣布完成。

### 本轮暴露的系统性问题

1. 仓储页面仍有“接口对象形状不统一”的风险，需要继续补 DTO 归一化。
2. `dist/assets` 里历史 chunk 文件会累积，虽然当前 `index.html` 指向新入口，但会造成排查噪声；后续应制定“打包产物清理策略”，但不能粗暴删除用户资料或历史报告。
3. 浏览器验收脚本必须继续坚持“登录主壳双闸门”，避免再次把登录页当成系统页。
4. 所有保存后回读都应使用“短轮询 + 明确超时”，不能只等固定 1 秒。

## 后续建议

优先级从高到低：

1. 对 CRM、采购、生产、订单也补同类“接口对象形状兜底”，重点防止子数组缺失导致白屏。
2. 把 `warehouse-filter-network-probe.cjs` 纳入诊断工具索引，避免成为孤儿脚本。
3. 设计构建产物清理规则：只清旧 chunk，不碰数据库、报告、治理文档和用户文件。
