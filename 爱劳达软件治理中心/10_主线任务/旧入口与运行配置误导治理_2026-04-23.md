# 旧入口与运行配置误导治理

- 日期：2026-04-23
- 范围：稳定入口审计、根启动器、运行配置、终端显示层乱码复核

## 本包结论

这次按“三步法 + 主控复核”处理侧线旧入口报告，没有直接照单全改。

## 已复核事项

### 1. 稳定入口审计脚本

- 文件：`scripts/stable-entrypoint-policy-audit-v1.cjs`
- 侧线疑点：脚本似乎引用了乱码文件名。
- 主控复核：Node 按 UTF-8 读取后，脚本中是真实文件名 `稳定启动.bat`、`正式启动.bat`、`启动系统.bat`、`停止服务.bat`。
- 处理：不改脚本，避免把显示层误解码当成源码损坏。
- 证据：`npm run audit:entrypoints` 通过，0 findings。

### 2. 根稳定启动器

- 文件：`稳定启动.bat`
- 侧线疑点：终端显示 echo 文案乱码。
- 主控复核：Node 按 UTF-8 读取，真实内容已经是正常中文。
- 处理：不改启动器。

### 3. runtime 数据修复脚本

- 文件：`backend/src/database/runtime-data-repair.ts`
- 侧线疑点：`PRODUCTION_MOJIBAKE_REPLACEMENTS` 可能把坏中文写回数据库。
- 主控复核：左侧是待替换的历史坏字符串，右侧目标是正常中文：
  - `化工胶水`
  - `化工 BOM 产线审计`
  - `化工 BOM 审计样本，仅使用内部代号`
- 处理：不改替换表，避免破坏修复逻辑。

### 4. 后端本地 `.env` CORS

- 文件：`backend/.env`
- 真实问题：原配置仅放行多个旧开发端口，反而没有稳定入口 `5001`。
- 已处理：收敛为稳定 5001 + 本项目 Vite 3000：
  - `http://127.0.0.1:5001`
  - `http://localhost:5001`
  - `http://localhost:3000`
  - `http://127.0.0.1:3000`
- 没有改动：JWT、数据库路径、上传路径。

## 证据

- `npm run audit:entrypoints`：通过，0 findings
- `npm run check:runtime`：通过，稳定入口 `http://127.0.0.1:5001` 可访问
- Node `.env` 检查：
  - `hasStable=true`
  - `hasOldPorts=false`

## 反思

- 本包最重要的是没有盲修。终端显示层乱码和源码真实乱码必须分开。
- 本轮实际修改只有 `backend/.env` 的 CORS 收敛，属于运行配置治理，不改变业务设计。
- 后续如要进一步降低误用概率，可再处理 `dual-port` 命名误导、`check-timeboxed-health.ps1` 副作用命名、打包前产物新鲜度校验。
