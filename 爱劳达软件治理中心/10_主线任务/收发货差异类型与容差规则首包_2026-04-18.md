# 收发货差异类型与容差规则首包

日期：2026-04-18

## 本包目标

把上一包的“收发货差异自动生成异常单”升级为可治理的规则体系：

- 差异单不再只有一个笼统的异常原因，新增可检索的 `discrepancyType`。
- 采购收货和客户签收都进入同一套容差规则判断。
- 规则支持 `allow / warn / manual_review / block` 四类动作。
- 超过阻止规则时，整笔收货/签收事务回滚，不留下脏收货单、脏库存或半截异常单。

## 已落地内容

### 1. 数据结构

`receipt_discrepancy_cases` 新增字段：

- `discrepancy_type`
- `tolerance_rule_id`
- `tolerance_action`
- `tolerance_percent`
- `tolerance_quantity`
- `variance_rate`
- `within_tolerance`
- `requires_quality_check`

新增规则表：

- `receipt_tolerance_rules`

默认规则：

- `DTR-PURCHASE-DEFAULT`：采购差异默认人工评审。
- `DTR-PURCHASE-QUALITY`：采购质量拒收默认人工评审并要求质检。
- `DTR-SHIPPING-DEFAULT`：客户签收差异默认人工评审。
- `DTR-SHIPPING-DAMAGED`：客户破损签收默认人工评审并保留售后/RMA 判断入口。

### 2. 后端逻辑

采购收货：

- 以采购订单数量作为参考数量。
- 默认差异类型为 `short_shipped`。
- 命中 `block` 时，采购收货批次、库存入库和差异单全部回滚。

发货签收：

- 以发货单数量作为参考数量。
- 默认差异类型为 `customer_short_signed`。
- 命中 `block` 时，签收批次和差异单全部回滚。

容差计算：

- 百分比容差：`referenceQuantity * quantityTolerancePercent / 100`
- 绝对值容差：`quantityToleranceAbs`
- 最终容差数量取二者较大值。
- `varianceRate = discrepancyQuantity / referenceQuantity * 100`

### 3. API

新增：

- `GET /api/receipt-discrepancies/tolerance-rules`
- `POST /api/receipt-discrepancies/tolerance-rules`

权限：

- 查看规则：当前沿用差异单授权入口。
- 创建规则：仅 `admin / manager`。

### 4. 前端服务层

补齐：

- `ReceiptDiscrepancyType`
- `ReceiptToleranceAction`
- `ReceiptToleranceRule`
- `receiptDiscrepancyService.getToleranceRules`
- `receiptDiscrepancyService.createToleranceRule`

采购/发货 service 已预留 `discrepancyType` 入参，后续页面接入时不用再改接口底座。

## 反幻觉说明

本包不能被解释为“收发货异常模块已经全部商业化完成”。

已经完成的是：

- 差异类型字段。
- 容差规则表。
- 创建差异单时自动判定规则。
- 阻止规则的事务回滚。
- API 级写入、读回和回归验证。

尚未完成的是：

- 独立的差异处理工作台 UI。
- 规则管理页面。
- 差异单与质检模块的正式联动。
- 差异单与 RMA、补发、索赔、财务扣款的正式联动。
- 客户/供应商维度的更细粒度规则模板。
- 承运商、批次、产品等级、合同条款维度的高级匹配。

## 下一包建议

优先顺序：

1. 做“差异处理工作台”页面，把采购拒收、客户短签、破损、错货都放到统一队列。
2. 做规则管理最小 UI，仅开放给 `admin / manager`。
3. 把 `requiresQualityCheck` 接到生产/质检入口，但先只做跳转和状态标记，不自动改库存。
4. 把 `manual_review` 的后续动作模板补成：补发、索赔、退货、RMA、财务扣减。
5. 再补浏览器级人工点测：采购差异、发货差异、规则新增、刷新读回、权限不可见。

## 边界原则

- 差异单是异常工作流入口，不直接替代库存凭证、财务凭证、RMA 或质检单。
- `allow` 只表示低风险自动关闭异常记录，不代表自动调整财务或索赔。
- `block` 必须保持事务回滚，不允许生成半截业务数据。
- 后续任何页面改造必须继续保留 API 读回和浏览器读回双证据。
