# 前端请求生命周期取消首包（2026-04-18）

## 范围
- 目标系统：爱劳达 ERP+CRM
- 固定入口：`http://127.0.0.1:5001/`
- 明确不碰：智仔 `5173/5180`
- 问题类型：快速连续切页时，旧页面请求未取消，10 秒后 timeout 串到新页面控制台；审计页请求失败缺少 catch，形成 `pageerror`。

## 改动
- `utils/api.ts`
  - 新增 `ApiRequestOptions`，支持向服务层传入 `AbortSignal`。
  - 新增 `isCanceledApiError()`，统一识别被取消请求。
  - 被取消请求不再输出 `console.error`。
  - timeout 错误保留为结构化错误，但不再由全局 axios 层额外刷 `API Error` 控制台噪声。
  - 保留旧 token 401 防误踢登录逻辑。
- 服务层新增可选 `signal`
  - `services/dashboard.service.ts`
  - `services/collections.service.ts`
  - `services/receiptDiscrepancy.service.ts`
  - `services/production.service.ts`
  - `services/shipping.service.ts`
  - `services/asset.service.ts`
  - `services/customer.service.ts`
  - `services/adjustment.service.ts`
  - `services/audit.service.ts`
- 页面首屏加载加入请求取消
  - `pages/Dashboard.tsx`
  - `pages/RiskControl.tsx`
  - `pages/ReceiptDiscrepancyWorkbench.tsx`
  - `pages/ProductionWorkspaceV2.tsx`
  - `pages/shipping/useShipping.ts`
  - `pages/AuditLogs.tsx`

## 修复的真实问题
- 快速切页后旧页面 API timeout warning 串页。
- 旧页面请求取消后仍然更新 state 的风险。
- 审计页 `fetchLogs()` 没有 catch，timeout 会升级成浏览器 `pageerror`。
- 被取消请求被误当成真实接口错误，污染验收报告。

## 反思
- 方向没有偏离：这包不是美化，也不是新增业务，而是修“真实人工快速切页会暴露的运行稳定性问题”。
