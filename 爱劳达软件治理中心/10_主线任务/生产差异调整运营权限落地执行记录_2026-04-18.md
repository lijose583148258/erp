# 生产、收发货差异、调整单运营权限落地执行记录（2026-04-18）

## 目标

本包继续清理后端固定角色白名单，处理三个仍属于运营主链路、但原先仍由 `authorize('admin', 'manager', ...)` 控制的模块：

- 生产管理
- 收发货差异
- 调整单中心

核心目标不是“让菜单能点”，而是让动态角色、权限点、数据范围三者同时生效，避免自定义角色后出现全局可见或越权写入。

## 改动范围

### 权限点

- 新增 `production.write`。
- 新增 `discrepancies.write`、`discrepancies.rules.manage`。
- 新增 `adjustments.read`、`adjustments.write`、`adjustments.apply`、`adjustments.reverse`。
- 前后端权限注册表同步更新。
- 前端菜单增加 `adjustment -> adjustments.read` 映射。

### 路由迁移

- `backend/src/routes/production.routes.ts` 从固定角色白名单改为 `production.read/write`。
- `backend/src/routes/receipt-discrepancy.routes.ts` 从固定角色白名单改为 `discrepancies.read/write/rules.manage`。
- `backend/src/routes/adjustment.routes.ts` 从固定角色白名单改为 `adjustments.read/write/apply/reverse`。

### 控制器范围守卫

- 生产读取必须具备 `warehouse_visible` 或 `finance_visible`。
- 生产写入必须具备 `warehouse_visible`。
- 收发货差异读取必须具备 `warehouse_visible` 或 `finance_visible`。
- 收发货差异处理必须具备 `warehouse_visible`。
- 容差规则管理仍保守限制为 `admin/manager/all`，避免普通动态角色误改全局规则。
- 调整单按领域映射数据范围：
  - `finance_visible` 可处理 `finance` 调整。
  - `warehouse_visible` 可处理 `production`、`inventory` 调整。
  - `all/admin` 可处理全部。
  - 无范围角色只能拿到空视图，不能写入。

## 新增验收脚本

- `scripts/operational-permission-scope-audit-v1.cjs`

脚本验证：

- 有 `production.read/write` 但无运营数据范围的动态角色不能读取或写入生产。
- 仓储范围角色可以读取生产并创建 BOM。
- 财务范围角色可以读取生产但不能写生产。
- 有 `discrepancies.*` 但无运营范围的动态角色不能读取差异或维护规则。
- 仓储/财务范围角色可以按范围读取差异。
- 无范围角色调整单只能看到空视图，不能写入调整单。

## 反思

- 这包没有偏离主线，仍在做“动态角色 + 权限点 + 数据范围 + 真实 API 验收”。
- 本包只迁移运营权限，不碰系统备份、审计日志、注册接口等高危系统入口。
- 调整单读接口对无范围角色采用空视图而不是 403，保持和客户/采购等范围读接口一致；写入仍严格 403。
- 后续应继续处理回款中心历史固定角色动作接口、系统/审计高危入口的保守权限建模，以及浏览器级角色切换点测。
