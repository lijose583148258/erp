# 服务器迁移 API 基址与失败可见化优化记录

日期：2026-04-25

## 本包目标

- 继续围绕“本地稳定两个月，后续可迁移服务器”的阶段 3 目标收口。
- 不做大换皮，不重写业务模块，只处理会导致上线迁移、人工输入、导入、审计回读时误判的细节问题。
- 乱码三步法默认开启：先确认 `utils/api.ts` 中文是源码损坏还是终端显示层误解码，再决定是否修复。

## 已修复问题

1. API 基址从“浏览器当前 hostname + 5001”改为本地与服务器双轨：
   - 本地 `localhost` / `127.0.0.1` / `::1` 仍自动连接 `:5001/api`。
   - 纯净运行版 `5001` 端口走同源 `/api`。
   - 非本地域名默认走同源 `/api`，避免服务器部署后浏览器错误访问客户本机的 `127.0.0.1` 或不存在的 `域名:5001`。
   - 显式 `VITE_API_BASE_URL` / `VITE_API_ABSOLUTE_URL` 仍优先，且自动去掉尾部斜杠。

2. 表格导入失败可见化：
   - `DataTable` 的 Excel/CSV 导入不再只写 `console.error`。
   - 空文件、读取失败、解析失败会通过系统通知反馈。
   - 读取成功时提示“已读取行数，但需要保存后刷新回读确认”，避免把临时解析误认为持久化成功。

3. 智能填表失败可见化：
   - `SmartFormFill` 解析失败不再静默。
   - 紧凑弹窗和普通面板都会显示红色错误卡片，同时触发系统通知。

4. 审计日志失败可见化：
   - 审计日志加载失败不再只写控制台。
   - 页面显示错误横幅，同时触发系统通知。
   - 加载过程接入 `DataTable` 的 loading 状态，避免空表被误判为无审计记录。

5. 仓储页面原生弹窗收口：
   - 仓库/库位新增权限不足和创建失败从 `alert()` 改为系统通知。
   - 保持页面风格一致，减少原生弹窗打断操作流。

6. 生产环境控制台噪声收口：
   - 登录失败保留用户可见通知，不再额外输出原始错误到控制台。
   - 壳版本和 i18n 映射日志只在开发模式输出。

7. 审计原因输入组件化：
   - 新增 `ReasonDialog`，统一承接冲销、冲回、作废等原因输入。
   - 货抵批次冲销、应收调整冲回、生产调账冲销不再使用浏览器原生 `prompt`。
   - 原因输入默认必填，确认前做前端校验，避免空原因进入审计链。
   - 生产冲销弹窗拆到 `pages/production/ProductionAdjustmentReverseDialog.tsx`，避免继续把主页面堆成巨文件。

## 三步法结论

- 发现点：PowerShell 中 `utils/api.ts` 中文注释和错误文案曾显示为乱码。
- 判断：用 Node 以 UTF-8 读取后确认源码包含正常中文，不包含常见坏字特征和替换字符。
- 修复：没有重写中文文案，只修 API 基址逻辑，避免把终端显示层问题误修成源码损坏。

## 剩余风险

- 这包只解决“基址迁移 + 失败可见化 + 仓储弹窗收口”，没有继续改业务流状态机。
- 部分页面仍存在 `prompt` 类审计原因输入，后续应替换成统一的业务原因弹窗，避免审计字段随意。
- `DataTable` 仍是兼容层，后续高价值页面应逐步迁移到 `EnterpriseDataGrid`，但不能一次性大换导致回归扩大。
- 纯净运行版同步时 EXE 被占用，虽然保留了有效 EXE 且验收通过，但后续打包前最好先关闭旧壳再同步，减少误判。
