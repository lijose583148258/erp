# 启动链防误伤与智仔隔离执行记录（2026-04-18）

## 范围

本包处理爱劳达启动链和其他项目端口混线的问题。目标是保证爱劳达启动、重启、验收时只处理爱劳达自己的端口和进程，不再误伤 `F:\智仔\frontend`。

## 根因判断

1. `scripts/start-stable-v2.ps1` 原稳定启动器会停止 `5173`。
2. 当前机器上 `5173/5180` 明确属于 `F:\智仔\frontend` 的 Vite 进程，不是爱劳达正式运行入口。
3. `启动系统.bat dev` 原开发链存在 `taskkill /F /IM node.exe`，会杀掉所有 Node 进程，包括别的项目、浏览器审计或后台任务。
4. 这类全局清理不会立刻表现成源码错误，但会制造“页面进错项目、服务莫名消失、多终端混乱”的运行层故障。

## 修改内容

1. 稳定启动器收窄端口清理：
   - `scripts/start-stable-v2.ps1` 不再停止 `5173`
   - 步骤文案改为 `Stop old AilaoDa listeners`
   - 保留爱劳达明确使用的 `5001/3000/3001/3002/4173`

2. 开发启动器移除全局 Node 误杀：
   - `启动系统.bat` 删除 `taskkill /F /IM node.exe`
   - 开发模式只按显式端口清理，不再杀全部 Node

## 验收证据

1. 端口归属复核：
   - `3000`：爱劳达 Vite
   - `5001`：爱劳达后端 `backend/dist/server.js`
   - `5173`：智仔 Vite
   - `5180`：智仔 Vite

2. 静态检查：
   - `scripts/start-stable-v2.ps1` PowerShell Parser 解析通过
   - `scripts/start-stable-v2.ps1` 与 `启动系统.bat` 中不再出现 `5173` 或 `taskkill /F /IM node`

3. 运行时健康检查：
   - 命令：`powershell -ExecutionPolicy Bypass -File .\scripts\check-runtime.ps1`
   - 结果：`health` 200，`home` 200

4. 乱码闸门：
   - `scripts/start-stable-v2.ps1`
   - `启动系统.bat`
   - UTF-8 扫描通过，无 `U+FFFD` 或常见 mojibake marker

## 反思

这次不是功能大改，但价值很高。之前用户反复遇到“挂到智仔”“多个浏览器/终端”“打不开”的感受，很多并不是业务代码错，而是启动链的清理边界太粗。稳定系统必须先保证启动器不会误伤其他项目，否则浏览器点测和后端验收都会被环境噪声污染。

## 剩余风险

1. `npm run dev:all` 仍会打开额外窗口，只适合开发调试，不应作为正式验收入口。
2. 稳定启动器仍会清理 `3000/3001/3002/4173`，后续如果这些端口也有其他项目占用，应继续改成“只清爱劳达进程”。
3. 当前正式稳定入口应优先使用 `稳定启动.bat`，开发入口 `启动系统.bat dev` 只用于调试。

## 下一步建议

1. 给启动器增加端口归属报告，启动前先打印端口、PID、命令行，再执行清理。
2. 把 `npm run dev:all` 标注为开发入口，避免用户误点后出现多窗口。
3. 后续 EXE 壳应只拉起独立后端和本地 WebView，不依赖全局端口扫描。
