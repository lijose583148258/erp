# 收发货差异工作台与规则管理首包

日期：2026-04-18

## 目标

把收发货差异从“采购、发货各自处理”收束成一个独立工作台，先完成差异队列查看、容差规则新增、角色可见入口、构建与 API 读回验证。

本包不直接生成质检、RMA、索赔或财务扣减凭证，避免一个页面越权改账。后续应把这些动作做成明确的业务单据流。

## 本包改动

- 新增页面：`pages/ReceiptDiscrepancyWorkbench.tsx`
- 新增浏览器验收脚本：`scripts/receipt-discrepancy-workbench-browser-audit-v1.cjs`
- 新增静态/API 验收脚本：`scripts/receipt-discrepancy-workbench-static-audit-v1.cjs`
- 注册懒加载入口：`app/activePathRegistry.ts`
- 注册页面渲染：`app/appContent.tsx`
- 注册侧边栏入口：`components/Layout.tsx`
- 注册命令面板入口：`components/CommandPalette.tsx`

## 当前能力

- 管理员、经理、仓库、财务可以看到“收发货差异”入口。
- 管理员、经理、仓库可以把差异单置为评审中或关闭。
- 财务可以查看差异队列，但本包不允许财务直接处理差异单。
- 管理员、经理可以新增容差规则。
- 容差规则保存后通过 API 读回验证，不只看按钮点击。
- 页面使用现有 `PageShell`、`ModuleHero`、`EnterpriseDataGrid`、`FormField`、`StatusBadge`，没有新建一套孤立样式系统。

## 浏览器验收状态

浏览器级脚本已补齐，但当前环境阻止 Playwright/Edge/Chrome 自动拉起浏览器：

```text
All browser launch strategies were blocked by spawn EPERM.
```

判定：

- 这不是 5 分钟卡死，脚本约 1 秒失败。
- 这不是业务页面断言失败，而是浏览器进程启动权限被拦截。
- 因此本包不能声明“浏览器人工点测通过”，只能声明“静态入口 + API 读回 + 构建通过”。

证据文件：

- `output/playwright/receipt-discrepancy-workbench-browser-audit-report-v1.json`

## 反幻觉结论

已通过：

- 页面入口注册不是死代码。
- 构建产物里存在差异工作台 chunk。
- 容差规则新增后能通过 API 读回。
- 差异单和容差规则后端回归未被本包破坏。
- 当前包没有新增 CDN 或 Google Fonts。
- 当前有效源码扫描没有发现乱码。

未完成：

- 浏览器真实点击、截图、控制台错误检查受 `spawn EPERM` 环境限制，未通过。
- 差异关闭目前只是快速状态处理，没有接上质检、RMA、索赔、财务扣减的正式动作流。
- 容差规则本包只有新增和查看，没有做编辑、停用、优先级冲突提示。
- 财务扣减、索赔、补发、退货、让步接收还没有形成可追溯单据链。

## 下一包建议

优先顺序：

1. 先恢复或替代浏览器运行层：解决 `spawn EPERM`，或使用已打开浏览器的 CDP 连接方式，拿到真实截图和控制台证据。
2. 再做“差异处理动作流”：质检单、RMA、索赔、补发、退货、让步接收、财务扣减分别生成明确业务记录。
3. 再做“容差规则治理”：编辑、停用、优先级冲突检测、命中解释、规则审计日志。
4. 再做“财务/库存对账”：差异关闭后必须能追踪是否影响库存、应收、应付、成本、索赔。
