# 回款中心前端权限与加载稳定执行记录（2026-04-18）

## 范围

本包承接“回款动作权限与数据范围落地”，专门收口前端层是否真实遵守后端动态权限，并处理浏览器验收中暴露的加载稳定性问题。

## 根因判断

1. `vite.config.ts` 未限制依赖扫描入口，Vite 开发服务会把 `output/browser-cdp-profile` 等浏览器审计产物当作入口扫描，出现 Edge Wallet 缓存依赖解析错误。
2. 回款中心首屏使用 `Promise.all` 一次并发拉取 7 个接口，在 React StrictMode 开发模式下会重复触发两轮请求；SQLite 后端慢响应时，Axios 10 秒超时会导致整页数据包失败，用户看到“加载中 / 0 条 / 偶发超时”。
3. `npm run lint` 没有忽略 `.vite-cache`，构建后 lint 会扫描第三方缓存文件，产生 2000+ 假错误。
4. 原浏览器测试脚本只看 API 或宽松按钮文本，容易把说明文字当动作按钮，不能作为上线证据。

## 修改内容

1. Vite 隔离运行产物：
   - `vite.config.ts` 增加 `server.watch.ignored`，排除 `.vite-cache`、`output`、`logs`、`runtime-db`、`scratchdb`、`temp*` 等运行产物。
   - `vite.config.ts` 增加 `optimizeDeps.entries: ['index.html']`，禁止把审计产物当依赖扫描入口。

2. 回款中心加载改为小闭环：
   - `pages/collections/useCollectionCenter.ts` 新增同 token in-flight 去重，降低 StrictMode 双请求对本地 SQLite 的冲击。
   - `pages/collections/useCollectionCenter.ts` 将首屏加载从 `Promise.all` 改为 `Promise.allSettled`，单个接口失败不拖死逾期表、台账、承诺、争议和拦截区。
   - 动作后的刷新使用 `loadData({ force: true })`，避免承诺付款、核销、释放拦截后读到旧缓存。
   - `pages/collections/CollectionCenterView.tsx` 的弹窗提交后刷新也改为强制刷新。

3. ESLint 治理收口：
   - `eslint.config.mjs` 增加 `.vite-cache/**`、`logs`、`runtime-db`、`scratchdb`、`temp*` 等忽略项，避免生成缓存污染源码验收。

4. 浏览器权限验收脚本：
   - 新增 `scripts/collection-ui-permission-browser-audit-v1.cjs`。
   - 脚本通过 API 创建真实动态角色、真实用户、真实客户、真实逾期订单、真实待核销回款。
   - 脚本用浏览器分别登录 viewer、operator、finance 三类角色，逐项检查按钮显隐，并做 UI 点击 + API 读回。

## 反思

本包没有改变业务风格，也没有绕过后端权限。真正解决的是“前端看起来有按钮但后端拒绝”“接口部分慢导致整页假空”“验收脚本误判按钮”的三类细节问题。

这次证明了一个重要规则：浏览器验收必须同时看 UI、API 回读和数据状态。只看构建通过或只看 HTTP 200 都会产生假绿。

## 剩余风险

1. 回款中心相关接口在本地 SQLite 上仍有 6-8 秒级响应的情况，后续应拆分 summary 读模型或增加轻量缓存，避免数据量变大后影响首屏。
2. 全仓仍有 106 个 lint warning，当前不阻断运行，但后续治理包应逐步清理。
3. Finance 视角能看到多条 `释放` 按钮，是因为历史和本轮测试数据中存在多条有效拦截，属于数据量现象，不是权限泄露；后续可做更清晰的分页和筛选默认值。

## 下一步建议

1. 按同样的浏览器角色脚本模式，补齐采购、仓储、生产、货抵的“按钮显隐 + UI 点击 + API/DB 读回”验收。
2. 对回款 summary 做后端性能治理，避免大量历史订单时首屏慢。
3. 将 `output`、`.vite-cache` 等运行产物隔离规则复制到后续所有审计脚本和 CI 说明中。
