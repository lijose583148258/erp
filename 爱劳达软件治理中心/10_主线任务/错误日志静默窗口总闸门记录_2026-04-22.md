# 错误日志静默窗口总闸门记录

## 背景

仅测试 `isExpectedBusinessRejection` 分类函数还不够，因为真实运行链路可能绕过分类逻辑，或者某个审计步骤仍把预期业务拒绝写进 `logs/error.log`。

## 本包目标

- 在阶段 3 和 release 总闸门中加入真实运行态静默窗口。
- 总闸门开始时记录 `logs/error.log` 字节数。
- 全部任务通过后再次检查字节数。
- 如果 `error.log` 增长，总闸门失败，并把新增片段写入报告。

## 改动

- `scripts/phase3-readiness-audit-v1.cjs`
  - 新增 `error-log-quiet-window` 合成步骤。
  - 阶段 3 全部任务通过后比较 `logs/error.log`。
- `scripts/run-release-verification-v1.cjs`
  - 新增 `error-log-quiet-window` 合成步骤。
  - release core/full 全部任务通过后比较 `logs/error.log`。

## 验收

- `node scripts/effective-source-mojibake-gate-v1.cjs`：通过。
- `npx tsc --noEmit`：通过。
- `npm run audit:log-classification`：通过。
- `npm run verify:phase3`：通过，16/16，`error-log-quiet-window` 通过。
- `npm run verify:release`：通过，23/23，`error-log-quiet-window` 通过。

## 结论

从本包开始，阶段 3 和 release 不再只是“业务步骤通过”，还会证明验收期间没有新增真实错误日志。这个闸门能防止后续再次出现“报告绿但 error.log 红”的假稳定。
