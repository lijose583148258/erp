# 客户控制器查询写入拆分与权限回归记录 2026-04-21

## 1. 背景

`backend/src/controllers/customer.controller.ts` 已经把导入导出、关联查询、客户池动作拆到子控制器，但主文件仍然混合了：

- 客户列表查询。
- 客户统计。
- 客户详情。
- 客户创建。
- 客户更新。
- 客户停用。

这会让客户主数据、客户池权限、销售数据范围、三语名称、多地址、多联系人等逻辑继续挤在一个控制器里。后续再修客户池或建档字段时，维护者容易把读链和写链混在一起。

## 2. 本轮拆分

| 文件 | 职责 |
| --- | --- |
| `backend/src/controllers/customer.controller.ts` | 只保留门面转发，统一挂载路由方法 |
| `backend/src/controllers/customer/customer-query.controller.ts` | 客户列表、统计、详情查询 |
| `backend/src/controllers/customer/customer-write.controller.ts` | 客户创建、更新、停用 |

拆分后行数：

| 文件 | 行数 |
| --- | ---: |
| `customer.controller.ts` | 54 |
| `customer-query.controller.ts` | 198 |
| `customer-write.controller.ts` | 371 |

## 3. 保持不变的业务约束

- 客户列表仍然走 `buildCustomerWhere`，不改变角色数据范围。
- 客户详情仍然走 `loadCustomerForRequest`，不绕过权限。
- 创建客户仍然保留销售角色私海规则、业务线校验、销售负责人校验。
- 更新客户仍然禁止通过普通更新接口直接修改客户池归属。
- 客户池归属仍然只能通过专用池接口调整。
- 停用客户仍然要求管理员权限。

## 4. 同步修正

`CRMCustomerFormCards.tsx` 原先同时导出组件和 `createEmptyAddress` / `createEmptyContact`，触发 React Fast Refresh 维护警告。本轮把工厂函数移到 `CRMCustomerFormFactories.ts`，保持组件文件只导出组件，清理 lint 警告。

## 6. 反思

这包是正确方向：没有改变客户业务含义，只把读链、写链、门面控制器拆开。它能减少后续维护成本，尤其是客户池、公海/内部池/私海、三语名称、多地址、多联系人这些逻辑继续演化时，不会再全部压在一个控制器里。

下一步如果继续客户主数据后端治理，优先拆的是 `customer-write.controller.ts` 内部的创建、更新、停用命令服务，而不是继续扩展控制器本身。
