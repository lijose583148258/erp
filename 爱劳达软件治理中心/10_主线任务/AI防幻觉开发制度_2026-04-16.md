# AI 防幻觉开发制度（2026-04-16）

状态：本助手默认执行  
适用范围：本助手在爱劳达 ERP + CRM 项目中的所有工作  
执行要求：从本文件生效后，本助手参与的所有开发、修复、审计、验收与上线准备，必须遵守以下制度。

## 一、制度目标

防止出现以下“假绿”现象：

- `build` 通过，但运行态不一致
- API 成功，但页面回读脱钩
- 本地可用，但切环境后炸掉
- 页面看起来正常，但数据没有真实落库
- 审计报告显示 `passed`，但报告口径本身不可信

## 二、总原则

### 1. AI 不是裁判，证据才是裁判

AI 只能生成候选改动、候选补丁、候选测试思路。

真正决定“是否完成”的只能是：

- 代码构建结果
- API 回读结果
- 浏览器真实回读结果
- 数据库核对结果
- 备份恢复与环境切换结果

### 2. 金额、库存、状态机、权限一律高风险

以下改动默认视为高风险，不允许只靠单层验证：

- 金额计算
- 订单/回款/货抵/调账
- 库存数量与批次
- 生产工单与质检
- 状态流转
- 角色权限
- 公海/私海/内池分配与收回

### 3. 旧入口、旧壳、旧目录不清，禁止直接下结论

只要项目里还存在：

- `.current`
- `.live`
- `.clean`
- 旧 `src/` 目录
- 兼容壳
- 历史对比目录

就必须先判断当前运行的到底是哪一层，再允许改动。

## 三、AI 开发强制流程

### 第一步：先判断问题层

任何问题先判断属于哪一层：

- 源码层
- 构建层
- 路由入口层
- 接口层
- 数据层
- 报告层
- 显示层

没有完成这一层判断，不允许直接“顺手重写一堆文件”。

### 第二步：只改最窄责任面

改动必须尽量局部化：

- 优先改真实活跃入口
- 优先改真实读写链
- 不同时混入无关 UI 美化
- 不同时混入结构性重构

### 第三步：修后必须真实验收

修复后至少要通过对应层级的验收，不允许只靠主观判断：

- 文案问题：必须过“禁乱码闸门”
- 接口问题：必须过 create/read-back
- 页面问题：必须过真实点击/保存/刷新/回读
- 环境问题：必须过稳定启动/健康检查/恢复验证

## 四、禁止事项

### 1. 禁止把 `build 通过` 说成“系统可上线”

`tsc`、`build`、`build:backend` 只代表静态和构建层通过。

### 2. 禁止把 `API 200` 说成“业务闭环已通”

必须至少再证明：

- 数据已真实落库
- 刷新后仍可回读
- 浏览器侧没有脱钩

### 3. 禁止只凭一张截图下结论

截图只能作为辅助证据，不能替代：

- 审计报告
- 关键记录 ID
- API 回读
- 数据库核对

### 4. 禁止在脏入口环境里乱修

如果：

- 运行地址不确定
- 端口不确定
- 旧 bundle 未清
- 启动链不确定

则先停在运行底座治理，不直接修业务。

## 五、固定护栏

### 1. 乱码三步法默认开启

只要遇到乱码、文案异常、文案脱钩，一律执行：

1. 先翻译
2. 再判断
3. 再修复

### 2. 禁乱码闸门默认开启

修复后必须验证：

- 关键正确文案必须存在
- 典型乱码关键词必须不存在

### 3. 5 分钟超时判定默认开启

任何运行或测试超过 5 分钟，必须判断是否卡住：

- 是否有新增输出
- 是否有健康检查变化
- 是否已经进入死等状态
- 是否需要重试、恢复或换路径

### 4. 审计报告字段防覆盖

报告字段命名不能和步骤状态字段冲突。  
如果步骤详情里也有 `status`，必须改成：

- `formulaStatus`
- `workOrderStatus`
- `batchStatus`

之类的专用字段，避免报告“假通过”。

## 六、分级执行规则

### A 类：允许 AI 直接推进

- 文案清污
- 低风险 UI 对齐
- 已有字段的前后端补线
- 报告字段修正
- 审计脚本补强

### B 类：允许 AI 写，但必须双验证

- 订单 / 回款 / 货抵 / 调账
- 生产 BOM / 工单 / 批次
- 导入导出
- 搜索与联想
- 多语言映射

要求至少通过：

- API 回读
- 浏览器回读

### C 类：必须先做业务设计再写

- 成本子账
- 本位币汇总
- 联产品 / 副产品
- 回用料分摊
- 公海私海规则
- 角色权限收回 / 派发

### D 类：必须先做恢复与环境验证

- EXE 打包
- 服务器迁移
- 长时间本地运行
- 数据迁移
- 恢复演练

## 七、完成定义

一个 AI 参与的改动，只有在以下条件满足后，才允许说“完成”：

1. 真实问题层已判明
2. 改动责任面清楚
3. 对应层级验收通过
4. 报告口径无冲突
5. 没有引入新的旧入口误判

## 八、默认执行结论

从现在开始，在爱劳达项目中：

- `AI 防幻觉开发制度` 作为本助手默认规则开启
- 不需要用户额外提醒
- 除非用户明确要求跳过，否则本助手不允许关闭
