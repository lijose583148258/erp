# 回款调账闭环系统工程拉正记录 2026-04-20

## 本包目标

把“回款中心 / 调账台账”从浏览器验收失败状态拉回真实业务闭环，要求不是只看页面能点，而是满足：

- 有真实客户主数据。
- 有真实销售订单。
- 有订单回款与承诺付款回读。
- 财务调账必须绑定真实订单。
- 调账创建、待处理、生效、冲销、数据库回读形成闭环。
- 所有运行 5 分钟内出结论，禁止长挂。

## 发现的问题

### 1. 浏览器验收脚本按输入框位置硬填

旧脚本使用 `inputs.nth(0/1/2...)` 填写调账表单，页面字段顺序一变就会填错。

风险：

- 很容易把 `targetRef`、`orderId`、`batchId`、`amountDelta` 填错位。
- 测试报告可能显示“点击过了”，但业务并没有按正确字段提交。
- 后续 UI 小调整会反复造成假失败。

### 2. 财务调账没有绑定真实订单

后端校验是正确的：`finance` 调账必须有 `orderId`，并且 `amountDelta` 不能为 0。

旧脚本把调账当作 `manual` 参考号单据提交，只填了 `targetRef`，导致后端返回 400：

- `Finance adjustment requires an orderId`
- 前端报告中显示为 `输入数据(body)格式错误`

结论：这是测试闭环设计错误，不是应该放松后端规则。

### 3. collections-adjustment 模块缺少真实依赖链

旧模块没有声明依赖 `crm -> orders`，但财务调账天然依赖订单。

已修正为：

```text
crm -> orders -> collections-adjustment
```

这样单独运行 `--module=collections-adjustment` 时，也会先自动建立客户和订单，再进入财务调账。

## 反思

### 方向没有偏离

本次没有为了让测试过而放松后端规则。相反，是把测试链路补成真实商业逻辑：

```text
客户 -> 订单 -> 回款/承诺付款 -> 财务调账 -> 生效 -> 冲销 -> 回读
```

### 后续固定要求

- 所有浏览器验收必须优先使用 `data-testid`，禁止按 `nth()` 猜字段。
- 涉及金额、库存、状态的模块必须有后端读回和数据库读回中的至少一项。
- 财务类单据不能无业务对象地假闭环，除非产品规则明确允许独立手工凭证。
- 模块依赖必须写进执行计划，不能让单模块测试脱离上游真实数据。
