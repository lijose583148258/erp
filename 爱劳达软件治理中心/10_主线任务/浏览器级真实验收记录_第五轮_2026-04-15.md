# 浏览器级真实验收记录（第五轮）

- 日期：2026-04-15
- 范围：CRM 详情主数据 / 地址 / 联系人；采购供应商新增；采购后端 create supplier API
- 执行方式：浏览器真实点测 + API 分层验证

## 本轮结论

### 1. CRM 地址与联系人读写链已收口

- 之前的专项浏览器脚本误判，根因不是地址字段天然丢失，而是抽屉滚动区和过快连续输入导致的点测不稳定。
- 修正 `useCRM.tsx` 后，客户详情页的以下链路已真实通过：
  - 备注编辑并刷新回读
  - 地址标签 / 注册名称 / 注册号 / 税号 / 国家代码 / 完整地址编辑并刷新回读
  - 联系人邮箱编辑并刷新回读
- 当前可以确认：CRM 地址与联系人主链在真实浏览器操作下已通过。

### 2. 采购模块当前卡点已缩小到“浏览器新增供应商 UI 动作”

- 浏览器在采购页新增供应商时，右侧新增表单会卡在保存动作前后，18 秒超时。
- 现象：
  - 表单字段可填写
  - 供应商名称、分类、联系人能进入输入框
  - 但浏览器点测仍未成功完成“保存后列表回读”
- 当前更像是：
  - 右侧表单滚动 / 保存按钮命中 / 保存后回读动作中的浏览器层问题
  - 不是后端 `create supplier` 总链天然坏掉

### 3. 采购后端 create supplier API 已单独验证通过

- 使用管理员登录后直接调用：
  - `POST /api/procurement/suppliers`
- 验证结果：
  - 返回 `success: true`
  - 新供应商成功写入
  - `contacts`、`addresses`、`supplierDisplayName` 均正常返回

## 本轮判断

- Procurement API：本轮通过
- Procurement 浏览器新增供应商：仍需继续做 UI 层动作定位，不应误判成后端总链故障
