# 生产工单完工并发幂等加固记录（2026-04-21）

## 本包目标

本包处理生产工单完工链路的并发风险。

生产完工不是单纯改状态，它会联动：

1. 工单状态。
2. 原料库存扣减。
3. 成品批次生成或成品批次数量增加。
4. 生产消耗库存凭证。
5. 生产产出库存凭证。
6. 成本台账。

因此这里必须比普通页面保存更严格，不能只靠前端禁用按钮。

## 发现的结构风险

原逻辑在完工前先读取工单状态，然后直接更新工单状态，后续再执行库存和成本副作用。

在用户双击、网络重试、浏览器重复提交或多人同时操作时，理论上可能出现：

1. 两个请求都认为工单还没完成。
2. 两个请求都进入完工副作用。
3. 成品批次重复生成。
4. 成品批次数量重复增加。
5. 原料库存重复扣减。
6. 成本台账重复写入。

这属于 P0 级生产/库存/成本一致性风险。

## 修复点

修改文件：

- `backend/src/services/production-mutation.service.ts`

修复内容：

1. 新增 `readWorkOrderDetail` 统一回读函数，避免返回结构分散复制。
2. 将工单状态写入从普通 `update` 改为：

   `updateMany({ where: { id, status: 当前刚读到的状态 } })`

3. 如果 CAS 没抢到，立即回读最新工单。
4. 如果最新状态已经是目标状态，按幂等成功返回，不再执行库存和成本副作用。
5. 如果最新状态不是目标状态，返回冲突错误，要求前端刷新后重试。

10. 回读成品库存，确认数量为 100，不重复增加。
11. 回读成品成本台账，确认只有 1 条成品完工成本记录。

## 当前结论

生产工单完工链路已完成本轮并发幂等加固。

现在的行为是：

1. 第一个完工请求执行真实库存和成本副作用。
2. 后续重复完工请求只回读已完成结果。
3. 不重复扣原料。
4. 不重复入成品。
5. 不重复写成品成本台账。

后续建议：

1. 继续把 CAS 模式扩展到货抵结算的审批、过账、冲销。
2. 对采购分批收货接口补一个专门的并发分批收货审计。
3. 把生产并发审计纳入 Phase3 日常或发布前验收队列。
