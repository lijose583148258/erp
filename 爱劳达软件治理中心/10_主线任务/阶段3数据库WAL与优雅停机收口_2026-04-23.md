# 阶段3数据库 WAL 与优雅停机收口_2026-04-23

## 背景

阶段 3 包级验收中多次出现 `audit_logs` 索引缺行：

- `row ... missing from index audit_logs_action_idx`
- `row ... missing from index audit_logs_resource_idx`
- `row ... missing from index audit_logs_resource_resource_id_idx`

复盘后确认不是 Schema 漂移、不是外键错误、不是业务表缺失。直接原因与本地验收期间频繁强杀 Node 运行进程有关：旧停止脚本使用 `Stop-Process -Force`，服务端收到停止时也没有关闭 HTTP server 和 Prisma 连接。

## 本次修复

| 层级 | 修复 |
| --- | --- |
| SQLite 运行层 | `backend/src/config/database.ts` 增加 `configureRuntimeDatabase()`，启动时设置 `journal_mode=WAL`、`busy_timeout=5000`、`foreign_keys=ON` |
| 服务端停机层 | `backend/src/server.ts` 增加 HTTP server 引用、Prisma `$disconnect()`、SIGTERM/SIGINT 优雅关闭、本地 shutdown signal watcher |
| 启停脚本层 | `scripts/stop-runtime.ps1` 和 `scripts/start-stable-v2.ps1` 先写 `shutdown.signal` 请求服务端自行关闭，12 秒未退出才强制停止 |
| 备份恢复层 | `backend/src/services/backup.service.ts` 在备份前 checkpoint WAL，在文件级恢复前断开 Prisma，恢复后重新配置连接 |
| 验收脚本层 | `backup-restore-data-fingerprint-audit-v1.ts` 和 `runtime-write-backup-restore-readback-audit-v1.ts` 读取备份文件时改用临时副本，避免审计脚本自己污染 manifest |

## 当前结论

当前稳定包已经进入 WAL + 优雅停机模式。后续停止 5001 时，默认先走本地 shutdown signal，不再直接强杀。只有服务端 12 秒内没有退出时，脚本才会 fallback 到强制停止。

这次修复属于主框架稳定性治理，不是业务补丁。它直接服务于“本地稳定运行两个月”和“后续可迁移服务器”的阶段 3 目标。

## 后续注意

| 项目 | 注意点 |
| --- | --- |
| 不要手动杀进程 | 后续停止系统优先使用 `scripts/stop-runtime.ps1` 或稳定包脚本 |
| 备份文件不要直接打开 | 审计备份内容时必须复制到临时副本再读取 |
| Shadow DB 仍是 P2 | `backend/prisma/*.db` 仍作为历史影子库保留，不参与当前运行 |
| REINDEX 仍保留 | `repair:db:reindex` 作为只修索引类完整性问题的恢复手段，不能替代优雅停机 |
