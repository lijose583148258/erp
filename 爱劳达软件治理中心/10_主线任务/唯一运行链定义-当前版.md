# 唯一运行链定义-当前版

## 目的

这份文档只定义一件事：

当前版本什么才算“正式运行”，什么只能算“开发辅助”或“临时应急”。

## 一、运行链分级

### A. 当前正式运行链

当前应视为唯一正式运行链的是：

1. 先构建前端与后端
2. 由后端 `5001` 同时提供 API 与构建后的前端静态页面
3. 健康检查以 `http://127.0.0.1:5001/health` 为准

对应入口：

- `F:\爱牢达\正式启动.bat`
- `F:\爱牢达\scripts\start-stable-v2.ps1`
- `F:\爱牢达\scripts\check-runtime.ps1`
- `F:\爱牢达\稳定启动.bat`

对应停止入口：

- `F:\爱牢达\停止服务.bat`
- `F:\爱牢达\scripts\stop-runtime.ps1`

说明：

- 这条链当前是“应急稳定链”
- 目标是保证 ERP 本体能跑、能测、能写
- 它优先于 `vite dev`

### B. 当前开发辅助链

以下入口只视为开发辅助链，不视为正式运行验收链：

- `npm run dev`
- `npm run dev:backend`
- `F:\爱牢达\启动系统.bat`

原因：

1. 当前机器上的 Vite 开发链存在 `spawn EPERM` 风险
2. 多条入口会制造“到底哪条链在跑”的混乱
3. 开发辅助链可以继续保留，但不能再被用于“系统已经稳定”的判定

## 二、当前正式端口定义

### 正式端口

- 后端/API/正式首页：`5001`

### 开发辅助端口

- 前端 dev：`5173`
- 其他历史端口：`3000`、`3001`、`3002`、`4173`

规则：

1. 只要讨论“当前系统是否能运行”，统一看 `5001`
2. `5173` 只用于开发观察，不作为正式验收依据

## 三、当前数据库路径定义

### 当前应急运行数据库

当前后端运行时数据库来自：

- `DATABASE_URL="file:%TEMP%/AilaoDaRuntime/stable.db"`

来源文件：

- `F:\爱牢达\backend\.env`
- `F:\爱牢达\backend\src\config\runtime.ts`
- `F:\爱牢达\backend\src\config\database.ts`

### 为什么是这个路径

当前机器上，以下路径不稳定或不可写：

- 工作区内 SQLite 写入曾出现 `disk I/O error`
- 外部 `D:\AilaoDaRuntime\stable.db` 曾出现只读/写失败

因此当前版采用 `%TEMP%` 作为应急可写路径，目的是先恢复 ERP 写入链。

### 当前判断

这条数据库路径是：

- 当前可运行
- 当前可写
- 当前用于恢复系统稳定

但它仍然属于“应急稳定方案”，不是长期最终归档方案。

## 四、当前正式健康检查

当前正式健康检查只有两个：

1. `GET http://127.0.0.1:5001/health`
2. `GET http://127.0.0.1:5001/`

对应检查脚本：

- `F:\爱牢达\scripts\check-runtime.ps1`

通过标准：

1. `/health` 返回 200
2. `/` 返回 200
3. 后端登录接口可正常返回 token
4. 最少一条写入链可成功写入并回读

## 五、运行超时规则

从当前版起，统一采用以下规则：

1. 超过 5 分钟的运行任务，直接判定为“卡住”
2. 长任务默认后台运行
3. 前台只看短结果
4. 卡住后只查：
   - 端口
   - 进程
   - 健康检查
   - 最近日志

## 六、当前真正的问题

当前不是“系统完全不能跑”，而是：

1. 正式运行链和开发辅助链并存
2. 正式数据库路径仍是应急方案
3. 多条历史脚本仍然存在，容易让人误启动到不同链路

## 七、后续唯一运行链收口顺序

1. 保持 `5001` 稳定链可用
2. 用真实业务闭环验证这条链
3. 验证通过后，再决定是否保留或降级 `启动系统.bat`
4. 最后再确定正式数据库长期落点
