# 构建产物边界与 EXE 打包白名单记录（2026-04-21）

## 背景

- 当前系统目标是先本地稳定运行，再平滑迁移到服务器部署。
- EXE / 本地壳打包时，最容易被旧 `dist` 产物、历史入口和陈旧资源误导，导致用户打开后看到旧页面、乱码页面或功能缺失页面。
- 本包目标不是换 UI，也不是改业务逻辑，而是收紧构建产物边界：只允许 `dist/index.html` 能真实引用到的资源进入当前有效产物链。

## 发现的问题

- 初次执行 `npm run audit:dist-assets` 时，发现：
  - `allAssets`: 9425
  - `referencedAssets`: 60
  - `staleAssets`: 9365
  - `missingAssets`: 0
- 这说明 `dist/assets` 内保留了大量旧构建文件。
- 虽然入口实际只引用 60 个资源，但旧资源继续留在目录里，会给 EXE 打包、人工排查和浏览器缓存判断造成假象。

## 已执行的修复

- `vite.config.ts`
  - 增加 `build.emptyOutDir = true`。
- `package.json`
  - `build` 改为先执行安全清理脚本，再执行 Vite 构建。
  - 增加 `audit:dist-assets` 入口。
- 新增 `scripts/dist-entry-asset-audit-v1.cjs`
  - 从 `dist/index.html` 出发递归解析 JS / CSS 引用。
  - 对比 `dist/assets` 中所有文件，输出：
    - 缺失资源
    - 入口可达资源
    - 陈旧资源
- 新增 `scripts/clean-dist-v1.ps1`
  - 只清理当前工作区内的 `dist`。
  - 先校验目标路径必须位于 `F:\爱牢达` 工作区内。
  - 禁止清理工作区根目录。
  - 清理后重新创建空 `dist`。
- 新增 `scripts/clean-dist-v1.cjs`
  - 保留为 Node 环境下的安全探针。
  - 如果 Node 删除后 `dist` 仍未清空，会明确失败，避免假通过。

## 为什么改用 PowerShell 清理

- 本机当前环境中，Node `fs.rmSync()` 曾返回成功，但 `dist` 实际没有被清掉。
- 继续依赖这种行为会造成“构建看似成功，旧产物仍在”的假绿。
- 因此本包采用 PowerShell `Remove-Item -LiteralPath`，并加入路径校验，保证只清理生成物目录。

## 对 EXE / 本地壳的意义

- 后续打包不能再直接相信 `dist/assets` 里“存在的所有文件”。
- 应以 `dist/index.html` 可达闭包为准。
- 若 `audit:dist-assets` 出现陈旧资源或缺失资源，不允许宣称 EXE 包稳定。
- 这能减少：
  - 打开旧页面
  - CSS 丢失
  - 图标/字体丢失
  - 乱码误判
  - 浏览器缓存与本地壳资源混淆

## 当前边界

- 本包只处理生成物边界和构建链。
- 没有删除业务数据。
- 没有清理用户上传文件、数据库、备份、历史治理文档。
- `dist` 属于可再生成产物，可以安全清理，但必须先校验绝对路径。
