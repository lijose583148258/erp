# 治理包并行执行总控矩阵 2026-04-20

## 总原则

本系统后续不再按“看到一个问题补一个补丁”的方式推进，而是按系统工程治理包执行。

固定顺序：

```text
梳理范围 -> 定义闭环 -> 审计真问题 -> 小步修复 -> 分层验收 -> 写入治理台账
```

固定闸门：

- 每个运行命令最多 5 分钟，超时即判定卡住。
- 遇到乱码默认执行“三步法”：先翻译、再判断层级、最后修复。
- 金额、库存、权限、状态类问题必须有 API/数据库/浏览器至少两层证据。
- 旧入口、旧脚本、旧控制器不能静默参与运行；不能接的要断开并标记。
- 不删除用户数据，不删除历史资料；只做隔离、标记、兼容壳或明确迁移。

## 当前已分配的 5 个子智能体

范围：

- `backend/src/controllers`

- `backend/src/validators`
- `services/*.service.ts`

- 导入导出丢字段
- 备份恢复不能证明
- 压测缺幂等对账

## 串行执行边界

这些动作不能并行乱做：

- Prisma schema / runtime DB 修复。
- 启停运行服务。
- 备份恢复演练。
- 大范围 UI 组件迁移。
- 金额、库存、权限核心逻辑修改。
- 删除、移动、隔离旧文件。

原因：这些动作会改变共同运行环境，必须由主线程按证据链串行执行。

## 并行执行边界

这些动作可以并行：

- 只读代码审计。
- 报告文件整理。
- 页面锚点缺失统计。
- API 字段差异统计。
- 旧脚本引用扫描。
- 角色权限矩阵对照。
- 导入导出字段映射对照。

## 下一步执行优先级

### P0 先修

- 调账、回款、货抵、库存、生产完工中任何会造成金额/库存/状态错误的真问题。
- 旧入口或旧脚本仍能影响当前运行的问题。
- 权限后端未拦截、AI 数据越权的问题。
- 备份恢复不能证明的问题。

### P1 紧随

- 浏览器验收缺锚点导致假失败的问题。
- 导入导出字段不完整。
- UI/i18n 切换后局部脱钩。
- 生产 BOM 复杂输入未完全 Excel 化。

### P2 后做

- 页面排版一致性。
- 文案精修。
- 报告格式美化。
- 旧文档索引增强。

## 完成定义

一个治理包只有同时满足以下条件，才算收口：

- 有明确业务闭环图。
- 有代码修改记录或明确“不需要修改”的理由。
- 有至少一条浏览器或 API 真实执行证据。
- 涉及金额/库存/状态时有数据库或后端读回。
- 有 5 分钟内完成的验证命令。
- 有治理中心记录。
