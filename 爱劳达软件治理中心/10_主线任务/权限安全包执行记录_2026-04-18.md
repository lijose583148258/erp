# 权限安全包执行记录 2026-04-18

## 本包目标

- 保证本地单机稳定运行时，订单、客户池、看板、AI 助手不会出现“页面能打开但数据越权”的假完整。
- 保证后续迁移服务器部署时，后端权限边界不依赖前端隐藏按钮，而是由 API 自身兜底。
- 保持既有 UI 风格和业务入口，不做大换皮，不删除历史文件。

## 修复内容

1. 订单创建权限收口
   - 销售只能为自己私海客户创建订单。
   - 销售不能绕过客户池规则，直接为公海客户创建订单。
   - 管理员可全局创建，经理按自身业务线或 mixed 业务线创建。
   - 非 active 客户禁止创建订单。

2. 订单修改与回款权限收口
   - 销售只能修改自己创建的 pending 订单。
   - 销售只能给自己创建的订单录入回款。
   - 经理、管理员、财务保持原有业务权限。
   - 该逻辑改为模块级纯函数，避免 Express 直接传类方法导致 `this` 丢失而返回 500。

3. 看板角色范围收口
   - 销售看板订单、客户、风险、佣金、逾期、待发货、售后按本人范围统计。
   - 销售看板不返回全局库存预警，避免通过库存预警推断生产和库存状态。
   - 经理看板保持全局形态。

4. 乱码闸门噪声清理
   - 将测试探针里的可见 `U+FFFD` 字符改成 `\uFFFD` 逃逸写法。
   - 保留乱码检测能力，但避免源码扫描误判为真实源码损坏。

5. 审计脚本增强
   - `orders-api-audit-v1.cjs` 改为先创建销售本人私海客户，再创建订单。
   - 增加销售不能给公海客户下单的断言。
   - 增加销售不能跨人修改订单、不能跨人录入回款的断言。
   - 新增 `dashboard-role-scope-audit-v1.cjs`，固定验证销售看板不暴露全局库存预警。

## 反思与纠偏

- 本包没有偏离“本地稳定运行、后续可迁移部署”的方向，因为修复点都落在后端 API 权限和可重复验收脚本，不依赖前端按钮隐藏。
- 发现并修正了一次真实误修风险：第一次把权限 helper 写成类方法，Express 路由直接传方法引用导致 `this` 丢失，脚本捕获为 500；已改成模块级纯函数，并用订单审计脚本回归。
- 本包没有删除旧文件，也没有重写 UI 风格。
- 仍需继续推进的方向：把同样的记录级权限模式扩展到 RMA 创建、样品、合同、货抵、仓储调整等高风险写入接口；并补长期并发与恢复验证，避免单次通过掩盖锁冲突或重复提交问题。
