# 成熟 ERP/CRM 对标缺口清单

日期：2026-04-17

## 结论

爱劳达 ERP+CRM 当前不是“完全不能用”，而是处在“页面和 API 多数存在，但部分业务闭环还没有成熟系统那种凭证层、状态层、权限层和对账层”的阶段。

本轮已确认：

- 仓储管理已经是独立页面，active path 为 `warehouse`。
- 默认仓库已改为幂等补齐，运行库已经真实回读 `WH-MAIN` 与 `LOC-RAW / LOC-FG / LOC-WIP / LOC-SCRAP`。
- `tsc --noEmit`、前端 build、后端 build、浏览器主验收均通过。
- PowerShell 默认输出会把 UTF-8 中文误显示成乱码，Node UTF-8 复核未发现本轮被怀疑文件的真实源码乱码。

## 对标来源

- Odoo Inventory：仓库、库位、批号、序列号、收发货、追溯报告。
- ERPNext Stock / Manufacturing：Stock Entry、Material Request、Batch、Work Order、Material Consumption、Stock Reservation。
- Zoho CRM Territory Management：区域/客户分配规则、经理权限、手动与自动分配、记录访问控制。
- Cin7 WMS：批次/效期、拣货路径、条码扫描、实时库存、补货预测、仓储绩效。

## 缺口一：库存缺少统一“库存交易凭证层”

当前状态：

- 已有 `Warehouse / Location / StockBalance`。
- 已有手动入库、库存余额读取、工单完工扣料。
- 有 `InventoryCostLedger`，但库存数量变化和成本凭证还没有完全统一。

成熟系统做法：

- ERPNext 使用 `Stock Entry` 作为统一库存移动凭证，覆盖入库、出库、调拨、生产领料、制造入库、返工、拆包。
- Odoo/Cin7 都把批次、库位、移动历史和追溯报告作为库存核心。

爱劳达缺口：

- 缺统一 `StockMovement / StockEntry` 单据。
- 缺库存移动原因枚举：采购入库、生产领料、完工入库、销售出库、退货、调拨、盘点、报废。
- 缺“库存余额 = 移动流水汇总”的对账机制。
- 缺取消/冲销/反审核机制，直接改余额后审计弱。

建议优先级：P0/P1。

## 缺口二：生产 BOM 与仓储之间仍需要更强闭环

当前状态：

- 已有化工 BOM 双行网格、Excel 粘贴、工单完工耗料确认。
- 后端已禁止无耗料记录直接完成 BOM 工单。

成熟系统做法：

- ERPNext 支持一个工单多次 Material Consumption，后续完工时按已耗料汇总。
- ERPNext 支持 Work Order stock reservation，避免同一库存被多个工单抢用。

爱劳达缺口：

- 缺工单领料/耗料的独立多次记录页面。
- 缺原料预留、释放、转 WIP、完工入成品的四段库存状态。
- 缺生产过程中的部分完工、返工、报废、损耗审批。
- 缺原料批次与成品批次的正反向追溯图。

建议优先级：P1。

## 缺口三：CRM 公海/私海已有基础，但缺成熟“区域与分配规则”

当前状态：

- 后端客户 controller 已有 `public / internal / private` 池、分配、释放、回收、转移、审计动作。
- 经理与销售的部分权限判断已经存在。

成熟系统做法：

- Zoho CRM 使用 Territory 分层、规则匹配、经理权限、自动/手动分配、账号/联系人/商机关联继承。

爱劳达缺口：

- 缺独立 Territory/业务区域模型。
- 缺客户自动分配规则：地区、行业、客户等级、来源、语言、销售线、容量。
- 缺分配冲突处理：多个销售可见、一个主负责人、协作人、经理兜底。
- 缺“回收原因、保护期、沉睡期、撞单合并”的显性规则。

建议优先级：P1。

## 缺口四：采购、供应商、仓储之间缺收货闭环

当前状态：

- 采购模块和供应商主数据已存在。
- 仓储模块有手工入库。

成熟系统做法：

- ERPNext Material Request / Purchase Receipt / Stock Entry 串起采购需求、采购订单、收货、库存。

爱劳达缺口：

- 缺采购订单到收货单的明确入口。
- 缺“部分到货、多批次到货、质检待入库、退货给供应商”的状态链。
- 缺采购入库自动生成库存移动凭证和成本凭证。

建议优先级：P1。

## 缺口五：销售、发货、回款已有链路，但缺更细三轴状态机

当前状态：

- 浏览器主验收已通过订单创建、回款录入、回款回读。
- 物流和发货页面存在。

成熟系统做法：

- 商业系统通常把订单状态拆成业务状态、履约状态、财务状态三轴，避免一个字段承载所有含义。

爱劳达缺口：

- 订单状态、发货状态、回款状态需要更明确解耦。
- 缺发货拣货单、装箱单、出库扣减、物流单号、签收回执的一条链。
- 缺部分发货、部分回款、部分退货的统一视图。

建议优先级：P1。

## 缺口六：货抵支付/换货贸易需要完整“协议-批次-抵扣-差额”模型

当前状态：

- 已有货抵模块和浏览器主验收入口。

成熟业务要求：

- 换货通常不是一次性完成，需要多批交付、多次抵扣、差额现金补齐、估值调整。

爱劳达缺口：

- 缺换货协议总额度、估值基准、交付批次、抵扣批次、剩余额度、差额现金的强约束。
- 缺每次换货的市场价快照和审批留痕。
- 缺与应收/应付/库存的对账映射。

建议优先级：P1。

## 缺口七：批量导入导出还未统一成平台能力

当前状态：

- BOM 有 Excel 粘贴。
- 部分模块有导出或 CSV。

成熟系统做法：

- 大量业务数据需要可控导入：模板、字段映射、预校验、失败行回执、重复处理。

爱劳达缺口：

- 缺统一 ImportJob / ExportJob。
- 缺导入模板版本管理。
- 缺失败行报告和回滚策略。

建议优先级：P2。

## 缺口八：权限与 AI 数据边界需要硬隔离

当前状态：

- 路由层有角色授权。
- 客户池有部分记录级权限。
- AI 模块存在，但需要继续确认是否只读当前角色可见数据。

成熟系统要求：

- AI 只能读取当前用户有权读取的数据，不能越权问答。
- 每次 AI 查询需要记录用户、范围、提示词摘要、返回摘要。

爱劳达缺口：

- 缺 AI 查询前的统一权限过滤器。
- 缺 AI 数据脱敏策略。
- 缺 AI 审计日志和敏感字段屏蔽。

建议优先级：P0/P1。

## 缺口九：验收链需要继续从“主流程”扩展到“异常和冲突”

当前状态：

- 浏览器主验收已通过。
- 生产浏览器专项脚本存在过时选择器风险。
- 并发脚本存在，但还需要覆盖更多业务闭环。

成熟系统要求：

- 不只测正常路径，还要测重复提交、网络中断、并发审批、超扣、撤销、恢复。

爱劳达缺口：

- 缺仓储专项浏览器验收脚本。
- 生产浏览器脚本需要跟随新 BOM 网格更新。
- 缺“长时运行 2 小时/8 小时”稳定报告。
- 缺数据库备份恢复后的浏览器回读证明。

建议优先级：P1。

## 下一轮最值钱执行顺序

1. 建立统一库存交易凭证 `StockMovement / StockEntry`。
2. 把采购收货、生产耗料、完工入库、销售出库全部接入库存交易凭证。
3. 为 CRM 增加 Territory/分配规则，不只靠角色和池状态。
4. 更新生产浏览器审计脚本，覆盖新 BOM 网格和完工耗料弹窗。
5. 增加仓储专项浏览器验收：建仓、建库位、入库、查库存、刷新回读。
6. 加 AI 数据边界审计：角色不可见数据不得被 AI 回答。
7. 再开始拆大文件：ProductionWorkspace、WarehouseWorkspace、customer.controller、barter.service。
