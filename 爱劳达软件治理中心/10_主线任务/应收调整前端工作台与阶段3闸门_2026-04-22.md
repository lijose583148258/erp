# 应收调整前端工作台与阶段 3 闸门_2026-04-22

## 本包目标

上一包已经把“贷项 / 折让 / 坏账 / 短款 / 汇差”从旧的 `paidAmount` 调整里拆出来，形成独立后端小闭环。本包继续补前端和验收链：

1. 财务经营工作台新增“应收调整工作台”。
2. 支持手填 + 联想选择订单，创建应收调整单。
3. 支持过账和冲回，动作后刷新财务看板。
4. 浏览器审计必须模拟真实销售建档和订单，再由财务页完成应收调整。
5. 阶段 3 总闸门纳入应收调整 API 链，避免后续改动把财务真实性打断。

## 乱码三步法结论

- 翻译意图：财务页、API 层和类型注释里需要展示的是正常中文/英文 UI 文案和错误提示。
- 判断层级：PowerShell `Get-Content` 输出曾显示乱码，但 Node 以 UTF-8 读取 `FinanceAnalyticsWorkspaceV2.tsx`、`utils/api.ts`、`types.ts`、`order.service.ts` 均为正常源码；本轮属于终端显示层误解码，不是源码损坏。
- 修复动作：不重写这些文件的中文文案，只在新增文件和触及文件里保持 UTF-8，并继续执行 `effective-source-mojibake-gate-v1.cjs`。

## 真实业务反思

- 这次没有把应收调整塞进回款弹窗，因为贷项、坏账、折让不是现金回款。
- 浏览器造数一开始被 CRM 私海规则拦截，说明客户归属规则仍在生效；脚本已改成销售创建客户和订单，再由财务页做应收调整，更贴近真实公司流程。
- 当前 UI 是第一版可用工作台，已经能覆盖创建、过账、冲回、金额回读，但还不是最终商业精修版。

## 后续建议

1. 在订单详情页增加“原应收 / 已收 / 应收调整 / 有效应收 / 未收”五段式金额卡片。
2. 在回款中心选中订单详情里展示应收调整历史，避免业务只看到回款看不到贷项。
3. 应收调整单后续可增加附件编号、审批流、会计科目、原因分类统计。
4. 如果后续接入正式财务系统，应收调整应导出为独立凭证，而不是回款凭证。
