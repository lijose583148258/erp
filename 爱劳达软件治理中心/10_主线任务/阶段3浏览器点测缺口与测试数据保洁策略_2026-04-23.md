# 阶段3浏览器点测缺口与测试数据保洁策略_2026-04-23

## 目的

当前后端链路和稳定包来源已经有较强证据，但浏览器逐页人工证据仍不完整。此文件固定下一轮点测和测试数据保洁规则，避免两个问题：

| 问题 | 风险 |
| --- | --- |
| 只看 API 通过 | 页面仍可能出现按钮脱钩、CSS 丢失、状态 undefined、语言切换失效 |
| 直接清理测试数据 | 可能误删真实业务数据或破坏审计证据链 |

## 浏览器点测总规则

| 规则 | 要求 |
| --- | --- |
| 入口 | 只使用 `http://127.0.0.1:5001/` |
| 来源 | 点测前先跑 `stable-package-origin-audit-v1.cjs` |
| 时间 | 单个脚本或动作超过 5 分钟判定卡住，不继续等待 |
| 截图 | 每个页面至少保留进入页、保存前、保存后、刷新回读四类截图 |
| 控制台 | 每页记录 console error、network failed、页面崩溃 |
| 语言 | 中文、英文、越南文至少抽样验证核心按钮和状态文案 |
| 乱码 | 遇到乱码先三步法：翻译意图、判断层级、只修对应层 |
| 回读 | 所有新增、修改、审批、核验、入库、出库都必须刷新后回读 |
| 权限 | 管理员、经理、业务、财务、仓库至少抽样验证可见性 |
| 数据 | 测试数据必须使用前缀，便于审计和保洁 |

## 已存在探针数据识别

| 前缀/特征 | 来源 | 处理原则 |
| --- | --- | --- |
| `runtime-write-` | 写入重启读回审计 | 暂不删除，先纳入审计证据 |
| `runtime-backup-` | 写入备份恢复读回审计 | 暂不删除，先纳入审计证据 |
| `auth_lifecycle_` | 账号生命周期审计 | 暂不删除，先确认是否为测试账号 |
| `BOM-`、`WO-`、`CHEM-` | 化工 BOM 与生产链审计 | 暂不删除，需按工单和库存联动核对 |
| `audit-` 或报告时间戳 | 审计脚本生成数据 | 暂不删除，先建立干跑清单 |

## 保洁策略

| 阶段 | 动作 | 是否允许改库 |
| --- | --- | --- |
| 1 | 只生成测试数据清单，按表、前缀、创建时间、关联链列出 | 否 |
| 2 | 对清单做白名单确认，区分真实业务数据、审计证据数据、可清理测试数据 | 否 |
| 3 | 清理前创建稳定库备份和业务表指纹 | 否 |
| 4 | 仅清理白名单内的测试数据，禁止按模糊中文名批量删除 | 是，但必须有备份 |
| 5 | 清理后跑数据库完整性、业务指纹、核心 API 回读、稳定包来源 | 是 |

## 禁止动作

| 禁止项 | 原因 |
| --- | --- |
| 直接删除 `D:\AilaoDaRuntime\stable.db` 内数据 | 可能破坏真实业务和审计证据 |
| 通过中文名称模糊删除客户或供应商 | 跨国公司多名场景可能误伤 |
| 删除没有完整外键追踪的数据 | ERP 数据链不是单向，可能影响财务、库存、审计 |
| 只清主表不清子表 | 会产生孤儿数据或报表漂移 |
| 没有备份就做清理 | 无法回滚 |

## 下一轮浏览器验收顺序

| 顺序 | 模块 | 原因 |
| --- | --- | --- |
| 1 | 登录、语言、角色、退出 | 入口不稳，后续所有点测都会误判 |
| 2 | CRM 客户建档 | 主数据是订单、回款、发货、AI 权限的上游 |
| 3 | 供应商与采购 | 采购右侧表单和仓储入库关联是高频操作 |
| 4 | 销售订单与回款 | 金额链路风险高，必须真实输入和回读 |
| 5 | 仓储库存 | 库存是采购、生产、发货的共同底座 |
| 6 | 生产 BOM | 化工配方 10 原料和代号保密输入复杂度最高 |
| 7 | 货抵支付 | 分批抵扣和金额等值交换接近回款，需要并发与余额证明 |
| 8 | 发货/RMA | 文件上传、回单和差异处置容易出现 UI 脱钩 |
| 9 | 财务分析 | 口径必须来自业务链，不允许假完整 |
| 10 | 备份恢复与 AI 隔离 | 属于上线前安全底线 |
