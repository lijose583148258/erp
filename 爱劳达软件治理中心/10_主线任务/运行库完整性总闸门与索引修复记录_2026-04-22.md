## 本轮发现的问题

### 1. 原 schema 审计存在假绿风险

- 旧实现只读取 `backend/prisma/schema.prisma`。
- 当前项目已使用 Prisma `prismaSchemaFolder`，真实模型在 `backend/prisma/models/*.prisma`。
- 风险：如果只扫入口 schema，可能漏掉客户、订单、采购、生产、仓储、回款等业务表，导致 schema 漂移没有被发现。
- 修复：`backend/src/database/runtime-schema-audit.ts` 改为扫描入口 schema 与 `models` 目录，共 9 个 schema 文件。

### 2. 当前运行库存在真实索引缺项

- 新闸门首次运行发现：
  - `audit_logs_action_idx`
  - `audit_logs_resource_idx`
  - `audit_logs_resource_resource_id_idx`
- SQLite `integrity_check` 返回 42 条 `row ... missing from index ...`。
- 外键检查为 0，说明业务关系未发现外键破损。
- 该类问题属于索引结构异常，不是业务表数据删除。

## 修复原则

- 不删除任何用户数据。
- 不直接清空日志表。
- 不使用 `git reset`、`checkout --` 或破坏性文件操作。
- 先备份，再修复。
- 只在完整性信息确认是“索引缺项”时自动执行 `REINDEX`。
- 如果出现非索引类损坏，修复脚本会拒绝自动处理，避免扩大损失。

参考依据：

- SQLite 官方 `PRAGMA integrity_check` 文档说明该检查会发现缺失索引项等数据库问题。
- SQLite 官方 `REINDEX` 文档说明该命令会删除并重新创建索引。

## 新增脚本

- `scripts/runtime-db-integrity-audit-v1.ts`
  - 只读检查运行库。
  - 检查 DB 文件存在、大小、路径边界。
  - 执行 `PRAGMA integrity_check`。
  - 执行 `PRAGMA foreign_key_check`。
  - 调用 Prisma schema 审计，确认表/列不漂移。
  - 检查关键业务表存在。
  - 报告历史影子 DB 文件，但 P2 不阻断。

- `scripts/runtime-db-reindex-repair-v1.ts`
  - 写入前自动备份。
  - 仅当损坏信息全部为索引缺项或索引条目数异常时才执行 `REINDEX`。
  - 修复后再次运行 `integrity_check`。
  - 修复不通过则退出失败。
