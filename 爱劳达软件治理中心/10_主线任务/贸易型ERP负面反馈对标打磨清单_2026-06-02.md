# 贸易型 ERP 负面反馈对标打磨清单（2026-06-02）

## 外部负面反馈归纳

1. 数据迁移和主数据质量被低估，脏客户、脏供应商、错误库存和错误成本会让报表、库存和财务对账失信。
2. 培训和变更管理不足，员工不知道差异是系统问题、数据问题还是自己操作问题，最终回到 Excel。
3. ERP 功能堆砌但流程职责不清，审批、库存、应收、售后、采购之间没有端到端闭环。
4. 高频作业 UI 复杂，表格密度差，移动端/触屏操作困难，错误提示不能指导下一步。
5. 报表和看板如果不按真实业务链路和数据范围生成，会变成“漂亮但不可决策”的展示层。

## 当前系统已收口项

1. 账号安全：请求鉴权回查用户启用状态、当前角色和数据范围；改密后旧 access token 与 refresh token 失效。
2. 高频表格：DataTable/EnterpriseDataGrid 操作列常显；搜索可识别 JSX 文本；导入失败给可见错误提示。
3. 移动作业：采购收货、发货签收抽屉的小屏布局降为 1-2 列，避免数字输入被挤压。
4. 诚实状态：商业运营面板标注为运营待办与提醒工作台，不宣称已自动反写订单、采购、库存或财务。
5. 术语文案：回款、货抵、签收差异、供应商空态等高频错误提示逐步中文化并指向下一步动作。

## 仍需作为 P0/P1 继续打磨

### P0：真实业务闭环

- RMA 仍偏“售后工单”，未同事务接退货入库、换货出库、退款/应收调整、差异案关闭。
- commercial workflow 仍是待办壳，未建立 `documentType -> domain service -> permission -> post action` 适配器。
- 收发差异 action 需要副作用矩阵：只登记、审批、真实过账必须区分命名和状态。

### P1：数据可信与迁移

- 需要主数据清洗入口：客户/供应商/商品/批次重复检测、缺失字段检测、导入前预检、导入后回读对账。
- 需要库存可信面板：账面库存、批次库存、流水汇总、异常差异、最近一次盘点时间统一展示。
- 需要迁移演练脚本：迁移前后客户数、供应商数、SKU 数、库存余额、应收余额、订单余额逐项对账。

### P1：用户采用

- 需要按岗位的新手任务流：销售开单、仓管收发、财务核销、采购收货、售后处理。
- 高频页面要提供“下一步”错误提示，而不是只返回参数错误或状态错误。
- 对移动端仓库/PDA/iPad 场景继续做点按尺寸、输入密度、固定操作入口验证。

### P2：经营决策

- BI 看板必须基于已验证的读模型或宽表，且必须带数据范围。
- 预警需要闭环：预警生成、责任人、处理动作、关闭原因、审计日志。
- 不允许用演示指标填充未接真实数据的经营页面。
