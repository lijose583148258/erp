# 当前问题与回正说明

## 结论

当前系统的主要问题，不是编译失败，也不是主链路明显断裂，而是**推进重点曾经偏向了细节清洗**，导致包级治理的优先级被稀释。

## 现阶段真实问题

### 1. 推进方向偏航

- 之前有一段时间把大量精力放在了三语显示、名称 fallback、局部展示统一上。
- 这些工作本身没有错，但它们属于细节治理，不应该压过包级主线。
- 结果是，包级任务看似很多都“做了”，但真正需要确认的风险点没有被持续盯住。

### 2. 运行验证还不够硬

- `npm run build` 和 `npm run build:backend` 已通过，说明主运行链路没有被打坏。
- 但浏览器级 smoke test 没有真正跑顺，当前环境对 dev / preview 存在限制。
- 所以不能把“构建通过”等同于“上线无风险”。

### 3. 交付体积仍偏大

- 前端打包仍有明显的 chunk 体积警告。
- 这说明代码拆分和按需加载还不够干净，后续维护和首屏性能仍有优化空间。

### 4. 仓库可追溯性弱

- 当前工作区不是标准 Git 仓库，缺少稳定的 diff / branch / commit 追踪。
- 这会放大回看和回滚成本，也会让“到底改了什么”不够透明。

### 5. 文档和代码还有历史遗留

- 治理中心原始文档曾存在编码损坏。
- 目前已经有“当前版”入口，但旧文档仍然存在，后续不建议继续在这些历史残留上做细碎修补。

## 现在应该怎么回正

1. 停止继续做碎片化的字符串 / 字段清洗。
2. 重新按包检查：每个包到底是否真的闭环。
3. 把风险优先级放回主线：
   - 运行稳定性
   - 浏览器冒烟验证
   - 模块边界
   - 体积与拆分
4. 只有在包级风险稳定后，再做细节治理。

## 当前建议顺序

1. 先做一次包级风险复核。
2. 再补一轮关键入口的浏览器冒烟检查。
3. 最后才考虑继续做名称、文案或展示层的统一。
