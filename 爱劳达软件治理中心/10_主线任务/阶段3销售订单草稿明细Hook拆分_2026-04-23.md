# 阶段3销售订单草稿明细 Hook 拆分_2026-04-23

## 背景

阶段 3 架构收口继续推进时，销售订单主 Hook `pages/sales-orders/useSalesOrders.ts` 仍承担页面总控、草稿状态、明细行编辑、OCR、导入、保存、付款和收款动作编排等职责。该文件已经经过一轮拆分，但仍是后续维护容易重复出错的位置。

本轮先处理风险最低、收益明确的职责：订单草稿与明细行编辑。

## 三步法复核

| 步骤 | 结论 |
| --- | --- |
| 翻译/识别 | PowerShell 读取时出现 `璇烽...` 等疑似乱码。 |
| 判断层级 | Node 按 UTF-8 直接读取后，源码中文为正常文本，如“请先粘贴 Excel 行数据”“订单保存失败”。这是终端显示层误解码，不是源码损坏。 |
| 修复动作 | 不改文案，不重写文件；仅做结构拆分，并继续跑有效源码乱码闸门。 |

## 本次改动

| 文件 | 作用 |
| --- | --- |
| `pages/sales-orders/useSalesOrderDraft.ts` | 新增草稿与明细编辑 Hook，集中管理 `formData`、`draftAvailable`、金额汇总、明细增删改、Excel 明细粘贴导入、草稿加载和清理。 |
| `pages/sales-orders/useSalesOrders.ts` | 移除草稿/明细编辑重复状态和函数，继续保留外部 `useSalesOrders()` 返回契约，避免页面消费层大改。 |

## 边界

本轮没有移动以下高风险逻辑：

- 订单保存 `handleSaveOrder`
- 编辑详情拉取 `openEditModal`
- OCR / AI 扫描
- 付款登记与核验
- 收款动作弹窗
- 发货跳转
- 权限判断

原因：这些逻辑跨 API、当前用户、选中订单、客户列表、弹窗状态和账款状态，适合后续单独包处理。
