# 跨模块记录级权限包执行记录 2026-04-18

## 本包目标

- 把订单模块已经验证过的“客户归属 + 记录归属”权限原则扩展到 RMA、样品、合同。
- 防止出现“列表过滤了，但通过 ID 直接创建、查看、修改、追加仍可越权”的典型 ERP 漏洞。
- 用共享工具降低后续维护成本，避免每个控制器各写一套权限判断。

## 修复内容

1. 新增共享权限工具
   - 文件：`backend/src/utils/recordAccess.ts`
   - `canUseCustomerForBusinessWrite`：统一判断客户是否允许被当前角色用于业务写入。
   - `canSalesWriteOwnedRecord`：统一判断销售是否只能操作自己创建/申请的记录。

2. RMA 售后权限收口
   - 创建 RMA 前先确认客户存在、客户 active、当前角色有权为该客户写入。
   - 销售不能为公海客户或非本人私海客户创建售后。
   - 处理 RMA 前先确认记录存在，避免不存在记录返回 500。

3. 样品权限收口
   - 创建样品前先确认客户存在、客户 active、当前角色有权为该客户写入。
   - 样品状态更新增加角色限制：仅 `admin / manager / warehouse / sales`。
   - 销售只能更新自己申请的样品，不能更新经理或他人创建的样品。

4. 合同权限收口
   - 销售合同列表只显示自己私海客户合同。
   - 销售通过 ID 访问非本人私海客户合同详情时返回 404，避免暴露记录存在性。
   - 创建合同前校验客户存在、active、客户归属权限。
   - 销售只能更新/追加自己创建且客户仍属于自己私海的合同。
   - 经理按业务线权限写合同，管理员全局。

5. 订单模块复用共享权限工具
   - 订单创建的客户归属判断切换到 `recordAccess.ts`，减少重复逻辑。

## 反思与纠偏

- 本包没有改 UI 风格，也没有大拆文件，只把高风险写入链路补上后端兜底。
- 这次选择“共享权限工具”是为了减少补丁化趋势，后续合同、样品、售后、订单共用同一判断入口，维护成本更低。
- 仍需继续推进：货抵、资产、调账、出货、采购关联销售订单等模块还需要同样做记录级权限和状态机审计，尤其是涉及库存、金额、过账、冲销的接口。
