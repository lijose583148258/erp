# 爱劳达 ERP+CRM 产品蓝图与分包执行台账

日期：2026-05-04

## 0. 主控结论

爱劳达不是通用 SaaS，也不是照搬大型 ERP。它应该做成一套面向中国/越南跨境中小企业的本地优先 ERP+CRM：

- 操作手感接近中国中小企业软件：开单、明细表、审核、反审核/冲销、往来账、库存流水、老板看板。
- 业务场景贴近越南靠近中国的贸易环境：中/越/英三套名称，多地址、多联系人，CNY/VND/USD，多仓库，多物流节点，货抵贸易，分批回款。
- 行业能力贴近胶水、树脂、涂料等化工生产：配方/BOM、10 种以上原料、原料代号保密、损耗、替代料、批次、成本台账。
- 运行目标是 Win10 本地稳定试跑两个月，后续可迁移服务器。

后续所有修改必须先回答四个问题：

1. 这个页面录入什么业务对象？
2. 保存后生成什么单据、流水或台账？
3. 它影响库存、财务、客户、权限、审计中的哪条链？
4. 完成后怎样回读证明没有丢数据？

## 1. 软件特点蓝图

### 1.1 产品定位

爱劳达是“跨境贸易 + 化工生产 + CRM 客户池 + 进销存财务闭环”的本地优先系统。

它不追求一开始覆盖所有大型 ERP 功能，而是优先把高频业务做到顺手、稳定、可审计：

- 客户从公海、内部池、私海流转到订单。
- 销售订单进入发货、回款、应收。
- 采购单进入收货、入库、供应商往来。
- 化工 BOM 进入工单、领料、完工、成品入库。
- 仓储所有库存变化都有流水。
- 货抵协议支持分批交付、分批抵扣、过账、冲销。
- 权限、AI、审计、备份恢复默认作为底座，不作为后补功能。

### 1.2 主要用户

| 角色 | 主要工作 | 不应越权 |
| --- | --- | --- |
| 超级管理员 | 组织、角色、权限、规则、全局审计 | 日常替业务人员开单 |
| 经理 | 客户分配、客户收回、审批、团队看板 | 绕过审计直接改历史归属 |
| 销售 | 客户跟进、销售订单、回款登记、样品/RMA 发起 | 看全局客户、核验自己回款 |
| 财务 | 回款核验、应收调整、货抵过账、账龄、现金流 | 改仓库实物、改客户池 |
| 仓库 | 入库、出库、调拨、签收、库存流水 | 财务核销、客户归属 |
| 采购 | 供应商、采购单、分批收货、采购差异 | 销售客户池、销售回款 |
| 生产 | 配方/BOM、工单、耗料、完工、批次 | 财务调账、普通库存主调拨 |
| AI 助手 | 当前权限内总结、提醒、格式化、风险提示 | 绕过权限读取不可见数据 |

## 2. 主业务闭环

| 闭环 | 起点 | 关键对象 | 终点 |
| --- | --- | --- | --- |
| CRM 客户闭环 | 线索/导入客户 | 公海、内部池、私海、联系人、地址、归属事件 | 可审计客户资产 |
| 销售到回款闭环 | 客户下单 | 销售订单、订单明细、回款记录、争议、核验 | 应收减少，订单财务状态更新 |
| 采购到入库闭环 | 采购需求 | 供应商、采购单、收货批次、差异、入库凭证 | 库存增加，采购状态更新 |
| 生产到成品闭环 | 配方/BOM | BOM、工单、领料、质检、完工、批次 | 原料扣减，成品入库，成本记录 |
| 仓储库存闭环 | 入库/出库/调拨 | 仓库、库位、库存余额、库存流水 | 库存可追溯，不允许负库存 |
| 发货签收闭环 | 销售订单待发货 | 发货单、物流、OCR、POD、签收凭证 | 订单履约状态、库存扣减、签收回执 |
| 货抵结算闭环 | 货抵协议 | 协议、批次、估值、抵扣、过账、冲销 | 应收、库存、财务台账一致 |
| 治理恢复闭环 | 运行系统 | 权限、审计、备份、恢复、稳定包、AI 隔离 | 可验证、可恢复、可迁移 |

## 4. 复杂页面统一设计

复杂页面不再允许把“建档、开单、审核、分析、台账、导出”堆在同一区域。后续只允许四种页面形态：

| 页面类型 | 用途 | 允许内容 | 禁止内容 |
| --- | --- | --- | --- |
| 工作台 | 看今天要做什么 | KPI、待办、风险、常用入口 | 大量编辑表单 |
| 列表页 | 找对象 | 搜索、筛选、状态、批量动作 | 多对象混表、复杂新建 |
| 对象页 | 看/改一个对象 | 主数据、明细、状态、相关记录、审计 | 无关对象的新建入口 |
| 动作页/弹窗 | 执行一次动作 | 本次动作字段、影响预览、确认按钮 | 主数据维护、历史大列表 |

### 4.1 高频输入模式

销售订单、采购单、BOM 明细、仓储调拨必须逐步变成：

```text
单据头表单 -> 明细 Excel 网格 -> 底部保存/提交/审核 -> 保存后回读证据 -> 台账可查
```

### 4.2 明细网格规则

- 支持手填、联想、编码搜索、名称搜索。
- 支持复制粘贴多行。
- 行级错误必须定位到具体行列。
- 保存前显示数量、金额、行数、库存影响。
- 保存后必须回读单号、明细条数、状态、相关台账。

### 4.3 高级字段规则

- 首屏只放高频字段。
- 贸易条款、扩展备注、附件、审计、内部控制字段默认折叠。
- 客户/供应商详情采用“主数据 / 地址 / 联系人 / 归属池 / 审计”五区块。

## 8. 每包固定验收制度

每包执行完必须通过以下顺序，不允许只看 build：

1. L0：确认问题层级和业务对象。
2. L1：`npx tsc --noEmit --pretty false`。
3. L1：`npm run build`。
4. L1：源码乱码闸门。
5. L2：运行入口检查，必须是 `http://127.0.0.1:5001`。
6. L3：目标模块 API 回读。
7. L3：目标模块浏览器点测。
8. L3：保存后刷新回读，不丢数据。
9. L4：涉及库存/金额/权限/备份时跑对应专项审计。
10. L5：如果声称可试跑，必须跑每日治理和稳定包审计。

所有命令默认 5 分钟上限。超过 5 分钟必须判定卡住并记录原因。

## 9. 多智能体执行规则

多智能体可以用于并行审计和分包实施，但主控不得直接信任子任务报告。

- 子智能体负责发现问题、提出补丁、实现小范围文件。
- 主控负责检查 diff、跑完整链路、判断是否合并进主线。
- 涉及钱、库存、权限、备份、AI 隔离的包必须主控复跑。
- 不允许多个智能体同时改同一个文件或同一领域状态机。
