# 包级风险优先级清单（当前版）

## 结论

当前系统的主要问题不是“功能没有做完”，而是**包级主线已经写成完成，但运行验证、交付可追溯性和前端体积控制仍有风险**。

## P0：立刻影响运行 / 上线

### 1. 浏览器级冒烟验证未完成

- 目前 `npm run build` 与 `npm run build:backend` 都已通过。
- 但 dev / preview 在当前环境里没有完成稳定的浏览器级冒烟验证。
- 这意味着“能编译”不等于“真实页面已充分验证”。

**影响**
- 上线前的最后一道真实体验检查还不完整。
- 关键入口、弹层、表格与状态切换仍需要真实浏览器确认。

**当前动作**
- 优先补关键入口冒烟，而不是继续做细节统一。

### 2. 前端打包体积偏大

- 构建仍有明显 chunk 体积警告。
- 这通常意味着：
  - 页面拆分还不够
  - 按需加载还不够细
  - 初始加载压力仍偏大

**影响**
- 首屏性能和后续维护都可能受影响。
- 后面再加功能时，体积风险会继续积累。

**当前动作**
- 暂时停止继续做碎片化字段清洗。
- 先把最重页面的加载边界和懒加载策略补清楚。

### 3. 仓库缺少标准 Git 追溯

- 当前工作区不是标准 Git 仓库。
- 缺少稳定的 diff、branch、commit 追踪。

**影响**
- 回看成本高。
- 回退成本高。
- 容易出现“改了什么说不清”的维护风险。

**当前动作**
- 尽快恢复可追溯仓库结构，至少要有可回看、可分支、可回滚的基础能力。

## P1：会影响后续维护 / 推进效率

### 4. 推进重点曾偏向细节清洗

- 近期大量精力投入到三语显示、fallback、单语残留统一。
- 这些工作有价值，但不应压过包级主线。

**影响**
- 容易让“做了很多”替代“真的收口了”。
- 让治理节奏偏散。

**当前动作**
- 先停细节清洗。
- 回到包级复核和风险验证。

### 5. 旧文档与当前版入口并存

- 当前版治理入口已经建立。
- 但历史文档仍然存在，且早期有编码损坏背景。

**影响**
- 新旧口径容易并存。
- 后续查阅容易混淆“历史说明”和“当前执行口径”。

**当前动作**
- 以后只用“当前版”入口推进。
- 历史文档仅作归档，不再继续修补。

## P2：只是美化治理 / 可后置

### 6. 三语名称的进一步统一

- 三语公司名、客户名、供应商名大部分已经贯通。
- 剩余点位属于展示优化，不影响主链路运行。

**影响**
- 主要是视觉一致性和局部体验。

**当前动作**
- 只在真实业务必要处补，不再作为主要工作。

### 7. AI / BI 细化和报表增强

- 这些属于扩展层。
- 不应抢占主线收口资源。

**当前动作**
- 等主线风险稳定后再推进。

## 当前建议顺序

1. 先补浏览器级冒烟验证。
2. 再处理前端体积与拆分边界。
3. 再恢复可追溯的 Git 结构。
4. 在此之前，停止继续做细节清洗。

## 当前执行原则

- 先风险，后美化。
- 先验证，后统一。
- 先主线，后扩展。
- 细节工作只做必要项，不再单独开新波次。
