# 全局结构与系统治理执行蓝图

## 当前产品边界

- 当前稳定形态：单租户、SQLite、本地或单服务器部署。
- 当前不承诺：多租户 SaaS、PostgreSQL 主从、多实例会话、正式通用审批引擎。
- 禁止用 `segment` 或销售数据范围冒充租户隔离。
- Commercial Workflow 当前只作为辅助待办，未完成事务、指派校验和业务单据联动前，不作为正式审批依据。

## P0 全局规则

1. 权限以数据库角色状态和权限清单为准；角色停用、清空权限必须立即生效，不允许代码默认权限回退。
2. 所有内部 API 请求统一经过 `utils/api.ts` 和领域 service；组件、页面不得自行拼 Token。
3. 页面活动入口以 `app/activePathRegistry.ts` 为加载权威源；导航、权限和活动入口必须通过一致性门禁。
4. Phase 3 必须前置后端编译和运行包来源验证，不能只验证前端或旧 `dist`。
5. 金额、库存、状态、权限改动必须同时完成 API 回读和浏览器回读。
6. 源码区只保留一个当前稳定包和一个回滚包；运行数据、发布产物、历史归档不得继续无上限堆积。

## 目录职责

- `app/`：应用壳、上下文、活动页面注册、前端权限。
- `components/ui/`：无业务含义的共享控件。
- `components/`：应用级共享组件；禁止新增领域专用业务面板。
- `pages/<domain>/`：领域页面、领域 hooks、领域展示组件。
- `services/`：前端领域 API 适配；一个服务只服务一个领域。
- `backend/src/controllers/`：HTTP 参数和响应边界，不承载核心状态机。
- `backend/src/services/`：领域事务和业务规则。
- `scripts/`：验证与运维；不得成为业务逻辑的第二实现。
- `runtime-data/`、`logs/`、`output/`：运行或验证产物，不属于活动源码。

## 渐进重构规则

- 不批量移动根目录到 `src/`，先建立兼容导出和路径门禁。
- 不直接删除 `DataTable`；冻结新增调用，逐步改造成 `EnterpriseDataGrid` 兼容包装层。
- 不为拆分而拆分金额、库存和状态机服务；先补唯一约束、事务和对账门禁。
- `BarterWorkspaceView.tsx`、`WarehouseWorkspace.tsx` 及两个大型浏览器审计按领域职责渐进拆分，每次只拆一个稳定边界并完成全链回归。

## PostgreSQL 与 SaaS 重构前置条件

1. 所有核心模型加入 `tenantId`，唯一键改为租户复合唯一键。
2. 建立 `TenantContext`，覆盖身份、权限、审计、主数据和交易表。
3. 金额由 `Float` 迁移为 Decimal/Numeric 或最小货币单位整数。
4. 库存来源建立数据库唯一约束，消除“先查后写”的并发窗口。
5. Refresh Token、令牌撤销和会话改为持久化共享存储。
6. 建立独立 PostgreSQL schema、导入、校验、回滚和对账链；现有 JSON 导出脚本不能视为迁移方案。
7. 备份与平台管理员连接必须明确 RLS 绕过和完整性验证策略。

## 前端统一标准

- 标准密度为默认；紧凑模式由用户显式开启。
- 移动端顶部只保留当前模块和必要入口，其余设置进入移动菜单。
- 粗指针设备交互目标最小高度 44px。
- 不依赖 Hover 暴露关键操作。
- 关键金额使用不换行、等宽数字和稳定列宽。
- 翻译统一采用目标语言、中文、键名的单一回退规则；共享组件不得写死业务语言。

## 验收顺序

1. 前后端编译。
2. 权限、账号生命周期和模块注册一致性。
3. 金额、回款、库存、生产成本和财务汇总对账。
4. 浏览器核心页面、语言、主题、移动端和业务职责边界。
5. 备份恢复、重启持久性、纯净包来源和最终打包。
