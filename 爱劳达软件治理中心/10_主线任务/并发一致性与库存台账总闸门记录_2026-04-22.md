# 并发一致性与库存台账总闸门记录 2026-04-22

## 结论

本包把两个原本偏治理包性质的检查提升到主线验收：

- `concurrency-consistency-audit-v1.cjs`
- `stock-ledger-reconcile-audit-v1.cjs`

它们分别覆盖：

- 多次写入、长读循环、订单 / 客户关键字段不漂移。
- 库存凭证、库存移动、余额、默认仓库 / 库位、幂等 sourceRef 不重复。

## 为什么要做

ERP 系统最怕的不是页面报错，而是：

- 用户重复点击后金额多记。
- 回款或货抵部分写入成功，另一半没有闭环。
- 出入库凭证重复生成。
- 默认仓库 / 库位丢失。
- 报表看起来正常，但库存台账与余额暗中漂移。

这些问题不是 TypeScript、构建或 HTTP 200 能发现的，所以必须进入 Phase 3 和 Release 总闸门。

## 验收目标

- `npm run audit:concurrency:consistency` 必须通过。
- `npm run audit:stock:ledger` 必须通过。
- `npm run verify:phase3` 必须包含这两个步骤。
- `npm run verify:release` 必须包含这两个步骤。
- 每个步骤仍然受 5 分钟上限控制，超过即判定卡住。

## 后续规则

后续只要涉及订单、回款、货抵、采购、发货、生产、仓储任一写入链路，都不能只跑功能 API。

必须至少补一层：

- 并发重复提交。
- 写后读回。
- 关联台账对账。
- 备份恢复后读回。
