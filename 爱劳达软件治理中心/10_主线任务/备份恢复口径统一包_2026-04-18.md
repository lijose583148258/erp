# 备份恢复口径统一包 2026-04-18

## 目标

解决同一系统在不同启动目录下看到不同备份目录的问题。

之前现象：

- 后端服务从项目根启动时，备份目录是 `F:\爱牢达\backups`。
- `npm --prefix backend run db:status` 从 `backend` 目录执行时，备份目录变成 `F:\爱牢达\backend\backups`。
- 这会造成“明明有备份，但状态显示 0”的假红，也会影响本地长跑和后续服务器迁移。

## 修改内容

### 1. 固定运行路径解析

修改文件：

- `backend/src/config/runtime.ts`

新增项目根路径解析规则：

- 相对路径不再基于 `process.cwd()`。
- 相对路径统一基于 `projectRoot`。
- 绝对路径仍按用户指定绝对路径执行。

影响字段：

- `backupDir`
- `logDir`
- `uploadDir`
- `frontendDistDir`

当前默认结果：

- 备份：`F:\爱牢达\backups`
- 日志：`F:\爱牢达\logs`
- 上传：`F:\爱牢达\uploads`
- 前端 dist：`F:\爱牢达\dist`
- 运行库：`D:/AilaoDaRuntime/stable.db`

### 2. 精准重启后端

没有使用 `scripts/stop-runtime.ps1`。

原因：

- 该脚本会停止多个端口，甚至停止所有 Node 进程。
- 当前机器存在无关 `F:\智仔` 进程，不能误杀。

本轮只停止 5001 上的爱劳达后端旧进程：

- 旧 PID：`3816`
- 新后端进程：`node backend/dist/server.js`

## 乱码三步法记录

### 发现

PowerShell `Get-Content` 显示 `backup-restore-api-audit-v1.cjs`、`manage-db.ts`、`system.controller.ts` 部分中文像乱码。

### 判断

使用 Node UTF-8 读取验证：

- `scripts/backup-restore-api-audit-v1.cjs` 源码中文正常，语法正常。
- `backend/src/database/manage-db.ts` 源码中文正常，TypeScript 转译解析正常。
- 当前未发现 `�` 替换符。

结论：

- 这是终端显示层编码问题，不是源码损坏。
- 本轮不重写这些文件。

## 当前结论

备份恢复口径已经统一，CLI、API、服务启动后的运行时口径一致。

可以支撑后续：

- 本地单机长跑。
- EXE 壳固定路径。
- 服务器部署迁移前备份。
- 线上迁移失败后回滚。

## 剩余风险

1. 还没有做“恢复到历史旧备份后再恢复回最新备份”的双向演练。
2. 还没有做备份文件损坏、缺失、路径穿越、非法文件名的安全测试。
3. 还没有做长时间运行下自动备份策略，例如每天启动前自动备份、每晚自动备份。
4. 还没有把备份状态在前端系统设置页做成清晰可见的运维面板。
