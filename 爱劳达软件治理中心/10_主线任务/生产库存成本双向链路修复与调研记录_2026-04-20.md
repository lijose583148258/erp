# 生产库存成本双向链路修复与调研记录 2026-04-20

## 结论

本轮把生产 BOM 的验证口径从“能完工、库存数量变化”提升到“原料批次、库存凭证、成本台账、成品批次价值”同时读回。

成熟 ERP 的生产库存链不是单向的：

- 正向链：原料入库 -> 批次价值层 -> 工单领料/消耗 -> 成品入库 -> 成品批次成本。
- 反向链：成品批次/客户问题 -> 工单 -> 原料批次 -> 入库来源/供应商/价值层。
- 财务链：库存余额不是直接改数，必须由库存凭证和成本台账推导；调整和冲销也应形成反向凭证，而不是覆盖旧记录。

## 调研依据

- Odoo 19 文档强调按批次/序列号做库存估值，可比较采购成本，并基于实际使用组件追踪制造品实际成本。
- Odoo 批次文档说明批次用于追踪产品从接收、存储、生产到发货的生命周期。
- ERPNext 文档说明工单可产生多次物料消耗 Stock Entry，完工时要同时考虑已消耗数量。
- ERPNext Stock Ledger 文档说明采购、制造、销售、转仓等出入库都记录在库存台账，包含数量、价值、物料、仓库。
- ERPNext Batch 文档说明批次物料每次库存交易都要带批次号。
- Dynamics 365 Supply Chain 文档说明库存关闭会把发出交易和接收交易匹配结算，并按库存估值方法影响财务报表。
- SAP Global Batch Traceability 示例说明生产订单同时关联原料批次发料和成品批次收货，形成网络化追溯。

## 本轮修复

1. 成本台账从工单一对一改为一对多。
   - 旧问题：`work_order_id` 唯一索引导致同一工单只能保留一条成本台账。
   - 修复：删除唯一约束，改为普通索引，运行库 repair 已生效。

2. 库存入库同步 ProductBatch。
   - 旧问题：仓库手工入库有 StockBalance，但没有 ProductBatch，生产扣料时无法写成本台账。
   - 修复：`warehouse_initial`、`warehouse_manual_inbound`、`warehouse_adjustment`、`procurement_receipt` 会同步批次主记录。

3. 生产扣料禁止静默跳过。
   - 旧问题：找不到 ProductBatch 时直接跳过，造成库存已扣但成本台账缺失。
   - 修复：缺少批次时直接抛错，阻止假完工。

4. 入库支持单位成本。
   - 旧问题：数量链闭合但金额全为 0。
   - 修复：手工入库可传 `unitCost` / `costAmountDelta`，生成原料批次价值层。

5. 完工成本反向汇总到成品。
   - 旧问题：成品批次只有数量，没有吸收原料成本。
   - 修复：先记录原料消耗成本，再把原料成本合计写入成品批次成本台账。

6. 新增工单成本链审计脚本。
   - `scripts/audit-work-order-ledgers-v1.cjs`
   - 用于读取指定工单的库存凭证、库存流水、成本台账和关联批次，避免浏览器/API 单点假绿。

## 仍需继续治理

1. 当前价值链是“单位成本手填/接口传入”的最小闭环，后续要接采购入库、采购发票、运费/关税/杂费分摊，形成更真实的到岸成本。
2. 成本台账的 `source_type` 目前仍复用 `production_completion` 区分正负数量，后续建议拆成 `production_material_consumption` 与 `production_finished_goods_receipt`，方便报表和审计。
3. 生产完工流程已避免静默跳过，但还需要并发双击完工、重复提交、库存不足、批次冲突的压力验证。
4. 化工 BOM 仍需要继续补“替代料、损耗率、投料上下限、含量/浓度、危险品/批检报告、保密代号”这些真实化工厂细节。
