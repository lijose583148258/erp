# 图标与模块命名注册表收口记录 2026-04-22

## 1. 本轮目标

本轮不是大换皮，而是把全局导航从页面补丁式配置收口成统一注册表，降低后续菜单名、图标、权限、命令搜索和 Figma 设计稿之间脱钩的风险。

核心原则：

1. 不改模块 `id`。
2. 不改后端 API。
3. 不改 `appContent.tsx` 页面路由映射。
4. 不改 `permissions.ts` 权限点和角色授权。
5. 只改显示层：短名、全名、图标语义、搜索别名和命令面板权限过滤。

## 2. 改动范围

| 文件 | 改动 |
| --- | --- |
| `components/navigation/moduleRegistry.ts` | 新增模块注册表，统一维护 20 个模块的短名、全名、描述、别名、业务域、图标、颜色和角色可见性 |
| `components/Layout.tsx` | 移除页面内散落的 `moduleIconMap` 和菜单配置，改为读取 `moduleRegistry`；移动端底部导航统一使用 `ModuleBadge` |
| `components/CommandPalette.tsx` | 命令面板改为读取 `moduleRegistry`；导航命令按 `canOpenModule(currentUser, module.id)` 过滤；支持中文、英文、越南文别名搜索 |

## 4. 显示命名策略

采用三层命名：

| 层级 | 用途 | 示例 |
| --- | --- | --- |
| 短名 | 侧边栏、底部导航、命令面板标题 | `货抵结算` |
| 全名 | 页面标题、Figma 组件说明、后续详情标题 | `货抵支付 / 换货贸易` |
| 搜索别名 | 命令面板和后续联想搜索 | `货抵`、`换货`、`barter`、`goods payment` |

## 5. 设计策略

本轮保留爱劳达当前轻玻璃、圆角、蓝色主调风格，不做大面积换皮。

图标策略：

1. 图标按业务语义选型，不追求炫。
2. 颜色按业务域收敛，不再让每个模块像独立海报。
3. 桌面侧边栏和移动端底部导航统一使用同一个 `ModuleBadge`。
4. 后续 Figma 组件库应以 `moduleRegistry` 为源，建立 `ModuleIconTile` 组件。

## 7. 本轮发现并纠正的问题

第一版注册表遗漏了 `FlaskConical` import。`npm run build` 没有暴露这个问题，但 `npx tsx` 模块 ID 对齐检查在运行时导入阶段发现 `ReferenceError`。

修正后重新验证：

1. 模块 ID 对齐检查 PASS。
2. 前端构建 PASS。
3. 全量 human-flow PASS。
4. Phase 3 PASS。

这说明后续不能只信 build，仍需保留运行时导入检查和浏览器实点测。
