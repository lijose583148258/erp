# 阶段 3 库存调拨 UI 闭环收口记录

日期：2026-04-23

## 目标

把已经通过 API 验收的仓储库存调拨能力接入仓储独立页面，形成仓管员可操作的小闭环：

1. 库存台账搜索到真实库存。
2. 点击库存行的“调拨”入口。
3. 选择目标库位、填写数量和备注。
4. 保存后刷新库存台账。
5. 用 UI 回读和 API 回读共同确认数量没有丢失。

## 本轮改动

### 前端页面

- `pages/WarehouseWorkspace.tsx`
  - 新增库存调拨状态。
  - 新增调拨保存逻辑。
  - 保存成功后同时刷新仓库汇总和库存台账。

- `pages/warehouse/WarehouseInventoryPanel.tsx`
  - 库存台账增加“操作”列。
  - 每条库存余额增加“调拨”按钮。
  - 数量为 0 的库存不允许发起调拨。

- `pages/warehouse/WarehouseTransferDialog.tsx`
  - 新增独立调拨弹窗。
  - 显示产品、批次、当前库位、可调数量。
  - 支持目标库位、调拨数量、备注。
  - 前端阻止同库位调拨、空库位、非正数、超库存。

- `pages/warehouse/warehouseWorkspaceTypes.ts`
  - 新增 `TransferFormState`，避免调拨表单状态散落在页面里。

### 验收脚本

- `scripts/warehouse-transfer-browser-audit-v1.cjs`
  - 先用 API 种一条原料库存。
  - 再以仓管员身份进行浏览器登录。
  - 在仓储页面搜索库存并点击调拨。
  - 保存后切到目标库位做 UI 回读。
  - 最后用 API 回读源库位和目标库位数量。

- `package.json`
  - 新增 `audit:warehouse:transfer:browser`。

## 仍不能宣称的内容

这不代表整个系统已经“完美上线”。仍需要继续收口：

1. 调拨记录的业务查询页：当前主要通过库存台账和 API 报告验证，后续应增加调拨单/库存流水可视化查询。
2. 调拨审批策略：当前是仓管员直接调拨，后续可按金额、物料类型、库位类型增加审批规则。
3. 生产领料与仓储调拨联动：当前是库存层闭环，后续要让生产投料、半成品、成品入库的移动路径更清晰。
4. 长时运行：阶段 3 闸门通过不等于两个月真实运行，需要继续做日检和 soak 包。
