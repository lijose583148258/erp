# 资产调账权限包执行记录 2026-04-18

## 本包目标

- 收紧库存、资产、调账这类“金额/库存/过账/冲销”高风险接口。
- 保证本地单机稳定运行时，普通销售不能通过 API 读取全局库存或资产余额。
- 保证后续服务器部署时，财务与仓库在调账领域上具备后端强制分离。

## 修复内容

1. 资产与库存读取权限收口
   - `/api/assets/balance`
   - `/api/assets/balance/:id`
   - `/api/assets/history`
   - `/api/assets/batches`
   - `/api/assets/summaries`
   - `/api/assets/transactions`
   - 上述读取入口统一限制为 `admin / manager / warehouse / finance`。
   - 销售不能读取全局库存批次、资产余额、资产历史，避免越权推断库存和客户资产占用。

2. 调账按领域分权
   - `finance` 只能处理财务调账。
   - `warehouse` 只能处理 `inventory / production` 调账。
   - `admin / manager` 保持全局权限。
   - 调账列表、概要、详情、创建、过账、冲销都按领域做后端兜底。

3. 审计脚本补充
   - 新增 `scripts/asset-adjustment-permission-audit-v1.cjs`。
   - 验证销售读取库存/资产被拒。
   - 验证财务可读取库存批次结构。
   - 验证仓库不能创建财务调账。
   - 验证财务不能创建库存调账。
   - 验证仓库不能过账财务调账。

## 反思与纠偏

- 本包没有触碰 UI 风格，只收紧后端权限和验收脚本。
- 资产读取收口可能会让销售角色无法进入全局资产模块，这是符合成熟 ERP 的方向；销售如需看客户相关包装物，应走客户详情下的受控子资源，而不是全局资产入口。
- 调账分域是必须做的：财务不应该能随意改库存，仓库也不应该能随意改回款/应收。
- 继续推进方向：货抵协议/货抵批次、采购与销售订单关联、发货真实扣库、调账并发幂等仍需要继续做压力和冲突审计。
