# 52_P3 团队账号生命周期浏览器审计证据修正

日期：2026-06-19

## 本次目标

验证“给员工创建个人登录账号、分配角色、停用账号后禁止登录”的企业版账号闭环。前置 API 审计已通过，但浏览器审计在停用用户步骤超时，需要判断是产品问题还是审计断言问题。

## 诊断结论

失败截图显示账号停用实际已经成功：

- 目标账号行的操作按钮已从“停用”变成“启用”。
- 这表示当前账号状态已是停用。
- 原审计脚本等待表格中出现“已停用”文字，但当前紧凑表格布局不一定显示状态列，因此断言过脆。

## 调整内容

- `team-account-lifecycle-browser-audit-v1.cjs` 停用用户后，不再只等待可见状态文字。
- 改为等待目标账号操作按钮变成“启用”。
- 随后调用团队 API 回读，确认 `isActive === false`。

## 为什么这样更可靠

按钮状态代表 UI 已刷新到“当前为停用，可执行启用”的状态；API 回读证明数据库和后端状态一致。两层证据比单看某个表格列更稳定，也更符合企业版发布审计。

## 验证结果

- `npm run audit:team:account-lifecycle`：通过
- `npm run audit:auth:account-lifecycle`：通过
- `npm run audit:permissions:assignment`：通过
- `npm run audit:ai:isolation`：通过
- `npm run verify:phase3`：通过

## 后续注意

账号与权限类浏览器审计应尽量使用“UI 状态 + API 回读”双证据，不要依赖某一列在不同密度、不同屏幕下必然可见。
