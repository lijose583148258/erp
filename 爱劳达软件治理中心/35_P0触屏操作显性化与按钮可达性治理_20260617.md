# 35_P0触屏操作显性化与按钮可达性治理_20260617

## 治理结论

本轮继续执行 P0 可用性底座，目标是避免一线员工在 iPad、仓库平板、触摸屏电脑上找不到操作入口，或因为图标按钮过小导致误触。

本轮没有新增业务功能，只治理操作可达性：

- 去掉过宽的触摸端全局 `group-hover` 强制显示规则。
- 保留 `touch-actions-visible` 作为明确的业务操作显性化标记。
- 将发货资产卡片的 hover 覆盖层改为固定底部按钮。
- 给销售订单行操作按钮补齐 `aria-label`、`title` 和 44px 级别触控尺寸。
- 提升通用工具栏辅助说明文本对比度。

## 修改范围

- `index.css`
  - 移除 `[class*="group-hover:opacity-100"]` 的触摸端全局强制显示。
  - 保留 `.touch-actions-visible` 和 `.app-row-actions` 的触控尺寸兜底。

- `pages/shipping/ShippingAssetsPanel.tsx`
  - 移除资产卡片 hover 覆盖层。
  - 改为固定可见的“归还/收回”按钮。
  - 客户名称增加截断和 `title`，避免长名称撑爆卡片。

- `pages/SalesOrders.tsx`
  - 销售订单行操作按钮补充 `aria-label`。
  - 行操作按钮统一 `min-h-11 min-w-11`，减少触屏误触。
  - 佣金审核、确认订单、快速发货、完成订单补齐标题语义。

- `components/ui/ActionToolbar.tsx`
  - 辅助描述文本从浅灰提升到更稳的 `text-slate-500`。

## 反幻觉校准

联网复核后，本轮方向与成熟可用性标准一致：

- W3C WCAG 2.1 / 2.2 对触控目标尺寸提出了明确要求，常见建议是至少 44px 或满足最小目标尺寸与间距。
- ERP 可用性研究将“操作难懂、费力、阻碍任务完成”视为典型负反馈。
- 移动端没有可靠 hover，关键业务操作不能只依赖悬停显示。

因此本轮不是美化，而是降低误触、找不到按钮、触屏不可操作这些上线级风险。
