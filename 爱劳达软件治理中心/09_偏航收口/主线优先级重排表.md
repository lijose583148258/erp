# 主线优先级重排表

## 原始优先级

V1.0 方案的原始顺序是：

1. 数据库升级
2. 回款追踪
3. 生产管理
4. 财务报表
5. 部署优化

这个顺序是对的，原因很简单：

- 没有稳的数据库，后面所有能力都不稳
- 没有回款闭环，财务就缺最关键的现金流
- 没有生产管理，ERP 就不像工厂系统
- 没有财务报表，管理层看不到经营结果
- 没有部署优化，系统无法长期交付

## 现在建议的优先级

### 第一优先级：数据库升级与数据持久化

目标：

- SQLite 过渡到 PostgreSQL
- 单机与线上部署共用同一套数据模型
- 备份、恢复、迁移、初始化统一

### 第二优先级：回款闭环

目标：

- 回款录入
- 账期计划
- 逾期预警
- 催收记录
- 核销和纠偏

### 第三优先级：生产管理主链路

目标：

- BOM
- 工单
- 工序流转
- 质检
- 库存联动

### 第四优先级：财务报表

目标：

- 应收应付
- 利润
- 现金流
- 成本与损耗
- 导出

### 第五优先级：部署与稳定性

目标：

- Docker / compose
- Nginx
- 日志
- 备份
- 健康检查

## 建议降级为支撑线的事项

- 调账中心
- 模板中心
- 文档治理
- 代码结构梳理
- mock 适配
- 基础看板
- AI 辅助

这些都重要，但它们应该服务于主线，而不是替代主线。

## 执行建议

如果后续按包推进，建议直接按下面顺序：

1. 数据库升级
2. 回款闭环
3. 生产管理
4. 财务报表
5. 部署验收

调账中心和模板体系则作为每一阶段的支撑件同步维护。
