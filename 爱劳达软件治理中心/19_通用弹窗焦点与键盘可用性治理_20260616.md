# 通用弹窗焦点与键盘可用性治理

日期：2026-06-16

## 1. 本节点结论

本节点修复的是通用确认弹窗和原因填写弹窗的键盘可用性问题。此前项目已经有 `useDialogFocus`，但通用弹窗没有复用，导致后续业务弹窗容易出现焦点外逃、Esc 行为不一致、屏幕阅读器语义不足等问题。

## 2. 已执行修复

- `components/ui/ConfirmDialog.tsx`
  - 接入 `useDialogFocus`
  - 增加 `role="dialog"`
  - 增加 `aria-modal="true"`
  - 增加 `tabIndex={-1}`
  - 默认聚焦取消按钮，避免危险操作弹窗默认落在确认按钮上

- `components/ui/ReasonDialog.tsx`
  - 接入 `useDialogFocus`
  - 增加 `role="dialog"`
  - 增加 `aria-modal="true"`
  - 增加 `tabIndex={-1}`
  - 默认聚焦原因输入框

## 3. 三步法乱码核查

审查 `RoleManagementPanel.tsx` 时，PowerShell 输出层出现疑似乱码。按“三步法”处理：

1. 用 Node 按 UTF-8 读取真实文件。
2. 统计疑似 mojibake 字符和正常中文关键词。
3. 结论：文件真实内容不是乱码，终端显示不可作为改文案依据。

本节点没有基于终端乱码误改中文文案。

## 5. 联网反幻觉复核

本节点使用官方资料复核方向：

- W3C WAI-ARIA APG Modal Dialog Pattern：模态框打开后，Tab 和 Shift+Tab 应留在弹窗内部。
- WCAG 2.2 No Keyboard Trap：键盘用户必须能用键盘退出或离开组件，不应被困住。

本系统已有 `useDialogFocus` 支持 Esc 关闭和关闭后恢复原焦点，因此本节点选择复用现有工具，而不是引入新的弹窗库或复杂组件体系。

## 6. 后续注意

- 后续新增弹窗应优先复用 `ConfirmDialog`、`ReasonDialog` 或接入 `useDialogFocus`。
- 不建议在当前阶段一次性重写所有历史弹窗，风险大且容易制造新崩溃。
- 下一轮可按真实高频页面逐个治理：销售订单、采购收货、仓库出入库、财务调整。
