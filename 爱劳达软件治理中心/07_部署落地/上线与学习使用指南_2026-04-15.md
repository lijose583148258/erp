## 1. 当前真实结论

### 1.1 现在是否能运行

可以稳定启动，当前已经确认：

- `http://127.0.0.1:5001/health` 返回 200
- `http://127.0.0.1:5001/` 返回 200
- 前后端当前采用单入口运行链
- `tsc --noEmit` 通过
- `npm run build` 通过

### 1.2 现在是否适合直接正式商用上线

还不建议直接定义为“完美正式上线”。

当前更准确的判断是：

- 适合先做单机学习、内部试运行、局域网试用
- 适合先做 1 台服务器的小规模试运营
- 还不适合跳过验收，直接当成“全部链路零风险”的正式生产版

原因不是系统完全不能跑，而是还有几项收尾工作没有全部验完：

- 浏览器级人工点测还没有全部收官
- 历史数据里的部分审计记录需要继续核验
- 旧薄壳文件和历史桥接链还要继续清理

## 2. 当前唯一推荐运行链

当前版本不要再把多个入口混着用。

### 2.1 本地学习和日常使用

推荐入口：

- 双击 `F:\爱牢达\启动系统.bat`

或命令行：

```powershell
npm run start
```

它实际调用的是：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-stable-v2.ps1
```

### 2.2 当前正式访问地址

- 系统入口：`http://127.0.0.1:5001`
- 健康检查：`http://127.0.0.1:5001/health`
- 默认账号：`admin / admin123`

### 2.3 不再作为正式验收入口的地址

这些只当开发辅助，不当正式运行链：

- `5173`
- `3000`
- `3001`
- `3002`
- `4173`

原因很简单：

- 它们容易引到历史入口
- 容易把前端 dev 链和正式链混掉
- 容易出现“我看到的不是现在这套系统”的误判

## 3. 数据库与文件落点

### 3.1 当前稳定运行库

当前稳定运行链默认把运行数据库放在：

```text
D:\AilaoDaRuntime\stable.db
```

启动脚本会优先保证这个运行库可写、可复用、可备份。

### 3.2 备份位置

当前项目内有备份能力，建议重点关注：

- `F:\爱牢达\backups`
- `F:\爱牢达\backend\logs`
- `F:\爱牢达\logs`

### 3.3 你要记住的一条原则

不要直接把工作区里的旧库、临时库、历史归档库混着当正式库使用。

当前应该认定：

- 正式运行看 `D:\AilaoDaRuntime\stable.db`
- 工作区数据库只作为种子、对照、修复参考

## 4. 最稳妥的上线顺序

如果你现在就要开始上这套系统，我建议走三阶段。

### 阶段 A：单机学习

适合你自己或 1 到 3 个内部人员先熟悉系统。

做法：

1. 用当前稳定入口 `5001` 启动
2. 用默认管理员账号登录
3. 先只学习主链路
4. 每学完一个模块，立刻做真实保存和回读

优先学习顺序：

1. 登录与首页
2. 客户管理
3. 订单管理
4. 回款中心
5. 采购与发货
6. 资产与调账
7. 货抵支付

### 阶段 B：局域网或单服务器试运营

适合 5 到 20 人以内的小规模团队。

推荐方式：

- 1 台 Windows 服务器
- Node 直接运行后端并托管前端
- 继续使用 SQLite
- 每天固定备份数据库

优点：

- 和当前本地稳定运行链最一致
- 上线风险最低
- 出问题最容易恢复

不建议一上来就做的事：

- 多节点部署
- 负载均衡
- 复杂微服务拆分
- 过早切 PostgreSQL

### 阶段 C：正式外网运营

适合你把主链路、权限、对账、上传、审计都跑顺之后再做。

这时再考虑：

- 域名
- HTTPS
- 反向代理
- PostgreSQL
- 更严格的日志和备份策略

## 5. 当前最推荐的服务器上线方案

### 5.1 近期最稳方案

当前最推荐的是：

- 服务器安装 Node.js 18+
- 上传整个项目
- 安装依赖
- 构建前后端
- 用后端托管前端静态文件
- 对外只开放一个端口

### 5.2 推荐命令

```powershell
npm install
npm --prefix backend install
npm run build
npm run build:backend
```

然后设置环境变量后启动：

```powershell
$env:NODE_ENV = "production"
$env:PORT = "5001"
$env:SERVE_FRONTEND = "true"
$env:DATABASE_URL = "file:D:/AilaoDaRuntime/stable.db"
$env:CORS_ORIGIN = "https://你的域名"
node backend/dist/server.js
```

### 5.3 为什么我更推荐这条线

因为它和你当前已经验证能跑的稳定链最接近：

- 少一层容器变量
- 少一层前后端分离误差
- 更容易对照本地问题
- 更适合当前还在持续治理阶段的版本

## 6. Docker 方案什么时候用

Docker 不是不能用，但我建议放在第二阶段之后。

适合条件：

- 你已经确认单服务器直跑稳定
- 你需要标准化部署
- 你愿意一起把 CORS、volume、反向代理再验一轮

当前 `docker-compose.yml` 采用的是：

- `web` 容器对外 `8080`
- `backend` 容器跑 `5000`
- 前端由 Nginx 托管
- `/api` 反代到后端

这条线后面可以继续用，但今天如果目标是“尽快稳上线”，优先级不如单服务直跑。

## 7. 上线前必须完成的检查

真正上线前，最少要过这份清单。

### P0 必做

1. 登录正常
2. 客户新增后可回读
3. 订单新增后可回读
4. 回款录入后金额正确
5. 上传链路至少测试 1 次
6. 导出链路至少测试 1 次
7. 数据库备份能生成
8. 用备份恢复一次测试库

### P1 强烈建议

1. 三语言切换至少逐页抽测
2. 客户池分配、收回、公海释放走一遍
3. 单客户资产余额、客户导出再现场验证一轮
4. 浏览器级 smoke 再补一轮

### P2 正式外网前最好做完

1. 域名和 HTTPS
2. 强密码和正式 JWT 密钥
3. 管理员账号改密
4. 角色权限按真实人员配置
5. 制定每日备份和每周恢复演练

## 8. 你怎么开始学习使用它

不要一上来试所有模块。正确方式是按角色学习。

### 8.1 你先学管理员视角

目标：

- 知道系统有哪些模块
- 知道客户、订单、回款、采购、发货、资产之间怎么串起来
- 知道哪里看日志、哪里看审计、哪里做备份

建议学习顺序：

1. 登录
2. 首页看总览
3. 客户模块看主数据
4. 新建一条客户
5. 新建一条订单
6. 去回款中心录一笔
7. 去资产或调账页看回读

### 8.2 再学业务员视角

目标：

- 能建客户
- 能录联系人和地址
- 能查自己的客户池
- 能跟单、看回款、看交付状态

### 8.3 再学财务和仓储视角

财务重点：

- 回款
- 调账
- 风险
- 导出

仓储或履约重点：

- 采购
- 出货
- 物流
- 换货或货抵

### 8.4 学习时最重要的方法

每学一个动作，都做四步：

1. 新增
2. 保存
3. 刷新
4. 回读核对

这样最容易尽早发现“表面成功、实际丢数据”的问题。

如果你问我“现在该怎么推进最稳”，我的建议是：

## 10. 当前一句话判断

当前版本已经可以作为：

- 学习版
- 内部试运行版
- 单服务器小规模试运营版

但还不能诚实地称为：

- 完全零风险的正式生产版

真正要到“更放心正式上线”，还差最后一轮浏览器级验收、历史数据核验和残留桥接清理。
