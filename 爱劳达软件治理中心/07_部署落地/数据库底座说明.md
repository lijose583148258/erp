# 数据库底座说明

这份说明对应当前“包2：数据库底座”。

## 当前策略

- 先以 SQLite 文件模式跑通单机和 Docker 线上部署
- 通过统一的管理命令完成准备、状态查看、备份和恢复
- 后续如果切换 PostgreSQL，只需要把运行配置和 Prisma 数据源切换掉，不改变业务模块结构

## 统一命令

当前只保留 `db:manage` 作为主入口，其他 `db:*` 都是薄封装。

在仓库根目录执行：

```bash
npm run db:manage -- prepare
npm run db:manage -- status
npm run db:manage -- backup
npm run db:manage -- seed
npm run db:manage -- restore backup-YYYY-MM-DDTHH-mm-ss-sssZ.db
```

## 命令含义

- `prepare`：创建 SQLite 目录和备份目录，并输出当前数据库状态
- `status`：查看数据库是否存在、备份数量、最新备份时间
- `backup`：立即创建一个新的数据库备份文件
- `seed`：初始化默认用户和示例数据
- `restore`：从指定备份文件恢复数据库

## 配套脚本

- `npm run db:seed`：初始化种子数据
- `npm run dev:backend`：启动后端开发服务
- `npm run start:backend`：启动后端生产服务

## 运行建议

- 单机使用时，先执行 `prepare` 和 `seed`
- 正式恢复前，先停掉后端服务，再执行 `restore`
- Docker 部署时，数据库文件、备份目录和日志目录都应挂载到卷

## Deprecated Commands

以下旧入口已不再作为主线使用：

- `db:init`
- `db:generate`
- `db:create`
- 旧的多租户迁移脚本入口
