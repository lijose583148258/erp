# 爱劳达 ERP+CRM 服务器正式上线操作手册

> 更新日期：2026-04-15
> 适用对象：系统管理员、实施人员、运维人员
> 目标：按当前真实稳定链，把系统部署到一台服务器并可恢复、可维护

---

## 1. 本手册适用的上线方式

本手册只针对当前最稳的上线方式：

- 1 台 Windows 服务器
- Node.js 直接运行
- 后端托管前端静态文件
- SQLite 作为当前阶段正式运行库
- 对外只暴露一个系统入口

不适用范围：

- 多节点部署
- Kubernetes
- 负载均衡
- 前后端分离多域名架构
- PostgreSQL 高并发版本

---

## 2. 上线前准备

### 2.1 服务器最低建议

- Windows Server 2019 或 2022
- 4 核 CPU
- 8GB 内存
- 80GB 以上磁盘
- 能访问外网下载安装 Node.js

### 2.2 必装软件

1. Node.js 18+
2. npm
3. Git
4. 7-Zip 或同类解压工具

### 2.3 建议目录

```text
D:\deploy\ailao\
D:\AilaoDaRuntime\
D:\AilaoDaRuntime\backups\
```

说明：

- `D:\deploy\ailao\` 放项目代码
- `D:\AilaoDaRuntime\stable.db` 放正式运行库
- `D:\AilaoDaRuntime\backups\` 放手工备份和应急恢复文件

---

## 3. 首次部署步骤

### 3.1 上传代码

把当前工作区完整上传到：

```text
D:\deploy\ailao\
```

### 3.2 安装依赖

进入项目根目录：

```powershell
cd D:\deploy\ailao
npm install
npm --prefix backend install
```

### 3.3 构建前后端

```powershell
npm run build
npm run build:backend
```

### 3.4 创建正式运行目录

```powershell
New-Item -ItemType Directory -Force -Path D:\AilaoDaRuntime | Out-Null
New-Item -ItemType Directory -Force -Path D:\AilaoDaRuntime\backups | Out-Null
```

### 3.5 准备数据库

如果是首次上线，有两种方式：

1. 从当前验证过的 `stable.db` 拷贝到服务器
2. 用当前工作区种子库初始化后，再导入业务样例

推荐第一种，因为更接近当前已验证运行链。

把库放到：

```text
D:\AilaoDaRuntime\stable.db
```

## 4. 正式启动命令

### 4.1 推荐环境变量

```powershell
$env:NODE_ENV = "production"
$env:PORT = "5001"
$env:SERVE_FRONTEND = "true"
$env:TRUST_PROXY = "true"
$env:DATABASE_URL = "file:D:/AilaoDaRuntime/stable.db"
$env:CORS_ORIGIN = "https://你的域名"
$env:JWT_SECRET = "请替换成正式强密钥"
$env:BACKUP_DIR = "D:/AilaoDaRuntime/backups"
$env:LOG_DIR = "D:/deploy/ailao/logs"
```

### 4.2 启动命令

```powershell
cd D:\deploy\ailao
node backend/dist/server.js
```

### 4.3 启动后检查

浏览器或命令行检查：

```powershell
Invoke-WebRequest http://127.0.0.1:5001/health -UseBasicParsing
Invoke-WebRequest http://127.0.0.1:5001/ -UseBasicParsing
```

通过标准：

- `/health` 返回 200
- `/` 返回 200
- 登录页可打开

## 5. 建议做成开机自启

当前阶段最简单稳妥的方式：

- 用 `schtasks` 或 Windows 任务计划程序
- 在服务器开机后自动执行启动脚本

建议先使用批处理或 PowerShell 包一层：

```powershell
cd D:\deploy\ailao
$env:NODE_ENV = "production"

$env:SERVE_FRONTEND = "true"
$env:TRUST_PROXY = "true"
```

## 6. 域名与反向代理

### 6.1 当前建议

如果要正式外网访问，建议：

- 域名先指向这台服务器
- 由 IIS 或 Nginx 做 80/443 反向代理
- 内部应用仍然跑在 `5001`

### 6.2 最重要的规则

外部用户只访问：

- `https://你的域名`

内部服务继续使用：

- `http://127.0.0.1:5001`

不要让用户直接用 `5001` 裸端口长期访问。

## 7. 上线当天的验收顺序

上线当天不要乱测，按下面顺序。

### 第一步：系统健康

1. 打开首页
2. 检查 `/health`
3. 登录管理员账号

### 第二步：主数据

1. 新建客户
2. 填一条联系人
3. 填一条地址
4. 保存后刷新回读

### 第三步：业务链

1. 建一条订单
2. 录一条回款
3. 查客户资产或余额
4. 导出一次

### 第四步：上传链

1. 上传一份样例文件
2. 刷新页面
3. 核对文件仍可读取

### 第五步：备份恢复

1. 触发一次手工备份
2. 复制备份到测试目录
3. 验证备份文件可被恢复使用

---

## 8. 每日运维动作

### 每天

1. 看系统是否能打开
2. 看 `health` 是否正常
3. 看当天是否有新备份
4. 抽查 1 条新增记录能否回读

### 每周

1. 做一次恢复演练
2. 抽查上传与导出
3. 抽查客户池流转
4. 抽查回款和调账

### 每次发版

1. 先备份数据库
2. 再替换代码
3. 再构建
4. 再启动
5. 再做最小回归验证

---

## 9. 故障时怎么处理

### 9.1 系统打不开

先查：

```powershell
netstat -ano | findstr :5001
```

再查：

```powershell
Invoke-WebRequest http://127.0.0.1:5001/health -UseBasicParsing
```

### 9.2 登录后全报错

优先怀疑：

- 数据库路径不对
- 数据库只读
- `JWT_SECRET` 或环境变量不一致

### 9.3 发布后页面异常

按这个顺序排查：

1. 是否重新执行了 `npm run build`
2. 是否重新执行了 `npm run build:backend`
3. 是否启动的是当前目录下的 `backend/dist/server.js`
4. 是否还是连到了旧数据库

---

## 10. 当前不建议做的事

1. 直接把开发端口 `5173` 暴露给用户
2. 多条启动链混着用
3. 一边修库一边正式录业务数据
4. 没有备份就直接升级
5. 现在就急着切 PostgreSQL

---

## 11. 上线完成后的标志

当下面这些都成立时，可以认为“服务器上线成功”：

1. 域名可访问
2. 登录正常
3. 客户新增可回读
4. 订单新增可回读
5. 回款金额正确
6. 上传正常
7. 导出正常
8. 备份正常
9. 第二天重启后仍能正常打开

---

不要跳过验收直接把它当成“零风险正式生产版”。
