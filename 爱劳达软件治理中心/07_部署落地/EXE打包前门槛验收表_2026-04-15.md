# EXE 打包前门槛验收表

> 更新日期：2026-04-15
> 目的：避免把仍在治理期的系统过早封装成更难排障的 EXE

---

## 1. 运行链门槛

- [ ] `npm run start` 可稳定启动
- [ ] 启动后固定落到 `http://127.0.0.1:5001`
- [ ] `/health` 持续正常
- [ ] 启动 30 次以上无随机换入口
- [ ] 运行库固定为同一正式路径

---

## 2. 数据门槛

- [ ] 客户新增后刷新可回读
- [ ] 联系人与地址新增后可回读
- [ ] 订单新增后可回读
- [ ] 回款录入后金额联动正确
- [ ] 货抵支付新增后可回读
- [ ] 上传后刷新可回读
- [ ] 导出文件有效

---

## 3. 恢复门槛

- [ ] 每天可生成备份
- [ ] 每周恢复演练成功
- [ ] 异常退出后可恢复
- [ ] 重启后仍进入正确入口
- [ ] 重启后仍连接正确数据库

---

## 4. UI 与语言门槛

- [ ] 登录页无乱码
- [ ] CRM 无乱码
- [ ] 回款中心无乱码
- [ ] 货抵支付无 `undefined`
- [ ] 中文 / 英文 / 越文切换正常
- [ ] 不再出现裸 HTML / CSS 丢失

---

## 5. 运维门槛

- [ ] 已明确数据库目录
- [ ] 已明确日志目录
- [ ] 已明确备份目录
- [ ] 已明确上传目录
- [ ] 已明确升级方式
- [ ] 已明确 EXE 是否内置 Node

---

## 6. 通过标准

只有当以上门槛全部通过，才建议进入 EXE 打包阶段。

否则更合理的做法是继续保持：

- 浏览器版
- 稳定启动链
- 本地准生产试运行
