# 货抵支付（Barter Payment）设计方案

## 1. 业务背景
为了提升爱牢达 ERP 系统的贸易灵活性，支持客户以物易物（如木材冲抵胶水款）的场景。系统需要将木材计方引擎并入财务核销流程，并建立非现金资产与订单金额的对冲逻辑。

## 2. 设计原则
- **高度集成**：计方引擎无缝嵌入支付界面。
- **追溯性**：每一笔货抵支付必须保留原始货物规格（长/宽/厚/件）。
- **核销闭环**：货抵金额自动更新订单 `paidAmount` 并同步客户账期状态。

## 3. 技术实现方案

### 3.1 数据库增强 (`schema.prisma`)
在 `PaymentRecord` 模型中增加 `barterMetadata` 字段：
```prisma
model PaymentRecord {
  // ... 原有字段
  method          String    // 增加 "barter" 类型
  barterMetadata  String?   // 存储 JSON 字符串：品名、规格(L*W*T)、单价、换算方数
}
```

### 3.2 计方引擎复用
复用 `backend/src/utils/TimberEngine.ts` 中的 `calculateCBM` 逻辑，在支付确认环节进行即时计算。

### 3.3 状态同步逻辑
更新 `CollectionStateService.recalculateOrderPaymentState`：
- 在统计 `verified` 状态的支付时，确保包含 `barter` 类型的金额。
- 联动审计日志，标记为 `PAYMENT_BARTER` 动作。

### 3.4 前端体验设计
- **动态表单**：选中支付方式为“货抵支付”后，动态展开木材规格输入框。
- **自动换算**：在输入规格后，界面即时显示换算出的立方数（CBM）及对应的金额占比。

## 4. 治理影响
- 本方案将木材模块从“僵尸代码”转化为系统的“贸易扩展组件”，实现了业务治理的闭环。
