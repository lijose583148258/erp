## 一、正名 .current/.live/.clean 代理文件

### 问题
页面组件采用"代理壳 + 后缀实体"双文件架构（如 `Samples.tsx` 只是 `export { default } from './Samples.current'`），导致：
- 模块解析多跳一层，增加构建和维护成本
- 开发者无法直观判断哪个文件是活跃实现
- IDE 跳转经常跳到空壳而非实体

### 操作

| 模块 | 原架构 | 正名后 | 删除的代理文件 |
|------|--------|--------|---------------|
| BarterWorkspace | `.tsx` (壳) → `.clean.tsx` (实体) + `.current.tsx` (壳) | `.tsx` (直接实体) | `.clean.tsx`, `.current.tsx` |
| Samples | `.tsx` (壳) → `.current.tsx` (实体) | `.tsx` (直接实体) | `.current.tsx` |
| TeamManagement | `.tsx` (壳) → `.current.tsx` (实体) | `.tsx` (直接实体) | `.current.tsx` |
| SalesOrderColumns | `.tsx` (壳) → `.live.tsx` (实体) | `.tsx` (直接实体) | `.live.tsx` |
| CRMCreateModal | `.tsx` (壳) → `.live.tsx` (实体) | `.tsx` (直接实体) | `.live.tsx` |
| CRMCustomerDrawer | `.tsx` (壳) → `.live.tsx` (实体) | `.tsx` (直接实体) | `.live.tsx` |
| useCRM hooks | `.ts` + `.live.tsx` + `.current.ts` → `.tsx` | `.ts` → `.tsx`（保留一层转发） | `.live.tsx`, `.current.ts` |
| team.controller | `.current.ts` → `.ts` | 直接使用 `.ts` | `.current.ts` + 4个dist产物 |
| team.service | `.current.ts` → `.ts` | 直接使用 `.ts` | `.current.ts` |

**共消除 13 个代理/后缀文件**

### 验证
- 构建：✓ 2901 模块 · 5.85s · 零警告
- 后端 tsc：✓ 零错误

## 六、与稳定运行相关的决策说明

| 决策 | 理由 |
|------|------|
| `fix-db` 迁入 `backend/scripts/` 而非删除 | 10万条数据本地运行时 SQLite 可能需要 VACUUM/修复 |
| `runtime-db/` 归档而非删除 | 保留历次 db 快照，2 个月内如需回滚可取回 |
| `backups/` 目录保留 | `BackupService` 每 24h 自动备份，30 天自动清理 |
| `logs/` 目录保留 | Winston 日志输出，问题定位必备 |
| 创建 `.gitignore` | 防止运行时数据意外提交造成仓库膨胀 |
