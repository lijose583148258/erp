# CRM极致细节规范 · 第六篇
**非CRM模块 — 完整页面级组装方案**

> 前五篇给出的是"组件级"规范——单个按钮、单个Tag、单个表单的像素定义。
> 但用户实际看到的是"一整个页面"，组件之间如何拼装、留多少间距、
> 哪个区域优先级最高，这些"页面级"决策前五篇没有覆盖。
> 本篇为CRM之外的全部模块给出完整页面组装方案：
> 区域划分、栅格比例、组件引用关系、首屏优先级。
> 每个模块都标注"引用第几篇第几节的哪个组件"，确保组件库与页面是同一套体系。

### 1.4 关键页面级决策

**为什么信息条(32px)在Step2而不是Step1显示止货警示？**
因为Step2是即将发货的实质内容录入阶段，止货警示需要在用户填完明细、
准备提交前再次出现一次，形成"双重确认"而不打断Step1的基础信息填写。

**表格区域的flex-1意味着什么？**
Header(56)+步骤(40)+信息条(32)+工具栏(32)+合计(100)+Footer(64) = 324px固定高度，
剩余 `92vh - 324px` 全部分配给表格区域，超出则表格内部滚动（虚拟滚动生效）。

### 2.4 关键页面级决策

**为什么库存预检和质检记录并排（双栏）而不是上下堆叠？**
两者在工单生命周期的不同阶段都重要（预检在投料前，质检在反应后），
并排展示让用户在工单进行的任何阶段都能看到"全局状态"，避免Tab切换。

**进度条节点动效与操作历史时间线动效的联动**：
当前步骤(`active`)在进度条上呼吸，时间线中对应条目的圆点也呼吸——
两处必须用同一个数据驱动（`currentStepId`），不能各自独立判断，
否则可能出现进度条显示"反应中"但时间线显示"投料中"的状态不一致。

## 十四、全模块页面级共性规则

### 14.1 页面顶部固定区高度规范

```
所有模块页面的固定头部区域统一遵循:
  统计卡组高度: 80px (含12px间距)
  工具栏/筛选行高度: 44px
  Tab切换行高度: 44px (含8px上下margin)
  
固定头部总高度建议不超过 80+44+44 = 168px，
超过此高度时考虑将统计卡组改为可折叠("收起统计"按钮)
```

### 14.2 列表页与详情页的转场

```css
/* 全模块统一: 列表行点击→详情页，使用"展开"而非"跳转"的视觉隐喻 */
@keyframes detail-expand-in {
  from { opacity: 0; transform: scale(0.98) translateY(8px); }
  to   { opacity: 1; transform: scale(1) translateY(0); }
}
.detail-page-container {
  animation: detail-expand-in var(--duration-slow) var(--ease-decelerate);
}
/* 与第三篇Modal进入动效相同曲线，保持"打开内容"的统一手感 */
```

### 14.3 跨模块审批条复用原则

调整中心、RMA、收货差异、样品审核——四个模块都用到"审批/审核"模式，
但视觉组件只有两套：
- **状态条样式**（第三篇3.1-3.5）：用于调整中心、RMA、收货差异（正式审批流）
- **卡片内审核行**（第四篇2.3）：用于样品（轻量审核，无需独立审批记录）

区分原则：**是否需要审批历史记录**。需要留痕的用状态条+`approvalStatus`字段；
不需要留痕、仅是当前状态切换的用卡片内联按钮。

### 14.4 所有"双栏并排"页面的响应式降级

工单详情页(库存预检+质检)、库位树+库存明细等双栏布局，
在窗口宽度 < 1024px 时统一降级为上下堆叠：
```css
.dual-panel-layout {
  display: grid;
  grid-template-columns: 1fr 1fr;
  gap: 16px;
}
@media (max-width: 1024px) {
  .dual-panel-layout {
    grid-template-columns: 1fr;
  }
}
```
