# 跨国贸易 ERP 企业版进一步优化蓝图

日期：2026-06-17

## 0. 本轮结论

不要推倒重构，也不要继续堆功能。

当前最优路线是：保留现有企业版工程底座，把最原始前端版本里的“高密度业务工作台”吸收回来，再补上跨国贸易 ERP 必须具备的国家、币种、税务、组织、仓库、物流、权限和弱网细节。

一句话目标：

> 让销售、财务、仓库、生产、管理员、经销商打开系统后，马上知道有什么异常、下一步点哪里、填错了错在哪里、操作后能不能追溯。

## 1. 三条设计原则

### 1.1 当前版保留什么

- 登录、强制改密、账号角色、权限视角、审计日志。
- 模块注册、懒加载、错误边界、发布冻结、打包治理。
- 真实后端服务、API 回读、运行时健康检查。
- 现有 CRM、订单、回款、仓储、生产、采购、发货、货抵、财务模块边界。

### 1.2 原始版吸收什么

- Dashboard 一屏显示风险和待办，不只是漂亮数字。
- 客户详情一屏显示信用、逾期、止货、催收、跟进、账务快照。
- 订单、库存、生产、催收都有直接动作入口。
- 页面密度高、少废话、少跳转、少装饰。

### 1.3 跨国版必须补什么

- 国家、组织、语言、币种、汇率、税号、地址、银行账户、时区。
- 中国总部、越南团队、海外仓、经销商、直营/渠道的数据范围。
- 原币、本位币、交易汇率、手续费、汇兑差额。
- 国际物流节点、清关、MSDS、COA、装箱单、发票附件。
- 越南语和英文长文本不撑爆布局。

## 2. P0：先治理高频可用性底座

P0 只做低风险、全局收益高的事，不大拆后端。

### 2.1 表格统一

目标：所有高频业务表格适合录单、查账、盘点、催收。

必须优化：

- 默认紧凑行高。
- 表头 sticky。
- 首列或关键业务列可固定。
- 操作列固定在右侧。
- 触屏设备操作按钮永远可见。
- 长文本默认截断，提供完整查看。
- 金额、数量、日期、状态格式统一。
- 分页数量、列显示、筛选条件尽量记忆。

涉及优先页面：

- CRM 客户列表。
- 销售订单列表。
- 回款逾期清单。
- 仓储库存台账。
- 生产工单列表。
- 采购订单列表。

验收标准：

- 1366px 宽度下一屏能看到主要字段和操作列。
- iPad / 触屏模式不依赖 hover 才能操作。
- 越南语长客户名、长批次号、长物流单号不会撑破表格。

### 2.2 表单统一

目标：减少误填、漏填、重复提交。

必须优化：

- 必填项提交前提示。
- 字符长度显示，如 42/50。
- 数量、金额、折扣、税率、汇率、手续费限制非法值。
- 明细行错误定位到具体行和字段。
- 保存失败不清空用户输入。
- 关闭弹窗前提示未保存。
- 创建成功显示单号，并支持跳转查看。
- 保存中禁用按钮，防重复提交。

优先表单：

- 新建客户。
- 新建订单。
- 登记回款。
- 仓库入库/调拨。
- 工单创建/完工。
- 采购收货。

验收标准：

- 不再出现只有“参数错误”的提示。
- 至少能提示“第 N 行、哪个字段、为什么错、下一步怎么改”。

### 2.3 状态徽章统一

目标：危险状态醒目、普通状态克制。

必须统一：

- 逾期、止货、信用拦截、库存不足、质检不合格、发货异常用强警示。
- 草稿、处理中、待确认、已完成用中性样式。
- 不能只靠颜色表达状态，必须有文字。
- 危险操作必须二次确认并填写原因。

优先状态：

- 客户信用状态。
- 订单回款状态。
- 发货状态。
- 库存可用状态。
- 工单状态。
- 质检状态。

## 3. P1：恢复高密度业务工作台

P1 不新增大模块，只增强六个核心工作台。

### 3.1 Dashboard：跨国经营风险驾驶舱

首屏必须回答：

- 今天有什么必须处理？
- 哪些风险会影响发货、收款、库存、生产？
- 中国、越南、经销商分别哪里异常？

首屏卡片：

- 今日待确认订单。
- 逾期回款金额。
- 止货客户数。
- 低库存 SKU。
- 在途物流异常。
- 待质检工单。
- 待完工工单。
- 待审批/待复核事项。

卡片要求：

- 每个数字都能点击进入对应列表。
- 每个风险卡显示前 3 条真实对象。
- 不能只展示总数。

### 3.2 CRM：客户详情恢复业务密度

客户详情首屏必须显示：

- 客户名称、国家、语言、币种、税号。
- 所属销售、业务线、直营/渠道。
- 信用额度、已用额度、逾期金额、逾期天数。
- 信用拦截、发货拦截、止货原因。
- 最近订单。
- 最近回款。
- 最近跟进。
- 下一步动作。

下一步动作区：

- 新建订单。
- 登记跟进。
- 催收提醒。
- 登记承诺付款。
- 进入回款中心。
- 信用止货。
- 解除止货。

禁止：

- 不在 CRM 里重复实现真实回款核销。
- 不在 CRM 里重复实现真实发货。
- CRM 只提供上下文和入口，业务过账仍回到对应中心。

### 3.3 销售订单：订单行工作台

订单行必须显示：

- 客户国家。
- 交易币种。
- 原币金额。
- 本位币折算金额。
- 汇率来源。
- 回款状态。
- 发货状态。
- 是否逾期。
- 是否止货/信用拦截。
- 是否库存不足。

快捷动作：

- 查看历史。
- 登记回款入口。
- 发货入口。
- 复制订单。
- 生成采购需求。

禁止：

- 订单页直接伪造财务核销。
- 订单页直接改库存余额。
- 订单确认后关键字段无审计修改。

### 3.4 回款中心：跨币种闭环

必须显示和处理：

- 订单原币应收。
- 实收币种。
- 交易汇率。
- 本位币折算。
- 手续费。
- 汇兑差额。
- 短款/超付。
- 承诺付款。
- 争议金额。
- 催收记录。
- 财务核验状态。

验收标准：

- 一笔部分回款能回读订单余额。
- 一笔跨币种回款能看到汇率和差额。
- 催收动作能追溯到客户、订单、操作人、时间。

### 3.5 仓储：跨国库存可用性

库存必须区分：

- 国家。
- 仓库。
- 库位。
- 批次。
- 在库。
- 在途。
- 冻结。
- 质检中。
- 已占用。
- 可用库存。
- 安全库存。

仓库人员首屏要看到：

- 哪些能发。
- 哪些不能发。
- 哪些低于安全库存。
- 哪些批次异常。
- 哪些调拨在途。

禁止：

- 只显示总库存。
- 无来源直接改库存。
- 调拨一步完成且无在途状态。

### 3.6 生产：轻量生产闭环，不伪装 MES

当前阶段只做 ERP 内的轻量生产链：

- BOM / 配方。
- 工单。
- 备料。
- 生产中。
- 质检。
- 完工扣料。
- 成品入库。
- 批次追溯。

必须增强：

- 工单锁定 BOM 版本快照。
- 完工幂等，重复提交不能重复扣料。
- 耗料区分标准耗料、实际耗料、替代料、损耗、返工补料。
- 质检不合格批次不能销售发货，除非让步审批。
- 工单结案页显示原料扣减、成品入库、成本台账、库存余额。

禁止：

- 宣称完整 MRP / APS / MES。
- 把复杂车间排程硬塞进 ERP。

## 4. P2：跨国业务模型补强

P2 开始触及模型和后端，但仍以“补上下文”为主，不做大爆炸重构。

### 4.1 主数据国际化

客户、供应商、员工、仓库、物料必须补齐：

- countryCode。
- defaultLanguage。
- defaultCurrency。
- taxId / businessLicenseNo。
- addressFormat。
- bankAccount。
- organizationId。
- businessSegment。

物料主数据补齐：

- materialCode。
- nameZh / nameEn / nameVi。
- spec。
- baseUnit。
- purchaseUnit。
- salesUnit。
- productionUnit。
- unitConversionRate。
- dangerousGoodsFlag。
- MSDS / COA 附件状态。

### 4.2 多币种规则

订单、采购、回款、财务必须保留：

- transactionCurrency。
- transactionAmount。
- baseCurrency。
- baseAmount。
- exchangeRate。
- exchangeRateDate。
- exchangeRateSource。

财务必须区分：

- 真实回款。
- 应收调整。
- 手续费。
- 汇兑损益。
- 坏账。
- 折让。

### 4.3 数据范围

账号授权要从“角色能做什么”升级为“这个人能看哪些数据”。

数据范围层级：

- 全集团。
- 指定国家。
- 指定公司/组织。
- 指定部门。
- 本人客户。
- 指定客户池。
- 指定仓库。
- 指定经销商。

管理员页面必须提供：

- 权限摘要。
- 高风险权限标识。
- 数据范围预览。
- 模拟该用户视角。

## 5. P3：发布冻结与企业版验收

P3 不再主要写功能，而是证明系统能交付。

### 5.1 角色化验收

至少跑通以下角色：

- 超级管理员。
- 中国总部经理。
- 越南销售。
- 财务。
- 仓库。
- 生产。
- 经销商。

每个角色验收：

- 登录。
- 首次改密。
- 默认首页。
- 可见模块。
- 不可见模块。
- 新增/编辑/查询。
- 权限拒绝提示。
- 刷新后数据回读。

### 5.2 核心链路验收

必须跑通：

- 客户建档 -> 建订单 -> 回款登记 -> 财务核验 -> 订单余额回读。
- 订单确认 -> 发货 -> 签收 -> 库存流水回读。
- 采购收货 -> 入库 -> 库存可用量回读。
- BOM -> 工单 -> 质检 -> 完工扣料 -> 成品入库 -> 批次追溯。
- 低库存 -> 采购建议/提醒 -> 采购收货后解除预警。

### 5.3 冻结包标准

打包前必须输出：

- 包路径。
- SHA256。
- 构建时间。
- Git commit。
- 默认端口。
- 数据库位置。
- 默认管理员说明。
- 回滚包路径。
- 已知限制。
- 验收结果。

冻结后规则：

- 任何源码变更都会使冻结失效。
- 要继续改，就重新 build、重新运行、重新验收、重新打包。

## 6. 需要优化还是重构的判断

### 只优化

满足以下情况，只做小范围优化：

- 页面能跑通，但密度低、长文本溢出、错误提示差。
- 业务逻辑正确，只是入口不清楚。
- 数据字段已存在，只是没有展示或没有聚合。
- 问题能放到公共组件或页面局部配置解决。

### 需要重构

满足以下情况，进入重构评审：

- 同一业务在多个页面重复录入并产生不一致。
- 页面靠用户记忆流程顺序才能完成闭环。
- 金额、库存、回款、发货、成本的口径不一致。
- 权限判断只在前端隐藏，没有后端拒绝。
- 数据模型缺少国家、币种、组织、仓库等关键上下文。
- 发布脚本无法证明源码、dist、运行目录、压缩包一致。

## 7. 禁止做法

- 为了视觉效果牺牲表格密度。
- 为了“干净”隐藏触屏关键操作。
- 每个页面单独写一套表格、表单、状态徽章。
- 页面写大段说明文字代替清晰流程。
- 把演示数据当真实业务闭环。
- 在销售订单、CRM、财务、仓储之间重复过账。
- 未经过回读验证就宣称修复成功。
- 冻结后改代码却不重新打包。

## 8. 建议执行顺序

### 第一批：P0 可用性底座

1. 表格密度和固定列统一。
2. 表单错误定位和长度限制统一。
3. 状态徽章口径统一。
4. 触屏操作可见性复核。
5. 文字缩放 100%-125% 回归。

### 第二批：P1 六个核心工作台

1. Dashboard 风险驾驶舱。
2. CRM 客户下一步动作。
3. 销售订单行工作台。
4. 回款跨币种闭环。
5. 仓储可用库存与批次。
6. 生产轻量闭环。

### 第三批：P2 跨国模型补强

1. 国家、语言、币种、税号、地址、银行字段。
2. 原币、本位币、汇率、汇差。
3. 组织、国家、仓库、经销商数据范围。
4. 国际物流和贸易附件状态。

### 第四批：P3 企业版冻结

1. 角色化浏览器验收。
2. 核心业务链路验收。
3. 冻结包 manifest。
4. 保留一个回滚包。
5. 输出企业版测试包。

## 9. 本蓝图与原始版本的关系

原始版本不能作为生产代码回退目标。

但原始版本证明了一个正确产品方向：

- 工作台要聚合风险。
- 客户详情要聚合动作。
- 订单、库存、生产、催收要少跳转。
- 业务人员需要的是“下一步做什么”，不是一堆漂亮模块。

当前企业版要做的是把这个产品方向接到真实后端、权限、跨国字段和发布冻结上。
