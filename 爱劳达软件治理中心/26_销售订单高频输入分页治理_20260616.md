# 销售订单高频输入分页治理

日期：2026-06-16

## 1. 本轮目标

根据 `25_成熟产品体验纠偏与执行准绳_20260616.md`，后续治理需要从“账号角色授权”回到高频业务页面。

本轮选择销售订单模块，是因为多份审计文件都把它列为高频核心入口：

- `爱老大全局分模块打磨方案.md`：销售订单是系统核心枢纽，字段和状态会联动物流、催收、财务。
- `爱劳达V2精准审计报告.md`：指出订单行表格在大量行时容易冻结，建议超过 50 行分页。
- `CRM极致细节规范_第六篇.md`：要求销售订单 Step2 明细区域应给表格足够空间，超 50 行应分页或虚拟滚动。

## 2. 现状复核

本轮没有重复做“客户选择器改 Combobox”，因为当前源码已经具备：

- `pages/sales-orders/SalesOrderHeaderForm.tsx`
- 客户选择器使用 `role="combobox"`。
- 支持客户名称、多语言名称、别名搜索。
- 支持键盘上下选择、Enter 选中、Escape 关闭。
- 账期已限制到 `1-365`。
- 备注已有 `1000` 字符计数和超限拦截。

因此 V2 审计报告里的部分问题已经被后续改动覆盖，不能再按旧报告重复改。

## 3. 已执行修复

文件：

- `pages/sales-orders/SalesOrderLineGrid.tsx`

修复内容：

1. 新增 `rowsPerPage = 50`。
2. 当订单明细超过 50 行时，只渲染当前页的 50 行受控输入。
3. 新增上一页/下一页分页条。
4. 分页只影响显示层，不改变 `formData.items` 数据结构。
5. 每个输入仍按原始下标 `index` 写回，保存载荷仍使用完整订单明细。
6. 粘贴 Excel 导入后回到第一页，避免导入后停留在不存在的分页位置。

## 4. 为什么这样改

这不是为了增加功能，而是为了防止高频录单场景卡顿。

原表格在 100+ 行时会同时渲染大量受控输入：

- 品名
- 规格
- 数量
- 单位
- 单价
- 折扣
- 税额
- 尺寸模式字段

每行约 7-10 个输入，200 行时就是上千个受控输入。对于普通办公电脑和远程桌面环境，这是明显的可用性风险。

本轮不引入虚拟滚动库，不重写表格，只做分页，是为了保持维护成本低。
