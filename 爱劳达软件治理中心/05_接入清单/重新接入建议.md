# 重新接入建议

## 建议按这个顺序重新接上

### 1. 先定主线

- 只保留一个“当前主项目”视图。
- 旧树 `Chemerp_v1.0` 先归档，不参与日常开发判断。
- 方案书、完成报告、评估报告分层存放，避免互相覆盖口径。

### 2. 先补数据库升级

- 把 SQLite 路线和 PostgreSQL 路线彻底定下来。
- 若要按 V1.0 继续，数据库升级应作为第一优先级。
- 迁移后再谈正式回款、财务、生产，否则后面的数据结构会反复返工。

### 3. 接回款追踪闭环

- 让 `PaymentRecord`、`ContractMilestone`、`collectionService.ts`、`dashboard.routes.ts` 真正形成一个闭环。
- 补上回款看板、逾期提醒、核销流程、催收任务。
- 把“已有模型”变成“可用流程”。

### 4. 再补生产管理

- 补 BOM、工单、工序、质检、库存联动。
- 这是目前最大块的空白。
- 不建议和财务报表同时硬冲，先把生产主链路接通。

### 5. 最后做财务报表和部署

- 财务报表要和回款、订单、成本、币种联动。
- 部署要把 Docker、Nginx、备份、监控、恢复策略收口。
- 这一步更像收尾，而不是重新造主干。

## 现在最值得优先接上的文件

- `backend/prisma/schema.prisma`
- `backend/src/controllers/order.controller.ts`
- `backend/src/routes/dashboard.routes.ts`
- `services/collectionService.ts`
- `services/dashboard.service.ts`
- `pages/Dashboard.tsx`

## 重新开始的正确方式

不是推倒重来，而是：

1. 先统一“当前主版本”
2. 再确认数据库底座
3. 接通回款闭环
4. 补生产
5. 补财务
6. 最后部署收口
