# 53_P3 干净运行包镜像同步治理

日期：2026-06-19

## 本次目标

继续验证企业版封装是否真的可迁移、可启动、可维护。干净运行包审计曾出现一次健康检查失败，进一步排查发现 E 盘运行包在原地刷新时可能保留旧的前端 hash 资产。

## 诊断结论

- 后端 `/health` 正常。
- F 盘稳定包桌面壳健康检查正常。
- E 盘干净运行包重跑后通过，说明前一次失败与运行切换期间的资产请求有关。
- 但 E 盘原地刷新确实可能残留旧 `dist/assets` 文件，不符合“纯净包”预期。

## 调整内容

`deploy-clean-runtime-package-v1.ps1` 增加受保护的镜像同步：

- `dist`
- `backend/dist`
- `backend/prisma`
- `scripts`

这些目录使用 `robocopy /MIR`，并在执行前校验目标路径必须位于 `E:\爱劳达纯净系统` 之内。`backend/node_modules` 仍使用普通复制，避免因为大量依赖文件增加部署失败面。

## 风险控制

- 不删除运行包外部文件。
- 不触碰 `D:\AilaoDaRuntime` 业务数据库、上传、备份、日志。
- 不改变启动脚本和业务代码。
- 只让干净运行包内的可再生程序文件与稳定包保持一致。

## 验证结果

- `npm run deploy:clean-runtime`：通过
- F/E `dist/assets` 文件名对比：一致
- `npm run audit:clean-runtime`：通过
- `npm run audit:desktop-shell`：通过
- `npm run audit:backup-restore`：通过
- `npm run audit:phase3:feature-preservation`：通过

## 后续注意

如果 E 盘目录被进程占用导致只能原地刷新，必须继续保持镜像同步，避免旧构建产物长期残留并干扰发布审计。
