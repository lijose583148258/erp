# 通用输入长度与溢出治理

日期：2026-06-16

## 1. 本节点结论

本节点处理的是“输入框可无限输入，超长客户名、供应商名、地址、备注容易撑坏布局或造成保存后显示异常”的可用性问题。

修复原则：不全局硬限制，不影响未评估字段；只给明确业务边界的高频字段加 `maxLength` 和字符计数。

PowerShell 对采购和供应商文件显示过疑似乱码。本节点按三步法处理：

1. 用 Node 按 UTF-8 读取真实文件。
2. 统计 `�` 和常见 mojibake 片段。
3. 结果：替换字符为 0，疑似 mojibake 片段为 0，中文关键词真实存在。

因此本节点没有基于终端显示去改文案。

## 5. 联网反幻觉复核

本节点使用官方与成熟设计系统资料复核方向：

- W3C WCAG 2.2 Input Assistance：表单应帮助用户避免和修正错误。
- W3C WCAG 3.3.1 Error Identification：检测到输入错误时，应以文本说明错误。
- GOV.UK Design System Character Count：对有限制的文本输入，字符计数能让用户提前知道剩余空间。
- USWDS Character Count：字符计数组件需要结合项目实际场景测试，不能只看组件孤立状态。

对应到本系统，字段长度限制不能只在后端报错，而应在用户录入时给出即时反馈；本节点方向正确，但仍需按模块继续覆盖更多高频表单。

## 6. 后续注意

- 不要给所有字段统一套一个默认长度，容易误伤业务。
- 后续优先覆盖销售订单行、仓库批次、收发货备注、CRM 联系人。
- 如果后端已有字段长度约束，前端上限应与后端保持一致。
